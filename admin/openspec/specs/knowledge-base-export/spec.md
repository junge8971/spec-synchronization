# Knowledge Base Export Specification

## Purpose

Предоставить реальный CSV-экспорт материалов базы знаний с выбором поддержанных полей и видимыми ограничениями экспорта вложенных данных прототипа.

## Requirements

### Requirement: Full selection CSV export

Экспорт списка SHALL передавать выбранные metadata export_fields в выбранном порядке и полный применённый search. Он SHALL выгружать весь отбор независимо от limit/offset страницы в пределах серверного export_max_rows, не более документированного лимита 10000 при текущем контракте. Пустой выбор SHALL блокировать отправку. UI MUST NOT экспортировать только загруженные строки или молча усекать результат.

#### Scenario: Export from a later page

- **WHEN** пользователь находится на второй странице и выгружает name/category_code/skill_names
- **THEN** запрос включает применённый отбор и выбранные поля, CSV включает весь серверный отбор, не только вторую страницу

#### Scenario: Server limit exceeded

- **WHEN** сервер отклоняет экспорт из-за превышения лимита
- **THEN** показано ограничение и предложение сузить отбор, частичный файл не объявляется полным

### Requirement: Saved detail export with visible unavailable sections

Экспорт карточки SHALL выгружать только сохранённый материал по ID. Новая карточка SHALL иметь недоступный экспорт с пояснением; dirty-карточка SHALL предупреждать, что выгружаются сохранённые данные. Modal SHALL сохранять состав прототипа: «Основное» с выбором поддержанных плоских полей и недоступные «Материалы», «Навыки (связи)», «Правила показа» с пояснениями об отсутствии API вложенного экспорта. Доступное плоское поле skill_names MUST NOT выдаваться за выгрузку связующей таблицы.

#### Scenario: Dirty detail export

- **WHEN** сохранённая запись изменена локально и открыт экспорт
- **THEN** пользователь видит предупреждение о сохранённых данных; запрос использует ID и fields без черновика

#### Scenario: Nested export selection

- **WHEN** открыт modal карточки
- **THEN** вложенные разделы видны с локальными пояснениями, не выбираются и не отправляются в неподдержанном payload

### Requirement: Truthful file delivery

UI SHALL скачивать действительный ответ API через штатный file transport, сохранять безопасное имя файла и освобождать временные ресурсы. HTTP/contract/download ошибки SHALL показываться вместо сообщения «Файл готов». Pending SHALL препятствовать повторной отправке; смена session owner SHALL исключать доставку старого файла новому контексту.

#### Scenario: Failed download

- **WHEN** экспорт вернул ошибку или файл не получен
- **THEN** нет фиктивной выгрузки и успешного уведомления; выбранные поля сохраняются для исправления/повтора
