# skill-phrase-conflicts Specification

## Purpose

Показать серверную подсказку о конфликтах текущей фразы и сохранить серверную валидацию сохранённых данных при продвижении навыка.

## Requirements

### Requirement: Global server conflict check

Single-phrase preflight SHALL выполняться сервером по активным группам неудалённых навыков во всём реестре, исключая собственный навык. Нормализация и классификация SHALL выполняться только сервером; клиент MUST NOT воспроизводить их или менять текст ради сравнения. Локальное сравнение загруженной страницы MUST NOT заменять глобальный результат. Без API SHALL отображаться unavailable без имитации проверки.

#### Scenario: Conflict outside current page

- **WHEN** сервер обнаруживает совпадение с навыком, отсутствующим на загруженной странице
- **THEN** совпадение отображается и влияет на отправку так же, как конфликт с видимым навыком

### Requirement: Exact and semantic conflict handling

UI SHALL показывать фразу, тип конфликта, близость в процентах, навык и домен из обязательных полей live API, сохраняя серверный порядок. Preflight SHALL служить подсказкой, а не разрешением на отправку полного набора. Сохранение фраз и переход `draft -> checking` MUST NOT блокироваться конфликтами или состоянием preflight. Продвижение, требующее readiness по контракту, SHALL проходить повторную серверную проверку сохранённых данных; exact блокирует такое продвижение, semantic сам по себе не блокирует.

#### Scenario: Exact match

- **WHEN** актуальный preflight содержит точное совпадение
- **THEN** показан блокирующий конфликт для дальнейшего продвижения, но сохранение фраз и `draft -> checking` остаются доступны по обычным правилам формы

#### Scenario: Semantic proximity

- **WHEN** актуальный результат содержит только смысловую близость
- **THEN** показано предупреждение с серверной близостью, но оно само по себе не блокирует отправку

#### Scenario: Required conflict details

- **WHEN** сервер возвращает конфликт с обязательными `skill/domain.id/name`
- **THEN** UI использует эти сведения без дополнительных запросов на раскрытие; отсутствие обязательных полей обрабатывается как некорректный ответ

#### Scenario: Server blocks advancement

- **WHEN** существующая команда продвижения, требующего readiness, получает `409 SKILL_CHECKS_BLOCKED`
- **THEN** UI показывает отказ и не считает переход успешным независимо от результата preflight

### Requirement: Check result freshness

Preflight SHALL относиться к текущей фразе и skill ID. Изменение любого из них SHALL сбрасывать результат. Pending, ошибка или устаревший результат MUST NOT считаться успешной проверкой. Preflight MUST NOT изменять сохранённые checks или подтверждать полный набор/версию. Серверная команда продвижения SHALL повторно обеспечивать ограничения по сохранённым данным независимо от preflight.

#### Scenario: Single-phrase preflight is not set readiness

- **WHEN** preflight одной фразы возвращает отсутствие конфликтов, а остальные группы или текущие правки полного набора не проверены
- **THEN** результат не меняет сохранённые проверки, не подтверждает отсутствие конфликтов в остальном текущем наборе и не разблокирует требующую проверки отправку

#### Scenario: Late response

- **WHEN** пользователь изменил фразу или skill ID, а затем пришёл успешный ответ старого запроса
- **THEN** старый ответ не отображается как актуальный и не подтверждает новый ввод

#### Scenario: Network failure

- **WHEN** запрос проверки завершился ошибкой
- **THEN** видны ошибка и повтор, а не сообщение «Конфликтов нет»; ошибка preflight сама по себе не блокирует сохранение или `draft -> checking`
