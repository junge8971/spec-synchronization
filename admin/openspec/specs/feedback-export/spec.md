# feedback-export Specification

## Purpose

Реализовать CSV-экспорт списка и карточки опросника в разделе обратной связи ЦАМ по опубликованному API, с отдельной приёмкой и сохранением ограничений первого этапа.

## Requirements

### Requirement: Server CSV export

Список SHALL экспортироваться POST /feedback/surveys/export с fields и текущим применённым search целиком, независимо от страницы. Карточка SHALL экспортироваться POST /feedback/surveys/{id}/export только с fields и только из сохранённых данных. Колонки/порядок SHALL выбираться по metadata export_fields, сейчас name/code/type_code/audience_type/status; минимум одно уникальное поле обязательно. Подписи колонок SHALL браться из metadata export_fields. Вложенные данные и пользовательские ответы MUST NOT обещаться в файле. Для новой несохранённой карточки export SHALL быть недоступен; для dirty существующей SHALL поясняться источник сохранённых данных.

UI SHALL скачивать реальный CSV UTF-8 с BOM из binary ответа, использовать безопасное имя из Content-Disposition и сохранять серверное содержимое, не генерировать файл из текущей страницы. CSV escaping и защита формул принадлежат backend. JSON/HTML вместо CSV, 404, 422 EXPORT_LIMIT_EXCEEDED, сеть, отмена и смена пользователя MUST NOT давать ложный файл/успех. Лимит SHALL браться из metadata export_max_rows; отсутствие строк SHALL допускать файл только с заголовками.

#### Scenario: Export beyond current page

- **WHEN** на странице 20 строк, а отбор содержит 85
- **THEN** запрос экспортирует весь search, CSV не строится из 20 отображаемых строк и сохраняет выбранный порядок полей

#### Scenario: Export saved card while editing

- **WHEN** пользователь выгружает существующую карточку с dirty draft
- **THEN** UI поясняет, что CSV содержит сохранённую запись; запрос не включает draft/questions/rules

#### Scenario: Limit or malformed file

- **WHEN** сервер вернул EXPORT_LIMIT_EXCEEDED или JSON вместо CSV
- **THEN** показана ошибка, скачивание и сообщение «Файл готов» не выполняются

### Requirement: Export settings dialog

Кнопка «Экспорт» SHALL открывать одно модальное окно настройки с чекбоксами и порядком колонок из metadata export_fields, кнопками «Экспорт» и «Отмена». Выбранные колонки SHALL перемещаться drag-and-drop за ручку с сохранением кнопок выше/ниже как альтернативы для клавиатуры и сенсорного экрана. Внешние, отменённые перетаскивания, drop на невыбранное поле и перемещение во время pending MUST NOT менять выбор или порядок. Выбор SHALL содержать от 1 до 100 уникальных разрешённых полей; пустой выбор SHALL блокировать отправку с пояснением. При пустом export_fields экспорт SHALL быть недоступен без запроса к export endpoint. Последний выбор и порядок SHALL сохраняться при повторном открытии в рамках текущей сессии, но MUST NOT переноситься другому пользователю. Pending SHALL блокировать повторные отправки; ошибки SHALL показываться в окне без потери выбора. Карточка MUST NOT содержать настройки поиска/фильтров; экспорт списка SHALL использовать только применённый отбор.

#### Scenario: Configure and reopen

- **WHEN** пользователь выбирает колонки и их порядок, закрывает настройку через «Отмена», Esc или клик вне и открывает её снова
- **THEN** запрос экспорта не отправляется при закрытии, сохраняется последний выбор текущей сессии, дубликат окна не возникает

#### Scenario: Invalid selection and unavailable export

- **WHEN** пользователь снял все чекбоксы либо metadata не предоставляет export_fields
- **THEN** отправка недоступна с пояснением, запрос экспорта не выполняется

#### Scenario: Applied selection only

- **WHEN** у пользователя есть применённый отбор и несохранённые изменения условий
- **THEN** экспорт списка использует применённый search, не включает черновик условий и не ограничивается текущей страницей

#### Scenario: Pending and retry after error

- **WHEN** пользователь повторно нажимает «Экспорт» во время ожидания, а запрос завершается ошибкой
- **THEN** второй запрос не отправляется, ошибка видна в настройке, выбранные колонки и порядок сохраняются для явного повтора

### Requirement: Export result dialog

После фактического получения и проверки CSV UI SHALL инициировать скачивание неизменённого серверного файла и показать одно модальное окно результата с именем из Content-Disposition. Для списка окно SHALL показывать фактическое количество записей полученного CSV без строки заголовков, кнопки «Закрыть» и «Вернуться к параметрам». Количество MUST NOT подменяться размером страницы, счётчиком поиска или числом физических переносов строк. Переносы строк и экранированные кавычки внутри CSV-поля SHALL учитываться как часть значения. Для карточки окно SHALL показывать код сохранённой карточки либо её идентификатор, не содержать поиска/фильтров и при dirty draft явно пояснять, что выгружены сохранённые данные. UI MUST NOT обещать подтверждённое сохранение файла на диск пользователя.

#### Scenario: Exact record count

- **WHEN** получен CSV с 85 записями, включая значения с переносами строк, разделителями и экранированными кавычками, а таблица содержит только 20 строк
- **THEN** результат показывает 85 записей и серверное имя файла, скачиваемые байты не изменяются

#### Scenario: Empty selection is a valid file

- **WHEN** сервер вернул корректный CSV только с заголовками
- **THEN** файл скачивается, окно результата показывает 0 записей; это не считается пустым или повреждённым ответом

#### Scenario: Return to parameters

- **WHEN** после экспорта списка пользователь нажимает «Вернуться к параметрам»
- **THEN** окно результата заменяется настройкой с сохранёнными колонками и порядком без автоматического повторного запроса

#### Scenario: Saved card result

- **WHEN** пользователь экспортирует существующую карточку с несохранённым изменением кода
- **THEN** результат идентифицирует сохранённую карточку по сохранённому коду либо ID и предупреждает, что изменения draft в файл не вошли

### Requirement: Export failures and session isolation

HTTP 4xx/5xx, включая 403/404/422 EXPORT_LIMIT_EXCEEDED, сеть, отмена, смена пользователя, JSON/HTML вместо CSV, пустой или повреждённый ответ и некорректное имя файла MUST NOT приводить к скачиванию или окну успеха. Ошибки SHALL объясняться отдельно от результата; превышение лимита SHALL предлагать уточнить отбор. Лимит SHALL использовать metadata export_max_rows с default 10000. Существующая защита от устаревших ответов SHALL сохраняться до скачивания и публикации результата; ресурсы временного Blob URL SHALL освобождаться. Несохранённая карточка без ID MUST NOT отправлять запрос экспорта.

#### Scenario: Failed or malformed response

- **WHEN** сервер вернул 403/404/422/5xx, JSON/HTML вместо CSV, пустой или повреждённый файл либо некорректное имя, или произошла сетевая ошибка
- **THEN** показана ошибка без файла и окна успеха; выбор колонок остаётся доступным текущему пользователю

#### Scenario: Cancellation or different session owner

- **WHEN** запрос отменён либо во время запроса сменился пользователь, после чего пришёл поздний ответ
- **THEN** поздний файл не скачивается, окно результата не открывается, данные и выбор прежнего пользователя не публикуются в новой сессии

#### Scenario: New unsaved card

- **WHEN** открыта новая карточка без сохранённого ID
- **THEN** экспорт недоступен и запрос не отправляется

### Requirement: Existing permission boundary

Поставка SHALL сохранять действующие защитные механизмы и серверную авторизацию, включая обработку 403. Новая UI-политика `ManagedResource:read` + `ManagedResource:export` MUST NOT считаться согласованной этой спецификацией: она остаётся отдельным вопросом из proposal. До отдельного согласования критерий Jira о новых UI permission mappings MUST NOT объявляться выполненным; отсутствие согласования MUST NOT трактоваться как разрешение обходить существующие ограничения.

#### Scenario: Server denies export

- **WHEN** backend отклоняет экспорт с 403
- **THEN** UI показывает ошибку без файла или успеха, не обходит отказ и не подменяет серверный ответ локально сгенерированным CSV

### Requirement: Accessible export interactions

Область этой задачи — выбор колонок и действия скачивания — SHALL поддерживать клавиатуру, доступные названия/ошибки, предсказуемый фокус и узкую компоновку. Приёмка SHALL проверять собственные элементы; реализация и приёмка соседних UI-возможностей MUST NOT требоваться для закрытия этой задачи сверх явно указанных зависимостей интеграции. Недоступные API MUST NOT имитироваться успешными заглушками.

#### Scenario: Keyboard and narrow layout within this task

- **WHEN** пользователь работает с элементами этой задачи клавиатурой на узком экране
- **THEN** действия, порядок колонок и ошибки доступны с клавиатуры и скринридера, содержимое не перекрывает управляющие элементы

#### Scenario: Close dialogs and restore focus

- **WHEN** пользователь закрывает настройку через «Отмена», Esc или клик вне либо результат через «Закрыть», Esc или клик вне
- **THEN** окно закрывается и фокус возвращается на исходную кнопку «Экспорт»; закрытие настройки без отправки не выполняет запрос

#### Scenario: No duplicate dialogs

- **WHEN** пользователь повторно нажимает кнопку открытия либо кнопку отправки во время pending
- **THEN** не появляются дубли модальных окон или запросов, фокус остаётся в активном окне
