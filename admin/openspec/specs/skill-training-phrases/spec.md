# skill-training-phrases Specification

## Purpose

Предоставить серверное хранение групп обучающих фраз навыка по предоставленному контракту MOS-809, не выдавая сохранение за фактическое применение.

## Requirements

### Requirement: Contract-backed phrase groups

Вкладка SHALL показывать intents из GET карточки с названиями и фразами, позволять добавлять/удалять группы, редактировать, сохранять через PUT intents и отменять изменения. Интерфейс MUST NOT отправлять придуманные поля в PATCH анкеты. Запрос SHALL соответствовать актуальной поставке: optional nullable ID группы — UUID любой версии; weight фразы — число >= 0 с default 1 при отсутствии. Некорректные значения MUST NOT молча удаляться или исправляться. Ограничение UUIDv7 для skill_id в пути SHALL сохраняться. Ограничения request MUST NOT автоматически ужесточать схему response.

#### Scenario: Contract validation

- **WHEN** пользователь сохраняет группы
- **THEN** имя содержит 1–255 символов, каждая группа содержит хотя бы одну непустую фразу длиной 1–500 символов, пустой набор групп допустим; дополнительные ограничения и дедупликация не вводятся

#### Scenario: Preserve intent metadata

- **WHEN** пользователь редактирует названия и тексты фраз
- **THEN** запрос сохраняет ID и остальные редактируемые по контракту поля существующих групп, а также допустимые веса неизменённых фраз

#### Scenario: Save and reopen groups

- **WHEN** пользователь добавляет группу, изменяет фразы и успешно сохраняет
- **THEN** повторная загрузка показывает подтверждённый сервером набор и его версию

#### Scenario: Weight boundaries

- **WHEN** формируется запрос с weight=0, отрицательным weight или без weight
- **THEN** ноль разрешён, отрицательное значение блокируется понятной ошибкой без потери ввода, отсутствующее получает контрактный default 1

#### Scenario: Intent UUID is not restricted to version seven

- **WHEN** запрос содержит корректный UUIDv4 группы либо некорректный UUID
- **THEN** первый принимается, второй отклоняется до мутации; UUIDv7 skill_id в пути по-прежнему обязателен

### Requirement: Template-aligned viewing and editing

Вкладка SHALL называться «Обучающие фразы» и показывать количество сохранённых групп. По умолчанию SHALL отображаться режим просмотра: карточки с названиями групп и фразами-чипами, кнопка «Изменить» справа сверху. Редактор SHALL показывать отдельные карточки групп, кнопки «Отмена»/«Сохранить» сверху и «Добавить группу фраз» снизу. Иконка удаления SHALL иметь доступное имя. Длинные фразы SHALL переноситься без потери текста.

#### Scenario: Enter and leave editing

- **WHEN** пользователь нажимает «Изменить», а затем отменяет изменения или успешно сохраняет
- **THEN** форма открывается с последним полученным серверным набором, а затем возвращается режим просмотра сохранённых групп; отмена не отправляет запрос записи

#### Scenario: Failed save stays editable

- **WHEN** сервер отклоняет сохранение
- **THEN** редактор остаётся открытым с введёнными данными и сообщением об ошибке

### Requirement: Phrase input and cancellation

В карточке фразы SHALL вводиться по строкам со счётчиком непустых фраз. В интегрированном шаге мастера SHALL поддерживаться разделение строками либо запятыми. Отмена SHALL восстанавливать сохранённый набор, ошибка записи SHALL сохранять draft. Ограничения групп и фраз SHALL соответствовать принятому контракту.

#### Scenario: Blank lines and count

- **WHEN** пользователь вводит несколько фраз с пустыми строками
- **THEN** пустые строки не увеличивают счётчик фраз

#### Scenario: Wizard separators

- **WHEN** в предоставленном отдельной задачей мастере введены фразы через запятую и перевод строки
- **THEN** шаг показывает отдельные непустые фразы и корректный счётчик

#### Scenario: Cancel or failed save

- **WHEN** сохранение завершилось ошибкой, затем пользователь отменяет изменения
- **THEN** до отмены draft не теряется, после отмены показан последний сохранённый набор без новой мутации

### Requirement: Saved version without invented application status

UI SHALL показывать сохранённую версию навыка из ответа API и сообщать, что применённая версия и состояние дообучения не предоставляются текущим API. Сохранение MUST NOT объявлять новую версию активной или обещать вымышленный срок. Полный индикатор применения отложен по решению пользователя.

#### Scenario: Saved version only

- **WHEN** сервер подтвердил сохранение новой версии
- **THEN** интерфейс показывает эту сохранённую версию и отсутствие данных о применении, не объявляя дообучение начавшимся или завершённым
