## Context

См. `proposal.md`: допускается локальная подготовка настроек, но серверное сохранение не описано. В HTML `wne/G9` есть имя и четыре режима; нажатие создаёт карточку только в useState без полного сохранения настроек. Копирование этого обработчика выдало бы локальный эффект за исполнение MOS-1016.

Конструктор MOS-1015 уже владеет черновиком и валидацией. При добавлении MOS-916 состояние переживает переключение вкладок, но не reload.

## Goals / Non-Goals

**Goals:** локальная подготовка имени и выбора намерения расписания без скрытого преобразования существующего периода.

**Non-Goals:** серверный Template DTO, cron, timezone default, вычисление следующего запуска, относительный период, мутация, cache invalidation, локальные «сохранённые шаблоны» и background timer.

## Decisions

### 1. Приватный блок существующего конструктора

Добавить приватный компонент настроек шаблона в `widgets/report-constructor`, не отдельную feature/entity без серверной сущности и второго потребителя. Имя и локальный режим принадлежат тому же состоянию формы; типы и runtime labels/defaults размещаются у владельца по соглашениям проекта. UI-режимы не объявляются API enum. Использовать уже установленные поля/select/button и форму из базы.

Альтернатива отдельный store или сохранение в localStorage не нужны и создают ложную устойчивость шаблона.

### 2. Локальная валидация не включает сохранение

Пустое/пробельное имя отмечается после взаимодействия с полем, а не красной ошибкой на первом открытии опционального блока. Не назначать выдуманные server maxLength или правила уникальности. Непустое имя исправляет ошибку, но «Сохранить» остаётся disabled. Сообщение об отсутствии API постоянно видно рядом с действием.

Нет mutation handler; кнопка не submit. Нажатие Enter не приводит к navigation, очистке формы или имитации успеха. Это проверяется независимо от работы соседнего disabled-экспорта, если MOS-919 уже применён.

### 3. Намерение расписания не равно расписанию сервера

Четыре подписи повторяют функциональный выбор прототипа. Для автоматического варианта дополнительно показать, что timezone и расчёт периода не определены и запуск не настроен. Браузерный часовой пояс, использованный для календарного черновика MOS-1015, не переносится автоматически в будущий scheduler.

Выбор ежемесячного режима не превращает абсолютные даты в «прошлый месяц» и не обещает повторять их. Переключение обратно на ручной убирает автоматическое намерение, но не делает запуск возможным. Не создавать cron или тестовый таймер, даже для демо.

### 4. Component-проверки и жизненный цикл

Проверить пустое/пробельное/непустое имя, все режимы, клавиатуру, сохранение диапазона при выборе месячного режима, отсутствие HTTP/успеха/новой карточки при Enter, сброс на reload. При наличии вкладок проверить сохранение имени и режима при возврате в конструктор. Хранилища и URL не используются.

## Risks / Trade-offs

- [Подпись «Ежедневно в 09:00» воспринимается как обещание] → постоянное объяснение несохранённого намерения и несогласованного timezone; нет следующего запуска или текста «Будет собираться».
- [UI-поля без write API принимают за завершённую функцию] → явно отделять этот PR от полной MOS-1016 в отчёте о поставке.
- [Будущий контракт задаёт другие настройки] → локальные ключи не являются wire-контрактом; расширение согласуется после получения API.

## Migration Plan

Отдельный PR после MOS-1015. MOS-916/MOS-919 не блокируют эту локальную поставку; последовательное применение всех PR должно сохранять их поведение. Откат удаляет локальный блок и поля черновика, без миграции серверных данных.

Перед серверным продолжением необходимы подтверждённые create/read схемы, порядок колонок и условия, режим периода, timezone, расписание, ошибки/конфликты имени, предметная область видимости и способ получения результата фонового запуска. После согласования обновить план; текущие задачи не содержат скрытого разрешения реализовать эти операции.

### Критерии заблокированного продолжения MOS-1016

Это целевая приёмка после согласования write/read API и обновления specs/tasks, не дополнительные исполняемые задачи текущего apply.

- **B16.1 — Устойчивое сохранение:** подтверждённая сервером операция сохраняет имя и полные настройки, новый шаблон виден после повторного чтения списка и после перезагрузки. Проверка: создать, повторно запросить список, заново открыть страницу; локально добавленная карточка без подтверждения не засчитывается. Обновление списка после успешной записи и ошибка самой записи различаются: ошибка последующего GET не должна провоцировать повторное создание уже сохранённого шаблона.
- **B16.2 — Полный round trip:** после открытия через MOS-916 восстановлены поверхность, все выбранные колонки в исходном порядке, условия AND/OR с типами/операторами/значениями, обе границы диапазонов, область/режим фразы/навык, период и его режим. Проверка: шаблон с нестандартным порядком колонок и разнородными условиями после create/read даёт те же настройки, а не defaults или только текстовое описание. Для неподдержанного значения требуется явное состояние, не молчаливое удаление.
- **B16.3 — Расписание и период:** ручной запуск сохраняется как отсутствие расписания; автоматические варианты сохраняют подтверждённые параметры и timezone. До активации согласуются время еженедельного/ежемесячного запуска, правила вычисления отчётного периода и его границ. Проверка: два последовательных автоматических запуска получают периоды по выбранному правилу, а не молчаливое повторение сохранённых абсолютных дат; календарные границы месяца и timezone учитываются по контракту. Frontend передаёт настройки, не выполняет scheduler, не объявляет несохранённое намерение включённым расписанием и не назначает скрытых defaults.
- **B16.4 — Видимость и результат:** контракт определяет предметную область доступности созданного шаблона и то, где читать состояние/результат фонового запуска, его автора, время и число строк/файл. Проверка: после подтверждённого фонового выполнения UI читает серверный результат в согласованном месте; открытая вкладка браузера не нужна для выполнения, значение last_run не подделывается клиентом. Конкретный механизм доставки/хранения результата пока не выбран. Клиентская auth/session/RBAC-модель этим критерием не вводится.
- **B16.5 — Ошибки:** ошибка создания, в том числе подтверждённый контрактом дубликат/конфликт имени или валидация настроек, не показывает успех, не очищает имя/период/поверхность/поля/условия/расписание и не добавляет фиктивную карточку. Проверка: ошибка имени у поля, сетевая ошибка, исправление ввода и повтор; правила уникальности, ограничения имени, retry/идемпотентность реализуются только по контракту. После подтверждённого успешного сохранения переход к списку и очистка имени не должны уничтожать ещё несохранённые изменения другого черновика.

Без этих проверок готовность локального блока не означает завершение серверного сохранения MOS-1016. Рабочий список после создания — часть согласованной интеграции с MOS-916, а не дополнительная реализация каталога в этом PR.
