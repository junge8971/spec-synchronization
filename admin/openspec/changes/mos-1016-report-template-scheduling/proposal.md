## Why

MOS-1016 требует сохранения настроек отчёта и серверного расписания. По согласованному ограничению «делаем возможное по существующим контрактам» сейчас можно подготовить локальную форму, но отсутствие write API не позволяет сохранять шаблон или обещать автоматический запуск.

## What Changes

- Дополнить конструктор из `mos-1015-report-constructor` блоком «Сохранить отчёт как шаблон»: имя и варианты «Без расписания, запуск вручную», «Ежедневно в 09:00», «Каждый понедельник», «Первого числа месяца».
- Хранить ввод только как локальный черновик, проверять пустое/пробельное имя; оставлять «Сохранить» недоступной независимо от валидности формы.
- Пояснять отсутствие сохранения и автоматических запусков, а для автоматических вариантов — несогласованные часовой пояс и расчёт периода.
- Не подменять абсолютный период конструктора относительным, не писать cron, не запускать таймер, не добавлять карточку в список и не показывать успех.
- Отдельный PR MOS-1016: текущая поставка не закрывает полные критерии серверного сохранения Jira-задачи.

### Deferred after contract agreement

Создание и повторное чтение шаблона, сохранение полей/поверхности/условий, режим периода для каждого запуска, timezone, настройки расписания, ошибки имён, область видимости и результат фонового запуска требуют API. Определение предметной видимости не означает введение клиентской auth/RBAC-модели. Эти вопросы не решаются предположениями в данном change. Матрица S01–S10 и критерии B16.1–B16.5 в `design.md` сохраняют полную исходную приёмку: повторное чтение, восстановление всех настроек, серверное расписание/результат и ошибки без потери ввода. Они не закрываются локальным UI.

## Capabilities

### New Capabilities

- `report-template-scheduling-draft`: Локальные настройки имени и намерения расписания с недоступным сохранением и без обещания серверного выполнения.

### Modified Capabilities

Нет.

## Impact

- `app/widgets/report-constructor`: приватный блок настроек шаблона и локальная модель/валидация; `app/pages/reports` при необходимости сохранения состояния между вкладками.
- Зависит от MOS-1015. Для текущего локального UI MOS-916 и MOS-919 не являются техническими блокерами; после MOS-916 необходимо сохранить ввод при переключении вкладок.
- Используются существующие формы и UI без новых библиотек, persistent storage, API DTO, mock endpoints или фоновых процессов.
