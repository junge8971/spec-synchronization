## MODIFIED Requirements

### Requirement: Contract-gated lifecycle

Карточка SHALL показывать текущий SkillResponse.status и шкалу опубликованных этапов. На основании разрешённых пользователем продуктовых допущений MOS-909 общая возможность lifecycle карточки SHALL предлагать только `draft → checking`, `sandbox → review`, `whitelist → prod` через опубликованный POST status с expected_version и Idempotency-Key. Эта матрица MUST NOT объявляться гарантией допустимости переходов backend. Для checking/training/autotest/review/prod/disabled в общей возможности lifecycle SHALL отсутствовать команды смены состояния, а не только блокироваться их отправка. В частности, она MUST NOT предлагать checking → training, training → autotest, autotest → sandbox или review → whitelist. Это ограничение SHALL относиться только к общей возможности lifecycle: отдельное ревью SHALL сохранять согласованный review → whitelist, а отдельное глобальное переключение — prod → disabled → prod через disable/enable. Общий опубликованный status API и распознаваемый enum MUST NOT сужаться до матрицы команд этой возможности. UI MUST NOT синтезировать результаты процессов, дополнительные enum или endpoints; обычный PATCH анкеты MUST NOT использоваться для lifecycle. Поддерживаемые анкета, фразы, подключение и отдельный мастер регистрации SHALL сохраняться независимо от lifecycle. Неизвестный status MUST NOT сопоставляться с «Черновик» или «Прод» по умолчанию.

#### Scenario: Current skill API

- **WHEN** карточка получена с опубликованным status без истории прохождения этапов
- **THEN** показаны текущий статус и шкала без отметок успешного прохождения; предложена только команда из матрицы для данного status, открытие карточки не выполняет мутаций

#### Scenario: Unknown server state

- **WHEN** ответ карточки содержит status вне опубликованного enum
- **THEN** UI показывает штатную ошибку чтения контракта без вымышленного статуса, шкалы и предложений перехода; правило совместимости неизвестных строк в списке не расширяет валидацию карточки

#### Scenario: Background refresh fails

- **WHEN** обновление карточки завершилось ошибкой при наличии ранее загруженных данных
- **THEN** старый статус обозначен как ранее загруженный, ошибка и повтор чтения доступны, команды перехода недоступны до успешного чтения

#### Scenario: Only the three approved generic commands

- **WHEN** актуальная карточка имеет draft, sandbox или whitelist и существующие условия доступа и безопасности позволяют действие
- **THEN** общая возможность lifecycle предлагает соответственно только «Отправить на проверку» в checking, «Отправить на ревью» в review или «Выкатить в прод» в prod; отправка требует существующего подтверждения и использует версию подтверждаемой карточки, без автоматической следующей команды

#### Scenario: No generic command in other recognized states

- **WHEN** актуальная карточка имеет checking, training, autotest, review, prod или disabled, в том числе у пользователя с разрешением смены статуса
- **THEN** общая возможность lifecycle не показывает ни одного инициатора перехода, не позволяет открыть новое подтверждение и не отправляет команду; ранее открытое подтверждение при смене статуса остаётся недействительным; чтение состояния остаётся доступно, а отсутствие команды не подменяет серверный статус и не означает завершение предыдущих этапов

#### Scenario: Separate command owners remain available

- **WHEN** навык в review открывается в отдельной возможности ревью либо prod/disabled отображается с отдельным глобальным переключением
- **THEN** отсутствие общей lifecycle-команды не запрещает согласованное действие соответствующего владельца с его собственными условиями и подтверждением; общая lifecycle-возможность не дублирует эти действия
