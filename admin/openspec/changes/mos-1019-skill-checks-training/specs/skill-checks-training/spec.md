## Purpose

Показывать достоверный серверный процесс проверки навыка, обучения модели и автотестов с восстановлением актуального запуска при повторном открытии.

## ADDED Requirements

### Requirement: Server-owned processing run

При наличии согласованного API UI SHALL показывать идентификатор запуска, его версию входных данных, проверку анкеты/фраз, обучение и автотесты с серверными промежуточными и конечными состояниями. Без API SHALL оставаться unavailable; локальное время MUST NOT завершать процесс успешно.

#### Scenario: Running and completed stages

- **WHEN** сервер последовательно сообщает промежуточный и конечный результат одного запуска
- **THEN** UI отображает эти состояния и идентификатор, не придумывая пропущенные результаты этапов

#### Scenario: Failed stage

- **WHEN** сервер сообщает ошибку обучения или автотестов
- **THEN** видны соответствующий этап и ошибка, а общая готовность не объявляется успешной

### Requirement: Recoverable run observation

Повторное открытие карточки SHALL восстанавливать процесс из серверных данных. Обновления SHALL следовать согласованному протоколу; при конечном состоянии наблюдение SHALL прекращать ненужные повторные запросы. Ошибка получения обновлений SHALL отличаться от ошибки самого запуска.

#### Scenario: Reopen running skill

- **WHEN** пользователь повторно открывает карточку во время обучения
- **THEN** показан существующий серверный запуск, а не новый локальный процесс

#### Scenario: Update request failure

- **WHEN** чтение очередного обновления не удалось
- **THEN** отображается ошибка получения данных с повтором и отметкой неактуальности оставленного результата

### Requirement: Version-specific readiness and sandbox

Успех запуска SHALL подтверждать только обработанную версию. Доступность песочницы SHALL определяться согласованными серверными данными; переход MUST NOT включать секрет в URL.

#### Scenario: Old run after phrase edit

- **WHEN** фразы имеют новую версию, а успешный запуск относится к старой
- **THEN** интерфейс не объявляет новую версию готовой на основании старого запуска

#### Scenario: Sandbox unavailable

- **WHEN** сервер ещё не подтвердил доступность песочницы
- **THEN** интерфейс объясняет недоступность и не создаёт фиктивный токен
