## Purpose

Реализовать ввод тегов, сегментов и групп операторов в разделе обратной связи ЦАМ по опубликованному API, с отдельной приёмкой и сохранением ограничений первого этапа.

## ADDED Requirements

### Requirement: Free survey labels

Теги, сегменты и группы операторов SHALL редактироваться chips внутри карточки, передаваться как tags/segments/operator_groups со строками имён через запятую. UI MUST NOT создавать отдельные CRUD-ресурсы меток, генерировать их API-коды или обещать глобальное удаление. Лимиты SHALL быть 100 различных меток, 150 символов в имени, 16000 во входной строке; запятая всегда разделитель. Пустая строка SHALL очищать связи, null MUST NOT отправляться. Канонический результат backend SHALL заменять сохранённое представление после успеха.

При audience_type=segment SHALL требоваться хотя бы одна непустая метка; переключение аудитории MUST NOT само очищать сохранённые метки.

#### Scenario: Canonical labels and clearing

- **WHEN** сервер нормализовал « жкх, ЖКХ, качество » в «ЖКХ, качество», затем пользователь удалил все chips
- **THEN** UI сначала показывает канонические имена, последующее сохранение передаёт пустую строку и очищает только связи опросника

### Requirement: Accessible labels interactions

Область этой задачи — chip-вводы меток — SHALL поддерживать клавиатуру, доступные названия/ошибки, предсказуемый фокус и узкую компоновку. Приёмка SHALL проверять собственные элементы; реализация и приёмка соседних UI-возможностей MUST NOT требоваться для закрытия этой задачи сверх явно указанных зависимостей интеграции. Недоступные API MUST NOT имитироваться успешными заглушками.

#### Scenario: Keyboard and narrow layout within this task

- **WHEN** пользователь работает с элементами этой задачи клавиатурой на узком экране
- **THEN** действия и ошибки доступны, содержимое не перекрывает управляющие элементы, закрытие имеющихся диалогов возвращает фокус
