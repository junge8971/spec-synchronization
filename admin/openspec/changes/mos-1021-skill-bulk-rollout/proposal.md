## Why

MOS-1021: реестр не позволяет выбрать несколько навыков и выполнить контролируемый выкат с результатом по каждому. Массовый успех нельзя выводить из одного успешного запроса или локального статуса.

## What Changes

- Чекбоксы строк, «выбрать все показанные», панель выбранных навыков.
- Выкат только допустимых состояний: согласованные в белые списки, из белых списков в prod.
- Отчёт по каждому навыку, частичные ошибки и безопасный повтор.
- Batch-команда предпочтительна; одиночные команды допустимы только при явном согласовании и с ограничением параллелизма.

## Capabilities

### New Capabilities

- `skill-bulk-rollout`: выбор и массовый выкат навыков из реестра.

### Modified Capabilities

Нет. Существующие серверный status-фильтр и отображение SkillStatus сохраняются; новые состояния и правила переходов не выводятся из прототипа.

## Impact

- `app/widgets/skills-registry/`, `app/entities/skill/`, предметная feature выката.
- **BLOCKED API:** `docs/api/contracts/openapi.json` содержит SkillStatus и version в списке/карточке, status-фильтр и POST `/api/control/api/skills/v1/skills/{skill_id}/status` с expected_version и UUID Idempotency-Key. Остаются несогласованными правила выката, batch либо разрешение ограниченного fan-out, per-item outcomes и восстановление неизвестного исхода. Surface publish не является публикацией навыка.
- MOS-1020 описывает бизнес-предшественник «согласован», но его соответствие серверным данным не определено: SkillStatus не содержит отдельного approved, а review нельзя автоматически считать согласованием. Готовность UI ревью не нужна для тестирования согласованных правил выката.
- Отдельная приёмка MOS-1021; один пользовательский отчёт по смешанному результату обязателен.
