## Purpose

Позволить выполнять контролируемый массовый выкат выбранных навыков из реестра с отчётом о результате каждого элемента.

## ADDED Requirements

### Requirement: Visible-row selection

Реестр SHALL предоставлять выбор показанных строк и панель выбранных навыков. «Выбрать все» SHALL обозначать только текущие показанные строки. Смена страницы, фильтра или сортировки SHALL сбрасывать выбор; скрытые элементы MUST NOT неявно попадать в команду.

#### Scenario: Select current page

- **WHEN** пользователь нажимает «Выбрать все» на странице реестра
- **THEN** выбраны только показанные навыки, а счётчик панели соответствует их числу

#### Scenario: Change page

- **WHEN** после выбора пользователь меняет страницу
- **THEN** выбор сбрасывается, навыки прошлой страницы не отправляются в следующую команду

### Requirement: Contract-backed eligible rollout

При наличии согласованного API выкат SHALL допускать переходы «согласован → белые списки» и «белые списки → prod» по серверным состояниям. Перед отправкой SHALL показываться целевой контур и число навыков; несовместимые переходы MUST NOT молча объединяться. Без API SHALL быть недоступно реальное действие выката.

#### Scenario: Ineligible selection

- **WHEN** выбор содержит навык в неподходящем состоянии
- **THEN** интерфейс объясняет непригодность и не выдаёт его за успешно выкаченный

#### Scenario: Server rejects changed state

- **WHEN** сервер отклоняет элемент, состояние которого изменилось после выбора
- **THEN** результат этого элемента содержит ошибку, а не локально вычисленный успех

### Requirement: Per-item outcome and safe retry

UI SHALL показывать результат каждого навыка и различать полный успех, частичный успех, ошибку и неизвестный исход. Использование одиночных команд SHALL требовать согласования и ограниченного параллелизма. Повтор MUST NOT повторно выполнять подтверждённо успешные элементы; неизвестный исход SHALL восстанавливаться по согласованному протоколу.

#### Scenario: Partial batch success

- **WHEN** сервер подтверждает успех части навыков и ошибки остальных
- **THEN** пользователь видит отдельные результаты по ID, а реестр обновляется без сообщения об успехе всей группы

#### Scenario: Lost response

- **WHEN** соединение оборвалось после отправки
- **THEN** интерфейс не объявляет все элементы неуспешными или успешными и не повторяет всю группу без выяснения исхода
