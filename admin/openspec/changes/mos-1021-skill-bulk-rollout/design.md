## Context

См. proposal.md. Реестр уже имеет серверную пагинацию, status-фильтр и отображение статуса. SkillListItemResponse и SkillResponse содержат status и version; опубликован POST `/api/control/api/skills/v1/skills/{skill_id}/status` с expected_version и UUID Idempotency-Key. Ни этот контракт, ни прототип не задают правила выката и серверную атомарность массового действия.

## Goals / Non-Goals

**Goals:** ограниченный, понятный выбор и точный результат каждого выката.

**Non-Goals:** выкат всего серверного реестра, новый job scheduler, surface publish вместо skill rollout.

## Decisions

- **BLOCKED API:** остаётся согласовать допустимые переходы и их предусловия, batch либо применение опубликованного POST status через ограниченный fan-out, per-item ошибки, семантику идемпотентности и чтение результата после неизвестного исхода. Наличие Idempotency-Key само по себе не гарантирует replay. SkillStatus не содержит approved: бизнес-состояние «согласован» нельзя приравнять к review без соглашения. Mock принимает любой опубликованный статус, но это не production-правило. Выбор batch либо согласованного fan-out фиксируется до реализации; fallback на одиночные команды самовольно не делать.
- Предлагаемая UI-граница: выбранными могут быть только показанные строки; при смене страницы/фильтра/сортировки выбор сбрасывается с понятным состоянием панели. Это не серверное «выбрать все».
- Перед действием показать целевой контур и число навыков. Не смешивать в одной команде несовместимые переходы; непригодные строки объясняются, а не молча пропускаются. Backend повторно проверяет состояние.
- Если согласован fan-out, использовать заданный предел параллелизма и отчёт по ID; Promise.all по всему выбору без лимита отвергнут. Для batch использовать серверные результаты, не считать HTTP 200 успехом каждого элемента.
- После результата перечитать реестр; повтор не должен повторно выкатывать подтверждённо успешные элементы. При timeout сначала выяснить исход по согласованному протоколу.

## Risks / Trade-offs

- Состояние изменилось после выбора → серверный version/state guard и ошибка конкретной строки.
- Потеря отчёта при refetch → хранить результат операции отдельно от текущей страницы до явного закрытия.

## Migration Plan

Расширить существующую таблицу/feature после API-gate; проверить частичный успех component-тестом. Откат UI убирает массовое действие, но не откатывает релиз на сервере.
