Общая информация
Версия контракта v1.1.
Контракт актуализирован по текущей реализации модуля команд.
Базовый путь /api/control/api/teams/v1/teams.
Для аутентификации используется Bearer-токен в заголовке Authorization.
Authorization: Bearer <token>
Общие заголовки
| Заголовок | Обязательность | Описание
| Authorization | Да | Bearer-токен пользователя
| X-Request-Id | Нет | UUID запроса. Backend создаёт значение, если заголовок не передан
Ответ содержит X-Request-Id с идентификатором запроса.
Общая модель ответа
Успешный HTTP-ответ содержит оболочку:
{
"code": "SUCCESS",
"data": {},
"message": "Операция выполнена успешно.",
"errors": []
}
Ответ с ошибкой содержит оболочку:
{
"code": "FAILED",
"data": null,
"message": "Описание ошибки.",
"errors": []
}
| Поле | Тип | Описание
| code | string | SUCCESS для успешного ответа, FAILED для ошибки
| data | object или null | Результат операции. При ошибке равно null
| message | string | Локализованное описание результата
| errors | array | Ошибки полей в формате { "field": string, "message": string }
1. Назначение и модель доступа
API предоставляет методы для:
получения доступных пользователю команд и карточки команды;
создания и изменения команды;
получения состава команды;
добавления, изменения роли и удаления участника.
Текущая модель доступа:
| Операция | Доступ
| Список команд | Администратор видит все команды. Обычный пользователь видит только команды, в которых состоит
| Карточка команды и состав | Администратор или участник команды
| Создание команды | Только администратор
| Изменение команды | Администратор или участник команды
| Добавление, изменение роли и удаление участника | Администратор или участник с ролью lead
1.1 Модель команды
| Поле | Тип | Описание
| id | UUID | Локальный идентификатор команды
| name | string | Уникальное без учёта регистра название, от 1 до 200 символов
| department_name | string | Название подразделения, от 1 до 200 символов
| member_count | integer | Вычисляемое число участников
| members | array | Участники команды
| surfaces | array | Поверхности, закреплённые за командой
| domains | array | Домены команды.
| skills | array | Навыки команды.
| created_at | date-time | Время создания команды
| updated_at | date-time | Время последнего изменения команды или её состава
1.2 Вложенные модели
Участник команды:
| Поле | Тип | Описание
| id | UUID | Идентификатор пользователя
| full_name.family_name | string | Фамилия
| full_name.name | string | Имя
| full_name.middle_name | string или null | Отчество
| email | string | Email пользователя
| roles | array[string] | Функциональные роли пользователя
| membership_role | string | Роль в команде со значением lead или member
| valid_from | date-time | Время добавления пользователя в команду
Поверхность команды:
| Поле | Тип | Описание
| id | UUID | Идентификатор поверхности
| name | string | Название поверхности
| status | string | draft, configured, review, sandbox, prod, disabled или archived
Домен команды:
| Поле | Тип | Описание
| id | UUID | Идентификатор домена
| name | string | Название домена
| skills_count | integer | Количество навыков в домене
Навык команды:
| Поле | Тип | Описание
| id | UUID | Идентификатор навыка
| name | string | Название навыка
2. Методы API
2.1 Получить список команд
GET /api/control/api/teams/v1/teams
Параметры запроса
| Параметр | Тип | Обязательность | Описание
| query | string | Нет | Поиск без учёта регистра по началу названия команды
| sort | string | Нет | Поля сортировки через запятую. Префикс - задаёт убывание
| limit | integer | Нет | От 1 до 100. По умолчанию используется 50
| offset | integer | Нет | Минимум 0. По умолчанию используется 0
Для сортировки доступны name, -name, created_at, -created_at, updated_at и -updated_at. По умолчанию используется name. Backend всегда добавляет id последним ключом сортировки.

2.4 Создать команду
POST /api/control/api/teams/v1/teams
Тело запроса
| Поле | Тип | Обязательность | Описание
| name | string | Да | Уникальное название, от 1 до 200 символов
| department_name | string | Да | Название подразделения, от 1 до 200 символов
| reason | string | Да | Основание изменения, от 1 до 1000 символов
Строковые поля очищаются от пробелов по краям.
{
"name": "Команда голосовых навыков",
"department_name": "Управление цифровых сервисов",
"reason": "Создание команды по заявке SDEXP-2301."
}
Успешный ответ
201 Created
{
"code": "SUCCESS",
"data": {
"id": "f24f0af5-e3ea-45e7-856d-b950fb94bd03",
"name": "Команда голосовых навыков",
"department_name": "Управление цифровых сервисов",
"member_count": 0,
"created_at": "2026-09-03T10:15:30Z",
"updated_at": "2026-09-03T10:15:30Z"
},
"message": "Команда создана.",
"errors": []
}
2.5 Изменить команду
PATCH /api/control/api/teams/v1/teams/{team_id}
Тело запроса
| Поле | Тип | Обязательность | Описание
| name | string | Да | Новое название, от 1 до 200 символов
| department_name | string | Да | Новое название подразделения, от 1 до 200 символов
| reason | string | Да | Основание изменения, от 1 до 1000 символов
{
"name": "Команда разговорных навыков",
"department_name": "Департамент цифровых продуктов",
"reason": "Изменение по заявке SDEXP-2310."
}
Успешный ответ
200 OK. Формат data совпадает с ответом создания команды. Он содержит id, name, department_name, member_count, created_at и updated_at.
2.6 Добавить участника
POST /api/control/api/teams/v1/teams/{team_id}/members
Пользователь не может быть добавлен в одну команду повторно.
Тело запроса
| Поле | Тип | Обязательность | Описание
| user_id | UUID | Да | Идентификатор пользователя
| membership_role | string | Да | lead или member
| reason | string | Да | Основание изменения, от 1 до 1000 символов
{
"user_id": "52f411aa-977b-4d26-9a5b-d896ca9c1e64",
"membership_role": "member",
"reason": "Добавление по заявке SDEXP-2325."
}
Успешный ответ
201 Created
{
"code": "SUCCESS",
"data": {
"id": "52f411aa-977b-4d26-9a5b-d896ca9c1e64",
"membership_role": "member",
"valid_from": "2026-09-03T10:25:00Z"
},
"message": "Пользователь добавлен в команду.",
"errors": []
}
2.7 Изменить роль участника
PATCH /api/control/api/teams/v1/teams/{team_id}/members/{user_id}
Тело запроса
| Поле | Тип | Обязательность | Описание
| membership_role | string | Да | Новая роль со значением lead или member
| reason | string | Да | Основание изменения, от 1 до 1000 символов
{
"membership_role": "lead",
"reason": "Назначение руководителем по заявке SDEXP-2330."
}
Успешный ответ
200 OK. Формат data совпадает с ответом добавления участника. valid_from не изменяется при смене роли.
2.8 Удалить участника
POST /api/control/api/teams/v1/teams/{team_id}/members/{user_id}/actions/remove
Запись о членстве физически удаляется. Причина сохраняется в доменном событии аудита.
Тело запроса
| Поле | Тип | Обязательность | Описание
| reason | string | Да | Основание изменения, от 1 до 1000 символов
{
"reason": "Исключение из команды по заявке SDEXP-2341."
}
Успешный ответ
200 OK
{
"code": "SUCCESS",
"data": {
"id": "52f411aa-977b-4d26-9a5b-d896ca9c1e64"
},
"message": "Пользователь удалён из команды.",
"errors": []
}
3. Ошибки
Ошибка валидации:
{
"code": "FAILED",
"data": null,
"message": "Запрос содержит некорректные данные.",
"errors": [
{
"field": "limit",
"message": "Input should be less than or equal to 100"
}
]
}
| HTTP | Условие
| 401 | Bearer-токен отсутствует или недействителен
| 403 | Пользователь не имеет доступа к команде или операции
| 404 | Команда не найдена
| 404 | Участник не найден в команде при изменении роли или удалении
| 409 | Команда с таким названием уже существует
| 409 | Пользователь уже состоит в команде
| 422 | Параметры пути, query-параметры или тело запроса не прошли валидацию
