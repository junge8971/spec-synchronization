1. Назначение
Прототип реализует административный раздел «A/B эксперименты» Центра управления Цифрового ассистента (ЦАМ). Раздел предназначен для настройки правил распределения пользовательских запросов между несколькими версиями одного сценария - например, между текущим и новым алгоритмом Диспетчера Команд (ЕСК).
Каждый эксперимент делит аудиторию на группы с заданными процентами. Каждая группа обрабатывается своим алгоритмом. Это позволяет проверить гипотезу на ограниченной части пользователей, не затрагивая всех.
Прототип полностью соответствует модели данных из PDF: 7 таблиц с префиксом ab_ (2 сущности, 1 связующая, 4 справочника).
2. Общая структура
Раздел состоит из двух экранов:
Список экспериментов - стартовый экран с таблицей, поиском, фильтрами и кнопкой создания.
Карточка эксперимента - экран редактирования с четырьмя вкладками: «Основное», «Группы и распределение», «Поверхности», «Правила запуска».
Переход между экранами - по клику на строку таблицы или по хлебным крошкам. При закрытии карточки без сохранения показывается модалка подтверждения.
3. Экран «Список экспериментов»
3.1. Таблица
Отображает все эксперименты со следующими колонками:
| Колонка | Источник | Сортировка
| Тест (название + код) | ab_experiment.name, ab_experiment.code | ✓
| Поверхности (чипсы) | ab_experiment_surface → surfaces.name | ✓
| Групп | COUNT(ab_group) | ✓
| Статус | ab_experiment.status → ab_statuses.display_name | ✓
| Стрелка «›» | - | -
Статусы подсвечиваются цветом: Активен - зелёный, Приостановлен - жёлтый, Завершён - красный, Черновик - светлый, Архив - серый. Клик по заголовку сортирует; повторный клик меняет направление; третий - снимает сортировку.
3.2. Поиск
Поле поиска (минимум 2 символа) ищет по:
названию теста,
служебному коду,
тегам групп (ab_group.tag).
3.3. Мультиселект-фильтры
| Фильтр | Источник | Логика
| Все поверхности | Справочник surfaces | Оставить тесты, действующие хотя бы на одной из выбранных
| Все статусы | ab_statuses (5 значений) | Фильтр по текущему состоянию
У каждого значения рядом с названием выводится код (monospace). Кнопка «Все ...» очищает фильтр.
3.4. Расширенный фильтр «⚙ Условия»
Конструктор произвольных условий:
Логика: И (все условия) / ИЛИ (любое условие).
Поля: Название, Код, Владелец, Статус, Режим запуска, Аудитория, Метрика, Количество групп, Приоритет, Поверхности.
Операторы: для текста - содержит/не содержит/равно/не равно/начинается с/заканчивается на/пусто/не пусто; для enum - входит/не входит (с чипсами); для чисел - =, ≠, >, ≥, <, ≤, между.
Применённые условия отображаются в панели-баре под фильтрами. На кнопке - бейдж с числом активных условий.
3.5. Меню «⋮»
Сохранить текущий фильтр - сохраняет поиск, мультиселекты и расширенные условия под именем.
Скопировать ссылку на отбор - формирует URL с параметрами и копирует в буфер.
Сохранённые фильтры - список с возможностью применить или удалить.
3.6. Прочее
Кнопка «Сбросить» - видна при активных фильтрах.
Счётчик справа - сколько тестов найдено.
Кнопка «＋ Создать тест» - открывает пустую карточку.
Кнопка «⤓ Экспорт» - модалка выбора полей ab_experiment.
4. Экран «Карточка эксперимента»
4.1. Шапка
Содержит:
название (name),
описание (description),
статус (цветная точка + подпись),
код (code, monospace),
владельца (owner),
даты (started_on - ended_on, если заданы),
мета-строку: Создан (created_at) и Изменён (updated_at).
Кнопки действий:
| Кнопка | Действие
| ⤓ Экспорт | Модалка выбора разделов
| Сохранить | Валидирует обязательные поля, сумму процентов, поверхности, уникальность тегов групп
| Приостановить | Переключает status между paused и active
| Выключить | Устанавливает status = 'completed' с подтверждением
| Закрыть | Модалка «Выйти без сохранения?»
4.2. Вкладка «Основное»
Две карточки: Основное и Гипотеза и метрика.
Левая - «Основное» (все поля привязаны к ab_experiment):
| Поле | Тип | Валидация
| Название теста | input | обязательное, уникальное
| Служебный код | input (monospace) | обязательное, уникальное, латиница
| Статус | select из ab_statuses (5) | -
| Команда-владелец | input (owner) | -
| Ответственный | select (responsible_user_id) | -
| Описание | textarea | -
| Дата начала | date (started_on) | -
| Дата окончания | date (ended_on) | -
| Теги | input через запятую (tags) | -
Правая - «Гипотеза и метрика»:
| Поле | Модель
| Что проверяем | hypothesis
| Основная метрика | metric_code из ab_metrics (4 значения)
| Минимальный размер выборки | min_sample_size
| Остановить при явном перевесе | auto_stop (switch)
4.3. Вкладка «Группы и распределение»
Две колонки: список групп (слева) и живой предпросмотр (справа).
Карточка группы (ab_group):
| Элемент | Поле
| Название (editable input) | name
| Процент распределения | percent
| Единица | % (disabled)
| Тег группы (monospace) | tag
| Ручка ⠿ для drag-and-drop | sort_order
| Крестик удаления | -
Drag-and-drop меняет порядок групп, обновляя sort_order. Порядок отражается в предпросмотре и легенде.
Сводка суммы процентов под карточками:
зелёная - если сумма = 100%;
красная с подсказкой «Не хватает N%» или «Перебор на N%» - иначе.
Сохранение блокируется, если сумма ≠ 100%.
Предпросмотр - тёмный макет с цветной полосой распределения и легендой:
сегменты соответствуют процентам, цвета фиксированы (палитра из 6 цветов);
подписи на сегментах показываются, только если ширина ≥ 12% - чтобы не сливались;
в легенде: цветная точка, название группы, тег группы, процент.
Кнопка «＋ Добавить группу» добавляет пустую карточку.
4.4. Вкладка «Поверхности»
Сетка кликабельных чипсов из справочника surfaces (ab_experiment_surface). Клик по чипу включает/выключает поверхность. Включённый - красный. Счётчик под сеткой показывает «Выбрано: N из M».
На невыбранных поверхностях эксперимент не действует - там продолжает работать текущая версия сценария.
4.5. Вкладка «Правила запуска»
Две карточки: Правила запуска и «Как это сработает».
Поля (привязаны к ab_experiment):
| Поле | Модель | Тип
| Когда включать | launch_mode из ab_launch_modes (3) | select
| Аудитория | audience_code из ab_audiences (4) | select
| Сегмент | segment | input, показывается только при audience_code = 'segment'
| Приоритет | priority | number
| Один пользователь всегда попадает в одну и ту же группу | stable_bucketing | switch
| Логировать группу в каждом запросе | log_group | switch
| При остановке - вернуть всех на контрольную группу | return_to_control_on_stop | switch
Блок «Как это сработает» - динамический список, пересобирается на каждое изменение полей. Показывает человеко-читаемую интерпретацию: аудитория, режим запуска, приоритет, поведение при стабильном распределении и логировании, поведение при остановке, шаги от запроса до аналитики.
5. Справочники
5.1. Статические (соответствуют ab_* из PDF)
| Константа | Таблица | Значений
| DICT_AB_STATUSES | ab_statuses | 5 (draft, active, paused, completed, archived)
| DICT_AB_AUDIENCES | ab_audiences | 4 (all, authorized, new, segment)
| DICT_AB_METRICS | ab_metrics | 4 (resolution_rate, response_time, csat, escalation_rate)
| DICT_AB_LAUNCH_MODES | ab_launch_modes | 3 (immediate, scheduled, manual)
5.2. Внешние данные
Поверхности (SURFACES) - из раздела «Поверхности», пара id → name (без создания).
Ответственные (RESPONSIBLE_USERS) - из СУДИР, пара id → name.
5.3. Демо-данные
Массив AB_DATA содержит 5 экспериментов с разными статусами, режимами запуска, аудиториями и метриками. Каждый - с массивом групп и массивом поверхностей.
6. Вспомогательные механизмы
6.1. Тост-уведомления
Появляются в правом нижнем углу на 2 секунды: «Группа добавлена», «Группа удалена», «Изменения сохранены», «Эксперимент завершён», «Фильтр сохранён».
6.2. Модальные окна
Экспорт списка/карточки - чекбоксы полей/разделов, кнопка «Выгрузить».
Подтверждение выхода - «Выйти без сохранения?».
Подтверждение завершения - стандартный confirm().
6.3. Drag-and-drop
Реализован для групп (ab_group.sort_order). Визуальная индикация: серый dragging у источника, красная рамка drop-target у цели. После перетаскивания sort_order пересчитывается, предпросмотр обновляется.
6.4. Валидация
При сохранении проверяется:
name и code не пусты и уникальны,
минимум 2 группы,
сумма процентов = 100%,
минимум одна поверхность,
теги групп уникальны между собой.
При неудаче - тост с конкретной причиной, поле подсвечивается красным.
6.5. Клавиатурные сокращения
Esc - закрыть модалку.
Клик по бэкдропу - закрыть модалку.
7. Соответствие модели данных
| Таблица PDF | Реализация
| ab_experiment | Объект draft + AB_DATA, все поля в UI
| ab_group | draft.groups[] с name, percent, tag, sort_order
| ab_experiment_surface | draft.surfaces[] - массив surface_id
| ab_statuses | DICT_AB_STATUSES, используется через status
| ab_audiences | DICT_AB_AUDIENCES, audience_code
| ab_metrics | DICT_AB_METRICS, metric_code
| ab_launch_modes | DICT_AB_LAUNCH_MODES, launch_mode
Все коды и подписи совпадают с PDF. Поле team_id не используется - владелец хранится строкой в owner. Теги групп - уникальны внутри эксперимента.
8. Ограничения и не реализовано
Серверная валидация - всё на клиенте, данные в памяти браузера и теряются при перезагрузке.
Soft delete (deleted_at в справочниках) - не задействован.
Загрузка реальных поверхностей и ответственных - используются статические массивы.
Журнал изменений - нет, только updated_at в шапке.
Запрет изменения tag для запущенного эксперимента - в PDF указано «проверка выполняется на сервере», в прототипе UI этого не блокирует.
Расписание запуска (launch_mode = scheduled) - не реализовано поле с датой/временем автоматического старта.
Согласование приоритетов пересекающихся экспериментов - предполагается серверная логика, в UI только поле priority.
9. Типичный сценарий работы
Открыть раздел «A/B эксперименты» в меню слева.
Найти тест через поиск или фильтры (поверхность, статус, расширенные условия).
Кликнуть по строке - открыть карточку.
Вкладка «Основное»: проверить название, код, статус, владельца, даты, теги, гипотезу, метрику, размер выборки, автостоп.
Вкладка «Группы и распределение»: задать название, процент и тег для каждой группы. Проверить сумму процентов (должна быть 100%) и предпросмотр распределения.
Вкладка «Поверхности»: выбрать поверхности, на которых действует эксперимент.
Вкладка «Правила запуска»: настроить режим запуска, аудиторию, сегмент, приоритет, переключатели. Проверить блок «Как это сработает».
Нажать «Сохранить» - сработает валидация.
При необходимости - «Приостановить» или «Выключить».
Вернуться к списку по хлебным крошкам.
Таблицы
Модель данных раздела "A/B тестирование"
Раздел "A/B тестирование" служит для настройки правил распределения пользовательских запросов между несколькими версиями одного сценария, например между текущим и новым алгоритмом Диспетчера Команд. Каждый эксперимент делит аудиторию на группы с заданными процентами.
Префикс таблиц раздела: ab_.
2. Связующие таблицы
2.1. ab_experiment_surface
Назначение: поверхности, на которых действует эксперимент.
Где используется:
список экспериментов - колонка "Поверхности", вывод чипсов;
список экспериментов - фильтр по поверхностям;
карточка эксперимента, вкладка "Поверхности" - сетка чипсов, клик включает или выключает поверхность;
карточка эксперимента, вкладка "Поверхности" - счётчик выбранных;
карточка эксперимента, вкладка "Основное" - проверка: выбрана хотя бы одна поверхность.
| Поле | Тип | Обязательность | Ключ | Комментарий
| id | UUID | да | PK | Идентификатор записи
| experiment_id | UUID | да | FK ab_experiment.id | Эксперимент
| surface_id | UUID | да | FK surfaces.id | Поверхность, таблица раздела "Поверхности"
| created_at | datetime | да | - | Дата создания связи
Первичный ключ: id. Ограничение: уникальный по (experiment_id, surface_id).
Примечание: surfaces.id принадлежит разделу "Поверхности" и в настоящем документе не создаётся.
3. Основные таблицы
3.1. ab_experiment
Назначение: A/B эксперимент. Ядро раздела.
Где используется:
список экспериментов - строка: название и код, поверхности, число групп, статус;
список экспериментов - поиск по названию, коду и тегу группы;
список экспериментов - фильтры по поверхностям и статусу, сортировка;
список экспериментов - кнопка "Создать тест";
карточка эксперимента - шапка: название, код, статус;
карточка эксперимента, вкладка "Основное" - название, служебный код, владелец и ответственный, описание;
карточка эксперимента, вкладка "Основное" - даты начала и окончания, теги;
карточка эксперимента, вкладка "Основное" - блок "Гипотеза и метрика": что проверяем, основная метрика, минимальный размер выборки, автостоп;
карточка эксперимента, вкладка "Группы и распределение" - сводка суммы процентов;
карточка эксперимента, вкладка "Правила запуска" - когда включать, аудитория, сегмент, приоритет;
карточка эксперимента, вкладка "Правила запуска" - переключатели: стабильное распределение, логирование группы, возврат на контрольную;
карточка эксперимента - кнопки "Сохранить", "Приостановить", "Выключить";
карточка эксперимента - проверка: заполнены обязательные поля, сумма процентов равна 100, выбрана хотя бы одна поверхность;
модалка экспорта - состав полей выгрузки.
| Поле | Тип | Обязательность | Ключ | Комментарий
| id | UUID | да | PK | Идентификатор эксперимента
| code | varchar(100) | да | U | Служебный код, латиница и подчёркивания
| name | varchar(255) | да | U | Название теста
| owner | varchar(200) | нет | - | Владелец эксперимента, подразделение
| responsible_user_id | UUID | нет | внешняя | Ответственный, идентификатор СУДИР
| description | text | нет | - | Кратко, что проверяется
| started_on | date | нет | - | Дата начала
| ended_on | date | нет | - | Дата окончания, пусто для ручного завершения
| tags | text | нет | - | Теги через запятую
| hypothesis | text | нет | - | Что проверяем
| metric_code | varchar(50) | нет | FK ab_metrics.code | Основная метрика
| min_sample_size | integer | нет | - | Минимальный размер выборки в каждой группе
| auto_stop | boolean | нет | - | Автоматическая остановка при явном перевесе
| status | varchar(32) | да | FK ab_statuses.code | Статус эксперимента
| launch_mode | varchar(32) | нет | FK ab_launch_modes.code | Когда включать
| audience_code | varchar(32) | нет | FK ab_audiences.code | Аудитория
| segment | varchar(255) | нет | - | Сегмент, если выбрана аудитория по сегменту
| priority | integer | нет | - | Приоритет при пересечении экспериментов
| stable_bucketing | boolean | да | - | Один пользователь всегда попадает в одну и ту же группу
| log_group | boolean | да | - | Логировать группу в каждом запросе
| return_to_control | boolean | да | - | При остановке вернуть всех на контрольную группу
| created_at | datetime | да | - | Дата создания записи
| updated_at | datetime | да | - | Дата последнего изменения
| deleted_at | datetime | нет | - | Дата мягкого удаления
Индексы: уникальный по code, уникальный по name, обычные по status, metric_code, audience_code.
Примечание: поле team_id из исходной модели удалено, команды не хранятся. Владелец хранится строкой в поле owner.
3.2. ab_group
Назначение: группа эксперимента с процентом распределения и тегом.
Где используется:
список экспериментов - колонка "Групп", число групп в тесте;
список экспериментов - поиск по тегу группы;

| Поле | Тип | Обязательность | Ключ | Комментарий
| id | UUID | да | PK | Идентификатор группы
| experiment_id | UUID | да | FK ab_experiment.id | Эксперимент
| name | varchar(255) | да | - | Название группы
| percent | integer | да | - | Процент распределения
| tag | varchar(64) | да | - | Тег группы, идёт в логи и аналитику
| sort_order | integer | да | - | Порядок группы в предпросмотре и легенде
| created_at | datetime | да | - | Дата создания записи
| updated_at | datetime | да | - | Дата последнего изменения
Индексы: обычный по experiment_id. Ограничения: сумма percent по эксперименту равна 100, уникальный по (experiment_id, tag).
Примечание: тег группы фиксируется до запуска. Изменение тега после запуска ломает сопоставление с аналитикой, поэтому поле не должно изменяться для запущенного эксперимента. Проверка выполняется на сервере.
