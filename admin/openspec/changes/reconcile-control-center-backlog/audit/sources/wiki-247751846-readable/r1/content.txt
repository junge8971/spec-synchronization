Описание
1. Назначение
Раздел «Справочники» - единый реестр справочников платформы ЦАМ. Здесь администратор управляет значениями, которые раньше были захардкожены в коде: статусы, типы, шрифты, формы элементов, категории базы знаний, причины оценок, правила вложений. Изменения применяются сразу после сохранения - без релиза и без участия разработчиков.
Раздел даёт администратору единый интерфейс для всех справочников, независимо от того, где физически хранятся их значения.
2. Ключевая идея: три типа справочников
Поведение каждого справочника зависит от его типа. Тип задаётся при создании и не меняется.
| Тип | Назначение | Что можно делать | Метка в UI
| Системный (system) | Значения, на которые завязана логика в коде. Например, статусы объектов | Только просмотр. Редактирование, добавление и удаление значений заблокированы | 🔒 Синий бейдж
| Информационный (informational) | Выпадающие списки в карточках, хранят метаданные объектов | Просмотр и редактирование. Значения можно добавлять, переименовывать, удалять | ✏ Зелёный бейдж
| Пользовательский (user) | Значения, которые нигде в карточках не отражаются - создаются для собственных нужд | Полный CRUD: редактирование, приостановка, удаление справочника и его значений | ✚ Фиолетовый бейдж
Дополнительно у справочника есть вид (kind):
Список значений - обычный перечень;
Правила вложений - уникальный справочник, описывающий политику загрузки файлов.
3. Экран «Список справочников»
3.1. Шапка
Заголовок «Справочники».
Описание раздела.
Кнопки: ⤓ Экспорт и ＋ Создать справочник.
3.2. Информационный баннер
Под шапкой - блок-подсказка, где простыми словами объяснены все три типа справочников: что они значат, что можно с ними делать, чем отличаются.
3.3. Таблица
Отображает все справочники со следующими колонками:
| Колонка | Что показывает | Сортировка
| Справочник | Название + код (monospace). У правил вложений - метка «📎 правила» | ✓
| Тип | Цветной бейдж: Синий / Зелёный / Фиолетовый | ✓
| Значений | Количество значений внутри справочника | ✓
| Владелец | Команда или подразделение | ✓
| Статус | Активен / Черновик / Приостановлен | ✓
| Стрелка «›» | Переход в карточку | -
Клик по заголовку сортирует по возрастанию, повторный клик - по убыванию, третий - снимает сортировку.
3.4. Поиск
Поле поиска (минимум 2 символа) ищет по названию, коду и описанию справочника.
3.5. Мультиселект-фильтры
| Фильтр | Значения
| Все типы | Системный · Информационный · Пользовательский
| Все статусы | Активен · Черновик · Приостановлен
Рядом с каждой опцией в выпадающем списке - серым шрифтом показан служебный код (system, informational, user).
3.6. Расширенный фильтр «⚙ Условия»
Конструктор произвольных условий:
Логика: И (все условия) / ИЛИ (любое условие).
Поля: Название, Код, Тип (enum), Владелец (текст), Статус (enum), Количество значений (число).
Операторы:
для текста - содержит / не содержит / равно / не равно / начинается с / заканчивается на / пусто / не пусто;
для enum - входит в / не входит в (с чипсами);
для чисел - =, >, ≥, <, ≤, между.
Применённые условия отображаются в панели-баре под фильтрами с кнопкой «Сбросить всё». На кнопке «⚙ Условия» - бейдж с числом активных условий.
3.7. Меню «⋮»
Сохранить текущий фильтр - сохраняет поиск, мультиселекты и расширенные условия под именем.
Скопировать ссылку на отбор - формирует URL с параметрами фильтрации и копирует в буфер.
Сохранённые фильтры - список с возможностью применить или удалить.
3.8. Кнопка «Сбросить»
Появляется, когда есть хотя бы один активный фильтр. Одним нажатием очищает всё.

название справочника,

статус (цветная точка + подпись),
код (monospace),
бейдж типа (Синий / Зелёный / Фиолетовый),
дату последнего обновления.
Кнопки в шапке - зависят от типа:
| Кнопка | Системный | Информационный | Пользовательский
| ⤓ Экспорт | ✓ | ✓ | ✓
| Сохранить | ✕ скрыта | ✓ | ✓
| Приостановить | ✕ скрыта | ✓ | ✓
| Удалить | ✕ скрыта | ✕ скрыта | ✓
| Закрыть | ✓ | ✓ | ✓
4.2. Пояснительный баннер
Под шапкой - блок, который объясняет поведение именно этого справочника:
Системный - «🔒 Только просмотр: логика в коде завязана на эти значения».
Информационный - «✏ Используется как выпадающий список в карточках. Просмотр и редактирование».
Пользовательский - «✚ Не отражается в других карточках. Полный CRUD».
Правила вложений - «📎 Единственный справочник, описывающий политику безопасности загрузки файлов».
4.3. Вкладки
Три вкладки:
Значения - таблица значений справочника.
Настройки - метаданные и правила изменения.
Проверка - автоматические проверки готовности.
5. Вкладка «Значения»
5.1. Общее поведение по типам
| Тип | Поведение на вкладке
| Системный | Все поля и переключатели disabled. Нет ручки drag-and-drop. Кнопка «＋ Добавить значение» скрыта. Кнопка удаления disabled
| Информационный | Полностью редактируемая таблица. Drag-and-drop работает, если allow_rename. Кнопки добавления и удаления активны, если разрешены настройками
| Пользовательский | Полностью редактируемая таблица с теми же правилами
| Правила вложений | Особая таблица с расширенным набором колонок (см. ниже)
5.2. Обычная таблица значений
Колонки:
| Колонка | Что редактируется
| Ручка ⠿ | Порядок вывода (drag-and-drop)
| Код | Служебный код значения, monospace
| Отображается как | Название, которое видят пользователи
| Описание | Подсказка для администраторов
| По умолчанию | Тумблер - только одно значение может быть по умолчанию
| Включено | Тумблер - доступность значения
| Удалить ✕ | Удаление значения
При клике на тумблер «По умолчанию»:
если значение уже было по умолчанию - снимается;
если не было - оно становится единственным, у остальных флаг автоматически сбрасывается.
При клике на тумблер «Включено» - значение становится доступным или недоступным в формах и фильтрах.
5.3. Таблица «Правила вложений»
Особый вид таблицы для kind = rules-attachments. Колонки:
| Колонка | Что редактируется
| Ручка ⠿ | Порядок вывода
| Код | Служебный код правила
| Категория | Название категории файлов
| Расширения | Разрешённые расширения через запятую
| MIME | Маска типа файла
| Макс. размер, МБ | Предел на один файл
| Макс. кол-во | Сколько файлов можно приложить за раз
| Зоны | Где действует: auth / auth, anon
| Включено | Тумблер активности
| Удалить ✕ | Удаление правила
Внизу - пояснение: «Приоритет проверки: сначала точное совпадение MIME, затем расширение. Если файл не подходит ни под одно включённое правило - он блокируется».
5.4. Кнопки управления
⤓ CSV - выгрузка всех значений справочника в CSV.
＋ Добавить значение - создаёт новую пустую строку. Доступно, если allow_add и тип не системный.
6. Вкладка «Настройки»
Две колонки: Основное и Правила изменения.
6.1. Блок «Основное»
| Поле | Тип | Редактируется
| Название | input | у системного - disabled; у остальных - активное
| Служебный код | input (monospace) | всегда disabled - код задаётся при создании
| Тип справочника | select (Системный / Информационный / Пользовательский) | всегда disabled - тип не меняется
| Описание | textarea | у системного - disabled
| Владелец | input | у системного - disabled
| Публикуется в API | тумблер | у системного - disabled
6.2. Блок «Правила изменения»
| Поле | Что делает | Поведение
| Разрешить добавлять новые значения | Управляет кнопкой «＋ Добавить значение» | у системного - снят и disabled
| Разрешить удалять значения | Управляет кнопкой «✕» в таблице значений | у системного - снят и disabled
| Разрешить переименовывать значения | Управляет полями ввода в строках значений | у системного - снят и disabled
| Значения обязательны для других сущностей | Признак обязательности | -
| Кэширование, секунд | Время кэша, 0 - без кэша | -
| Комментарий к изменениям | Свободный текст для журнала | -
7. Вкладка «Проверка»
Автоматически прогоняет список проверок и показывает результаты.
7.1. Сводка
Верхний блок со статусом:
зелёный - все проверки пройдены;
жёлтый - есть предупреждения;
красный - есть критичные ошибки.
Рядом - счётчик пройденных проверок из общего числа.
7.2. Список проверок
Каждая проверка - строка с иконкой:
| Иконка | Значение
| ✓ зелёный | Проверка пройдена
| ! жёлтый | Предупреждение
| ✕ красный | Ошибка - блокирует сохранение
Общие проверки (для всех типов):
Указано название справочника.
Указан служебный код.
Код справочника уникален.
Заполнено описание.
Указан владелец.
Добавлено хотя бы одно значение.
У всех значений заполнен код.
У всех значений заполнено отображаемое название.
Коды значений уникальны внутри справочника.
Не более одного значения по умолчанию.
Дополнительные проверки для правил вложений:
У всех правил указаны расширения.
У всех правил указаны MIME-маски.
У всех правил указаны зоны действия.
Есть хотя бы одно включённое правило.
7.3. Действия
↻ Перепроверить - прогнать проверки заново.
Счётчик на вкладке «Проверка» показывает количество проблемных проверок (ошибки + предупреждения). Если есть - вкладка подсвечивается красным и становится жирной.
8. Создание нового справочника
Открывается по кнопке «＋ Создать справочник» в шапке списка.
8.1. Модалка
Поля:
| Поле | Обязательность | Валидация
| Название | обязательное | непустое
| Служебный код | обязательное | латиница + цифры + подчёркивания, первая буква - латинская; уникальный
| Описание | необязательное | -
| Владелец | необязательное | по умолчанию «Команда ЦАМ»
8.2. Логика создания
По умолчанию создаётся пользовательский справочник (type = 'user').
Системные и информационные справочники создаются разработчиками - в интерфейсе их создать нельзя.
Валидация в реальном времени: как только пользователь ввёл код, он проверяется на соответствие регулярному выражению и на уникальность. При конфликте поле подсвечивается, кнопка «Создать» блокируется.
Созданный справочник получает статус «Черновик», пустой список значений и полный набор разрешений (allowAdd = allowDelete = allowRename = true).
После создания справочник сразу открывается в карточке - можно добавлять значения.
9. Экспорт
Два вида экспорта:
9.1. Экспорт списка справочников
Открывается по кнопке «⤓ Экспорт» в шапке списка. Модалка с чекбоксами полей:
| Поле | По умолчанию отмечено
| Название справочника | ✓
| Служебный код | ✓
| Тип | ✓
| Владелец | ✓
| Количество значений | ✓
| Статус | ✓
| Описание | -
| Дата обновления | -
Экспортируется текущая выборка с учётом активных фильтров. Файл - CSV в кодировке UTF-8 с BOM.
9.2. Экспорт значений справочника
Кнопка «⤓ CSV» на вкладке «Значения». Выгружает все значения текущего справочника в CSV. Для правил вложений - колонки: Код, Категория, Расширения, MIME, Макс. размер, Макс. кол-во, Зоны, Включено, Примечание.
10. Приостановка и удаление
10.1. Приостановка
Кнопка «Приостановить» в шапке карточки доступна для информационных и пользовательских справочников. Переключает статус между Активен и Приостановлен.
Приостановленный справочник:
остаётся в реестре,
не исчезает из списка,
но его значения не подтягиваются в формы и фильтры.
10.2. Удаление
Кнопка «Удалить» доступна только для пользовательских справочников. При нажатии - подтверждение, после чего справочник и все его значения удаляются из реестра.
Системные и информационные справочники удалить нельзя.
11. Динамическое поведение
11.1. Автоматическое обновление счётчиков
Счётчик значений на вкладке «Значения» обновляется при добавлении/удалении.
Счётчик проблем на вкладке «Проверка» пересчитывается при каждом изменении.
Счётчик найденных справочников в списке обновляется при фильтрации.
11.2. Отслеживание изменений
Флаг dictDirty устанавливается при любом изменении. Если пользователь попробует закрыть карточку - система спросит подтверждение.
11.3. Обновление даты
При сохранении обновляется updatedAt и выводится в шапке карточки.
13. Типичный сценарий работы
Открыть раздел «Справочники» в меню слева.
Найти нужный справочник через поиск, мультиселекты или расширенные условия.
Кликнуть по строке - открыть карточку.
Вкладка «Значения» - посмотреть или отредактировать список (если тип не системный).
Если справочник новый или изменился - перейти на вкладку «Проверка» и убедиться, что все проверки пройдены.
При необходимости изменить настройки на вкладке «Настройки».
Нажать «Сохранить» - изменения применятся сразу.
При необходимости - «Приостановить» или «Удалить» (для пользовательских).
Вернуться к списку по хлебным крошкам.
Готово - изменения в справочнике автоматически подхватятся во всех разделах, где он используется: в формах, выпадающих списках, фильтрах и API.

| Тип | Количество полей | Что это

| Информационный | 8 | Выпадающие списки в карточках, метаданные объектов. Просмотр и редактирование.
| Пользовательский | 0 | В существующих разделах таких полей нет - они создаются отдельно, например «Каналы обращений», «Округа Москвы», «Приоритеты заявок».
Итого: 32 поля в 7 разделах платформы, которые логично вынести в справочники.
Главное решение по разделу
Раздел "Справочники" не хранит значения чужих справочников. Он ведёт их реестр и управляет ими.
Основания:
Значения системных и информационных справочников принадлежат разделам-владельцам: skill_statuses в разделе "Навыки", surface_types в разделе "Поверхности", kb_categories в разделе "База знаний".
Раздел "Справочники" даёт единый интерфейс управления, но физическое хранение остаётся в разделе-владельце, чтобы не дублировать данные и не создавать вторую точку правды.
Для пользовательских справочников значения хранятся в единой таблице ref_dictionary_user (см. п. 3.4).
Реестр ref_dictionary имеет связь 1 к 1 с таблицей-хранилищем: для системных/информационных - с таблицей раздела, для пользовательских - с ref_dictionary_user.
Следствие: в базе нет отдельной таблицы ref_dictionary_value под каждый пользовательский справочник. Таблица ref_storage_tables упразднена
Только один справочник принадлежит самому разделу: правила вложений (ref_attachment_rule). Он хранится в разделе, так как описывает политику безопасности загрузки файлов и не относится к другому разделу.
3. Основные таблицы
3.1. ref_dictionary
Назначение: реестр справочников системы. Одна запись описывает один справочник.
Где используется:
список справочников - строка: название и код, тип влияния, число значений, владелец, статус;
список справочников - поиск по названию, коду и описанию от 2 символов;
список справочников - фильтры по типу влияния и статусу;
список справочников - метка "правила" у справочника правил вложений;
список справочников - сортировка;
модалка создания справочника - название, служебный код, тип справочника, владелец, описание;
карточка справочника - шапка: название, описание, статус, служебный код, метка типа, дата обновления;
карточка справочника, вкладка "Настройки" - основное: название, служебный код, тип влияния, описание, владелец, публикация в API;
карточка справочника, вкладка "Настройки" - правила изменения: разрешение добавлять, удалять, переименовывать значения, обязательность значений, кэширование, комментарий к изменениям;
карточка справочника - кнопки "Сохранить", "Приостановить", "Удалить";
карточка справочника, вкладка "Проверка" - проверки готовности к сохранению и активации;
модалка экспорта - состав полей выгрузки.
Важно: Связь ref_dictionary с таблицей-хранилищем значений: 1 к 1. Для системных и информационных справочников - таблица раздела-владельца (storage_table). Для пользовательских - единая таблица ref_dictionary_user (storage_table = 'ref_dictionary_user').

| updated_at | datetime | да | - | Дата последнего изменения

3.2. ref_attachment_rule
Назначение: правила вложений. Единственный справочник, принадлежащий самому разделу. Описывает политику загрузки файлов пользователями и операторами.
Где используется:
карточка справочника "Правила вложений", вкладка "Значения" - таблица правил: код, категория, расширения, MIME, максимальный размер, максимальное количество, зоны, включено;
карточка справочника "Правила вложений" - редактирование правила;
карточка справочника "Правила вложений" - включение и отключение правила;
карточка справочника "Правила вложений" - удаление правила, если разрешено настройками;
карточка справочника "Правила вложений", вкладка "Проверка" - проверки расширений, MIME, зон и наличия включённых правил.
| Поле | Тип | Обязательность | Ключ | Комментарий
| id | UUID | да | PK | Идентификатор правила
| code | varchar(64) | да | U | Служебный код правила
| display_name | varchar(150) | да | - | Категория: изображения, документы, аудио, видео
| extensions | varchar(500) | да | - | Разрешённые расширения через запятую
| mime | varchar(255) | да | - | Маска типа файла, например image/*
| max_size_mb | integer | да | - | Предел на один файл, мегабайты
| max_count | integer | да | - | Сколько файлов можно приложить за раз
| zones | varchar(100) | да | - | Зоны действия: auth или auth, anon
| is_enabled | boolean | да | - | Если выключено, загрузка таких файлов блокируется
| note | text | нет | - | Примечание администратора
| sort_order | integer | да | - | Порядок вывода правил
| created_at | datetime | да | - | Дата создания записи
| updated_at | datetime | да | - | Дата последнего изменения
Индексы: уникальный по code.
Порядок проверки: сначала точное совпадение MIME, затем расширение. Если файл не подошёл ни под одно включённое правило, он блокируется.
3.3. ref_dictionary_user
Назначение: единая таблица хранения значений пользовательских справочников. Все пользовательские справочники хранят значения в одной таблице, связанной с реестром через внешний ключ на ref_dictionary.id.
Где используется:
карточка справочника, вкладка "Значения" - таблица значений пользовательского справочника;
карточка справочника, вкладка "Значения" - ручка перетаскивания, код, отображаемое название, описание, переключатели "По умолчанию" и "Включено";
карточка справочника, вкладка "Значения" - добавление, деактивация, мягкое удаление значений;
список справочников - счётчик числа значений по dictionary_id.
| Поле | Тип | Обязательность | Ключ | Комментарий
| id | UUID | да | PK | Идентификатор записи
| dictionary_id | UUID | да | FK ref_dictionary.id | Справочник-владелец
| code | varchar(50) | да | U | Код значения
| display_name | varchar(150) | да | - | Отображаемое название
| description | text | нет | - | Описание значения
| sort_order | smallint | да | - | Порядок вывода
| is_default | boolean | нет | - | Значение по умолчанию
| is_active | boolean | да | - | Доступность значения
| deleted_at | datetime | нет | - | Дата мягкого удаления
| created_at | datetime | да | - | Дата создания записи
| updated_at | datetime | да | - | Дата последнего изменения
Индексы: уникальный по (dictionary_id, code), обычный по dictionary_id, обычный по is_active.
