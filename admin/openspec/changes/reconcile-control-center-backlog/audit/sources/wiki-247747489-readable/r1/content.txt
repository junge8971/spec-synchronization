1. Назначение
Раздел «Состояние системы» - централизованный пульт управления платформой ЦАМ. Здесь собраны все элементы платформы, которые можно включать и отключать без релиза: модули ЦАМ-панели и функции Цифрового ассистента. Каждый элемент управляется рубильником - состояние применяется сразу, без сохранения и без участия разработчиков.
Раздел защищён: доступ только для администратора платформы, о чём явно сообщает метка «🔒 Доступ только для администратора платформы» под заголовком.
2. Общая структура
Раздел состоит из двух экранов:
Список элементов - стартовый экран с вкладками, таблицей, поиском, фильтрами и кнопкой создания.
Карточка элемента - экран просмотра/редактирования одного элемента с большим рубильником в шапке.
Переход между экранами - по клику на строку таблицы или по хлебным крошкам.
3. Экран «Список элементов»
3.1. Шапка
Заголовок «Состояние системы».
Краткое описание раздела.
Метка доступа «🔒 Доступ только для администратора платформы».
Кнопки: ⤓ Экспорт и ＋ Создать запись.
3.2. Информационный блок
Под шапкой - карточка «Рубильники платформы» с пояснением: каждое изменение применяется сразу, отключение критичных элементов может повлиять на работу всего ЦАМ.
3.3. Сводка
Четыре счётчика по текущей вкладке:
| Метрика | Что показывает
| Включено | Количество элементов с enabled = true
| Отключено | Количество элементов с enabled = false
| Критичных | Количество элементов с critical = true
| Всего | Общее число элементов на вкладке
3.4. Вкладки
Две вкладки с автоматическим подсчётом количества:
| Вкладка | Что показывает
| Модули ЦАМ панели | 15 модулей (12 предопределённых + 3 пользовательских)
| Функции Цифрового ассистента | 14 функций (12 предопределённых + 2 пользовательских)
При переключении вкладки:
пересчитывается сводка;
перестраивается мультиселект «Все разделы» - оставляет только те группы, что есть на вкладке;
сбрасывается фильтр по разделу.
3.5. Таблица
Отображает элементы со следующими колонками:
| Колонка | Что показывает | Сортировка
| Элемент | Название + код (monospace). Рядом - красная точка для критичных и фиолетовый бейдж «своя» для пользовательских | ✓
| Раздел | Логическая группа элемента | ✓
| Последнее изменение | Дата и время + ФИО изменившего | ✓
| Состояние | Инлайн-переключатель + подпись «Включено» / «Отключено» | ✓
| Стрелка «›» | Переход в карточку | -
Клик по заголовку сортирует по возрастанию, повторный клик - по убыванию, третий - снимает сортировку.
3.6. Поиск
Поле поиска (минимум 2 символа) ищет по:
названию,
служебному коду,
разделу,
описанию.
3.7. Мультиселект-фильтры
Четыре независимых фильтра с чекбоксами:
| Фильтр | Значения
| Все состояния | Включено / Отключено
| Все разделы | Динамический список - только группы, присутствующие на текущей вкладке
| Критичность | Критичный / Обычный
| Все типы | Модуль / Функция
Кнопка «Все …» внутри каждого фильтра сбрасывает его.
3.8. Расширенный фильтр «⚙ Условия»
Открывает инлайн-панель с конструктором произвольных условий:
Логика - И (все условия) / ИЛИ (любое условие).
Поля: Название, Код, Раздел, Состояние (enum), Критичность (enum), Тип (enum).
Операторы:
для текстовых - содержит / не содержит / равно / не равно / начинается с / заканчивается на / пусто / не пусто;
для enum - входит в / не входит в (с чипсами).
Применённые условия отображаются в панели-баре под фильтрами с кнопкой «Сбросить всё». На кнопке «⚙ Условия» - бейдж с числом активных условий.
3.9. Меню «⋮»
Сохранить текущий фильтр - сохраняет поиск, мультиселекты и расширенные условия под именем.
Скопировать ссылку на отбор - формирует URL и копирует в буфер.
Сохранённые фильтры - список с возможностью применить или удалить.
3.10. Кнопка «Сбросить»
Появляется, только когда есть хотя бы один активный фильтр (поиск, мультиселект или расширенное условие). Одним нажатием очищает всё.
3.11. Инлайн-переключатель в строке
Клик по тумблеру меняет состояние сразу. Если элемент критичный и включён - система запросит подтверждение перед отключением. Автоматически обновляются:
updatedAt - текущее время,
updatedBy - текущий пользователь,
счётчики сводки,
счётчик найденных записей.
4. Экран «Карточка элемента»
4.1. Шапка карточки
Содержит:
название элемента (H1),
код (monospace),
иконку типа (🧩 для модуля, 🧠 для функции),
метку критичности (красная точка + «критичный» / «обычный»),
фиолетовый бейдж «своя» - только у пользовательских записей.
Кнопки в шапке:
⤓ Экспорт - заглушка с тостом.
Сохранить - только для пользовательских записей.
Удалить - только для пользовательских записей.
Закрыть - подтверждение выхода.
4.2. Блок-шапка с рубильником
Под заголовком - карточка с большой иконкой типа, названием, кодом, метками критичности и «своя», а справа - большой рубильник с подписью состояния.
При отключении критичного элемента - запрос подтверждения. Изменение применяется мгновенно.
4.3. Блок «Параметры»
Поля:
| Поле | Тип | Редактируется
| Описание | textarea | только для isCustom = true
| Тип | select из SYS_TYPES (Модуль / Функция) | disabled всегда - определяется вкладкой
| Раздел | select из SYS_GROUPS (8 групп) | только для isCustom = true
| Критичность | select: Обычный / Критичный | только для isCustom = true
| Влияет на | select из SYS_IMPACTS (13 значений) | только для isCustom = true
Для предопределённых записей все поля заблокированы - их можно только просматривать. Для пользовательских - редактируются и сохраняются кнопкой «Сохранить».
4.4. Блок «Как это работает»
Справочная информация о поведении элементов при переключении:
Переключатель меняет состояние сразу, без сохранения и релиза.
Для модулей панели - раздел появляется/скрывается из меню у всех пользователей.
Для функций ассистента - функция начинает/перестаёт применяться в диалогах.
При отключении критичного элемента система просит подтверждение.
Все действия пишутся в журнал.
5. Модалка «Создать запись»
Открывается по кнопке «＋ Создать запись» в шапке списка.
Поля:
| Поле | Обязательность | Валидация
| Наименование | обязательное | непустое
| Код | обязательное | непустой, уникальный по всей системе
| Раздел | необязательное | select из SYS_GROUPS
Логика:
Тип новой записи определяется текущей вкладкой: на «Модулях» создаётся модуль, на «Функциях» - функция.
Валидация в реальном времени: как только пользователь вводит код, он сверяется со всеми существующими кодами (и модулей, и функций). При дубликате поле подсвечивается, выводится ошибка «Такой код уже используется», кнопка «Создать» блокируется.
Кнопка «Создать» активна только когда поля корректны.
После создания запись получает isCustom = true, enabled = true, critical = false, impact = SYS_IMPACTS[0].
Новая запись сразу открывается в карточке.
6. Экспорт
Открывается по кнопке «⤓ Экспорт» в шапке списка. Модалка с чекбоксами:
| Поле | По умолчанию
| Название | ✓
| Служебный код | ✓
| Тип | ✓
| Раздел | ✓
| Состояние | ✓
| Критичность | ✓
| Последнее изменение | ✓
Пользователь может снять лишние галочки, после нажатия «Выгрузить» показывается подтверждение «Файл готов».
7. Поведение при переключении
| Тип элемента | Что происходит
| Модуль ЦАМ панели | Раздел скрывается из бокового меню у всех пользователей, переход на него недоступен, данные не удаляются
| Функция Цифрового ассистента | Функция перестаёт применяться в диалогах, логи и метрики по ней перестают поступать
| Критичный элемент | Перед отключением запрашивается подтверждение
8. Вспомогательные механизмы
8.1. Тост-уведомления
Появляются в правом нижнем углу на 2 секунды. Сопровождают все значимые действия: включение/отключение элемента, сохранение, удаление, создание, применение фильтра.
8.2. Модалки
Создать запись - наименование, код, раздел.
Экспорт - чекбоксы полей.
Подтверждение выхода - «Выйти без сохранения?».
8.3. Валидация
При создании: обязательность наименования и кода, уникальность кода по всей системе.
При сохранении карточки (для пользовательских): обязательность наименования.
8.4. Клавиатурные сокращения
Esc - закрыть модалку.
Клик по бэкдропу - закрыть модалку.
9. Типичный сценарий работы
Открыть раздел «Состояние системы» в меню слева.
Выбрать вкладку - «Модули ЦАМ панели» или «Функции Цифрового ассистента».
Найти элемент через поиск, мультиселекты или расширенные условия.
Включить/выключить рубильник прямо в строке таблицы. Для критичных - подтвердить отключение.
Открыть карточку элемента, чтобы проверить описание, влияние, критичность.
Для пользовательской записи - отредактировать поля и сохранить; при необходимости - удалить.
Создать новую пользовательскую запись через модалку - при этом код проверится на уникальность.
Экспортировать текущую выборку с выбранными полями.

Описание таблиц раздела «Состояние системы» (под прототип)
1. sys_toggle
Назначение: модули ЦАМ-панели и функции Цифрового ассистента с их текущим состоянием. Ядро раздела.
Где используется:
вкладки «Модули ЦАМ панели» и «Функции Цифрового ассистента» - списки элементов;
сводка сверху: включено, отключено, критичных, всего;
счётчики рядом с названием вкладок;
колонки списка: элемент с кодом, раздел, последнее изменение, состояние;
метка критичного элемента красной точкой;
метка «своя» для пользовательских записей;
переключатель состояния прямо в строке таблицы;
фильтры по состоянию, разделу, критичности, типу;
поиск по названию, коду и описанию;
сортировка по колонкам;
карточка элемента - шапка с иконкой типа, названием, кодом, меткой критичности и большим рубильником;
карточка элемента - описание и поля «Тип», «Раздел», «Критичность», «Влияет на»;
карточка элемента - переключение состояния;
карточка элемента - подтверждение при отключении критичного элемента;
модалка создания записи - валидация уникальности кода;
модалка экспорта - состав полей выгрузки.
| Поле | Тип | Обязательность | Ключ | Комментарий
| id | UUID | да | PK | Идентификатор элемента
| code | varchar(100) | да | U | Служебный код элемента. Уникален по всей таблице
| name | varchar(255) | да | - | Название элемента
| kind | varchar(32) | да | FK sys_toggle_kinds.code | Тип: module - модуль ЦАМ панели, function - функция ассистента
| group | varchar(50) | да | FK sys_toggle_groups.code | Логическая группа внутри вкладки
| description | text | да | - | Полное описание, за что отвечает элемент
| impact | text | нет | FK sys_toggle_impacts.code (мягкая связь) | На что влияет элемент. Хранится как текст, но подсказки - из справочника
| critical | boolean | да | - | Признак критичного элемента
| enabled | boolean | да | - | Текущее состояние рубильника
| updated_at | datetime | да | - | Дата и время последнего изменения
| updated_by | varchar(200) | да | - | Кто изменил состояние
| is_custom | boolean | да | - | Признак пользовательской записи
Индексы: уникальный по code; обычные по kind, group, enabled, critical, is_custom.
Ограничения:
code - уникален глобально, не только внутри kind. При создании новой записи проверяется отсутствие дубликата в обеих вкладках.
is_custom = false - предопределённые записи: поля kind, group, critical, impact, description доступны только для чтения.
is_custom = true - пользовательские записи: все поля редактируются, доступны кнопки «Сохранить» и «Удалить».
Отличие от исходной модели: объединены данные из sys_toggle и часть информации, которая раньше писалась в sys_toggle_history (последнее изменение с датой и автором - теперь прямо в основной таблице). Добавлены поля is_custom и impact вынесен в отдельный справочник для подсказок.

| search | jsonb | да | - | Тело фильтра: поиск, мультиселекты, расширенные условия
| created_at | datetime | да | - | Дата создания
| updated_at | datetime | да | - | Дата последнего изменения
Индексы: уникальный по (user_id, name) - при сохранении фильтра с существующим именем запись перезаписывается.
6. Реестр таблиц раздела
| № | Таблица | Роль
| 1 | sys_toggle | Основная сущность
| 2 | sys_toggle_kinds | Справочник (2 значения)
| 3 | sys_toggle_groups | Справочник (8 значений)
| 4 | sys_toggle_impacts | Справочник (13 значений)
| 5 | system_state_managed_resource_saved_filters | Сохранённые фильтры
Всего таблиц: 5.
7. Сводка внешних ключей
| Таблица | Поле | Ссылается на
| sys_toggle | kind | sys_toggle_kinds.code
| sys_toggle | group | sys_toggle_groups.code
| sys_toggle | impact | sys_toggle_impacts.code (мягкая связь - значение хранится как текст)
| system_state_managed_resource_saved_filters | user_id | внешняя, СУДИР
Ссылки во внешние системы: sys_toggle.updated_by - идентификатор СУДИР (в прототипе хранится ФИО строкой для упрощения демонстрации).
8. Что изменилось по сравнению с исходной моделью
| Что | Исходная модель | Новая модель (под прототип)
| История переключений | Отдельная таблица sys_toggle_history (append-only) | Не хранится, в основной таблице остаются только updated_at и updated_by
| Действия переключения | Справочник sys_toggle_actions (2 значения) | Удалён - нет истории, действия негде использовать
| Подсказки для impact | Свободный текст без справочника | Добавлен справочник sys_toggle_impacts (13 значений)
| Групп в справочнике | 7 (content, platform, core, security, speech, dialog, analytics) | 8 - добавлена группа «Пользовательские» для кастомных записей
| Пользовательские записи | Не предусмотрены | Добавлено поле is_custom, модалка создания, валидация уникальности кода
| Код группы | group_code (код) | group - хранится значение, но по смыслу то же самое
| Сохранённые фильтры | Не описывались | Добавлена таблица system_state_managed_resource_saved_filters
