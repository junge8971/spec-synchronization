API Contract
Общая информация
Версия контракта: v1
Тип изменения:
Новые методы управления пользователями.
Базовый путь: /api/access
Аутентификация: прикладная сессия в защищённой HttpOnly cookie.
Общие заголовки
| Заголовок | Обязательность | Описание
| X-Request-Id | Нет | UUID запроса. Backend создаёт значение, если заголовок не передан
| Idempotency-Key | Для изменяющих команд | UUID, который однозначно идентифицирует команду
Ответ содержит X-Request-Id с идентификатором запроса.
Общая модель ответа
Каждый HTTP-ответ содержит общую оболочку:
{
"code": "SUCCESS",
"data": {},
"message": "Операция выполнена успешно.",
"errors": []
}
| Поле | Тип | Описание
| code | string | Машиночитаемый код результата
| data | object или null | Результат операции. При ошибке равно null
| message | string | Описание результата для пользователя
| errors | array | Детали ошибок. При успешном ответе массив пуст
Элемент errors может содержать code, message, field и details. Набор полей зависит от типа ошибки.
1. Цель задачи
Предоставить административному интерфейсу API для:
получения списка пользователей;
получения карточки пользователя;
активации пользователя;
блокировки пользователя.
История действий над пользователем не входит в этот контракт. Административный интерфейс получает её через Query API сервиса аудита по типу объекта user и идентификатору пользователя. Endpoint и модель ответа определяет контракт сервиса аудита.
2. Методы API
2.1 Получить список пользователей
GET /api/access/api/v1/users
Разрешение: users.read
Параметры запроса
| Параметр | Тип | Обязательность | Описание
| query | string | Нет | Поиск без учёта регистра по началу фамилии, имени, отчества или email.
| status | string | Нет | Одно или несколько состояний через запятую
| role | string | Нет | Один или несколько кодов ролей через запятую. Профиль должен иметь хотя бы одну из указанных ролей
| sudir_subject_id | string | Нет | Точное совпадение
| created_from | date-time | Нет | Нижняя граница created_at, включительно
| created_to | date-time | Нет | Верхняя граница created_at, не включительно
| sort | string | Нет | Поля сортировки через запятую. Префикс - задаёт убывание
| limit | integer | Нет | Число записей на странице от 1 до 100. Значение по умолчанию: 50
| offset | integer | Нет | Число пропускаемых записей. Минимальное значение: 0. Значение по умолчанию: 0
Допустимые значения status:
pending;
active;
suspended;
Допустимые поля сортировки:
full_name;
status;
created_at;
updated_at.
Предварительные коды ролей:
| Код | Название в C4
| platform_admin | Администратор платформы
| security_admin | Администратор безопасности
| super_admin | Супер-администратор
| support | Клиентский сервис
| assessor | Асессор
| skill_team | Команда навыка
| surface_owner | Владелец поверхности
| product_manager | Менеджер продукта
| executive | Руководитель
Сортировка по умолчанию: full_name,id. Backend добавляет id последним ключом для стабильного порядка.
created_from должен быть меньше created_to.
Пример запроса
GET /api/access/api/v1/users?query=иван&status=active,suspended&sort=full_name&limit=1&offset=0
X-Request-Id: 89902ade-eab6-47b3-9e6e-7b75a895c192
Успешный ответ
200 OK
{
"code": "SUCCESS",
"data": {
"items": [
{
"id": "52f411aa-977b-4d26-9a5b-d896ca9c1e64",
"sudir_subject_id": "6748921",
"name": {
"family_name": "Иванов",
"name": "Иван",
"middle_name": "Иванович"
},
"email": "ivan.ivanov@example.org",
"roles": [
"platform_admin"
],
"status": "active",
"version": 5,
"created_at": "2026-08-20T11:03:51Z",
"updated_at": "2026-09-02T16:21:09Z"
}
],
"pagination": {
"limit": 1,
"offset": 0,
"current_page": 1,
"total_items": 137,
"total_pages": 137
}
},
"message": "Список пользователей получен.",
"errors": []
}
current_page вычисляется как floor(offset / limit) + 1.
total_pages вычисляется как ceil(total_items / limit).
Пустой результат возвращает 200 OK, пустой массив items, total_items: 0 и total_pages: 0.
Поля пагинации
| Поле | Тип | Описание
| limit | integer | Запрошенное число записей на странице
| offset | integer | Число пропущенных записей
| current_page | integer | Номер текущей страницы, начиная с 1
| total_items | integer | Общее число записей с учётом фильтров
| total_pages | integer | Общее число страниц при текущем limit
Поля элемента списка
| Поле | Тип | Обязательность | Описание
| id | UUID | Да | Локальный идентификатор профиля
| sudir_subject_id | string | Да | Идентификатор субъекта СУДИР
| name.family_name | string | Да | Фамилия
| name.name | string | Да | Имя
| name.middle_name | string или null | Да | Отчество
| email | string или null | Да | Email
| roles | array[string] | Да | Коды назначенных ролей. Для профиля без назначений массив пуст
| status | string | Да | Административное состояние
| version | int64 | Да | Версия профиля
| created_at | date-time | Да | Время создания профиля
| updated_at | date-time | Да | Время последнего изменения профиля

2.3 Активировать пользователя
POST /api/access/api/v1/users/{user_id}/actions/activate
Разрешение: users.activate
Допустимые переходы:
pending -> active;
suspended -> active.
Параметры пути
| Параметр | Тип | Описание
| user_id | UUID | Локальный идентификатор профиля
Заголовки
| Заголовок | Тип | Обязательность | Описание
| Idempotency-Key | UUID | Да | Уникальный ключ команды
Тело запроса
| Поле | Тип | Обязательность | Описание
| expected_version | int64 | Да | Положительная версия, которую получил клиент
| reason | string | Да | Основание длиной от 1 до 1000 символов
{
"expected_version": 4,
"reason": "Доступ согласован по заявке SDEXP-1234."
}
Успешный ответ
200 OK
{
"code": "SUCCESS",
"data": {
"id": "52f411aa-977b-4d26-9a5b-d896ca9c1e64",
"status": "active",
"version": 5,
"updated_at": "2026-09-02T16:21:09Z"
},
"message": "Пользователь активирован.",
"errors": []
}
Старая прикладная сессия не восстанавливается после активации. Пользователь проходит вход заново.
2.4 Заблокировать пользователя
POST /api/access/api/v1/users/{user_id}/actions/block
Разрешение: users.block
Допустимый переход: active -> suspended.
Параметры пути
| Параметр | Тип | Описание
| user_id | UUID | Локальный идентификатор профиля
Заголовки
| Заголовок | Тип | Обязательность | Описание
| Idempotency-Key | UUID | Да | Уникальный ключ команды
Тело запроса
| Поле | Тип | Обязательность | Описание
| expected_version | int64 | Да | Положительная версия, которую получил клиент
| reason | string | Да | Основание длиной от 1 до 1000 символов
{
"expected_version": 5,
"reason": "Доступ приостановлен по заявке SDEXP-1234."
}
Успешный ответ
200 OK
{
"code": "SUCCESS",
"data": {
"id": "52f411aa-977b-4d26-9a5b-d896ca9c1e64",
"status": "suspended",
"version": 6,
"updated_at": "2026-09-03T10:15:30Z"
},
"message": "Пользователь заблокирован.",
"errors": []
}
После успешного ответа все прикладные сессии пользователя недействительны. Команда не изменяет глобальную блокировку или токены СУДИР.
2.5 Обработка конкурентных и повторных команд
Backend сравнивает expected_version с текущей версией профиля. При успешном изменении backend увеличивает version на единицу.
Повтор команды с тем же Idempotency-Key, HTTP-методом, URI и телом возвращает исходный HTTP-статус и исходное тело. Повтор не изменяет профиль второй раз. Тот же ключ с другим HTTP-методом, URI или телом возвращает IDEMPOTENCY_KEY_REUSED.
Конфликт версии
409 Conflict
{
"code": "VERSION_CONFLICT",
"data": null,
"message": "Профиль был изменён другим запросом.",
"errors": [
{
"code": "VERSION_CONFLICT",
"message": "Ожидаемая версия профиля не совпадает с текущей.",
"details": {
"id": "52f411aa-977b-4d26-9a5b-d896ca9c1e64",
"expected_version": 5,
"current_version": 6
}
}
]
}
Клиент после VERSION_CONFLICT повторно получает карточку пользователя. Клиент не повторяет команду автоматически.
Недопустимый переход
409 Conflict
{
"code": "INVALID_STATE_TRANSITION",
"data": null,
"message": "Переход состояния профиля запрещён.",
"errors": [
{
"code": "INVALID_STATE_TRANSITION",
"message": "Нельзя заблокировать пользователя в текущем состоянии.",
"details": {
"id": "52f411aa-977b-4d26-9a5b-d896ca9c1e64",
"current_status": "pending",
"requested_status": "suspended"
}
}
]
}
2.6 Формат ошибок
{
"code": "VALIDATION_ERROR",
"data": null,
"message": "Запрос содержит некорректные данные.",
"errors": [
{
"code": "OUT_OF_RANGE",
"field": "limit",
"message": "Значение должно быть от 1 до 100."
}
]
}
| HTTP | code | Условие
| 400 | VALIDATION_ERROR | Параметр или тело запроса не прошло проверку
| 401 | UNAUTHENTICATED | Нет действующей сессии
| 403 | ACCESS_DENIED | Нет требуемого разрешения
| 403 | USER_NOT_ACTIVE | Профиль текущего пользователя не находится в состоянии active
| 404 | USER_NOT_FOUND | Профиль не найден или его существование нельзя раскрывать
| 409 | VERSION_CONFLICT | expected_version не совпадает с текущей версией
| 409 | INVALID_STATE_TRANSITION | Переход из текущего состояния запрещён
| 409 | IDEMPOTENCY_KEY_REUSED | Ключ идемпотентности уже использован с другим телом
| 503 | AUTHORIZATION_UNAVAILABLE | Обязательная проверка доступа недоступна
