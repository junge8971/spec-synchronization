. Назначение
Раздел «Шаблоны ответов» - это административный инструмент управления типовыми текстами, которые цифровой ассистент (ЦАМ) использует при общении с пользователем: приветствия, уточняющие вопросы, сообщения об ошибке, переводы на оператора, благодарности, инструкции.
Главная ценность: формулировки меняются через веб-интерфейс, без участия разработчиков и без выпуска релиза. Изменения вступают в силу сразу после сохранения.
Прототип полностью соответствует модели данных из PDF: 7 таблиц с префиксом tpl_ (1 основная сущность, 2 связующие, 3 справочника, 1 внешняя зависимость на СУДИР).
2. Общая структура
Раздел состоит из двух экранов:
Список шаблонов - стартовый экран с таблицей, поиском, фильтрами и кнопкой создания.
Карточка шаблона - экран редактирования с двумя вкладками: «Основное» и «Связи».
Переход между экранами - по клику на строку таблицы или по хлебным крошкам. При закрытии карточки без сохранения показывается модалка подтверждения.
3. Экран «Список шаблонов»
3.1. Таблица
Отображает все шаблоны со следующими колонками:
| Колонка | Источник | Сортировка
| Шаблон (название + код) | tpl_template.name, tpl_template.code | ✓
| Тип | tpl_template.type_code → tpl_types.display_name | ✓
| Область применения | tpl_template.scope_code → tpl_scopes.display_name | ✓
| Статус | tpl_template.status → tpl_statuses.display_name | ✓
| Стрелка «›» | - | -
Статусы подсвечиваются цветом: Активен - зелёный, Приостановлен - жёлтый, Черновик - светлый, Архив - серый.
Клик по заголовку сортирует по возрастанию, повторный клик - по убыванию, третий - снимает сортировку.
3.2. Поиск
Поле поиска (минимум 2 символа) ищет по:
названию шаблона,
служебному коду,
тексту ответа.
3.3. Мультиселект-фильтры
| Фильтр | Источник | Значений
| Все типы | tpl_types | 8
| Все статусы | tpl_statuses | 4
| Все области | tpl_scopes | 6
У каждого значения рядом с названием выводится код (monospace). Кнопка «Все ...» очищает фильтр.
3.4. Расширенный фильтр «⚙ Условия»
Конструктор произвольных условий:
Логика: И (все условия) / ИЛИ (любое условие).
Поля: Название шаблона, Служебный код, Тип (enum), Область применения (enum), Статус (enum), Владелец (текст).
Операторы: для текста - содержит / не содержит / равно / не равно / начинается с / заканчивается на / пусто / не пусто; для enum - входит в / не входит в (с чипсами).
Применённые условия отображаются в панели-баре под фильтрами. На кнопке «⚙ Условия» - бейдж с числом активных условий.
3.5. Меню «⋮»
Сохранить текущий фильтр - сохраняет поиск, мультиселекты и расширенные условия под именем.
Скопировать ссылку на отбор - формирует URL с параметрами и копирует в буфер.
Сохранённые фильтры - список с возможностью применить или удалить.
3.6. Прочее
Кнопка «Сбросить» - видна при активных фильтрах.
Счётчик справа - сколько шаблонов найдено.
Кнопка «＋ Создать шаблон» - открывает пустую карточку.
Кнопка «⤓ Экспорт» - модалка выбора полей tpl_template.
4. Экран «Карточка шаблона»
4.1. Шапка
Содержит:
название (name),
назначение (description),
статус (цветная точка + подпись),
код (code, monospace),
владельца (owner).
Кнопки действий:
| Кнопка | Действие
| ⤓ Экспорт | Модалка выбора разделов
| Сохранить | Валидирует уникальность name и code, обязательность текста
| Приостановить | Переключает status между paused и active
| В архив | Устанавливает status = 'archived' с подтверждением
| Закрыть | Модалка «Выйти без сохранения?»
4.2. Вкладка «Основное»
Две колонки: метаданные (слева) и текст ответа + предпросмотр (справа).
Левая - «Основное» (все поля привязаны к tpl_template):
| Поле | Тип | Валидация
| Название | input | обязательное, уникальное
| Служебный код | input (monospace) | обязательное, уникальное, латиница
| Тип шаблона | select из tpl_types (8) | обязательное
| Область применения | select из tpl_scopes (6) | обязательное
| Описание | textarea | -
| Владелец | input (owner, строка) | -
| Ответственный | select (responsible_user_id) | -
| Статус | select из tpl_statuses (4) | -
| Теги | input через запятую (tags) | -
Правая - «Текст ответа»:
textarea с плейсхолдерами: {имя}, {адрес}, {номер_заявки}, {дата};
переключатель «Шаблон активен» (active), синхронизированный со статусом: ON → active, OFF → paused;
живой предпросмотр в тёмном макете чата: обновляется по мере ввода текста.
Текст ответа - обязательное поле: при сохранении пустого значения поле подсвечивается красным.
4.3. Вкладка «Связи»
Две сетки чипсов:
«Навыки, к которым привязан шаблон» (tpl_template_skill):
12 навыков из раздела «Навыки»;
каждый чип: название, категория, skill_id (monospace);
клик включает/выключает;
счётчик «Выбрано: N из M».
«Компоненты и поверхности» (tpl_template_surface):
6 поверхностей из раздела «Поверхности»;
каждая - с surface_id;
клик включает/выключает;
счётчик «Выбрано: N из M».
Ассистент может использовать шаблон только тогда, когда пользователь работает в одном из выбранных навыков и на одной из выбранных поверхностей.
5. Справочники
5.1. Статические (соответствуют tpl_* из PDF)
| Константа | Таблица | Значений
| DICT_TPL_TYPES | tpl_types | 8 (greeting, farewell, clarify, refusal, to_operator, error, thanks, instruction)
| DICT_TPL_SCOPES | tpl_scopes | 6 (all, zhkh, edu, health, transport, social)
| DICT_TPL_STATUSES | tpl_statuses | 4 (draft, active, paused, archived)
Все коды и подписи совпадают с PDF один-в-один.
5.2. Внешние данные
Навыки (ALL_SKILLS) - из раздела «Навыки», пара id → name + cat.
Поверхности (SURFACES) - из раздела «Поверхности», пара id → name.
Ответственные (RESPONSIBLE_USERS) - из СУДИР, пара id → name.
5.3. Демо-данные
Массив TPL_DATA содержит 8 шаблонов с разными типами, областями, статусами и полными настройками связей. Каждый - с массивом навыков и массивом поверхностей.
6. Вспомогательные механизмы
6.1. Тост-уведомления
Появляются в правом нижнем углу на 2 секунды: «Изменения сохранены», «Шаблон приостановлен», «Шаблон переведён в архив», «Фильтр сохранён».
6.2. Модальные окна
Экспорт списка/карточки - чекбоксы полей/разделов, кнопка «Выгрузить».
Подтверждение выхода - «Выйти без сохранения?».
Подтверждение архивации - стандартный confirm().
6.3. Валидация
При сохранении проверяется:
name не пусто и уникально,
code не пусто и уникально,
текст ответа заполнен.
При неудаче - тост «Проверьте обязательные поля», проблемное поле подсвечивается красным.
6.4. Клавиатурные сокращения
Esc - закрыть модалку.
Клик по бэкдропу - закрыть модалку.
7. Соответствие модели данных
| Таблица PDF | Реализация
| tpl_template | Объект draft + TPL_DATA, все поля в UI
| tpl_template_skill | draft.skills[] - массив skill_id
| tpl_template_surface | draft.surfaces[] - массив surface_id
| tpl_types | DICT_TPL_TYPES, используется через type_code
| tpl_scopes | DICT_TPL_SCOPES, scope_code
| tpl_statuses | DICT_TPL_STATUSES, status
Все коды и подписи совпадают с PDF. Связи хранятся по id (skill_id, surface_id), а не по названиям. owner - строка, responsible_user_id - внешний id.
8. Ограничения и не реализовано
Серверная валидация - всё на клиенте, данные в памяти браузера и теряются при перезагрузке.
Soft delete - не задействован.
Загрузка реальных навыков, поверхностей и ответственных - используются статические массивы.
Проверка плейсхолдеров - не валидируется, что все {...} в тексте корректны.
Журнал изменений - нет, только визуальные метки в шапке.
Мультиязычность шаблонов - не реализована (в модели не предусмотрена).
9. Типичный сценарий работы
Открыть раздел «Шаблоны ответов» в меню слева (блок «Контент»).
Найти шаблон через поиск, фильтры или расширенные условия.
Кликнуть по строке - открыть карточку.
Вкладка «Основное»: проверить название, код, тип, область, описание, владельца, теги, статус.
Справа отредактировать текст ответа, при необходимости вставить плейсхолдеры. Проверить, как выглядит предпросмотр в макете чата.
Вкладка «Связи»: выбрать навыки и поверхности, к которым привязан шаблон.
Нажать «Сохранить» - сработает валидация.
При необходимости - «Приостановить» или «В архив».
Вернуться к списку по хлебным крошкам.
Таблицы
1. Модель данных раздела "Шаблоны ответов"
Раздел "Шаблоны ответов" - управление типовыми текстами, которые цифровой ассистент использует при общении с пользователем: приветствие, уточняющий вопрос, сообщение об ошибке, перевод на оператора, благодарность. Формулировки меняются без релиза.
Префикс таблиц раздела: tpl_.
2. Связующие таблицы
2.1. tpl_template_skill
Назначение: навыки, к которым привязан шаблон. Ассистент использует шаблон, когда пользователь работает с одним из этих навыков.
Где используется:
карточка шаблона, вкладка "Связи" - сетка навыков с названием и категорией;
карточка шаблона, вкладка "Связи" - клик по чипу включает или отключает навык;
карточка шаблона, вкладка "Связи" - счётчик "Выбрано: N" под сеткой.
| Поле | Тип | Обязательность | Ключ | Комментарий
| id | UUID | да | PK | Идентификатор записи
| template_id | UUID | да | FK tpl_template.id | Шаблон
| skill_id | UUID | да | FK skills.id | Навык, таблица раздела "Навыки"
| created_at | datetime | да | - | Дата создания связи
Первичный ключ: id. Ограничение: уникальный по (template_id, skill_id).
Примечание: skills.id принадлежит разделу "Навыки" и в настоящем документе не создаётся.
2.2. tpl_template_surface
Назначение: поверхности, на которых доступен шаблон.
Где используется:
карточка шаблона, вкладка "Связи" - сетка компонентов и поверхностей;
карточка шаблона, вкладка "Связи" - счётчик выбранных поверхностей.
| Поле | Тип | Обязательность | Ключ | Комментарий
| id | UUID | да | PK | Идентификатор записи
| template_id | UUID | да | FK tpl_template.id | Шаблон
| surface_id | UUID | да | FK surfaces.id | Поверхность, таблица раздела "Поверхности"
| created_at | datetime | да | - | Дата создания связи
Первичный ключ: id. Ограничение: уникальный по (template_id, surface_id).
Примечание: surfaces.id принадлежит разделу "Поверхности" и в настоящем документе не создаётся.
3. Основные таблицы
3.1. tpl_template
Назначение: шаблон ответа. Ядро раздела.
Где используется:
список шаблонов - колонки: шаблон с кодом, тип, область применения, статус;
список шаблонов - поиск по названию, коду и тексту ответа от 2 символов;
список шаблонов - фильтры по типу и статусу, сортировка;
список шаблонов - кнопка "Создать шаблон";
карточка шаблона - шапка: название, назначение, статус, код;
карточка шаблона, вкладка "Основное" - название, служебный код, тип шаблона, область применения, описание;
карточка шаблона, вкладка "Основное" - владелец и ответственный, теги;
карточка шаблона, вкладка "Основное" - блок "Текст ответа" с плейсхолдерами;
карточка шаблона, вкладка "Основное" - переключатель "Шаблон активен";
карточка шаблона, вкладка "Основное" - предпросмотр ответа в чате;
карточка шаблона - кнопки "Сохранить", "Приостановить", "Выключить";
карточка шаблона - проверка уникальности названия и кода, заполненности текста;
модалка экспорта - состав полей выгрузки.
| Поле | Тип | Обязательность | Ключ | Комментарий
| id | UUID | да | PK | Идентификатор шаблона
| code | varchar(100) | да | U | Служебный код, латиница
| name | varchar(255) | да | U | Название шаблона
| type_code | varchar(50) | да | FK tpl_types.code | Тип шаблона
| scope_code | varchar(50) | да | FK tpl_scopes.code | Область применения
| description | text | нет | - | Короткое пояснение, для чего шаблон
| owner | varchar(200) | нет | - | Владелец шаблона, подразделение
| responsible_user_id | UUID | нет | внешняя | Ответственный, идентификатор СУДИР
| tags | text | нет | - | Теги через запятую
| text | text | да | - | Текст ответа, поддерживает плейсхолдеры
| status | varchar(32) | да | FK tpl_statuses.code | Статус шаблона
| created_at | datetime | да | - | Дата создания записи
| updated_at | datetime | да | - | Дата последнего изменения
| deleted_at | datetime | нет | - | Дата мягкого удаления
Индексы: уникальный по code, уникальный по name, обычные по type_code, scope_code, status.
Плейсхолдеры текста ответа: {имя}, {адрес}, {номер_заявки}, {дата}.
Примечание: поле team_id из исходной модели удалено, команды не хранятся. Владелец хранится строкой в поле owner.
