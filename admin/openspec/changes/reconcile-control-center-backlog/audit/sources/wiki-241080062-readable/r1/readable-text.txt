Статусная модель для навыков. Описание модели
Общие принципы раздела
Каталог навыков - единственный источник правды. Всё, что нужно знать о навыке, собрано в его карточке: анкета, содержание, параметры подключения, показатели, история. Переписка и отдельные таблицы не дополняют каталог.
Путь навыка задан состояниями. Навык всегда находится в одном из состояний жизненного цикла. Произвольный переход невозможен.
Проверки до людей. Сначала работают автоматические проверки: заполненность анкеты, пересечения фраз, доступность сервиса. Человек на ревью смотрит то, что машина проверить не может.
Конфликт формулировок решается до обучения. Если фраза уже занята другим навыком, обучение модели не запускается.
Решение человека всегда с причиной. Возврат на доработку и отключение навыка требуют основания из списка и комментария.
Отключение навыка не требует релиза. Навык выключается из интерфейса и сразу перестаёт отвечать; пользователь получает согласованный текст, а не ошибку.
Область видимости роли применяется всегда. Команда навыка видит только свои навыки и домены; продуктовая команда видит все.
Управление командами и пользователями - вне границ раздела «Навыки». Раздел использует справочники команд, доменов и роли, которые приходят из административного контура.
Сквозные требования: жизненный цикл, состояния, сообщения, аудит
Жизненный цикл навыка
Навык проходит 11 состояний:
Черновик - анкета заполняется, навык виден только своей команде. Переводит команда навыка.
На проверке - навык отправлен, идут автоматические проверки. Переводит система.
Отклонён - возвращён с замечанием, ждёт исправления. Переводит команда навыка.
Обучение модели - идёт дообучение доменного классификатора. Переводит система.
Автотесты - идут автоматические тесты навыка. Переводит система.
Песочница - навык доступен для проверки в живом диалоге. Переводит команда навыка.
На ревью - ждёт проверки группой качества. Переводит группа качества.
Согласован - проверка пройдена, ждёт выката. Переводит продуктовая команда.
Белые списки - работает на ограниченной аудитории. Переводит продуктовая команда.
Прод - работает на всех пользователях. Переводит продуктовая команда.
Отключён - выведен из работы с основанием. Переводит продуктовая команда / эксплуатация.
Требования:
ЖЦ-1. Переходы между состояниями выполняются только по правилам жизненного цикла.
ЖЦ-2. Нельзя перескочить обязательный этап: проверки → обучение → автотесты → песочница → ревью → выкат.
ЖЦ-3. В карточке навыка отображается полоса жизненного цикла с пройденными, текущим и будущими этапами.
ЖЦ-4. Для каждого состояния определён ответственный, который может перевести навык дальше.
ЖЦ-5. Возврат на доработку и отключение требуют причины и комментария.
ЖЦ-6. Отключение и включение фиксируются в истории навыка и в журнале действий.
Состояния и сообщения
Раздел подчиняется общему стандарту состояний системы:
Состояние объекта - статус навыка в реестре и карточке, полоса жизненного цикла, живое состояние. Один статус на объект.
Решение человека - возврат с ревью, отключение навыка: что решено, кто, когда, причина, комментарий.
Отклонение от регламента - в мониторинге: значение, порог, разница.
Инцидент - уровень, срок устранения, кто устраняет.
Результат действия - сообщение с ограниченным временем показа.
Отсутствие данных не ошибка - навык без показателей, пустая очередь ревью и непроверенный стенд оформляются нейтрально с пояснением причины.
Сбой обработки - в разделе навыков не применяется; сбои видны в разборе диалогов.
Требования:
СОСТ-1. Для каждого состояния предусмотрены нейтральные, предупреждающие и ошибочные визуальные состояния.
СОСТ-2. Ошибки валидации показываются рядом с полем и не блокируют остальную форму, кроме случаев, когда блокировка прямо предусмотрена.
СОСТ-3. Действия с ограниченным временем показывают сообщение о результате и не требуют перезагрузки страницы.
Аудит и история
АУД-1. Все изменения карточки навыка, содержания, подключения, статусов, токенов, отключений и включений фиксируются в истории навыка.
АУД-2. В истории указываются: дата и время, автор, действие, объект, подробности.
АУД-3. Решения ревьюера, отключения и включения дополнительно попадают в журнал действий административного контура.
АУД-4. История не переписывается: предыдущие замечания сохраняются даже после повторного ревью.
Функциональные требования по экранам
Реестр навыков (РЕЕ)
Назначение: точка входа в раздел. Показать, какие навыки есть, в каком они состоянии и с каким сейчас проблема.
Требования из постановки:
PEE-1. Система показывает реестр навыков с назначением, служебным идентификатором и версией.
PEE-2. В строке выводятся домен и команда-владелец навыка.
PEE-3. В строке выводится статус навыка из жизненного цикла.
PEE-4. В строке выводится готовность: состояние обучения модели и результат автотестов.
PEE-5. В строке выводится число диалогов с участием навыка за 30 дней.
PEE-6. В строке выводятся дата последнего изменения и дата создания навыка.
PEE-7. Навык с открытым инцидентом помечается в строке с указанием уровня и сути.
PEE-8. Навык, данные которого не обновлялись дольше срока регламента, помечается в строке.
PEE-9. Навык с конфликтом формулировок помечается в строке; признак ведёт на вкладку проверок.
PEE-10. Поиск выполняется по названию, назначению, служебному идентификатору и команде.
PEE-11. Реестр фильтруется по статусу и по домену.
PEE-12. Реестр сортируется по названию, домену, статусу, числу диалогов и дате изменения.
PEE-13. По умолчанию навыки упорядочены по состоянию: сначала требующие действия, затем работающие.
PEE-14. Отбор отражается в адресе страницы и восстанавливается по ссылке.
PEE-15. Система показывает число найденных навыков.
PEE-16. Навыки отмечаются в списке для действий над несколькими сразу.
PEE-17. Отмеченные согласованные навыки переводятся в белые списки одним действием.
PEE-18. Отмеченные навыки из белых списков выкатываются в продуктив одним действием.
PEE-19. Команда навыка видит в реестре только свои навыки.
PEE-20. Переход в карточку навыка выполняется нажатием на строку.
PEE-21. Раздел содержит вкладки реестра, доменов и очереди ревью; у очереди выводится число навыков на проверке.
Дополнительно из прототипа:
ПРТ-РЕЕ-1. В таблице отображаются колонки: выбор, навык, домен/команда, статус, готовность, диалоги, изменение, переход.
ПРТ-РЕЕ-2. Под названием навыка выводятся назначение, служебный идентификатор, версия, признаки инцидента, просрочки данных и конфликта.
ПРТ-РЕЕ-3. Конфликт формулировок оформлен как ссылка на вкладку проверок и не считается инцидентом.
ПРТ-РЕЕ-4. Массовые действия доступны только для ролей «Продуктовая команда» и «Супер-администратор».
ПРТ-РЕЕ-5. Массовый перевод в белые списки применяется только к согласованным навыкам; массовый выкат на прод - только к навыкам из белых списков.
ПРТ-РЕЕ-6. Пустые состояния различают «нет навыков у команды» и «ничего не найдено по фильтрам».
ПРТ-РЕЕ-7. Если у команды нет домена, экран предлагает сначала создать домен, затем навык.
ПРТ-РЕЕ-8. Для команды без навыков доступны кнопки «Создать домен» и «Добавить навык».
Домены (ДОМ)
Назначение: домен - область навыков со своей командой и адресом интеграции.
Требования из постановки:
DOM-1. Система показывает список доменов с описанием, владельцем и рабочей зоной.
DOM-2. В строке домена выводится число навыков, входящих в него.
DOM-3. Домен создаётся с названием, описанием, владельцем и адресом интеграции.
DOM-4. У домена задаются рабочие зоны: авторизованная, неавторизованная или обе.
DOM-5. Домен изменяется; изменения попадают в историю.
DOM-6. Навык привязывается к домену при создании и может быть перенесён в другой домен.
DOM-7. Команда видит и ведёт только свои домены.
Дополнительно из прототипа:
ПРТ-ДОМ-1. Домен создаётся и редактируется в отдельном окне.
ПРТ-ДОМ-2. Адрес интеграции проверяется на уникальность: два домена не могут указывать на одну ссылку.
ПРТ-ДОМ-3. Для адреса интеграции выводится ошибка, если не заполнено доменное имя.
ПРТ-ДОМ-4. В списке доменов отображаются название, описание, владелец, API-адрес, зоны и число навыков.
ПРТ-ДОМ-5. Редактирование домена доступно команде навыка и продуктовой команде.
ПРТ-ДОМ-6. Удаление домена с навыками недоступно: сначала нужно перенести навыки в другой домен.
Мастер подключения навыка (MAC)
Назначение: провести команду от пустой формы до отправки навыка на проверку.
Требования из постановки:
MAC-1. Навык заводится пошагово: анкета, обучающие фразы, подключение, проверка.
MAC-2. В анкете задаются название, основная функциональность, ожидаемый результат, домен и рабочая зона.
MAC-3. Переход к следующему шагу недоступен, пока не заполнены обязательные поля текущего.
MAC-4. На шаге обучающих фраз задаются группы фраз и извлекаемые сущности с синонимами.
MAC-5. Система проверяет фразы на пересечение с фразами других навыков прямо в мастере.
MAC-6. При точном совпадении фраз отправка на проверку блокируется с указанием навыка-владельца фразы.
MAC-7. На шаге подключения задаётся адрес сервиса навыка.
MAC-8. На шаге подключения описано, что произойдёт после отправки и сколько это займёт.
MAC-9. На шаге проверки выводится сводка заполненности с указанием незаполненного.
MAC-10. Незавершённая анкета сохраняется как черновик и доступна для продолжения.
MAC-11. Отправка передаёт навык на проверку платформенной команде и переводит его в соответствующий статус. (В прототипе не показано.)
MAC-12. Созданный навык принадлежит команде, от имени которой он заведён.
Дополнительно из прототипа:
ПРТ-МАС-1. Мастер состоит из шагов: «Анкета», «Обучающие фразы», «Подключение», «Проверка».
ПРТ-МАС-2. На шаге «Анкета» валидируются название, функциональность, ожидаемый результат, контактное лицо.
ПРТ-МАС-3. На шаге «Обучающие фразы» можно добавлять несколько групп, вводить фразы построчно или через запятую, видеть количество фраз.
ПРТ-МАС-4. Конфликтующие фразы подсвечиваются, показывается навык-владелец.
ПРТ-МАС-5. На шаге «Проверка» кнопка «Отправить на проверку» заблокирована при точных конфликтах или незаполненном названии.
ПРТ-МАС-6. Доступны действия «Сохранить черновик» и «Отправить на проверку».
ПРТ-МАС-7. После отправки навык появляется в реестре в статусе «На проверке».
ПРТ-МАС-8. Если домен ещё не заведён, мастер предлагает создать домен и сохраняет черновик.
Карточка навыка: обзор (КАРН)
Назначение: собрать в одном месте всё, что нужно знать о навыке.
Требования из постановки:
КАРН-1. Система показывает анкету навыка: служебный идентификатор, расширенное описание, ожидаемый результат, тип, рабочую зону, ограничения, комментарии, связанные материалы, версию и даты.
КАРН-2. В анкете выводится контактное лицо; имя ведёт к карточке с должностью и контактами.
КАРН-3. Система показывает полосу жизненного цикла с отметкой пройденных этапов и текущего.
КАРН-4. Для навыка в продуктиве выводится живое состояние: работает или отключён, с какого момента и сколько времени.
КАРН-5. Решение ревьюера выводится в карточке с причиной, комментарием, автором и датой.
КАРН-6. В блоке готовности выводятся состояние обучения модели, результат автотестов и наличие конфликтов формулировок.
КАРН-7. В блоке диалогов выводятся число диалогов с участием навыка, доля успешных сценариев и число полученных вложений за 30 дней.
КАРН-8. Из блока диалогов открывается список диалогов с участием этого навыка.
КАРН-9. В блоке оценок выводятся доля хороших ответов, число собранных оценок, число низких оценок и порог регламента.
КАРН-10. В блоке оценок выводится охват оценивания: доля оценённых ответов от общего числа.
КАРН-11. Если оценок меньше порога достоверности, доля не рассчитывается и выводится пояснение.
КАРН-12. В блоке шагов выводятся целевое число шагов сценария, фактическое, медиана и отклонение.
КАРН-13. В блоке шагов выводятся доля диалогов длиннее цели и доля не дошедших до результата, с переходом к таким диалогам.
КАРН-14. Период показателей указан явно, включая указание, входит ли текущий день.
КАРН-15. Карточка навыка правится владельцем навыка и продуктовой командой.
КАРН-16. Каждый блок карточки указывает, что именно он считает; числа в разных блоках не обязаны совпадать по смыслу.
КАРН-17. Вкладка мониторинга доступна только для навыка, работающего в продуктиве.
Дополнительно из прототипа:
ПРТ-КАРН-1. Шапка карточки содержит домен, команду, название, назначение, статус, кнопки «Редактировать», «На ревью», «Вернуть», «Согласовать», «Выкатить».
ПРТ-КАРН-2. Для навыка в продуктиве или отключённого выводится строка живого состояния с длительностью и датой.
ПРТ-КАРН-3. Для навыка с инцидентом выводится уровень, суть, кто отвечает, срок устранения.
ПРТ-КАРН-4. Для навыка с конфликтом формулировок выводится предупреждение и ссылка на проверки.
ПРТ-КАРН-5. Редактирование карточки выполняется в модальном окне с полями анкеты и связанными материалами.
ПРТ-КАРН-6. При сохранении карточки фиксируется список изменённых полей.
ПРТ-КАРН-7. Блок «Диалоги» содержит кнопку перехода в диалоги с фильтром по навыку.
ПРТ-КАРН-8. Блок «Оценки» содержит кнопку перехода в диалоги с оценками по навыку.
ПРТ-КАРН-9. Блок «Шаги до результата» при отклонении содержит кнопку разбора длинных диалогов.
ПРТ-КАРН-10. Для навыка не в продуктиве блоки показателей пусты и объясняют, что данных пока нет.
ПРТ-КАРН-11. Если навык отключён, живое состояние это показывает, а показатели продолжают отражать прошлый период.
Карточка навыка: обучающие фразы (ФРА)
Назначение: вести содержание навыка.
Требования из постановки:
ФРА-1. Система показывает группы обучающих фраз навыка с названием сценария.
ФРА-2. В группе выводятся все обучающие фразы.
ФРА-3. В группе выводятся извлекаемые сущности и их синонимы.
ФРА-4. Число групп обучающих фраз выводится на вкладке.
ФРА-5. Группы, фразы, сущности и синонимы добавляются, изменяются и удаляются.
ФРА-6. Изменение содержания у работающего навыка ставит навык на повторную проверку.
ФРА-7. При сохранении содержания выполняется проверка пересечений с другими навыками.
ФРА-8. Содержание навыка правит только команда-владелец и продуктовая команда.
Дополнительно из прототипа:
ПРТ-ФРА-1. Фразы отображаются чипами; конфликтующие фразы подсвечиваются.
ПРТ-ФРА-2. При редактировании можно добавлять и удалять группы фраз.
ПРТ-ФРА-3. Для каждой группы показывается количество фраз.
ПРТ-ФРА-4. При сохранении фраз запускается дообучение классификатора; интерфейс предупреждает, что изменения появятся на проде через несколько часов.
ПРТ-ФРА-5. Если фраза занята другим навыком, сохранение возможно, но навык попадает на доработку с указанием конфликта.
Карточка навыка: проверки (ПРВ)
Назначение: показать одним экраном, что мешает навыку двигаться дальше.
Требования из постановки:
ПРВ-1. Система показывает перечень автоматических проверок навыка с результатом каждой.
ПРВ-2. У проверки указано, блокирует ли её результат движение навыка дальше.
ПРВ-3. У непройденной проверки указано, что именно не так и где это исправить.
ПРВ-4. Система показывает состояние обучения модели и ожидаемое время завершения. (В прототипе не показано.)
ПРВ-5. Система показывает результат автотестов и перечень замечаний при неуспехе. (В прототипе не показано.)
ПРВ-6. Система показывает сведения о последней проверке в песочнице: дата, автор, результат.
ПРВ-7. Конфликты формулировок выводятся таблицей: фраза, конкурирующий навык, домен, тип совпадения, мера близости.
ПРВ-8. Точное совпадение формулировок блокирует отправку навыка дальше.
ПРВ-9. Близкая по смыслу формулировка выводится как предупреждение и движение не блокирует.
ПРВ-10. Число конфликтов выводится на вкладке проверок.
ПРВ-11. Автотесты и обучение запускаются повторно после исправления замечаний.
Дополнительно из прототипа:
ПРТ-ПРВ-1. Автоматические проверки включают: обязательные поля анкеты, наличие обучающих фраз, точные совпадения, близкие по смыслу формулировки, параметры подключения.
ПРТ-ПРВ-2. Блок «Обучение модели» показывает статус и ожидаемое время.
ПРТ-ПРВ-3. Блок «Последняя проверка в песочнице» показывает дату, результат и автора.
ПРТ-ПРВ-4. Блок «Автотесты» показывает статус и замечания при неуспехе.
ПРТ-ПРВ-5. Таблица конфликтов содержит фразу, навык, домен, тип совпадения и близость.
ПРТ-ПРВ-6. При точном совпадении отображается блокирующая ошибка; при смысловом - предупреждение.
Карточка навыка: подключение (ПОД)
Назначение: задать параметры интеграции и выдать ключи.
Требования из постановки:
ПОД-1. Система показывает адрес сервиса навыка и версию контракта подключения.
ПОД-2. Система показывает, требуется ли навыку авторизация пользователя.
ПОД-3. Система показывает параметры навыка, доступные для настройки на стороне поверхности.
ПОД-4. Система выдаёт токены по контурам: песочница, белые списки, продукты.
ПОД-5. Действующий для текущего состояния навыка токен выделяется.
ПОД-6. Значение токена копируется одним действием.
ПОД-7. Токен отзывается и выпускается заново. (В прототипе не показано.)
ПОД-8. Из карточки подключения открывается песочница для проверки навыка.
ПОД-9. Незаполненный адрес сервиса выводится явно и отмечается в проверках.
Дополнительно из прототипа:
ПРТ-ПОД-1. Токены отображаются карточками по контурам: «Песочница», «Белые списки», «Прод».
ПРТ-ПОД-2. Недействующий токен помечается как не выданный.
ПРТ-ПОД-3. Для действующего токена доступна кнопка копирования.
ПРТ-ПОД-4. В блоке подключения показывается контракт и требование авторизации.
ПРТ-ПОД-5. Для навыка с параметрами поверхности выводится список этих параметров.
Карточка навыка: мониторинг (МОН)
Назначение: показать, как навык работает в продуктиве.
Требования из постановки:
МОН-1. Система показывает показатели навыка за сутки: доступность, время ответа, долю хороших оценок.
МОН-2. У каждого показателя выводится порог регламента.
МОН-3. Пороговые значения задаются по навыку и изменяются.
МОН-4. Отклонение от регламента выводится тройкой: фактическое значение, порог и разница.
МОН-5. Отклонения собраны в один блок, отдельных пометок у полей нет.
МОН-6. Система показывает дату последнего обновления данных навыка и регламент обновления.
МОН-7. Превышение допустимой давности данных выводится как отклонение.
МОН-8. Система показывает время последнего обращения к навыку и отмечает длительный простой.
МОН-9. Система показывает согласованный текст, который увидит пользователь при недоступности навыка.
МОН-10. Система показывает ответственных по навыку: владельца, технического представителя и заместителя.
МОН-11. Имя ответственного ведёт к карточке с должностью, командой и контактами.
МОН-12. Система показывает зависимости навыка: внешние системы, ответственную сторону, состояние и время проверки.
МОН-13. Система показывает инциденты по навыку: уровень, суть, срок устранения, кто устраняет и состояние.
МОН-14. Инциденты ведутся во внешней системе, в центре управления они только отображаются.
МОН-15. Система передаёт во внешнюю систему сведения о выходе показателей за пороги. (В прототипе не показано.)
МОН-16. Плановое окно обслуживания задаётся заранее и исключается из расчёта показателей.
МОН-17. Заместитель ответственного обязателен: навык не остаётся без второго контакта.
Дополнительно из прототипа:
ПРТ-МОН-1. Показатели за сутки выводятся тремя карточками с порогами и цветовой индикацией.
ПРТ-МОН-2. Блок отклонений выводит метрику, фактическое значение, порог и разницу.
ПРТ-МОН-3. Блок данных навыка содержит дату обновления, регламент, давность и текст при сбое.
ПРТ-МОН-4. Блок ответственных содержит контакты в поповере: почта, мессенджер, телефон.
ПРТ-МОН-5. Блок зависимостей содержит таблицу внешних систем, владельца, состояния и времени проверки.
ПРТ-МОН-6. Блок инцидентов содержит таблицу с уровнем, описанием, причиной, ответственным, сроком и состоянием.
ПРТ-МОН-7. Для плановых работ выводятся окно, причина и исключение из расчёта.
ПРТ-МОН-8. Если оценок меньше порога достоверности, доля не рассчитывается и выводится пояснение.
Карточка навыка: история (ИСТ)
Назначение: ответить на вопрос «кто и когда это изменил».
Требования из постановки:
ИСТ-1. Система показывает ленту событий навыка от свежих к старым.
ИСТ-2. У события выводятся время, автор и суть изменения.
ИСТ-3. В историю попадают изменения карточки и содержания навыка. (В прототипе не показано в полном составе.)
ИСТ-4. В историю попадают переходы между состояниями с указанием основания.
ИСТ-5. В историю попадают решения ревьюера с причиной и комментарием.
ИСТ-6. В историю попадают отключения и включения навыка с основанием.
ИСТ-7. Прошлые решения ревьюера сохраняются при повторной отправке навыка на проверку.
Дополнительно из прототипа:
ПРТ-ИСТ-1. История выводится таблицей: дата, пользователь, действие, подробности.
ПРТ-ИСТ-2. В историю попадают создания навыка, изменения карточки, проверки в песочнице, решения ревьюера, отключения и включения.
ПРТ-ИСТ-3. Для событий из смежных систем указывается, что действие выполнила система, а не человек.
Очередь ревью (РЕВ)
Назначение: рабочее место группы качества.
Требования из постановки:
РЕВ-1. Система показывает очередь навыков, отправленных на ревью, с указанием домена и команды.
РЕВ-2. Для выбранного навыка выводятся сведения, нужные для решения: ожидаемый результат, готовность, конфликты, дата отправки.
РЕВ-3. Для выбранного навыка выводятся его обучающие фразы.
РЕВ-4. Система показывает перечень критериев проверки с пояснением каждого.
РЕВ-5. Ревьюер отмечает выполненные критерии; число отмеченных видно на экране.
РЕВ-6. Согласование навыка недоступно, пока не отмечены все критерии.
РЕВ-7. Возврат на доработку требует причины из списка и комментария.
РЕВ-8. Решение ревьюера выводится в карточке навыка и в его истории.
РЕВ-9. Команда навыка получает уведомление о решении.
РЕВ-10. Из очереди открывается полная карточка навыка.
РЕВ-11. Число навыков на ревью выводится на вкладке раздела.
РЕВ-12. Согласованный навык переходит в состояние, из которого его выкатывают по контурам.
Дополнительно из прототипа:
ПРТ-РЕВ-1. В очереди отображаются домен, команда, ожидаемый результат, дата отправки, состояние обучения, результат автотестов, конфликты и статус.
ПРТ-РЕВ-2. Критерии проверки включают: сценарий проходится до конца; формулировки можно задать по-разному; тексты соответствуют редакционной политике; обучающие фразы исчерпывающие, но не избыточные; поведение при ошибке понятно пользователю.
ПРТ-РЕВ-3. Возврат на доработку оформляется модальным окном с причиной и комментарием.
ПРТ-РЕВ-4. После согласования навык получает статус «Согласован»; после возврата - «Отклонён».
ПРТ-РЕВ-5. Если очередь пуста, экран прямо сообщает об этом.
Песочница (ПЕС)
Назначение: проверить навык в живом диалоге до выката.
Требования из постановки:
ПЕС-1. Система позволяет вести диалог с проверочным контуром ассистента.
ПЕС-2. Для каждого ответа выводится трассировка: классификация, выбранный навык, вызовы внешних систем.
ПЕС-3. В трассировке выводятся домен и мера уверенности классификатора.
ПЕС-4. В трассировке выводятся адрес внешней системы, код ответа и длительность вызова.
ПЕС-5. Система показывает параметры подключения проверяемого навыка.
ПЕС-6. Система ведёт историю проверок навыка: дата, автор, результат.
ПЕС-7. Результат последней проверки выводится в карточке навыка.
ПЕС-8. Проверка в песочнице недоступна, пока не завершено дообучение классификатора.
ПЕС-9. Песочница работает на отдельном контуре и на пользователей не влияет.
Дополнительно из прототипа:
ПРТ-ПЕС-1. Экран песочницы содержит диалог со стендом, подсказки-примеры запросов и поле ввода.
ПРТ-ПЕС-2. Для каждого ответа показываются интент, домен, навык, уверенность, сервис этики, тайминги.
ПРТ-ПЕС-3. Тайминги выводятся по этапам: пре-роутер, доменный классификатор, сервис навыка, итого.
ПРТ-ПЕС-4. Ошибка обработки выводится отдельным блоком с указанием этапа и кода.
ПРТ-ПЕС-5. Доступны действия: «Синхронизировать с продом», «Смоделировать сбой», «Перевыпустить токен».
ПРТ-ПЕС-6. Для роли «Владелец поверхности» песочница показывает конфигурацию поверхности и предупреждает об отключённых модулях.
ПРТ-ПЕС-7. История проверок сохраняется и доступна для перехода к трассировке.
Отключение навыка (ОТК)
Назначение: быстро вывести навык из работы и так же быстро вернуть.
Требования из постановки:
ОТК-1. Навык отключается из карточки без релиза и перестаёт отвечать на всех поверхностях.
ОТК-2. Отключение подтверждается отдельным действием с пояснением последствий.
ОТК-3. В окне подтверждения выводится масштаб: число диалогов за 30 дней и поверхности, где навык работает.
ОТК-4. Отключение требует основания из списка: инцидент, плановые работы, нарушение обязательств команды.
ОТК-5. При отключении задаётся текст, который увидит пользователь.
ОТК-6. Состояние навыка передаётся ядру ассистента. (В прототипе не показано.)
ОТК-7. Обращения по теме отключённого навыка направляются в общий сценарий ответов.
ОТК-8. Команда навыка уведомляется об отключении с указанием основания. (В прототипе не показано.)
ОТК-9. Навык включается обратно тем же действием; включение записывается с основанием.
ОТК-10. Отключение и включение доступны продуктовой команде и эксплуатации.
ОТК-11. Отключение и включение попадают в историю навыка и в журнал действий.
ОТК-12. Живое состояние навыка выводится в карточке: работает или отключён, с какого момента.
Дополнительно из прототипа:
ПРТ-ОТК-1. Отключение доступно из карточки навыка в продуктиве.
ПРТ-ОТК-2. В модальном окне отключения отображаются масштаб, выбор основания и текст для пользователя.
ПРТ-ОТК-3. Кнопка отключения заблокирована, пока не выбран текст для пользователя.
ПРТ-ОТК-4. Для отключённого навыка доступно действие «Включить» с подтверждением.
ПРТ-ОТК-5. После отключения в карточке отображается статус «Отключён», длительность и текст заглушки.
ПРТ-ОТК-6. Для ролей без прав кнопка отключения недоступна, выводится пояснение.
Дополнительные требования из прототипа, не противоречащие постановке
Навигация и общая структура
ПРТ-НАВ-1. Раздел «Навыки» содержит вкладки: «Реестр», «Домены», «Ревью».
ПРТ-НАВ-2. Вкладка «Ревью» показывает счётчик навыков на проверке.
ПРТ-НАВ-3. Карточка навыка содержит вкладки: «Обзор», «Обучающие фразы», «Проверки», «Подключение», «Мониторинг», «История».
ПРТ-НАВ-4. Вкладка «Мониторинг» отображается только для навыка в продуктиве или отключённого.
ПРТ-НАВ-5. Из карточки навыка доступны переходы в диалоги, отчёты и песочницу.
Фильтры, поиск, сортировка
ПРТ-ФИЛЬТР-1. В реестре есть поиск по названию, назначению, служебному идентификатору и команде.
ПРТ-ФИЛЬТР-2. В реестре есть фильтры по статусу и домену.
ПРТ-ФИЛЬТР-3. В реестре есть сортировка по названию, домену, статусу, числу диалогов и дате изменения.
ПРТ-ФИЛЬТР-4. Выбранные фильтры и сортировка отражаются в URL и восстанавливаются по ссылке.
ПРТ-ФИЛЬТР-5. В очереди ревью доступен выбор навыка из списка.
ПРТ-ФИЛЬТР-6. В песочнице доступны подсказки-примеры запросов.
Массовые действия
ПРТ-МАСС-1. В реестре можно отметить несколько навыков.
ПРТ-МАСС-2. Для отмеченных согласованных навыков доступно действие «В белые списки».
ПРТ-МАСС-3. Для отмеченных навыков из белых списков доступно действие «Выкатить на прод».
ПРТ-МАСС-4. Массовые действия доступны только продуктовой команде и супер-администратору.
ПРТ-МАСС-5. Если среди отмеченных нет подходящих по статусу навыков, выводится пояснение.
Валидации и ошибки
ПРТ-ВАЛ-1. В мастере навыка обязательные поля анкеты, фраз и подключения валидируются по шагам.
ПРТ-ВАЛ-2. Адрес сервиса проверяется на заполненность и формат.
ПРТ-ВАЛ-3. Адрес интеграции домена проверяется на уникальность.
ПРТ-ВАЛ-4. При точном совпадении фраз отправка на проверку блокируется.
ПРТ-ВАЛ-5. При близких по смыслу фразах выводится предупреждение, но отправка не блокируется.
ПРТ-ВАЛ-6. При возврате с ревью обязательны причина из списка и комментарий.
ПРТ-ВАЛ-7. При отключении обязательны основание и текст для пользователя.
Пустые состояния
ПРТ-ПУСТ-1. Если у команды нет навыков, экран объясняет порядок: сначала домен, затем навык, и даёт обе кнопки.
ПРТ-ПУСТ-2. Если по фильтрам ничего не найдено, экран сообщает, что дело в фильтрах, и предлагает их изменить.
ПРТ-ПУСТ-3. Если очередь ревью пуста, экран сообщает об этом прямо.
ПРТ-ПУСТ-4. Если у навыка нет показателей, блоки объясняют, что данных пока нет, а не показывают нули.

Модель данных раздела «Навыки» Центра управления ЦАМ
БД-Навыки.svg
Описание модели данных
1. Модель данных раздела "Навыки"
Раздел "Навыки" - каталог навыков цифрового ассистента, единственный источник правды о навыке. Документ описывает операционную базу данных раздела. Показатели работы навыков читаются из витрины диалогов и в базе не хранятся.
Префикс таблиц раздела: skill_.
2. Связующие таблицы
2.1. skill_domain_zones
Назначение: зоны работы домена. Домен может работать в нескольких зонах.
Где используется:
вкладка "Домены", карточка домена - выбор зон работы домена;
вкладка "Домены", список - вывод зон в строке домена;
карточка навыка, шаг "Анкета" мастера - определение рабочей зоны навыка по зонам домена.
| Поле | Тип | Обязательность | Ключ | Комментарий
| id | UUID | да | PK | Идентификатор записи
| domain_id | UUID | да | FK skill_domains.id | Домен
| zone_code | varchar(32) | да | FK skill_zones.code | Код зоны
| created_at | datetime | да | - | Дата создания записи
Первичный ключ: id. Ограничение: уникальный по (domain_id, zone_code).
2.2. skill_type_links
Назначение: типы навыка. Один навык может иметь несколько типов.
Где используется:
мастер создания навыка, шаг "Анкета" - выбор типа навыка;
карточка навыка, вкладка "Обзор" - вывод типа навыка;
окно редактирования анкеты - изменение типа навыка;
реестр навыков - фильтрация по типу.
| Поле | Тип | Обязательность | Ключ | Комментарий
| id | UUID | да | PK | Идентификатор записи
| skill_id | UUID | да | FK skills.id | Навык
| type_code | varchar(32) | да | FK skill_types.code | Код типа навыка
| created_at | datetime | да | - | Дата создания записи
Первичный ключ: id. Ограничение: уникальный по (skill_id, type_code).
2.3. skill_review_decision_criteria
Назначение: отмеченные критерии в конкретном решении ревью. Обеспечивает счётчик "Отмечено N из 5".
Где используется:
вкладка "Ревью" - отметка выполненных критериев ревьюером;
вкладка "Ревью" - вывод счётчика отмеченных критериев;
вкладка "Ревью" - разблокировка кнопки "Согласовать" при полном наборе;
вкладка "История", карточка навыка - сохранение состава отмеченных критериев в решении.
| Поле | Тип | Обязательность | Ключ | Комментарий
| id | UUID | да | PK | Идентификатор записи
| decision_id | UUID | да | FK skill_review_decisions.id | Решение ревьюера
| criterion_code | varchar(50) | да | FK skill_review_criteria.code | Отмеченный критерий
| created_at | datetime | да | - | Дата отметки
Первичный ключ: id. Ограничение: уникальный по (decision_id, criterion_code).
3. Таблицы доменов
3.1. skill_domains
Назначение: домены навыков. Домен объединяет навыки одной предметной области, задаёт владельца и адрес интеграции.
Где используется:
вкладка "Домены", список - таблица доменов с числом навыков;
вкладка "Домены", форма создания и редактирования - ввод названия, описания, владельца, адреса интеграции, зон;
вкладка "Домены" - проверка уникальности адреса интеграции;
вкладка "Домены" - запрет удаления домена, в котором есть навыки;
мастер создания навыка, шаг "Анкета" - выбор домена, проверка наличия домена;
реестр навыков - фильтрация по домену и вывод домена в строке;
карточка навыка - вывод домена в шапке.
| Поле | Тип | Обязательность | Ключ | Комментарий
| id | UUID | да | PK | Идентификатор домена
| code | varchar(100) | да | U | Служебный код домена
| name | varchar(100) | да | U | Название домена
| description | text | да | - | Описание домена
| owner | varchar(200) | да | - | Владелец, подразделение
| api_url | varchar(2000) | да | U | Адрес интеграции домена
| created_at | datetime | да | - | Дата создания записи
| updated_at | datetime | да | - | Дата последнего изменения
| deleted_at | datetime | нет | - | Дата мягкого удаления
Индексы: уникальный по code, уникальный по name, уникальный по api_url.
4. Основные таблицы
4.1. skills
Назначение: навыки цифрового ассистента. Ядро раздела, отображается в реестре и карточке.
Где используется:
реестр навыков - строка навыка: назначение, служебный код, версия, домен, статус, готовность, число диалогов, даты, признаки инцидента и конфликта;
реестр навыков - поиск по названию, назначению, служебному коду;
реестр навыков - фильтры по статусу и домену, сортировка;
мастер создания навыка, шаг "Анкета" - ввод названия, функциональности, ожидаемого результата, домена, рабочей зоны;
мастер создания навыка, шаг "Проверка" - сводка заполненности;
карточка навыка, вкладка "Обзор" - анкета навыка и полоса жизненного цикла;
карточка навыка, окно редактирования - изменение полей анкеты и связанных материалов;
карточка навыка - живое состояние, версия, даты создания и изменения;
карточка навыка, вкладка "Проверки" - состояние обучения и результат автотестов;
вкладка "Ревью" - сведения о навыке для решения;
карточка навыка, отключение - смена статуса и сохранение текста заглушки;
массовые действия реестра - смена статуса для отмеченных навыков.
| Поле | Тип | Обязательность | Ключ | Комментарий
| id | UUID | да | PK | Идентификатор навыка
| service_id | string(100) | нет | U | Уникальный идентификатор навыка во внешнем сервисе
| code | varchar(100) | да | U | Служебный код, отображается в интерфейсе
| name | string(120) | да | - | Название навыка

| expected_result | text | да | - | Ожидаемый результат
| description | text | нет | - | Расширенное описание
| display_version | varchar(20) | да | - | Бизнес-версия навыка
| status | varchar(32) | да | FK skill_statuses.code | Статус жизненного цикла
| domain_id | UUID | да | FK skill_domains.id | Домен навыка
| author_user_id | UUID | нет | внешняя | Автор навыка, идентификатор СУДИР
| contact_user_id | UUID | да | внешняя | Контактное лицо, идентификатор СУДИР
| limitations | text | нет | - | Ограничения использования
| comments | text | нет | - | Комментарии
| related_materials | jsonb | нет | - | Связанные материалы, список объектов название и ссылка
| connection | jsonb | нет | - | Параметры подключения
| training | varchar(32) | да | FK skill_training_states.code | Состояние обучения модели
| training_eta | varchar(100) | нет | - | Ожидаемое время завершения обучения
| autotest | varchar(32) | да | FK skill_autotest_states.code | Результат автотестов
| autotest_note | text | нет | - | Замечания автотестов при неуспехе
| created_at | datetime | да | - | Дата создания записи
| updated_at | datetime | да | - | Дата последнего изменения
| deleted_at | datetime | нет | - | Дата мягкого удаления
Индексы: уникальный по service_id, уникальный по code, обычные по status, domain_id.
Структура connection, тип jsonb:
| Поле | Тип | Комментарий
| endpoint | string | Адрес сервиса навыка
| contract_version | string | Версия контракта подключения
| auth_required | boolean | Признак необходимости авторизации
| auth_type | string | Тип авторизации, например transport_token
Структура related_materials, тип jsonb, массив объектов: title (string), url (string).
Примечание: service_id и code это разные атрибуты. service_id приходит из внешнего сервиса, code задаёт человек.

Назначение: группы обучающих фраз навыка.
Где используется:
карточка навыка, вкладка "Обучающие фразы" - список групп с числом фраз;
мастер создания навыка, шаг "Обучающие фразы" - создание и удаление групп;
карточка навыка, вкладка "Обучающие фразы", режим изменения - добавление и удаление групп;
карточка навыка, вкладка "Проверки" - вывод числа групп.
| Поле | Тип | Обязательность | Ключ | Комментарий
| id | UUID | да | PK | Идентификатор группы фраз
| skill_id | UUID | да | FK skills.id | Навык
| name | string(255) | да | - | Название группы фраз

| updated_at | datetime | да | - | Дата последнего изменения
| deleted_at | datetime | нет | - | Дата мягкого удаления

4.3. skill_phrases
Назначение: обучающие фразы навыка, элементы внутри группы фраз.
Где используется:
карточка навыка, вкладка "Обучающие фразы" - вывод фраз чипами и подсветка конфликтующих;
мастер создания навыка, шаг "Обучающие фразы" - ввод фраз построчно или через запятую, счётчик фраз;
карточка навыка, вкладка "Проверки" - источник проверки пересечений;
вкладка "Ревью" - вывод фраз навыка для принятия решения.
| Поле | Тип | Обязательность | Ключ | Комментарий
| id | UUID | да | PK | Идентификатор фразы
| intent_id | UUID | да | FK skill_intents.id | Группа фраз
| phrase | text | да | - | Текст фразы
| normalized_phrase | text | нет | - | Нормализованный текст для проверки пересечений
| created_at | datetime | да | - | Дата создания записи

4.4. skill_conflicts
Назначение: конфликты формулировок между навыками. Заполняется автоматически при сохранении фраз.
Где используется:
реестр навыков - признак конфликта в строке навыка со ссылкой на проверки;
карточка навыка, вкладка "Проверки" - таблица конфликтов: фраза, конкурирующий навык, домен, тип совпадения, мера близости;
карточка навыка, вкладка "Проверки" - блокировка при точном совпадении и предупреждение при смысловом;
карточка навыка, вкладка "Обзор" - предупреждение о конфликте со ссылкой на проверки;
мастер создания навыка, шаг "Обучающие фразы" - онлайн-проверка пересечений;
вкладка "Ревью" - сведения о конфликтах для решения.
| Поле | Тип | Обязательность | Ключ | Комментарий
| id | UUID | да | PK | Идентификатор конфликта
| skill_id | UUID | да | FK skills.id | Навык-владелец фразы
| phrase | text | да | - | Исходная фраза
| normalized_phrase | text | нет | - | Нормализованная фраза
| conflicting_skill_id | UUID | да | FK skills.id | Конфликтующий навык
| conflict_type | varchar(32) | да | FK skill_conflict_types.code | Тип конфликта
| score | float | да | - | Оценка степени совпадения
| created_at | datetime | да | - | Дата обнаружения
| updated_at | datetime | да | - | Дата последнего изменения
| deleted_at | datetime | нет | - | Дата мягкого удаления
Индексы: обычные по skill_id, conflicting_skill_id.
Примечание: домен конкурирующего навыка в интерфейсе выводится соединением с skill_domains, отдельное поле не хранится.
4.5. skill_monitoring
Назначение: пороги мониторинга и текст заглушки. Фактические значения читаются из витрины диалогов. Одна запись на навык.
Где используется:
карточка навыка, вкладка "Мониторинг" - пороги показателей за сутки;
карточка навыка, вкладка "Мониторинг" - блок отклонений: факт, порог, разница;
карточка навыка, вкладка "Мониторинг" - настройка и изменение порогов;
карточка навыка, вкладка "Мониторинг" - текст, который увидит пользователь при недоступности навыка;
карточка навыка, вкладка "Мониторинг" - плановое окно обслуживания, исключаемое из расчёта;
карточка навыка, отключение - подстановка текста заглушки.

| created_at | datetime | да | - | Дата создания записи
| updated_at | datetime | да | - | Дата последнего изменения

4.7. skill_incidents

Где используется:
реестр навыков - признак открытого инцидента с уровнем и сутью;
карточка навыка, вкладка "Обзор" - блок инцидента: уровень, суть, ответственный, срок устранения;
карточка навыка, вкладка "Мониторинг" - таблица инцидентов: уровень, описание, причина, кто устраняет, срок, состояние.

4.8. skill_metrics
Назначение: снимок агрегированных показателей навыка за период. Источник - витрина диалогов.
Где используется:
карточка навыка, вкладка "Обзор" - блок диалогов: число диалогов, доля успешных, вложения за 30 дней;
карточка навыка, вкладка "Обзор" - блок оценок: доля хороших, число оценок, число низких, охват;
карточка навыка, вкладка "Обзор" - блок шагов: целевое, фактическое, медиана, отклонение;
карточка навыка, вкладка "Обзор" - пояснение при недостатке оценок;
карточка навыка, вкладка "Мониторинг" - показатели за сутки и отклонения.

Уточнения как найти в прототипе:
skill_types - карточка навыка "Вода", на вкладке "Обзор", поле "Тип навыка: Информационный и транзакционный". В форме редактирования и в мастере создания навыка это поле - выпадающий список.
skill_domains - вкладка "Домены", таблица с колонками "Домен", "Владелец", "Зона", "Навыков". Кнопка "Создать домен" над таблицей.
skill_check_statuses - карточка навыка "Вода", вкладка "Проверки", блок "Автоматические проверки", 5 строк. Каждая строка - одна проверка с результатом: пройдено, не пройдено, предупреждение, заблокировано.
skill_sandbox_results - карточка навыка "Вода", вкладка "Проверки", блок "Последняя проверка в песочнице", строка "Результат: Успешно". В песочнице - запись результата после проверки навыка в диалоге со стендом.
skill_check_types - карточка навыка "Вода", вкладка "Проверки", блок "Автоматические проверки", 5 строк: "Заполнены обязательные поля анкеты", "Задана хотя бы одна группа обучающих фраз", "Нет точных совпадений фраз с другими навыками", "Нет близких по смыслу формулировок", "Указаны параметры подключения реализации". Это 5 кодов: anketa, phrases, exact_conflicts, semantic_conflicts, endpoint.
skill_training_states - карточка навыка "Вода", вкладка "Проверки", блок "Обучение модели: Готово". В реестре навыков - колонка "Готовность", первая строка (у "Парковки" - "В процессе", у "Отопления" - "Не обучена", у "Вода" - "Готово").
skill_autotest_states - карточка навыка "Вода", вкладка "Проверки", блок "Автотесты: Успешно". В реестре навыков - колонка "Готовность", вторая строка (у "Вода" - "Успешно", у "Отопления" - "Не пройдено", у "Социальные выплаты" - "Неуспешно").
skill_responsible_roles - карточка навыка "Вода", вкладка "Мониторинг", блок "Ответственные", три строки: "Владелец навыка", "Технический представитель", "Заместитель". Это 3 кода: owner, tech, backup.
skill_responsibles - карточка навыка "Вода", вкладка "Мониторинг", блок "Ответственные". Поле user_id - UUID из СУДИР. На вкладке "Обзор" - блок "Контактное лицо", кнопка "Соколова Марина Андреевна".
skill_review_decision_types - вкладка "Ревью", две кнопки: "Согласовать" (заблокирована, пока не отмечены все 5 критериев) и "Вернуть на доработку". Два кода: approved, rejected.
skill_review_criteria - вкладка "Ревью", блок "Критерии проверки", 5 чекбоксов с описаниями. Каждый чекбокс - одна запись справочника (c1 - c5). Счётчик "Отмечено 0 из 5 критериев", блокирует кнопку "Согласовать".
