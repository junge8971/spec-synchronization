Функциональное описание прототипа «База знаний»
1. Назначение
Прототип реализует административный раздел «База знаний» Центра управления Цифрового ассистента (ЦАМ). Раздел - это хранилище материалов и ссылок, которые ассистент предлагает пользователю в диалоге: как инструкции, ответы или темы для изучения.
Прототип полностью соответствует модели данных из PDF: 10 таблиц с префиксом kb_ (3 сущности, 1 связующая, 6 справочников).
2. Общая структура
Раздел состоит из двух экранов:
Список записей - стартовый экран с таблицей, поиском, фильтрами и кнопкой создания.
Карточка записи - экран редактирования с четырьмя вкладками: «Основное», «Материалы», «Навыки», «Правила показа».
Переход между экранами - по клику на строку таблицы (открыть) или по хлебным крошкам (вернуться). При закрытии карточки без сохранения показывается модалка подтверждения.
3. Экран «Список записей»
3.1. Таблица
Отображает все записи со следующими колонками:
| Колонка | Источник | Сортировка
| Материал (название + код) | kb_entry.name, kb_entry.code | ✓
| Категория | kb_entry.category_code → kb_categories.display_name | ✓
| Навыки (чипсы) | kb_entry_skill → skills.name | -
| Ссылок | COUNT(kb_link) | ✓
| Статус | kb_entry.status → kb_statuses.display_name | ✓
| Стрелка «›» | - | -
Статусы подсвечиваются цветом: Активен - зелёный, Приостановлен - жёлтый, Черновик - светлый, Архив - серый.
3.2. Поиск
Поле поиска (минимум 2 символа) ищет по названию, служебному коду, категории и отображаемым названиям навыков.
3.3. Мультиселект-фильтры
| Фильтр | Справочник | Показывает
| Все категории | kb_categories | 5 категорий с кодами
| Все статусы | kb_statuses | 4 статуса с кодами
У каждого значения рядом с названием выводится код в моноширинном шрифте. Кнопка «Все ...» очищает фильтр.
3.4. Расширенный фильтр «⚙ Условия»
Конструктор произвольных условий:
Логика: И (все) / ИЛИ (любое).
Поля: Название, Код, Категория, Статус, Тип материала, Язык, Ссылок, Навыки.
Операторы: для текста - содержит/не содержит/равно/не равно/пусто/не пусто; для enum - входит/не входит (с чипсами); для чисел - =, >, ≥, <, ≤, между.
Применённые условия отображаются в панели-баре под фильтрами. На кнопке - бейдж с числом активных условий.
3.5. Меню «⋮»
Сохранить текущий фильтр - сохраняет поиск, мультиселекты и расширенные условия под именем.
Скопировать ссылку на отбор - формирует URL с параметрами и копирует в буфер.
Сохранённые фильтры - список с возможностью применить или удалить.
3.6. Прочее
Кнопка «Сбросить» - видна при активных фильтрах.
Счётчик справа - сколько записей найдено.
Кнопка «＋ Создать запись» - открывает пустую карточку.
Кнопка «⤓ Экспорт» - модалка выбора полей kb_entry.
4. Экран «Карточка записи»
4.1. Шапка
Содержит:
название (name),
назначение (description),
статус (цветная точка + подпись),
код (code, monospace),
категорию (category_code),
мета-строку: Создан (created_at) и Изменён (updated_at).
Кнопки:
| Кнопка | Действие
| ⤓ Экспорт | Модалка выбора разделов
| Сохранить | Проверяет уникальность name и code, обновляет updated_at
| Приостановить | Переключает status между paused и active
| В архив | Устанавливает status = 'archived' с подтверждением
| Закрыть | Модалка «Выйти без сохранения?»
4.2. Вкладка «Основное»
Две карточки: Основное и Когда использовать.
Левая - «Основное» (kb_entry):
| Поле | Тип | Валидация
| Название | input | обязательное, уникальное
| Служебный код | input (monospace) | обязательное, уникальное, латиница
| Категория | select из kb_categories | обязательное
| Описание | textarea | -
| Команда-владелец | input (строка, owner) | -
| Ответственный | select (responsible_user_id) | -
| Теги | input (строка через запятую, tags) | -
Правая - «Когда использовать» (kb_entry):
| Поле | Тип
| Тип материала | select из kb_material_types (5 значений)
| Язык | select из kb_languages (2 значения)
| Актуально до | date (valid_until)
| Открывать в новом окне | switch (open_in_new_tab)
4.3. Вкладка «Материалы» (kb_link)
Две колонки: список ссылок (слева) и живой предпросмотр (справа).
Карточка ссылки содержит:
| Элемент | Поле модели
| Заголовок (editable input) | title
| Ссылка (monospace) | url
| Короткое описание | description
| Теги через запятую | tags
| Ручка ⠿ для drag-and-drop | обновляет sort_order
| Крестик удаления | -
Клик по карточке - она становится активной (красная рамка), предпросмотр справа обновляется.
Кнопка «＋ Добавить ссылку» - добавляет пустую карточку в конец.
Предпросмотр - тёмный макет чата:
пример вопроса пользователя,
ответ бота с карточкой ссылки: заголовок, описание, URL (без схемы), теги-чипсы.
Пустое состояние: «Ссылок пока нет - добавьте первую слева».
4.4. Вкладка «Навыки» (kb_entry_skill)
Сетка кликабельных чипсов. Каждый чип:
название навыка (skills.name),
категория навыка (мелким серым шрифтом),
skill_id (моноширинный, для наглядности привязки к skills.id).
Клик включает/выключает навык. Включённый - красный. Счётчик под сеткой показывает «Выбрано: N из M».
Привязка хранится по skill_id - как того требует модель. В списке записей эти навыки выводятся как чипсы отображаемых названий.
4.5. Вкладка «Правила показа» (kb_display_rule)
Две карточки: Правила предложения и Пример срабатывания.
«Правила предложения»:
| Поле | Модель | Тип
| Когда предлагать | trigger_mode из kb_trigger_modes (4) | select
| Триггерные слова и фразы | trigger_words | input (через запятую)
| Формат ответа | reply_format из kb_reply_formats (3) | select
| Максимум ссылок | max_links | number
| Приоритет | priority | number
| Эксклюзивно | exclusive | switch
| Показывать только релевантные региону | region_relevant | switch
«Пример срабатывания» - статический макет чата с примером вопроса «Как снять показания счётчиков воды?» и ответом бота с карточкой ссылки. Внизу пояснение про сортировку материалов по приоритету.
5. Справочники
5.1. Статические (соответствуют kb_* из PDF)
| Константа | Таблица | Значений
| DICT_KB_CATEGORIES | kb_categories | 5 (zhkh, edu, health, transport, social)
| DICT_KB_STATUSES | kb_statuses | 4 (draft, active, paused, archived)
| DICT_KB_MATERIAL_TYPES | kb_material_types | 5 (instruction, reference, service_link, video, document)
| DICT_KB_LANGUAGES | kb_languages | 2 (russian, english)
| DICT_KB_TRIGGER_MODES | kb_trigger_modes | 4 (user_asks, trigger_words, dialog_hint, manual_only)
| DICT_KB_REPLY_FORMATS | kb_reply_formats | 3 (inline_link, card, link_list)
5.2. Внешние данные
Навыки (ALL_SKILLS) - из раздела «Навыки», 12 штук с id, name, cat.
Ответственные (RESPONSIBLE_USERS) - из СУДИР, пара id → name.
5.3. Демо-данные
Массив KB_DATA содержит 6 записей с разными категориями, статусами, типами материалов, языками и полными настройками правил показа. Каждая - с массивом ссылок и массивом привязанных навыков.
6. Вспомогательные механизмы
6.1. Тост-уведомления
Появляются в правом нижнем углу на 2 секунды: «Ссылка добавлена», «Ссылка удалена», «Запись приостановлена», «Изменения сохранены», «Фильтр сохранён».
6.2. Модальные окна
Экспорт списка/карточки - чекбоксы полей, кнопка «Выгрузить».
Подтверждение выхода - «Выйти без сохранения?».
Подтверждение архивации - стандартный confirm().
6.3. Drag-and-drop
Реализован для ссылок (kb_link.sort_order). Визуальная индикация: серый dragging у источника, красная рамка drop-target у цели. После перетаскивания sort_order пересчитывается.
6.4. Валидация
Обязательность: name и code - при пустом значении поле подсвечивается красным.
Уникальность: проверка по массиву KB_DATA при совпадении названия или кода с другой записью.
При сохранении валидация выполняется повторно.
6.5. Клавиатурные сокращения
Esc - закрыть модалку.
Клик по бэкдропу - закрыть модалку.
7. Соответствие модели данных
| Таблица PDF | Реализация
| kb_entry | Объект draft + KB_DATA, все поля в UI
| kb_link | draft.links[] с title, url, description, tags, sort_order
| kb_display_rule | draft.display_rule со всеми 7 полями + created_at
| kb_entry_skill | draft.skills[] - массив skill_id
| kb_categories | DICT_KB_CATEGORIES, используется через category_code
| kb_statuses | DICT_KB_STATUSES, kb_entry.status
| kb_material_types | DICT_KB_MATERIAL_TYPES, kb_entry.material_type
| kb_languages | DICT_KB_LANGUAGES, kb_entry.language
| kb_trigger_modes | DICT_KB_TRIGGER_MODES, kb_display_rule.trigger_mode
| kb_reply_formats | DICT_KB_REPLY_FORMATS, kb_display_rule.reply_format
Все коды и подписи совпадают с PDF. Поля owner - строка, responsible_user_id - внешний id. Связка навыков - по skill_id, а не по названию.
8. Ограничения и не реализовано
Серверная валидация - всё на клиенте, данные в памяти браузера и теряются при перезагрузке.
Soft delete (deleted_at) - поле в структуре, но кнопки удаления нет (только архивация).
Загрузка реальных навыков и ответственных - используются статические массивы.
Журнал изменений - нет, только updated_at в шапке.
Создание новых категорий - справочник kb_categories помечен в PDF как пользовательский, но в прототипе редактирование справочника не предусмотрено (это отдельный раздел «Справочники»).
9. Типичный сценарий работы
Открыть раздел «База знаний» в меню слева.
Найти запись через поиск или фильтры (категория, статус, расширенные условия).
Кликнуть по строке - открыть карточку.
Вкладка «Основное»: проверить название, код, категорию, описание, теги, тип материала, язык, дату актуальности.
Вкладка «Материалы»: добавить ссылки (заголовок, URL, описание, теги), расставить порядок перетаскиванием, проверить предпросмотр.
Вкладка «Навыки»: выбрать навыки (по skill_id), к которым привязан материал.
Вкладка «Правила показа»: задать триггер, формат ответа, максимум ссылок, приоритет, эксклюзивность, региональность.
Нажать «Сохранить».
При необходимости - «Приостановить» или «В архив».
Вернуться к списку по хлебным крошкам.
Готово - теперь, когда пользователь спросит по теме, ЦАМ сможет прислать ему нужную ссылку или инструкцию.
Таблицы
Модель данных раздела "База знаний"
Раздел "База знаний" - хранилище материалов и ссылок, которые ЦАМ предлагает пользователю в диалоге: инструкции, ответы и темы для изучения. Каждая запись это тема, внутри которой лежит одна или несколько ссылок. Запись привязывается к навыкам.
Префикс таблиц раздела: kb_.
2. Связующие таблицы
2.1. kb_entry_skill
Назначение: связь записи базы знаний с навыками, к которым она привязана.
Где используется:
карточка записи, вкладка "Навыки" - сетка чипсов, клик добавляет или убирает навык;
карточка записи, вкладка "Навыки" - счётчик "Выбрано: N" под сеткой;
список записей - колонка "Навыки", вывод чипсов привязанных навыков;
список записей - поиск учитывает названия навыков;
список записей - фильтр по навыкам.
| Поле | Тип | Обязательность | Ключ | Комментарий
| id | UUID | да | PK | Идентификатор записи
| kb_entry_id | UUID | да | FK kb_entry.id | Запись базы знаний
| skill_id | UUID | да | FK skills.id | Навык, таблица раздела "Навыки"
| created_at | datetime | да | - | Дата создания связи
Первичный ключ: id. Ограничение: уникальный по (kb_entry_id, skill_id).
Примечание: skills.id принадлежит разделу "Навыки" и в настоящем документе не создаётся.
3. Основные таблицы
3.1. kb_entry
Назначение: материал базы знаний. Центральная таблица раздела.
Где используется:
список записей - колонки: материал с кодом, категория, навыки, число ссылок, статус;
список записей - поиск по названию, коду, категории и навыкам;
список записей - фильтры по категории и статусу;
список записей - сортировка по колонкам;
карточка записи - шапка: название, назначение, статус, код, категория;
карточка записи, вкладка "Основное" - название, служебный код, категория, описание;
карточка записи, вкладка "Основное" - владелец и ответственный, теги;
карточка записи, вкладка "Основное" - блок "Когда использовать": тип материала, язык, актуально до, открывать в новом окне;
карточка записи - кнопки "Сохранить", "Приостановить", "Выключить";
модалка экспорта - состав полей выгрузки.
| Поле | Тип | Обязательность | Ключ | Комментарий
| id | UUID | да | PK | Идентификатор записи
| code | varchar(100) | да | U | Служебный код, латиница
| name | varchar(255) | да | - | Название материала
| category_code | varchar(50) | да | FK kb_categories.code | Категория
| status | varchar(32) | да | FK kb_statuses.code | Статус записи
| description | text | нет | - | Описание
| owner | varchar(200) | нет | - | Владелец записи, подразделение
| responsible_user_id | UUID | нет | внешняя | Ответственный, идентификатор СУДИР
| tags | text | нет | - | Теги через запятую
| material_type | varchar(32) | да | FK kb_material_types.code | Тип материала
| language | varchar(16) | да | FK kb_languages.code | Язык материала
| valid_until | date | нет | - | Актуально до
| open_in_new_tab | boolean | да | - | Открывать ссылку в новом окне
| created_at | datetime | да | - | Дата создания записи
| updated_at | datetime | да | - | Дата последнего изменения
| deleted_at | datetime | нет | - | Дата мягкого удаления
Индексы: уникальный по code, обычные по category_code, status, material_type.
Примечание: поле team_id из исходной модели удалено, команды не хранятся. Вместо него владелец хранится строкой в поле owner.
3.2. kb_link
Назначение: ссылка внутри материала базы знаний. Одна запись содержит несколько ссылок, порядок меняется перетаскиванием.
Где используется:
карточка записи, вкладка "Материалы" - карточки ссылок с полями: заголовок, адрес, короткое описание, теги;
карточка записи, вкладка "Материалы" - перетаскивание карточек за ручку для смены порядка;
карточка записи, вкладка "Материалы" - удаление ссылки;
карточка записи, вкладка "Материалы" - кнопка "Добавить ссылку";
карточка записи, вкладка "Материалы" - предпросмотр, как ссылка появится в чате;
карточка записи, вкладка "Материалы" - пустое состояние "Пока ни одной ссылки";
список записей - колонка "Ссылок", количество ссылок у записи.
| Поле | Тип | Обязательность | Ключ | Комментарий
| id | UUID | да | PK | Идентификатор ссылки
| kb_entry_id | UUID | да | FK kb_entry.id | Запись базы знаний
| sort_order | integer | да | - | Порядок отображения и выдачи
| title | varchar(255) | да | - | Заголовок, видимый пользователю в чате
| url | varchar(1024) | да | - | Адрес ссылки
| description | varchar(500) | нет | - | Короткое описание
| tags | varchar(500) | нет | - | Теги через запятую
| created_at | datetime | да | - | Дата создания записи
| updated_at | datetime | да | - | Дата последнего изменения
Индексы: обычный по kb_entry_id. Порядок ссылок определяет порядок выдачи пользователю.
3.3. kb_display_rule
Назначение: условия, при которых ЦАМ предлагает материал пользователю в диалоге. Связь одна к одной с записью.
Где используется:
карточка записи, вкладка "Правила показа" - блок "Правила предложения": когда предлагать, триггерные слова, формат ответа, максимум ссылок, приоритет;
карточка записи, вкладка "Правила показа" - переключатели "Эксклюзивно" и "Показывать только релевантные региону пользователя";
карточка записи, вкладка "Правила показа" - блок "Пример срабатывания" с макетом чата;
карточка записи, вкладка "Правила показа" - пояснение о сортировке материалов по приоритету.
| Поле | Тип | Обязательность | Ключ | Комментарий
| id | UUID | да | PK | Идентификатор правила
| kb_entry_id | UUID | да | FK kb_entry.id, U | Запись, связь одна к одной
