## Architecture

Approved chain: configured MPMM session preparation → validated Control API `/me` → session/access boundary → permitted UI → shared protected transport → backend authorization. Generation changes close the boundary and invalidate server data without conflating a same-user refresh with account replacement. Historical security governance describes broader СУДИР/ППО responsibilities; it is not a replacement architecture.

Remaining **existing deployment questions** are availability of the common session at the UI origin, configured HTTPS origin/path destinations, preflight/actual CORS responses for Origin, both X-token headers, Content-Type, Idempotency-Key and methods, shared refresh rotation compatibility, valid `/me`, and server permission/object-scope enforcement including dialogs (`A/design.md`:133–141,153–155,170). An endpoint configuration does not transfer localStorage across origins; no cross-origin token bridge or `credentials:include` follows. These are unverified here, not newly discovered production failures. Historical idle/account-blocking, dual-entry and audit ownership/retention remain documentary reconciliation questions only.
