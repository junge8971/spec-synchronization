Рекомендация: **keep + узкий new**, без восстановления устаревшей генерации идентификатора.

1. **Keep:** нынешнюю семантику назначения канала сервером, payload и существующие recovery-требования.
2. Если parent принимает дополнительное планирование, создать только узкую delta, например:
   - `openspec/changes/fix-surface-registration-long-domain-layout/proposal.md`;
   - `.../specs/surface-registration/spec.md`;
   - `.../tasks.md`.
3. Минимальный сценарий delta: при вводе длинного домена около 200 символов шаг сведений не создаёт горизонтального переполнения страницы, сохраняет полное введённое значение и продолжает показывать серверное назначение канала вместо вычисленного идентификатора.
4. В tasks оставить открытой component-проверку длинного и короткого значения в `app/widgets/surface-registration/ui/tests/surface-registration.test.tsx`: сохранность ввода, отсутствие генерации канала, ограничение контейнера. 5. **Question, не blocker для статической сверки:** если требуется именно обрезание идентификатора, сначала определить актуальный отображаемый элемент. Не переносить MOS-1164 автоматически на экран результата регистрации и не вводить лимит данных в 200 символов.
