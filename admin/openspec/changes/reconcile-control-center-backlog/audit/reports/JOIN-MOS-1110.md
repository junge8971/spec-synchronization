## 2. API: применимость и пределы

R2 относится к клиентскому позиционированию раскрытого элемента, **не требует нового endpoint, payload или изменения backend-контракта**.

В `app/features/surface-registration/ui/steps/surface-details-step.tsx:40–57` список строится из импортированных `surfaceTypeValues` и `surfaceTypeLabels`; в этом блоке нет запроса справочника при раскрытии.

Сохранённые бизнес-требования определяют значения типа, но не геометрию popup. Дополнительно найденное описание `SurfaceType` в `sources/wiki-243776365/r1/content.json`, `$.text`, фрагмент «Поле type использует SurfaceType» перечисляет `portal`, `portal_section`, `mobile_application`. Эта страница имеет название «Бизнес-анализ: Диалоги» и используется лишь как дополнительный контекст, не как authority для геометрии формы.

Полная сверка контрактов регистрации вне scope. Ни успешный POST, ни доступность серверного справочника не доказывают исправление MOS-1110.

## 4. Код и тесты

### Код

`app/features/surface-registration/ui/steps/surface-details-step.tsx:40–57`:

- доступное имя trigger — «Тип поверхности»;
- trigger имеет `w-full`;
- `<SelectContent>` используется без собственных параметров позиционирования;
- варианты отображаются внутри `SelectItem`.

`app/shared/ui/select.tsx:55–94`:

- используется `@base-ui/react/select`;
- значения по умолчанию: `side='bottom'`, `sideOffset=4`, `align='center'`, `alignOffset=0`, `alignItemWithTrigger=true`;
- popup размещается через `Portal → Positioner → Popup`;
- ширина включает `w-(--anchor-width)` и `min-w-36`.

**Вывод:** связь с якорем реализована штатным механизмом библиотеки. При этом `alignItemWithTrigger=true` не равно доказанному требованию «смещения нет». Нельзя по одному этому prop ни объявить дефект воспроизведённым, ни назначить его причиной. Сочетание минимальной ширины, ширины якоря и фактического layout требует отдельной проверки.

### Тесты

`app/widgets/surface-registration/ui/tests/surface-registration.test.tsx:159–171`, тест `places surface type and domains in adjacent columns on wider screens`:

- проверяет `grid`, `md:grid-cols-2`;
- проверяет соседство поля типа и группы доменов;
- проверяет классы ширины доменов.

Он **не раскрывает список и не проверяет координаты popup**. Его существование нельзя засчитать как регрессионную проверку R2.

Целевой поиск по тестам приложения не выявил проверки `alignItemWithTrigger` или геометрии раскрытого списка типа поверхности. Тесты не запускались; отсутствие подходящей проверки в просмотренных результатах не объявляется абсолютным отсутствием всех возможных косвенных проверок.

## 5. Минимальная planning-коррекция

После независимого ревью предложить **новый узкий change**, без изменения архивов:

1. `openspec/changes/fix-surface-type-dropdown-alignment/proposal.md`  
   Зафиксировать только MOS-1110: отсутствие смещения выбора типа в форме добавления. Исключить фильтр реестра, выбор владельца, API и соседние дефекты.

2. `openspec/changes/fix-surface-type-dropdown-alignment/specs/surface-registration/spec.md`  
   Добавить требование, например `Surface type dropdown remains anchored to its field`:
   > При раскрытии выбора «Тип поверхности» в форме добавления список SHALL сохранять привязку к соответствующему полю без несогласованного смещения.

   Сценарий: открыть форму → раскрыть выбор → список соответствует положению своего поля. Не закреплять без доказательств конкретные offsets, сторону раскрытия или запрет штатной коррекции у края viewport.

3. `openspec/changes/fix-surface-type-dropdown-alignment/tasks.md`  
   Оставить все новые задачи незавершёнными:
   - определить воспроизводимый критерий выравнивания по доступному визуальному свидетельству либо уточнённому acceptance;
   - проверить и при необходимости локально скорректировать использование `SelectContent`, не меняя глобальный shared-default без отдельной оценки;
   - добавить компонентную регрессию выбранной настройки позиционирования и сохранения выбора; повторное раскрытие с другим выбранным типом использовать как граничный случай проверки, а не как новое историческое требование;
   - явно отделить структурную компонентную проверку от визуальной геометрии.

**Question:** точный визуальный критерий остаётся открытым из-за недоступного изображения. Для фиксации planning-gap это не blocker; для заявления «дефект исправлен» доказательств недостаточно. Browser/E2E не включать как автоматически разрешённые работы.

**Keep:** API, исторические ledgers, archive/main specs и существующие feature-checkboxes в рамках этой сверки. No-op по всему заданию не оправдан: явного spec-сценария и целевой проверки R2 не найдено.
