## Architecture and important qualifications

### Mounted path, not component/demo inference

`app/root.tsx:21–25` exports session loader and fallback, then ApplicationRoot. ApplicationRoot places **ApplicationLayout (including header/help/navigation) inside SessionBoundary**, with mock tools outside. `SessionBoundary:14–23` requires runtime ready session for visible children; before owner confirmation there are no children, and an existing owner's subtree is Activity-hidden/inert while not ready. `SessionStatus:10–27` provides checking, redirecting or error/retry. Initial hydrate fallback has only status/mock tools. `CurrentUser:7` independently hides non-ready/missing-principal data.

Therefore the isolated assertion named “keeps the header available without a confirmed profile” (`application-header.test.tsx:23–35`) must not be reported as actual pre-bootstrap shell/help availability. It mounts the header directly. Similarly, the layout test's “without an auth request” title excludes the actual root loader/boundary. Session-boundary tests `:62–118` verify generic child withholding/hiding/owner replacement, not an open profile Popover or help portal across transitions.
