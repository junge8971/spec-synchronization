## Architecture

`app/routes.ts` installs descriptors from the application registry, which composes the base registry and optional public exports (`app/application/constants/application-routes.constants.ts:1–6`). Optional internals were not audited. Root exports bootstrap and ApplicationRoot (`app/root.tsx:21–25`); ApplicationRoot places the Outlet under SessionBoundary and ApplicationLayout (`app/application/ui/application-root.tsx:11–24`). The access boundary filters navigation/tabs and substitutes denial before business content/breadcrumbs. This is UI policy, not backend authorization.

Tab state flows URL → `useSectionTab` → permission-filtered context → selection helper; `handleSectionTabChange` ignores invalid/same values, preserves other query, deletes only original-default tab and invokes normal search navigation (`app/shared/lib/handlers/section-tab.handlers.ts:11–23`). `section-tabs.test.tsx:40–109` asserts PUSH, unchanged key on reselect, Back/Forward, reopening and keyboard selection for one transition in each section. These sampled assertions are not exhaustive tab-transition/runtime proof.

Dynamic breadcrumbs consume the same entity query hooks as detail pages, not loader data. Dialogue test explicitly asserts one fetch; no generalized production cache guarantee follows. No shadcn accessibility implementation audit was performed: findings are limited to composition and concrete accessibility assertions in the inspected tests.
