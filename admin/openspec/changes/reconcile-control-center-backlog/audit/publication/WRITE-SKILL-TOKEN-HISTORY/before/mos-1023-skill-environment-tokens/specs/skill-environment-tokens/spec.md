## Purpose

Предоставить достоверные сведения о токенах навыка по контурам и безопасное выполнение согласованных операций с секретами.

## ADDED Requirements

### Requirement: Server token metadata

При наличии согласованного API UI SHALL показывать контур, состояние, область и сроки токена из серверного ответа. «Не выдан» SHALL отображаться только по явному состоянию сервера. Без API SHALL показываться unavailable, а ошибка загрузки MUST NOT трактоваться как отсутствие токена.

#### Scenario: No token issued

- **WHEN** сервер явно сообщает, что токен контура не выдан
- **THEN** показано «Не выдан» без сгенерированного значения

#### Scenario: Metadata failure

- **WHEN** запрос сведений завершился ошибкой
- **THEN** показаны ошибка и повтор, а не «Не выдан»

### Requirement: Controlled disclosure and rotation

Раскрытие и перевыпуск SHALL следовать согласованным серверным правилам. Перед перевыпуском UI SHALL объяснять последствия для старого токена и требовать подтверждение. Ошибка или неизвестный исход MUST NOT выдавать фиктивный секрет или автоматически инициировать новый перевыпуск.

#### Scenario: Cancel rotation

- **WHEN** пользователь отменяет подтверждение перевыпуска
- **THEN** серверная операция не отправляется и состояние токена не изменяется клиентом

#### Scenario: Rotation response lost

- **WHEN** ответ перевыпуска потерян
- **THEN** UI показывает неизвестный исход и восстанавливает состояние по согласованному протоколу вместо повторного выпуска

### Requirement: Secret-safe sandbox integration

Переход в песочницу SHALL передавать только skill ID без секрета в URL. Карточка и песочница SHALL одинаково интерпретировать серверную модель токенов. Раскрытый секрет MUST NOT попадать в постоянное браузерное хранилище, обычный persistent cache, логи или сообщения ошибок и SHALL очищаться при закрытии раскрытия/смене навыка.

#### Scenario: Navigate to sandbox

- **WHEN** пользователь переходит в песочницу из карточки
- **THEN** URL содержит идентификатор навыка, не токен, а песочница получает нужные сведения через согласованный API

#### Scenario: Close disclosed token

- **WHEN** пользователь закрывает раскрытый секрет или выбирает другой навык
- **THEN** секрет больше не отображается и не сохраняется для восстановления из постоянного хранилища
