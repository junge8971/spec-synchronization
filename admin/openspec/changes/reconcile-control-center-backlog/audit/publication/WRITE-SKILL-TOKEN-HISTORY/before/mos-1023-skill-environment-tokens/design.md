## Context

См. proposal.md. SkillConnectionSchema знает только признак/тип transport_token. Прототип показывает токены по контурам, но не определяет безопасный протокол обращения с секретом.

## Goals / Non-Goals

**Goals:** метаданные и ограниченное по контракту раскрытие секрета без утечки при навигации.

**Non-Goals:** авторизация посетителя, auth bootstrap, сохранение секрета как текстового поля анкеты.

## Decisions

- **BLOCKED API/security:** согласовать контуры, metadata DTO, состояния, сроки/область, раскрытие (включая одноразовость), перевыпуск/отзыв, ошибки и подтверждение последствий. Пока правил нет, операции с секретом не реализовывать.
- Метаданные могут находиться в обычном Query cache; раскрытый секрет не класть в общий persistent cache, URL, localStorage, логи или telemetry. Держать только во временном состоянии соответствующего UI, очищать при закрытии/смене навыка. Точные время и способ раскрытия определяет контракт.
- Карточка и песочница используют одну предметную модель/API из entities/skill, а не копии токенов. Переход передаёт только skill ID; песочница получает нужные данные самостоятельно через согласованный API.
- «Не выдан» — положительное утверждение из ответа. Ошибка, неизвестное состояние и отсутствие операции в контракте имеют отдельное отображение.
- Перевыпуск — явное подтверждение с последствиями для старого токена; никакого optimistic success и автоматического повторного выпуска после timeout.

## Risks / Trade-offs

- Логирование тела ошибки может раскрыть секрет → показывать безопасные сообщения, тестировать отсутствие секрета в URL и хранилище.
- Перевыпуск принят, ответ потерян → восстановление по согласованному протоколу, не второй выпуск.

## Migration Plan

После gate интегрировать metadata, затем согласованные операции и приёмник skill ID в песочнице. Изменение общего диалогового движка не требуется. Откат UI не восстанавливает отозванные токены; оператору нельзя обещать обратимость.
