## Why

[Jira MOS-1257](https://task.mos-team.ru/browse/MOS-1257): [FE][Обратная связь] Реализовать ввод тегов, сегментов и групп операторов.

Нужна отдельная реализуемая поставка этой FE-подзадачи по обновлённому API и принятой границе прототипа. План, приёмка и выполнение учитываются отдельно от остальных задач MOS-1246.

## What Changes

- Chips tags/segments/operator_groups внутри карточки, строковая сериализация и канонические имена backend. Отдельных реестров и глобального CRUD меток нет.
- Сохранить ограничения API, ввод при ошибках, доступность и действующую безопасность.

### Deferred scope

Отдельные CRUD/реестры тегов, сегментов и групп, а также общий редактор справочников не входят.

## Capabilities

### New Capabilities

- `feedback-labels`: Chips tags/segments/operator_groups внутри карточки, строковая сериализация и канонические имена backend. Отдельных реестров и глобального CRUD меток нет.

### Modified Capabilities

Нет. Общие capabilities HTTP, permissions и MPMM сохраняются; scope соседних FE-подзадач сюда не переносится.

## Impact

Приватные chip-вводы редактора, разбор и сериализация строк меток.

Зависимости: [MOS-1251](../mos-1251-feedback-editor/proposal.md)

Зависимость от MOS-1251 — только foundation draft/editor (его tasks 1.1–1.4), не закрытие всего change. После этой задачи MOS-1251 выполняет общую композицию.

Граница: UI по прототипу, операции по API, неподдержанное отложено. Исполнение правил и сбор реальных ответов пользователей не входят. Новые зависимости не требуются без отдельного обоснования. Это planning change: код приложения и Jira при разделении не меняются.
