## Why

[MOS-1026](https://task.mos-team.ru/browse/MOS-1026): в карточке навыка нужны ответственные, внешние зависимости и инциденты. Локальный контракт уже содержит чтение этих сведений, но интерфейс пока показывает только показатели мониторинга.

## What Changes

- Дополнить вкладку «Мониторинг» блоками по предоставленному пользователем прототипу `/home/user/Загрузки/Прототип. Центр управления.html`: ответственные и плановые работы рядом с показателями, ниже — таблицы зависимостей и инцидентов.
- Показывать доступные контакты, состояние зависимостей и серверные инциденты только для чтения. Для стороны устранения использовать `side`; нормативы уровней P0–P3 — из прототипа, не как срок, рассчитанный сервером.
- Использовать опубликованные GET ответственных, мониторинга и инцидентов; дополнить существующие локальные моки демонстрационными ответами и покрыть основные состояния тестами.
- Показывать внешний ID инцидента. Опубликованный DTO не содержит URL: ссылку не выдумывать; подключение URL при появлении согласованного контракта остаётся ограничением.
- Не добавлять редактирование ответственных, подтверждение уведомлений, редактирование postmortem или управление внешней системой.

## Capabilities

### New Capabilities

- `skill-operations-info`: read-only эксплуатационные сведения и инциденты навыка.

### Modified Capabilities

Нет.

## Impact

- `app/widgets/skill-details/`, `app/entities/skill/`, существующие Express-моки и unit/component-тесты; мониторинг MOS-1025 переиспользуется без дублирования GET.
- Контракт: `docs/api/contracts/openapi.json`, снимок от 02.11.2026. GET `/skills/v1/skills/{skill_id}/responsibles`, `/monitoring` и `/incidents` доступны в локальной схеме; актуальность и работа на контуре не проверены. Для реализации описанных блоков новый API не требуется.
- Ссылка на внешний инцидент, плановый срок устранения и отдельное состояние подключения источника отсутствуют в DTO. Норматив из прототипа не является датой устранения; пустой ответ не доказывает, что источник подключён и инцидентов никогда не было.
- Не выводить ответственных из состава команды и не подменять назначение основным contact анкеты. Данные моков не подтверждают реальную интеграцию. Browser/E2E-проверки — только с отдельного явного разрешения пользователя.
