## Why

MOS-1041: `/dialogs/:dialogId` сейчас показывает заглушку, а разбор обращения требует переписки, участников и вложений. Новый PDF задаёт единый ответ карточки и состояния отказов вместо недостающих моделей старого контракта.

## What Changes

- Карточка по chat_id: общая информация, переписка, участники, пользователь и несколько операторов.
- Единая загрузка данных для карточки и будущих вкладок MOS-1042/MOS-1043; независимое открытие по прямой ссылке.
- Показ вложений и защищённая работа с binary-содержимым по режимам view/download без автоматического скачивания.
- Крошки с topic и fallback «Диалог <chat_id>» после загрузки; сохранение basename.
- Применение нового состава счётчиков: total/to_skill/to_operator, без вымышленного «без адресата».

## Capabilities

### New Capabilities

- `dialog-details`: единая карточка, переписка, участники и содержимое вложений.

### Modified Capabilities

- `control-center-shell`: готовая карточка диалога вместо future placeholder и предметная подпись её крошек.

## Impact

- `app/routes/dialog-details.tsx`, `app/pages/dialog-details/ui/dialog-details-page.tsx`, владелец крошек; новый detail API в `entities/dialog` и композиция карточки.
- Целевые методы относительно `/api/control/api/dialogs/v1`: `GET /dialogs/{chat_id}`, `GET /dialogs/{chat_id}/attachments/{attachment_id}/content?mode=view|download`.
- Источники: MOS-1041; `/home/user/Загрузки/Прототип. Центр управления.html`; PDF `/home/user/Загрузки/241085439_bf1810bba3974ef1b9dbac2d3a41d66b-051026-1642-740.pdf`, v1.0, 2.3, 2.5, 3.5, 3.7, 7–8.
- **GATE:** согласовать бизнес-контракт, chat_id, источник вложений, режимы безопасного просмотра; общую публикацию типов координировать с MOS-1037. В проекте HTTP-клиент пока читает JSON, а карточка навыка адресуется UUID, не service_id из диалога.
- MOS-1042 владеет представлением оценок/оснований, MOS-1043 — маршрутом, MOS-1044 — изменением категорий, MOS-1045 — экспортом. Эта задача предоставляет им данные, но не подменяет их реализацию.
