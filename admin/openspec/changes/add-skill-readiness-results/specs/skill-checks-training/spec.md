## MODIFIED Requirements

### Requirement: Server-owned current processing status

UI SHALL показывать текущий этап из опубликованного SkillResponse.status и возвращённые сохранённые результаты checks отдельно от этапа процесса. Статусы checking/training/autotest SHALL отображаться как проверка, обучение и автотесты с теми же подписями, что в существующей карточке. Этап SHALL различаться текстом, а не только цветом. Локальное время MUST NOT менять статус, объявлять предыдущие этапы успешными или создавать проценты, ETA, run ID, логи и ошибки процесса.

UI SHALL показывать check_type, status, blocking, message и checked_at для возвращённых проверок в опубликованном порядке anketa, phrases, exact_conflicts, semantic_conflicts, endpoint. Статусы passed, failed, warning, blocked и признак блокировки SHALL различаться текстом, не только цветом. passed имеет blocking=false и message=null; только blocked имеет blocking=true; failed и warning SHALL отображаться как неблокирующие результаты с серверным корректирующим сообщением, а не как техническая ошибка процесса. UI MUST NOT вычислять результаты, вводить ранги статусов или подменять отсутствующие результаты успешными. Пустой checks SHALL обозначать отсутствие вычисленных результатов.

Успешное чтение SHALL обновлять сохранённые результаты даже при неизменных version и updated_at. Результаты SHALL относиться к последнему успешному чтению данного skill ID, а не гарантировать актуальность всех открытых карточек в реальном времени. Обновление результатов MUST NOT сбрасывать несохранённый ввод или менять версию, относительно которой пользователь начал редактирование.

#### Scenario: Server changes processing stage

- **WHEN** очередное чтение возвращает training вместо checking
- **THEN** карточка показывает обучение без объявления проверки успешной и без выдуманных результатов пропущенных этапов

#### Scenario: Server status does not change

- **WHEN** повторные чтения продолжают возвращать training
- **THEN** UI сохраняет этот этап без локального завершения, процентов, ETA или ошибки по истечении времени

#### Scenario: Persisted results are displayed

- **WHEN** чтение возвращает пять сохранённых проверок
- **THEN** UI показывает их в порядке anketa, phrases, exact_conflicts, semantic_conflicts, endpoint с текстовыми статусами, блокировкой, серверными сообщениями и checked_at, не выводя успех из текущего этапа

#### Scenario: Empty uncomputed results

- **WHEN** сервер возвращает checks=[]
- **THEN** UI сообщает, что результаты не вычислены, и не показывает пять успешных проверок

#### Scenario: Failed and warning are nonblocking

- **WHEN** возвращены failed или warning с blocking=false и корректирующим message, а также blocked с blocking=true
- **THEN** UI показывает первые результаты как неблокирующие, последний как блокирующий, сохраняет сообщения и не объявляет технический сбой обучения или право запуска команды

#### Scenario: Fresh checks with unchanged record version

- **WHEN** успешное чтение того же навыка возвращает изменённые checks или checked_at при прежних version и updated_at во время редактирования
- **THEN** UI обновляет результаты, сохраняет несохранённый ввод и исходную версию редактора, не объявляя текущий ввод проверенным

### Requirement: Read failure is not process failure

Ошибка получения обновлений SHALL отображаться как ошибка чтения, а не обучения или автотестов. При наличии ранее загруженной карточки UI SHALL помечать показанный этап и сохранённые результаты проверок как последние загруженные данные, приостанавливать периодическое чтение и предоставлять ручной повтор. Успешное чтение SHALL возобновлять наблюдение только при checking/training/autotest. Без ранее полученных данных SHALL сохраняться штатное состояние ошибки загрузки. Повтор SHALL выполнять только GET, без запуска проверок или повторной отправки мутации; ошибка чтения MUST NOT заменять сохранённые результаты на passed или failed.

#### Scenario: Update request failure

- **WHEN** чтение очередного обновления завершается ошибкой после ранее полученного training
- **THEN** UI показывает последние данные с ошибкой обновления и повтором, не объявляет обучение проваленным и приостанавливает polling

#### Scenario: Successful retry

- **WHEN** ручной повтор успешно возвращает training либо sandbox
- **THEN** ошибка чтения снимается; для training автообновление возобновляется, для sandbox остаётся выключенным

#### Scenario: Stale results and read-only recovery

- **WHEN** очередное чтение не удаётся после успешной загрузки checks и пользователь повторяет чтение
- **THEN** до успеха сохраняются последние результаты с признаком устаревших данных и ошибкой чтения; повтор отправляет только GET, не пересчитывает проверки, не повторяет запись и не сбрасывает несохранённый ввод

### Requirement: Status observation does not establish readiness

UI SHALL ограничиваться наблюдением за status и возвращёнными сохранёнными checks. UI MUST NOT считать status подтверждением результатов отдельных проверок, а status или checks — подтверждением обработки текущей версии фраз или доступности песочницы. Идентификаторы запусков, привязка к обработанному вводу, полноценные результаты и технические ошибки процесса, повторный запуск с правилами состояния и прав и готовность песочницы SHALL оставаться недоступными до отдельного согласования API и области работ; существующие команды MOS-909 сохраняются без расширения. GET и восстановление чтения MUST NOT описываться как запуск или повтор проверки. Сохранённые checks MUST NOT подменяться результатом однократного preflight фразы.

#### Scenario: Sandbox status without readiness API

- **WHEN** сервер возвращает sandbox без данных о проверках и обработанной версии
- **THEN** UI показывает этот текущий статус и прекращает polling, но не объявляет все проверки успешными, не разрешает песочницу на основании одного status и не создаёт токен

#### Scenario: Passed checks do not prove applied input or sandbox readiness

- **WHEN** все возвращённые проверки имеют passed, включая endpoint
- **THEN** UI показывает сохранённые результаты, но не объявляет текущие редактируемые фразы обученными, сервис доступным или песочницу готовой и не предлагает новый повторный запуск
