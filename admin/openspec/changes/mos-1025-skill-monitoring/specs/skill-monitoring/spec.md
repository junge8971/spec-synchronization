## Purpose

Показывать фактическое состояние конкретного навыка, соблюдение регламента и свежесть внешних данных без подмены отсутствующих измерений.

## Delivery stages

Этап 26.10.2026 согласован как read-only отображение опубликованного снимка MOS-1397. Требования Per-skill monitoring and thresholds, Separate freshness timestamps и Monitoring data availability ниже остаются целевыми: неподдержанные API части не закрываются текущим этапом. Нельзя объявить всю MOS-1025 завершённой.

## ADDED Requirements

### Requirement: Published monitoring snapshot

UI SHALL читать мониторинг выбранного skill ID независимо от анкеты и показывать доступность и хорошие оценки в процентах, время ответа в секундах, давность данных в днях, сохранённые пороги и серверные отклонения. UI MUST NOT вычислять собственные отклонения, период или минимальную выборку. Источник SHALL отображаться текстом в строке сведений; для `mock` SHALL сохраняться пояснение, что это не реальные измерения. По уточнению пользователя от 27.10.2026 отдельный бейдж «Демонстрационные данные» MUST NOT отображаться. `observed_at` SHALL обозначаться как время снимка с часовым поясом, не как дата обновления внешних данных или последнего обращения. Недоступные API сведения о периоде, выборке и отдельных датах MUST NOT подменяться вымышленными значениями. По запросу пользователя поясняющий абзац об этих ограничениях MUST NOT отображаться; ограничения сохраняются в документации и открытых задачах.

#### Scenario: Demonstrative snapshot

- **WHEN** сервер возвращает source=mock и показатели выбранного навыка
- **THEN** UI показывает источник в строке сведений, значения, единицы и время снимка UTC, без отдельного demo-бейджа и абзаца об ограничениях API

#### Scenario: Boundary and deviations

- **WHEN** сервер возвращает evaluated и отклонения, в том числе пустой список при равенстве порогу
- **THEN** UI следует серверной оценке без пересчёта по округлённым значениям; нарушения обозначены текстом, фактом, порогом и величиной отклонения

### Requirement: Published snapshot states and isolation

UI SHALL различать not_configured, maintenance, no_data и evaluated; положительная оценка допустима только для evaluated. settings=null SHALL означать отсутствие настроенных порогов, metrics=null — отсутствие показателей, а 0 SHALL оставаться числовым нулём. Loading/error/retry SHALL относиться только к мониторингу; retry SHALL выполнять новый GET. HTTP error MUST NOT превращаться в «не настроен». Смена skill ID MUST NOT показывать предыдущий снимок. UI MUST NOT отправлять PUT настроек и изменять несохранённую анкету.

#### Scenario: Maintenance and absent settings

- **WHEN** ответ сообщает maintenance либо not_configured
- **THEN** показано приостановление оценки с окном обслуживания либо отсутствие настройки, без ложной нормы и без заявления отсутствия подключения

#### Scenario: Missing metrics and zero

- **WHEN** metrics=null либо содержит нулевой показатель
- **THEN** UI соответственно показывает отсутствие данных либо измеренный ноль, не смешивая состояния

#### Scenario: Failure and identity change

- **WHEN** мониторинг отвечает ошибкой, пользователь повторяет запрос или выбирает другой навык
- **THEN** анкета остаётся доступна, повтор делает новый запрос, данные прежнего навыка не подставляются

### Requirement: Per-skill monitoring and thresholds

При наличии согласованного API UI SHALL показывать фактические значения доступности, времени ответа и качества оценок вместе с единицами, периодом и порогами. Нарушения SHALL определяться по согласованным правилам сравнения и достаточности выборки; агрегаты дашборда MUST NOT заменять per-skill данные.

#### Scenario: Threshold violation

- **WHEN** серверные измерения и достаточная выборка подтверждают нарушение регламента
- **THEN** показаны показатель, значение, порог и нарушение в сопоставимых единицах

#### Scenario: Threshold boundary

- **WHEN** значение равно порогу
- **THEN** состояние соответствует согласованному знаку сравнения, а не результату округления для отображения

### Requirement: Separate freshness timestamps

UI SHALL различать обновление анкеты, обновление внешних данных и последнее обращение к навыку. Отсутствующая дата MUST NOT заменяться updated_at анкеты или текущим временем.

#### Scenario: Recently edited stale data

- **WHEN** анкета изменена сегодня, но внешние данные обновлялись ранее
- **THEN** свежесть отражает дату внешних данных, независимо от даты изменения анкеты

### Requirement: Monitoring data availability

UI SHALL различать unavailable API, серверное «не подключён», недостаточную выборку, null, реальный ноль и ошибку запроса. Ошибка мониторинга MUST NOT скрывать анкету; повтор SHALL заново запрашивать данные.

#### Scenario: Not connected

- **WHEN** сервер явно сообщает отсутствие подключения к мониторингу
- **THEN** UI показывает это состояние без вымышленных измерений

#### Scenario: Missing and zero measurements

- **WHEN** один показатель равен null, а другой равен 0
- **THEN** первый показан как отсутствие данных, второй — как измеренный ноль

#### Scenario: Insufficient sample or failure

- **WHEN** выборки недостаточно либо чтение завершилось ошибкой
- **THEN** UI соответственно объясняет недостаточность либо предлагает повтор и не объявляет качество нормальным
