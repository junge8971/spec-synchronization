## Why

MOS-1025 требует мониторинга конкретного навыка. GET мониторинга опубликован на T, но пока возвращает демонстрационный снимок и не покрывает все целевые требования.

## What Changes

- Согласованный пользователем этап от 26.10.2026: read-only вкладка мониторинга по опубликованному GET, показатели, сохранённые пороги и серверные отклонения.
- Источник `source=mock` в строке сведений, время снимка, состояния not_configured/maintenance/no_data/evaluated, loading/error/retry. По запросу от 27.10.2026 убрать отдельный demo-бейдж и абзац об ограничениях API, расширить фиксированные локальные снимки для исходных навыков.
- Недоступные период, минимальная выборка, дата внешних данных и последнее обращение не выдумываются; целевые требования остаются открытыми.
- Без PUT настроек, зависимостей/инцидентов MOS-1026, аналитики MOS-1030, новых permissions или зависимостей пакетов.

## Capabilities

### New Capabilities

- `skill-monitoring`: поэтапное подключение достоверно подписанного read-only мониторинга навыка.

### Modified Capabilities

Нет.

## Impact

`app/entities/skill/`, `app/widgets/skill-details/`, существующие Express mocks и тесты. GET и типы уже присутствуют в сохранённом контракте 26.10.2026. Используются штатные transport, query и UI.

Чтение Swagger не доказывает работу бизнес-API. Реализация текущего этапа не закрывает всю MOS-1025. Проверки unit/component/HTTP; browser/E2E — только при отдельном явном разрешении по AGENTS.md.
