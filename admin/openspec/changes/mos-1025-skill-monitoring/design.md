## Context

См. proposal.md. Пользователь согласовал реализацию доступной read-only части с сохранением открытых требований. Источники, прочитанные 26.10.2026:

- [Swagger T](https://nchat-t-tech.mos.ru/api/control/docs), [OpenAPI](https://nchat-t-tech.mos.ru/api/control/openapi.json).
- [MOS-1397](https://task.mos-team.ru/browse/MOS-1397): provider сейчас mock, фиксированные снимки и правила отклонений.
- [MOS-1025](https://task.mos-team.ru/browse/MOS-1025): целевые требования.
- [Контракт навыков](https://wiki.mos-team.ru/spaces/KR/pages/241097511): общий формат дат RFC3339; не описывает новый мониторинг.

GET `/api/control/api/skills/v1/skills/{skill_id}/monitoring` уже входит в aggregate/split/generated контракт проекта. PUT остаётся вне этапа. Источник live пока mock; это не клиентский fallback и не доказательство реального мониторинга.

## Goals / Non-Goals

**Goals:** отдельное чтение по skill ID; понятное происхождение показателей и состояний; независимость ошибки мониторинга от анкеты.

**Non-Goals:** настройка порогов, расчёт метрик или отклонений на frontend, зависимости и инциденты, синтез дат/периода/выборки, новые auth-механизмы.

## Decisions

### Семантика принятого этапа

| Поле                                          | Представление и правило                                                                                                                |
| --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| availability / threshold_availability         | Проценты; нарушение при факте ниже порога                                                                                              |
| rating / threshold_rating                     | Хорошие оценки, проценты; нарушение при факте ниже порога                                                                              |
| response_seconds / threshold_response_seconds | Секунды; нарушение при факте выше порога                                                                                               |
| data_age_days / threshold_data_age_days       | Дни; нарушение при факте выше порога, не timestamp                                                                                     |
| deviations                                    | Серверные code/actual/threshold/difference/unit; frontend не пересчитывает. Равенство порогу не нарушение                              |
| source                                        | Источник показывается в строке сведений; mock поясняется как нереальные измерения. Отдельный demo-бейдж удалён по запросу пользователя |
| observed_at                                   | Только «Время снимка», отображение UTC с подписью часового пояса; не дата внешних данных или последнего вызова                         |
| settings=null                                 | Пороги не настроены, не «не подключён»                                                                                                 |
| metrics=null                                  | Нет данных, не нули; отдельные числовые поля не nullable по текущему DTO                                                               |
| not_configured                                | «Мониторинг не настроен», нет оценки нормы                                                                                             |
| maintenance                                   | «Технические работы: оценка приостановлена», сохранённое окно и причина; отклонения подавлены backend                                  |
| no_data                                       | «Нет данных для оценки», без положительного статуса                                                                                    |
| evaluated                                     | Серверная оценка; текст «Нарушение» / «Без нарушения» только здесь                                                                     |
| Период/выборка                                | API не предоставляет. Значения не выдумывать; поясняющий абзац в UI удалён по запросу пользователя                                     |

Отдельные query/client внутри entities/skill используют существующий transport, AbortSignal и ключ с skill ID. Вкладка в widget не меняет анкету, не запускает мутации и не зависит от MOS-1026/MOS-1030. Ошибка, включая 403/404/501, не трактуется как not_configured. Retry повторно выполняет GET. Данные предыдущей skill ID не используются как placeholder.

Использовать существующие Card/Badge/Button без chart-библиотеки. Визуальная правка по скриншотам пользователя от 27.10.2026: три компактные карточки (доступность, время ответа, хорошие оценки), отдельный список серверных отклонений и строки давности данных/времени снимка/источника/обслуживания. При недостаточной ширине контейнера карточки и строки перестраиваются в одну колонку. Дробные значения форматируются по ru-RU без пересчёта серверных оценок; строка источника сохраняется, отдельный demo-бейдж и поясняющий абзац об отсутствующих API данных удалены по последующему запросу пользователя. Соседние блоки ответственных, зависимостей, инцидентов и аналитики из референсов не добавляются. Проверять DTO на границе; неизвестные состояния/коды и неверные даты дают ошибку, а не ложную норму. Dependencies из ответа не выводятся в текущем этапе.

Express получает отдельный GET handler с воспроизводимыми credential-free fixtures. По уточнению 27.10.2026 исходные навыки имеют нормальный снимок по умолчанию, а фиксированные ID-привязанные варианты покрывают нарушения («Отопление»), давность 74/30 дней («Вода»), техработы («Парковки»), no_data («Домашнее задание») и not_configured («Болталка»). Новые навыки остаются not_configured. Перестановка списка не меняет снимок навыка; настройки получают отдельный устойчивый UUID для каждого навыка. Существующий механизм сценариев 403/500/delay сохраняется. Настройки не создаются при чтении; PUT остаётся 501. Фикстуры не подтверждают backend-приёмку.

### Открытые целевые требования — не блокируют согласованный этап

Период измерений/часовой пояс периода, минимальная выборка и её недостаточность, отдельные dataUpdatedAt/lastCallAt, серверное состояние отсутствия подключения и nullable отдельных метрик пока не согласованы. Они остаются отдельными незавершёнными задачами; нельзя объявить MOS-1025 выполненной или архивировать change по результатам этого этапа.

## Risks / Trade-offs

- Mock-источник принимают за реальный → строка источника с пояснением происхождения показателей.
- Время снимка принимают за свежесть внешних данных → раздельная подпись и объяснение отсутствующих дат; никаких вычисленных дат из data_age_days.
- Пустой deviations принимают за норму во время обслуживания → положительный статус только при evaluated.
- Проверки браузером: CLI context требует локальный Playwright, но AGENTS.md и прежние tasks запрещают browser/E2E без отдельного разрешения. До такого разрешения выполнять unit/component/HTTP, browser-проверку оставить открытой; инструкции проекта не менять.

## Migration Plan

Подключить существующий GET и новую вкладку, заменить устаревшее сообщение обзора о полном отсутствии API на указание вкладки и её ограничений. Откат UI не изменяет настройки backend. Запустить unit/component/HTTP и quality checks; реальную интеграцию и browser-приёмку не заявлять.
