# Spec Delta

## MODIFIED Requirements

### Requirement: Registration and existing surface persistence

Регистрация SHALL включать проверенный `enabled_skills` в существующий POST создания поверхности и сохранять действующее требование хотя бы одного сценария. Остальные поля и результат регистрации SHALL соответствовать `surface-registration`: запись не включает приветствие, не зависит от поиска занятости доменов и подтверждается свежим GET карточки после POST. Карточка SHALL инициализировать редактор из GET поверхности и сохранять состав отдельным `PUT /api/control/api/surfaces/v1/surfaces/{surface_id}/enabled-skills`; пустой состав при редактировании SHALL допускаться по контракту. Запрос MUST NOT менять оформление через `/configuration`. Успех SHALL отображаться только после успешного ответа; для регистрации итоговый результат SHALL подтверждаться чтением созданной карточки. Повторное открытие SHALL показывать сохранённые данные. Сетевые ошибки, включая 422, SHALL отображаться без сброса черновика и без фиктивного успеха. Для регистрации повтор POST SHALL допускаться только после подтверждённого отказа согласно `surface-registration`; при неизвестном результате POST повтор создания SHALL блокироваться, при известном ID повтор SHALL выполнять только GET. Правила повторов PUT в карточке этим изменением не меняются.

#### Scenario: Create surface with configured skills

- **WHEN** завершена валидная регистрация с двумя навыками
- **THEN** POST создания содержит оба skill_id с их параметрами, а результат регистрации подтверждается новым GET карточки полученного ID

#### Scenario: Edit and clear existing surface

- **WHEN** пользователь снимает все навыки существующей поверхности и сохраняет
- **THEN** PUT enabled-skills содержит пустой массив, оформление не отправляется и после успешного ответа повторное открытие показывает пустой состав

#### Scenario: Save rejected

- **WHEN** сервер отклоняет сохранение в карточке или подтверждённо отклоняет создание контрактным ответом 422
- **THEN** пользователь видит ошибку, введённые параметры остаются и доступен повтор без двойной параллельной отправки

#### Scenario: Creation response is lost

- **WHEN** результат POST регистрации неизвестен
- **THEN** выбранные навыки и параметры сохранены, повтор создания блокируется, успешное сохранение не заявляется

#### Scenario: Creation succeeded but read failed

- **WHEN** POST регистрации вернул ID, а подтверждающий GET завершился ошибкой
- **THEN** параметры остаются видимыми и повтор выполняет только GET полученного ID без POST или PUT
