## Context

См. `proposal.md`: имя Jira-задачи не означает, что отсутствующий API можно реализовать предположительно. `shared/api/http-client.ts` принимает JSON и проверяет envelope; ни API экспорта, ни общего файлового клиента сейчас нет. HTML генерирует CSV из демодиалогов — это не эквивалент полной серверной выборки.

Design фиксирует неоднозначную границу между доступным UI и отложенной транспортной реализацией, чтобы apply не создал speculative инфраструктуру.

## Goals / Non-Goals

**Goals:** одно понятное недоступное действие в готовом конструкторе, отсутствие побочных эффектов при попытке выгрузки.

**Non-Goals:** Blob transport, CSV encoder, файл из preview, endpoint export, MIME/filename parser, экспорт шаблона, строка на сообщение и ids. Общий JSON-клиент не трогаем.

## Decisions

### 1. Минимальное представление ограничения

В блок параметров `widgets/report-constructor` добавить существующую UI-кнопку «Сформировать выгрузку» с disabled и поясняющим текстом рядом. Не создавать feature с одним disabled-действием, capability service или флаг из environment. Текст связывается с действием доступным описанием и остаётся читаемым без hover.

Альтернатива скрыть действие полностью не объясняет отличие от прототипа; активная кнопка с ошибкой после клика создаёт ложное ожидание.

### 2. Отсутствие пути выполнения

В текущем scope нет handler экспорта и download helper. Действие не является submit формы. Штатный локальный обработчик формы не отправляет отчёт при Enter; проверка охватывает и этот путь. Валидность периода/полей не меняет disabled: это техническая недоступность операции, не бизнес-валидация черновика.

### 3. Проверки без браузера

Component-тест подтверждает доступное пояснение и disabled как на валидной, так и на невалидной форме. Попытки клика/Enter не должны создавать report HTTP, object URL, download или success-сообщение; разрешённые запросы справочников не запрещаем. Тест не подменяет экспорт endpoint, которого ещё нет.

## Risks / Trade-offs

- [PR не предоставляет скачивание] → явно принимать только unavailable UI; MOS-919 как серверная функция остаётся заблокированной.
- [Заранее реализованный общий транспорт окажется несовместим с API] → не создавать его до подтверждения response/ошибок/заголовков.

## Migration Plan

Самостоятельный небольшой PR после MOS-1015, без зависимостей от MOS-916/MOS-1016. Откат удаляет добавленное действие и тесты; серверных изменений нет.

Для будущего расширения сначала согласовать request/response, MIME, Content-Disposition/доступность заголовка, ограничения экспорта и ошибки. Затем расширить существующий транспорт ровно для подтверждённого формата. Критерии полной MOS-919: одинаковые с preview период/поверхность/условия/порядок колонок; вся выборка; UTF-8 BOM и `;`; корректное имя, null, кавычки и переносы; JSON/HTML-ошибка не сохраняется как CSV. Неизвестные лимиты и форматы сейчас не назначаются.

### Критерии заблокированного продолжения MOS-919

Критерии описывают будущую приёмку, а не активируют серверную функцию в текущей spec. Endpoint, DTO, лимиты, имя/заголовки и механизм получения файла требуют контракта до реализации.

- **B919.1 — Выборка:** экспорт передаёт согласованные период/режим периода, поверхность, условия и выбранные колонки в их порядке; при одинаковых параметрах его выборка совпадает с серверным preview. Выгружается полная выборка, а не ограниченные строки preview/загруженной страницы, основной формат — одна запись на диалог. Проверка: данных больше лимита preview, изменённый AND/OR/диапазон/область фразы и несколько колонок в нестандартном порядке. Смена параметров после preview не позволяет без предупреждения выдать старую выборку за новую; способ обновления/маркировки stale согласуется с MOS-1015. Поведение пустой выборки и «За всё время» подтверждается контрактом, не угадывается.
- **B919.2 — Файл:** скачивается серверный CSV с UTF-8 BOM, разделителем `;`, заголовками и колонками в выбранном порядке, корректным именем согласно согласованному ответу/правилу именования. Проверка: байты BOM, разделитель, порядок заголовков/ячеек и имя с кириллицей; браузер не пересобирает файл из preview и не дублирует BOM. Источник имени и доступность заголовка при CORS согласуются заранее; статическое демоимя не назначается серверным контрактом.
- **B919.3 — Значения:** null представлен пустым значением, но 0 не теряется; кириллица, кавычки, разделитель внутри ячейки и переносы строк сохраняются корректно. Проверка: эталонный серверный файл с этими значениями разбирается в нужные записи/колонки; перенос внутри текста не превращает один диалог в несколько записей. Клиент сохраняет серверные байты, не лечит некорректную CSV-схему самодельным сериализатором.
- **B919.4 — Ошибки и результат:** non-2xx, JSON-ошибка, HTML-ошибка и некорректный успешный ответ не скачиваются под видом CSV; показывается ошибка без успеха и без потери настроек. Проверка: ошибка вместо файла, сеть/отмена и ограничения размера по будущему контракту; реальное выполнение имеет понятное pending-состояние и не порождает случайные параллельные выгрузки повторным нажатием. Точные коды и пределы не выдумываются. Для принятого файла ресурсы скачивания освобождаются после использования.

Экспорт строк на сообщение, selected ids и параметры в конце CSV из сценария выгрузки диалогов не добавляются сюда: эти действия не нужны для завершения MOS-919. Общая транспортная часть появится только вместе с подтверждённым файловым ответом.
