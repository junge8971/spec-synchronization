## Why

[Jira MOS-1256](https://task.mos-team.ru/browse/MOS-1256): [FE][Обратная связь] Реализовать смену статуса и удаление опросника.

Нужна отдельная реализуемая поставка этой FE-подзадачи по обновлённому API и принятой границе прототипа. План, приёмка и выполнение учитываются отдельно от остальных задач MOS-1246.

## What Changes

- PUT draft/active/paused/disabled, подтверждение выключения и soft-delete, dirty-защита и обновление server state.
- Сохранить ограничения API, ввод при ошибках, доступность и действующую безопасность.

- Подтверждать выключение во всех путях смены статуса; отмена сохраняет draft, успех не отправляет дублирующий PUT.

### Deferred scope

Статус archived не используется: контрактный код — disabled. Восстановления удалённого опросника в API нет.

## Capabilities

### New Capabilities

- `feedback-lifecycle`: PUT draft/active/paused/disabled, подтверждение выключения и soft-delete, dirty-защита и обновление server state.

### Modified Capabilities

Нет. Общие capabilities HTTP, permissions и MPMM сохраняются; scope соседних FE-подзадач сюда не переносится.

## Impact

Действия карточки/реестра и инвалидирование запросов через entity.

Зависимости: [MOS-1250](../mos-1250-feedback-registry/proposal.md); [MOS-1251](../mos-1251-feedback-editor/proposal.md)

Граница: UI по прототипу, операции по API, неподдержанное отложено. Исполнение правил и сбор реальных ответов пользователей не входят. Новые зависимости не требуются без отдельного обоснования. Это planning change: код приложения и Jira при разделении не меняются.
