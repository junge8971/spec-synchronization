## Purpose

Реализовать смену статуса и удаление опросника в разделе обратной связи ЦАМ по опубликованному API, с отдельной приёмкой и сохранением ограничений первого этапа.

## ADDED Requirements

### Requirement: Status changes and deletion

Статус SHALL меняться PUT полем status с кодами draft/active/paused/disabled из lookup. Выключение SHALL использовать disabled, не archived. Выключенная запись SHALL оставаться доступной в CRUD. Выключение и удаление SHALL требовать подтверждения; dirty draft SHALL до отдельной операции быть явно сохранён либо операция отменена. Успех SHALL обновлять detail, реестр и счётчики по серверному результату. DELETE SHALL трактоваться как soft-delete без восстановления в данном API; код остаётся занят. 404 повторного удаления MUST NOT скрываться как подтверждённый успех текущего запроса.

Переход сохранённого опросника из любого другого статуса в disabled SHALL требовать подтверждения и через отдельную кнопку, и через выбор статуса с «Сохранить». При отмене запрос MUST NOT отправляться, draft SHALL сохраняться. При обычном сохранении подтверждение SHALL охватывать один PUT со статусом и остальными изменёнными полями; повторный PUT статуса MUST NOT отправляться. Повторное сохранение уже disabled без смены статуса MUST NOT требовать подтверждения выключения.

#### Scenario: Disable versus delete

- **WHEN** опросник выключен через PUT status=disabled
- **THEN** запись остаётся доступна; только отдельный подтверждённый DELETE удаляет её из реестра и приводит к 404 detail/export

#### Scenario: Dirty card lifecycle action

- **WHEN** пользователь вызывает смену статуса при несохранённых изменениях
- **THEN** UI предлагает сохранить их перед операцией либо отменить действие; ошибки не уничтожают draft

#### Scenario: Disable through ordinary form save

- **WHEN** пользователь меняет active на disabled в поле статуса, правит описание и нажимает «Сохранить»
- **THEN** показано подтверждение выключения; отмена сохраняет draft без запроса, согласие отправляет один PUT с обоими изменениями

#### Scenario: Edit an already disabled survey

- **WHEN** исходный статус disabled не меняется, изменено только описание
- **THEN** обычное сохранение не требует нового подтверждения выключения

### Requirement: Accessible lifecycle interactions

Область этой задачи — действия статуса, подтверждения и удаления — SHALL поддерживать клавиатуру, доступные названия/ошибки, предсказуемый фокус и узкую компоновку. Приёмка SHALL проверять собственные элементы; реализация и приёмка соседних UI-возможностей MUST NOT требоваться для закрытия этой задачи сверх явно указанных зависимостей интеграции. Недоступные API MUST NOT имитироваться успешными заглушками.

#### Scenario: Keyboard and narrow layout within this task

- **WHEN** пользователь работает с элементами этой задачи клавиатурой на узком экране
- **THEN** действия и ошибки доступны, содержимое не перекрывает управляющие элементы, закрытие имеющихся диалогов возвращает фокус
