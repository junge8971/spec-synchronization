## Context

См. proposal.md. `intents-tab.tsx` — unavailable; `/skills/new` — заглушка. Прототип содержит локальные группы и уведомление о дообучении, но в `openapi.json` таких DTO и операций нет.

## Goals / Non-Goals

**Goals:** серверные группы плюс локальный несохранённый draft, пригодный для вкладки и шага мастера.

**Non-Goals:** копирование локального реестра/таймера обучения из прототипа, весь мастер создания, проверка глобальных конфликтов.

## Decisions

- **BLOCKED API:** интеграцию и её финальные DTO не реализовывать до контракта чтения/записи, стабильных ID групп, версии набора и применённой версии. Согласовать ограничения группы/фразы, пустые группы, дубликаты, удаление последней группы и concurrency. Это входной gate, не задача «догадаться при реализации».
- Редактор — отдельная feature, API — entities/skill, композиция — widget. Не импортировать будущую feature создания в feature редактора; общую форму поднимать только к реальному общему владельцу.
- В карточке парсить непустые строки; в шаге мастера — строки и запятые по задаче. Нормализация для глобальной проверки принадлежит MOS-1018/backend; split/trim не объявляется алгоритмом конфликтов.
- Отмена возвращает последний серверный набор. Ошибка сохраняет draft. После успешной записи читать серверную версию/состояние; сохранено не значит опубликовано. Не обещать конкретное время обучения из демо.
- Без API сохранять truthful unavailable; локальный рабочий редактор с «успешным сохранением» отвергнут как ложная интеграция.

## Dependencies and acceptance gate

MOS-1019 поставляет подробности процесса, но индикатор применения фраз должен иметь свой согласованный источник. MOS-1018 добавляет проверку отдельным change. Для интеграции шага мастера нужен отдельный согласованный change создания навыка; пока его нет, соответствующая задача остаётся незакрытой. Component-проверка парсера не заменяет приёмку мастера.

## Risks / Trade-offs

- Потеря draft при refetch/смене навыка → явная отмена/защита несохранённого ввода.
- Сохранение новой версии при работающей старой → показывать обе версии по серверу, не переключать применённую локально.

## Migration Plan

После снятия gate обновить план по принятому API, затем заменить только intents unavailable. Откат возвращает unavailable, не откатывая сохранённые фразы на сервере.
