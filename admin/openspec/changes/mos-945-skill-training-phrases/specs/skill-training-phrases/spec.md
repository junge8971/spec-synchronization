## Purpose

Предоставить серверное хранение групп обучающих фраз навыка и отличать сохранение новой версии от её фактического применения.

## ADDED Requirements

### Requirement: Contract-backed phrase groups

При наличии согласованного API вкладка SHALL показывать группы с названиями и фразами, позволять добавлять/удалять группы, редактировать, сохранять и отменять изменения. До появления API интерфейс MUST NOT выдавать локальное сохранение за серверное и SHALL сохранять unavailable-состояние.

#### Scenario: API unavailable

- **WHEN** контракт не описывает чтение и запись групп
- **THEN** интерфейс сообщает о неподдержанной функции и не отправляет придуманные поля в PATCH анкеты

#### Scenario: Save and reopen groups

- **WHEN** пользователь добавляет группу, изменяет фразы и успешно сохраняет
- **THEN** повторная загрузка показывает подтверждённый сервером набор и его версию

### Requirement: Phrase input and cancellation

В карточке фразы SHALL вводиться по строкам со счётчиком непустых фраз. В интегрированном шаге мастера SHALL поддерживаться разделение строками либо запятыми. Отмена SHALL восстанавливать сохранённый набор, ошибка записи SHALL сохранять draft. Ограничения групп и фраз SHALL соответствовать принятому контракту.

#### Scenario: Blank lines and count

- **WHEN** пользователь вводит несколько фраз с пустыми строками
- **THEN** пустые строки не увеличивают счётчик фраз

#### Scenario: Wizard separators

- **WHEN** в предоставленном отдельной задачей мастере введены фразы через запятую и перевод строки
- **THEN** шаг показывает отдельные непустые фразы и корректный счётчик

#### Scenario: Cancel or failed save

- **WHEN** сохранение завершилось ошибкой, затем пользователь отменяет изменения
- **THEN** до отмены draft не теряется, после отмены показан последний сохранённый набор без новой мутации

### Requirement: Saved and applied phrase versions

После изменения опубликованного навыка UI SHALL различать сохранённую и применённую версии по серверным данным и показывать состояние дообучения. Сохранение MUST NOT немедленно объявлять новую версию активной или обещать вымышленный срок.

#### Scenario: Retraining after publication

- **WHEN** сервер сохранил новую версию, но сообщает, что она ещё обучается и не применена
- **THEN** интерфейс показывает сохранение и ожидание применения, не заменяя активную версию локально
