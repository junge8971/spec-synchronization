## Purpose

Реализовать серверные сохранённые фильтры опросников в разделе обратной связи ЦАМ по опубликованному API, с отдельной приёмкой и сохранением ограничений первого этапа.

## ADDED Requirements

### Requirement: Personal saved searches

Фильтры SHALL храниться сервером через /saved-filters с resource=feedback-surveys и полным search. Имя SHALL иметь 1–150 символов и не состоять из пробелов. UI SHALL предоставлять создание, постраничный список, применение, явное обновление выбранного по ID и удаление. Одинаковые имена SHALL допускаться и MUST NOT вызывать автоматическую перезапись. PUT search SHALL заменять объект целиком; resource MUST NOT изменяться. При применении SHALL восстанавливаться query, обычные фильтры, conditions, sort, limit с offset=0. Недоступный фильтр SHALL обрабатываться как 404; устаревший search SHALL показывать ошибку без молчаливого частичного применения/localStorage fallback.

#### Scenario: Duplicate names

- **WHEN** пользователь сохраняет новый фильтр с уже существующим именем
- **THEN** создаётся новый filter ID; только отдельное действие обновления выбранного фильтра вызывает PUT его ID

#### Scenario: Apply and update complete search

- **WHEN** сохранённый фильтр содержит две conditions, sort и offset=40, затем применяется
- **THEN** реестр восстанавливает все параметры с offset=0; явное обновление передаёт полный текущий search, ошибки сохраняют форму

### Requirement: Accessible saved-filters interactions

Область этой задачи — формы и список сохранённых фильтров — SHALL поддерживать клавиатуру, доступные названия/ошибки, предсказуемый фокус и узкую компоновку. Приёмка SHALL проверять собственные элементы; реализация и приёмка соседних UI-возможностей MUST NOT требоваться для закрытия этой задачи сверх явно указанных зависимостей интеграции. Недоступные API MUST NOT имитироваться успешными заглушками.

#### Scenario: Keyboard and narrow layout within this task

- **WHEN** пользователь работает с элементами этой задачи клавиатурой на узком экране
- **THEN** действия и ошибки доступны, содержимое не перекрывает управляющие элементы, закрытие имеющихся диалогов возвращает фокус
