## Context

См. [proposal.md](proposal.md) и [дельту спецификации](specs/skill-catalog-experience/spec.md). В `SkillRegistryFilters` оба списка используют общий `SelectContent` без параметров позиционирования. По умолчанию Base UI может наложить список на поле при открытии мышью, выравнивая текст выбранного пункта по значению поля. Это объясняет, почему результат может зависеть от выбранного пункта и способа открытия, но ещё не подтверждает причину MOS-1050 в текущей сборке.

## Goals / Non-Goals

**Goals:** отделить смещение при достаточном месте от штатного поведения у края окна; при подтверждении дефекта устранить его средствами существующего позиционера.

**Non-Goals:** замена компонента, общая настройка всех списков, изменение ширин полей, высоты списков, API или механизма записи фильтров в URL.

## Decisions

1. **Сначала измерить исходное положение.** На `/tsam-panel/skills` открыть мышью каждый список с исходным и выбранным значением. После анимации сравнить прямоугольники поля и списка в Playwright MCP: при достаточном месте верх списка не выше низа поля, а левые края совпадают с допуском в 1 CSS px на округление. Записать ширину окна, выбранные значения и наблюдаемые отклонения. Открытие только клавиатурой может не задействовать режим наложения Base UI; скриншот из Jira не заменяет проверку текущей сборки.
2. **При подтверждении дефекта настроить два места вызова.** Задать `align="start"` и `alignItemWithTrigger={false}` у «Статус» и «Домен» по примеру `app/features/surface-registry-filter/ui/surface-registry-filters.tsx`. Сохранить стандартное открытие вниз, отступ, ширину по полю и штатное размещение при нехватке места. Менять общий `SelectContent` или компенсировать смещение CSS-отступом не нужно: первое затронет другие экраны, второе не учитывает выбранный пункт и границы окна. Если замеры указывают на другой механизм, не распространять правку на общий компонент без уточнения плана.
3. **Проверить позицию и поведение отдельно.** Геометрию и доступность вариантов проверить интерактивно на `yarn dev` с моками, на обычной и узкой ширине, в том числе при нехватке места снизу. Компонентная проверка покрывает выбор, `Escape`, фокус и URL; JSDOM не подтверждает геометрию. Оставить существующие проверки фильтрации и пагинации.

## Risks / Trade-offs

- Штатный перенос при нехватке места легко принять за баг → проверять положение сначала при достаточном месте, затем отдельно у края окна. Если дефект не воспроизвёлся, сохранить наблюдения и не менять код.
- Локальная среда или Playwright MCP могут быть недоступны → зафиксировать блокер и оставить визуальную проверку незавершённой. Моки не подтверждают работу реального backend.

## Migration Plan

Миграция не нужна. При регрессии откатить только настройки позиционирования двух списков.
