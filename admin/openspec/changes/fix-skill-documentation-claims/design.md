## Context

Мотивация — `proposal.md`. Быстрая локальная сверка, не возобновление `reconcile-control-center-backlog` и не проверка стенда.

Подтверждённые источники:

- `app/entities/documentation/model/constants/documentation-articles.constants.ts`, статья `skill-register`: немедленная проверка пересечений, серверный черновик/отправка на проверку обещаны без оговорок.
- `app/features/skill-registration/ui/steps/registration-review.tsx`: показывает неподключённую проверку пересечений и явно отделяет создание от обучения и ревью.
- `openspec/specs/skill-registration/spec.md`: Phrase groups in registration, Connection and truthful final review, Recoverable non-atomic registration, Creation without guaranteed replay, Safe browser-local registration storage.
- `openspec/specs/documentation-search/spec.md`: поиск по содержимому, в том числе сценарий запроса `НЕОДНОЗНАЧНОСТИ`, и сохранение URL/истории/фокуса.
- `app/entities/documentation/model/documentation-articles.test.ts`: фиксирует 14 статей, их ID и порядок, но не проверяет правдивость инструкции регистрации.

## Goals / Non-Goals

**Goals:** исправить только пользовательский текст и его регрессионные проверки, используя существующие структуры блоков статей.

**Non-Goals:** новая документационная платформа, изменение мастера, preflight/lifecycle API, справочник версий контрактов, изменение `skill-params`, маршрутов, бизнес-валидации или auth. Не утверждать отсутствие опубликованного API: текущая проблема — отсутствие подключённой функции в мастере.

## Decisions

1. **Редактировать данные статьи, не UI и роутинг.** Сохранить ID `skill-register`, группу, порядок и существующие типы блоков. Альтернатива — новая статья/redirect — создаёт ненужную миграцию ссылок.
2. **Описывать наблюдаемый сценарий и действующие требования.** Четыре шага, создание навыка, локальное восстановление при доступном хранилище, отсутствие автоматического обучения. Ошибка после подтверждённого создания требует продолжения незавершённого этапа, а неизвестный исход создания не разрешает повторный POST. Не давать опасный универсальный совет «повторите регистрацию».
3. **Не удалять предметное объяснение пересечений.** Сохранить термин «неоднозначности» в правдивом контексте: проверка нужна для их выявления, но сейчас не подключена. Это сохраняет существующий поисковый сценарий без закрепления ложного обещания. Не подключать MOS-1018 ради соответствия старому тексту.
4. **Проверять содержание и совместимость.** Позитивные assertions на локальное восстановление, неподключённую проверку и отсутствие запуска обучения дополнить отрицательными на старые обещания. Поисковая регрессия должна находить исправленную статью по тексту блока; существующие проверки ID, групп, URL и доступности не ослаблять.

## Risks / Trade-offs

- [Позднее будет подключён preflight или изменён мастер] → будущий владелец интеграции обновляет документацию вместе с поведением; этот change не прогнозирует неподтверждённую поставку.
- [Исправление копии сломает поиск по «неоднозначности»] → сохранить предметное объяснение и проверку поиска по телу статьи.
- [Остальные вопросы раздела будут приняты за решённые] → границы быстрой сверки перечислены ниже; никакие feature checkboxes не закрываются.

## Результат краткой сверки раздела

Просмотрены сохранённые адресные отчёты и текущие task lists, с точечной перепроверкой кода реестра, фильтров, документации и финального шага регистрации. Полная повторная проверка всех proposal/design/spec/code/tests раздела и свежести внешних источников не выполнялась.

Не решённые этой сверкой вопросы:

- MOS-1022: ссылка параметров ведёт на существующую `skill-params` про тренировочные фразы; текущая main spec явно требует этот ID. Нужен выбор владельцем правильного материала/назначения, до него не менять ссылку и не переписывать статью параметров автоматически.
- MOS-1050: сохранённая жалоба на смещение dropdown не подтверждена текущей геометрией. Component-тест открытия не доказывает позиционирование; требуется актуальное визуальное свидетельство, а для browser-проверки — отдельное разрешение. Спекулятивной правки общего Select нет.
- Утверждённые версии контрактов, ограничения фраз, расширение domain selector и полный review-return требуют предметных решений; примеры и прототип не становятся новыми правилами валидации.
- Дополнительные наблюдения по порядку инцидентов/справочникам и настройкам мониторинга остаются у MOS-1026/MOS-1025 и в сохранённой очереди `reconcile-control-center-backlog/audit/pending-publication.md`; эта сверка не согласует новые записи и не доказывает backend delivery.

## Migration Plan

После отдельного apply изменить статью и тесты; миграции API/данных/URL не нужны. При регрессии откатить только текст и относящиеся к нему проверки, не менять бизнес-поведение ради документации.
