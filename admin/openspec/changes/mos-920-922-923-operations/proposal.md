## Why

[MOS-920](https://task.mos-team.ru/browse/MOS-920), [MOS-922](https://task.mos-team.ru/browse/MOS-922) и [MOS-923](https://task.mos-team.ru/browse/MOS-923) требуют работающего управления глобальными модулями, заглушками и окнами технических работ. Сейчас в `/ops` подключён отдельный реестр рубильников MOS-1570, но три указанных сценария не подключены к бизнес-API; наличие схем и локальных обработчиков не означает готового UI или подтверждённой интеграции.

## What Changes

- Добавить экран глобальных модулей по предоставленному пользователем прототипу: серверные список, сводка и «Что видит пользователь», безопасные включение и отключение с обязательным текстом, подтверждением последствий и актуальной версией.
- Сохранить существующий реестр MOS-1570 в отдельной внутренней вкладке раздела; экран глобальных модулей становится обычным начальным содержимым вкладки «Модули и навыки». Сохранить переходы к карточкам рубильников, фильтры, ранее сформированные ссылки и действующую политику доступа. Это изменение начального экрана `/ops`, согласованное пользователем; модель рубильников не подменяет модель модулей ассистента.
- Подключить библиотеку существующих заглушек: три текста по каждому объекту, inline-редактирование, единый `is_applied` для объекта и отдельный серверный предпросмотр фактической текущей конфигурации. Создание новой записи заглушки остаётся вне scope до подтверждения контракта.
- Добавить список и форму окон техработ, редактирование и отмену по серверным состояниям. Выбор целей охватывает ассистента, модули, навыки и поверхности из соответствующих источников без скрытого выбора и фильтра `prod`; окончательную допустимость определяет backend. Форма показывает две явно обозначенные иллюстрации введённых текстов, не выдавая их за серверный расчёт приоритетов.
- Новое окно создаётся действием «Запланировать»; существующие `draft` отображаются и редактируются. Атомарное создание черновика не описано: отдельную кнопку создания draft и последовательность публикации с последующим снятием с публикации не добавлять до согласования backend.
- Дополнить существующие Express-моки только для проверяемых сценариев раздела, сохранив действующие mock-конвенции модулей, credential-free режим и отсутствие ролевого enforcement. Явно ограничить локальную имитацию приоритетов теми случаями, которые она действительно воспроизводит; она не подтверждает поведение backend.

## Capabilities

### New Capabilities

- `assistant-module-control`: серверные сводка, реестр, preview и подтверждённое управление глобальными модулями.
- `operation-stub-library`: каталог существующих заглушек, единое применение и различение редактора и эффективного preview.
- `maintenance-windows`: список, форма, серверный жизненный цикл, изменение и отмена окон технических работ.

### Modified Capabilities

- `control-center-shell`: совместное размещение глобальных модулей и существующих рубильников в `/ops` с сохранением прямых ссылок и границ доступа.
- `control-center-mock-server`: адресные воспроизводимые сценарии заглушек и техработ для проверки нового UI без утверждения полной backend-семантики.

## Impact

- Затрагиваются композиция `app/application/ui/operations-route.tsx`, `app/pages/operations/`, новые предметные слайсы по правилам FSD, существующий публичный API `app/optional/system-state/`, обработчики `mocks/maintenance.mjs` и `mocks/stubs.mjs` и соответствующие тесты. Новое исключение для optional-модуля не предполагается.
- Контракт — `docs/api/contracts/openapi.json`; пользовательский `/home/user/Загрузки/message.txt` побайтово совпадает с исходной выгрузкой, импортированной в репозиторий. Разделы: `assistant-modules/v1/modules` и `maintenance/v1`; Confluence указывает для второго иной префикс `assistant-ops/v1`; их совместимость не подтверждена. Доступность и фактические правила развёрнутого backend этим не подтверждаются. Нормализация security и существующие generated-типы сохраняются.
- Источники поведения: [контракт модулей](https://wiki.mos-team.ru/pages/viewpage.action?pageId=241088180), [контракт заглушек и техработ](https://wiki.mos-team.ru/pages/viewpage.action?pageId=241092242), [бэклог](https://wiki.mos-team.ru/spaces/KR/pages/243766779/Бэклог+tsam-assistant-management-front), [аналитика рубильников](https://wiki.mos-team.ru/pages/viewpage.action?pageId=247747489) и `/home/user/Загрузки/Прототип. Центр управления.html`. Разрешение спорных backend-семантик и подтверждение draft-статуса контракта MOS-920 остаются отдельными интеграционными gates.
- Существующие session/permissions, безопасность, обработка ошибок и доступность сохраняются; новые auth-модели, права и API не вводятся. Прототипные агрегированные состояния навыков/поверхностей и добавление заглушки не симулируются вместо неподтверждённого API.
- Проверки реализации: unit/component, адресные HTTP-тесты моков, typecheck, lint, test, format и build; `api:check` при изменении API-типов. Интерактивная проверка локального UI через Playwright MCP, автоматические E2E/browser suites и любые действия на внешнем UI допустимы только после отдельного явного разрешения пользователя; отсутствие разрешения или инструмента фиксируется как непроверенная часть.
