## Purpose

Дать пользователю возможность безопасно редактировать существующие тексты недоступности и видеть текущий серверный результат для выбранного объекта.

## ADDED Requirements

### Requirement: Existing stub catalogue and grouped texts

Библиотека SHALL получать серверный каталог существующих записей для `assistant`, `module`, `skill`, `surface` с поддерживаемыми поиском, фильтрами и пагинацией. Для каждой цели SHALL быть различимы `full_stub_text`, `substitute_response_text` и `warning_banner_text`, включая отсутствие nullable текста. Три текста относятся к одной записи и SHALL иметь один общий признак `is_applied`; UI MUST NOT выдавать его за три независимых переключателя. Новую запись заглушки или новый target UI MUST NOT создавать до согласования такой операции.

#### Scenario: Three texts share one flag

- **WHEN** одна цель имеет три разных текста
- **THEN** они показаны с отдельными подписями и редактированием, но имеют общий контроль применения записи

#### Scenario: Missing text or empty catalogue

- **WHEN** текст равен null либо сервер возвращает пустую страницу каталога
- **THEN** отсутствие текста и пустой результат видимы без вымышленного текста; ошибка загрузки не обозначается пустым каталогом

### Requirement: Safe inline editing and application

Редактор SHALL сохранять существующую запись по её `target_type` и `target_id`, передавая обязательный `is_applied` и только предусмотренные контрактом текстовые поля. Пустая или состоящая только из пробелов новая текстовая строка MUST NOT сохраняться; исходный null и отсутствие изменения SHALL оставаться различимыми, текст длиной более 2000 символов SHALL отклоняться. Отмена редактирования SHALL возвращать последнее подтверждённое значение без запроса. `is_applied=false` SHALL обозначаться как черновик, `true` — как запрос немедленного применения с учётом серверных приоритетов; UI MUST NOT утверждать, что один флаг доказывает фактический вывод текста. Неописанную политику очистки существующего значения и сохранение отдельной живой версии MUST NOT выдумывать.

#### Scenario: Edit one text

- **WHEN** пользователь сохраняет непустой текст одного вида у существующей цели
- **THEN** запрос содержит обязательный общий `is_applied` и изменённое поле, а остальные значения не подменяются пустыми строками или случайными значениями

#### Scenario: Cancel or fail

- **WHEN** пользователь отменяет ввод либо сохранение отклоняется сервером
- **THEN** при отмене восстанавливается подтверждённое значение без записи, при ошибке ввод и ошибка остаются доступными без ложного успеха

### Requirement: Effective server preview is separate from editor

Предпросмотр для выбранной цели SHALL запрашивать серверный `GET /stubs/{target_type}/{target_id}/preview` и показывать возвращённые сообщения, состояние и источник без предположений о допустимых значениях `source`. Он SHALL быть обозначен как текущий серверный результат с учётом применимых окон, а не как preview несохранённого текста или будущего времени. UI MUST NOT самостоятельно рассчитывать приоритеты окон. Подтверждённое сохранение и последующий сбой чтения preview SHALL оставаться разными результатами.

#### Scenario: Active maintenance overrides ordinary text

- **WHEN** серверный preview сообщает результат активной техработы, отличающийся от сохранённого обычного текста
- **THEN** UI показывает результат и источник сервера, не подменяя их введённым или сохранённым текстом заглушки

#### Scenario: Save succeeds but preview fails

- **WHEN** PUT подтвердил сохранение, но последующий GET preview завершился ошибкой
- **THEN** сохранение остаётся подтверждённым, а preview показывает отдельную ошибку и повтор чтения

### Requirement: Stub errors and session ownership

UI SHALL различать загрузку, отказ доступа, 404, ошибки валидации/конфликта, сетевую ошибку и невалидный ответ. Мутация с неизвестным исходом MUST NOT повторяться автоматически; пользователь SHALL иметь возможность заново прочитать текущую запись и preview перед явным решением. Поздний ответ предыдущего пользователя или выбранной цели MUST NOT менять текущий экран. Тексты SHALL отображаться как текст, а не исполняемая разметка.

#### Scenario: Uncertain result or changed principal

- **WHEN** соединение теряется после PUT либо principal заменён до завершения ответа
- **THEN** отсутствует автоматический повтор и фиктивное подтверждение; поздний результат старого контекста не меняет данные нового пользователя
