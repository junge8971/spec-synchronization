## Purpose

Предоставить серверное состояние включения навыка и подтверждённое глобальное включение/отключение по skill_id без подмены операциями других сущностей.

## ADDED Requirements

### Requirement: Server skill state

При наличии согласованного API UI SHALL показывать серверное состояние «включён/отключён» конкретного навыка. Отсутствие API SHALL оставлять реальные команды недоступными; ошибка чтения MUST NOT трактоваться как отключение. Состояние MUST NOT выводиться из lifecycle-статуса, состояния модуля или состава навыков отдельных поверхностей. Длительности и подробный список затронутых поверхностей SHALL оставаться вне MVP и не блокировать его при наличии минимального API.

#### Scenario: Read disabled skill

- **WHEN** сервер сообщает, что выбранный навык отключён
- **THEN** UI показывает «Отключён» по серверным данным без вычисления длительности и загрузки списка поверхностей

#### Scenario: API unavailable or read failed

- **WHEN** контракт включения навыка отсутствует либо чтение состояния завершилось ошибкой
- **THEN** UI не предоставляет реальную команду по вымышленному или устаревшему состоянию; отсутствие API объясняется отдельно от ошибки чтения с повтором

### Requirement: Confirm global disable and enable

Перед отключением или включением UI SHALL требовать отдельное подтверждение с идентификацией навыка, текущим и целевым состоянием и объяснением глобальной области действия по согласованному контракту. Отмена MUST NOT отправлять запрос. Команда SHALL относиться к skill_id; операции модулей, массовое изменение поверхностей и перевод lifecycle в draft MUST NOT использоваться как замена.

Минимальная форма SHALL ограничиваться подтверждением; основание и сообщение жителю не требуются вне обязательных полей будущего согласованного API. Если такие поля обязательны по контракту, UI SHALL валидировать их без фиктивных значений. Диалог и действия SHALL сохранять клавиатурную доступность и понятные текстовые подписи.

#### Scenario: Confirm disable

- **WHEN** пользователь подтверждает глобальное отключение включённого навыка и сервер подтверждает применённое отключение
- **THEN** UI показывает отключённое состояние этого навыка, не выполняя серию обновлений поверхностей и не меняя локально его lifecycle

#### Scenario: Confirm enable

- **WHEN** пользователь подтверждает глобальное включение отключённого навыка и сервер подтверждает применённое включение
- **THEN** UI показывает включённое состояние по серверному результату

#### Scenario: Cancel confirmation

- **WHEN** пользователь отменяет подтверждение
- **THEN** мутация не отправляется, состояние не меняется клиентом

### Requirement: Consistent global action outcome

UI SHALL предотвращать повторную отправку в pending и менять отображаемую включённость только по подтверждённым серверным данным. При известном изменении состояния до отправки SHALL требоваться новое подтверждение; серверные guards SHALL применяться согласно API без выдуманного impact-протокола. Ошибка команды SHALL отображаться без сообщения об успехе и без потери контекста выбранного навыка или введённых обязательных полей.

При неизвестном исходе UI SHALL предложить чтение актуального состояния, не объявляя успех или гарантированную отмену. Автоматические повторная и обратная команды MUST NOT выполняться. Новая команда SHALL требовать успешного чтения и отдельного осознанного подтверждения по согласованным правилам API.

#### Scenario: Pending or changed state

- **WHEN** пользователь повторно нажимает действие во время команды либо до отправки стало известно об изменении состояния
- **THEN** второй запрос не создаётся; изменившееся состояние требует нового подтверждения

#### Scenario: Request failure

- **WHEN** сервер отклоняет переключение
- **THEN** UI показывает ошибку без локального успеха, сохраняя контекст навыка и ввод обязательных по контракту полей

#### Scenario: Response lost

- **WHEN** ответ команды потерян
- **THEN** UI показывает неизвестный исход и предлагает чтение состояния без повторной или обратной команды; ошибка чтения сохраняет неопределённость, успешное чтение показывает текущее состояние без приписывания его потерянному запросу
