## Purpose

Обеспечить осознанное глобальное отключение и включение навыка с подтверждением последствий для всех связанных поверхностей.

## ADDED Requirements

### Requirement: Server skill state and global impact

При наличии согласованного API UI SHALL показывать состояние навыка, длительность работы/отключения и затронутые поверхности из серверных данных. Без API SHALL быть недоступны реальные команды; методы модуля/поверхности MUST NOT подменять операцию навыка.

#### Scenario: Skill disabled before page visit

- **WHEN** пользователь открывает ранее отключённый навык
- **THEN** длительность определяется серверными сведениями, а не временем открытия страницы

### Requirement: Confirm global disable and enable

Перед отключением UI SHALL объяснить последствия для всех затронутых поверхностей и требовать основание и непустое сообщение жителю. Включение SHALL иметь отдельное подтверждение возобновления ответов. Отмена MUST NOT отправлять команду.

#### Scenario: Missing disable information

- **WHEN** пользователь пытается отключить навык без основания или сообщения
- **THEN** команда не отправляется, обязательные поля обозначены доступными ошибками

#### Scenario: Confirm enable

- **WHEN** пользователь подтверждает включение и сервер принимает команду
- **THEN** UI отражает серверное включённое состояние и последствия для связанных поверхностей

#### Scenario: Cancel confirmation

- **WHEN** пользователь отменяет отключение или включение
- **THEN** мутация не выполняется

### Requirement: Consistent global action outcome

UI SHALL предотвращать повторную отправку в pending и менять отображаемое состояние только по подтверждённому серверному результату. При изменившейся версии/impact SHALL требоваться новое подтверждение. Ошибка SHALL сохранять введённый текст; неизвестный исход MUST NOT автоматически запускать повторную или обратную операцию.

#### Scenario: Stale impact

- **WHEN** сервер отклоняет команду из-за изменившихся последствий
- **THEN** пользователь видит новые сведения и необходимость повторного подтверждения вместо автоматического отключения

#### Scenario: Request failure

- **WHEN** команда завершилась ошибкой
- **THEN** сообщение об успехе отсутствует, введённое основание/сообщение не теряются
