## 1. BLOCKED — минимальный API навыка

Согласовано сокращение до серверной включённости и команд переключения по skill_id. Реализация остаётся заблокированной до 1.1: текущий контракт не предоставляет ни состояние, ни команды. Длительности и подробный список затронутых поверхностей отложены и не входят в gate.

- [ ] 1.1 Получить минимальный согласованный контракт чтения состояния и включения/отключения навыка по skill_id: глобальная область действия, обязательные поля, подтверждение применения команды, ошибки и перечитывание при неизвестном исходе. Зафиксировать имеющиеся серверные guards, не придумывая endpoints или отдельный impact/replay API; если обязательны основание/сообщение жителю, согласовать форму. Проверка: опубликованный контракт и уточнённые design/spec/tasks однозначно задают запросы и результаты без требований длительностей и списка поверхностей.
- [ ] 1.2 После 1.1 подключить контрактные типы, runtime-валидацию и чтение/команды через существующий transport; проверка: API-тест skill ID, payload, подтверждённого ответа и ошибки, yarn api:check. Методы модулей/поверхностей и POST lifecycle status не использовать как замену.

## 2. Состояние и подтверждение

- [ ] 2.1 Показать серверную включённость и состояния загрузки/ошибки с повтором в карточке, без длительностей и перечня поверхностей; проверка: component-тест включённого/отключённого навыка и ошибки чтения без подстановки «Отключён» или доступной команды по старым данным.
- [ ] 2.2 Добавить отдельные подтверждения включения и отключения с именем/ID навыка и глобальной областью действия; дополнительные поля только если обязательны по согласованному API. Проверка: component-тест обоих действий, отмены без запроса, клавиатурного фокуса и валидации обязательных полей при их наличии в контракте.
- [ ] 2.3 Реализовать pending, проверку актуальности подтверждения и обновление только по серверному результату; ошибки сохраняют контекст и ввод, неизвестный исход предлагает чтение без автоматической повторной/обратной команды. Проверка: component-тест успешного переключения, двойного нажатия, изменившегося состояния, отказа и потерянного ответа с успешным/неуспешным перечитыванием.
