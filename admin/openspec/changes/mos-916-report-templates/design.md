## Context

См. `proposal.md`: текущая поставка — навигация и unavailable-каталог, не API шаблонов. База страницы/черновика появляется в `mos-1015-report-constructor`. Изучены `shared/lib/hooks/use-section-tab.ts`, `shared/config/constants/section-tabs.constants.ts`, `pages/operations/ui/operations-page.tsx` и `application/ui/section-tabs.test.tsx`: URL-вкладки и component-проверки истории уже существуют.

HTML использует `templates` по умолчанию и `builder` для конструктора. Демокнопка запуска только меняет вкладку, а экспорт использует текущие настройки формы; эти обработчики не являются рабочим сценарием шаблона.

## Goals / Non-Goals

**Goals:** расширить существующие соглашения навигации, сохранить локальный черновик и отличить отсутствие контракта от отсутствия записей.

**Non-Goals:** карточки на fixtures, клиент списка/деталей/экспорта, enum расписаний API, типы last_run, retry несуществующего endpoint, создание шаблонов и выполнение расписаний.

## Decisions

### 1. Штатные URL-вкладки

Добавить `reportsTabs` в существующий технический сегмент конфигурации, связать с разделом и крошками по соседним реализациям. Использовать `useSectionTab` и имеющиеся Tabs, без своего парсера URL или history API. `templates` — default, `builder` — явный query. Эта поставка меняет начальное отображение `/reports` с конструктора базы на вкладку шаблонов; прямой `?tab=builder` остаётся совместимым.

Альтернатива с локальным useState вкладки проще на несколько строк, но ломает прямые ссылки и историю; новый вложенный маршрут для двух вкладок не нужен.

### 2. Минимальный unavailable-каталог

Текст состояния и переход к конструктору — приватный компонент страницы reports, не отдельный пустой widget/entity. Нет массива пустых шаблонов, числа 0, демонстрационных карточек или неиспользуемой модели шаблона. Переход меняет только вкладку, не называется запуском шаблона.

Альтернатива загрузить придуманные endpoints либо отрисовать 5 карточек HTML создаёт ложную бизнес-функцию. Компонент карточки откладываем до реальных данных, а не пишем неиспользуемый каркас.

### 3. Жизненный цикл черновика

Состояние формы базы остаётся на уровне страницы выше переключаемых панелей. Не дублировать его в query или storage; не сбрасывать при смене `tab`. Все добавленные позднее поля имени/расписания должны использовать тот же жизненный цикл. Запросы справочников не нужны до открытия конструктора; переход между вкладками не должен превращаться в повторное создание черновика.

### 4. Проверки и точная область изменений

Расширить существующие section-tab component-тесты отчётностью: прямой URL, default/unknown, повторяющиеся query, клавиатура, назад/вперёд, крошки. Добавить проверку сохранения изменённого черновика и unavailable-каталога без API запросов. Не требовать тестов реальной карточки/404 до согласования DTO; отсутствие endpoints не симулировать как 404.

## Risks / Trade-offs

- [Шаблоны по умолчанию ведут на unavailable] → видимый переход в рабочий локальный конструктор и сохранённый direct link.
- [Размонтирование панели теряет форму] → владелец состояния выше вкладок и тест возврата к черновику.
- [Change ошибочно принимают за всю MOS-916] → в итогах PR перечислять заблокированные list/detail/export и критерии полной задачи.

## Migration Plan

Отдельный PR после MOS-1015; MOS-919 не является зависимостью текущего объёма. Откат убирает вкладки/конфигурацию и возвращает прямой конструктор, без изменения серверных данных.

После появления контракта отдельное согласованное расширение должно покрыть реальный список/ошибки, `last_run=null` как отсутствие запусков, полное восстановление параметров, экспорт по ID выбранного шаблона и 404 исчезнувшего шаблона. Расписание только отображается; браузер его не исполняет.

### Критерии заблокированного продолжения MOS-916

Это перечень полной приёмки для будущего согласованного API, не требования активной delta spec и не разрешение подключить методы по старому backlog.

- **B916.1 — Каталог:** при успешной загрузке реальные карточки показывают имя и описание, а количество соответствует серверному списку/total с учётом согласованной пагинации. Проверка: непустой список, успешный пустой список, loading, ошибка и повтор; серверная ошибка не превращается в пустой каталог, fixtures не используются. Текущее unavailable отличимо от этих будущих состояний.
- **B916.2 — Метаданные:** карточка показывает подтверждённое расписание либо «запуск вручную», дату, автора и число строк последнего запуска. Проверка: last_run=null даёт текст об отсутствии запусков без вымышленной даты/автора; существующий запуск с rows=0 отображает настоящий 0, а не отсутствие запуска. Автор фонового запуска берётся из согласованных данных, не из фиктивного пользователя. Время/часовой пояс отображаются по договорённой семантике. Просмотр расписания не запускает таймер или задачу в браузере.
- **B916.3 — Открытие:** действие на карточке загружает параметры именно выбранного шаблона и открывает конструктор с сохранёнными периодом/режимом периода, поверхностью, порядком колонок и всеми условиями, включая AND/OR, обе границы диапазона, режим/область фразы и навык. Проверка: два шаблона с разными настройками последовательно восстанавливают свои значения, а не текущий черновик; отсутствующий или несовместимый параметр не отбрасывается молча. Это открытие параметров, не самостоятельный фоновый запуск. Wire-состав и вычисление относительного периода сначала согласуются.
- **B916.4 — Экспорт:** действие «Выгрузить» относится к ID выбранного серверного шаблона, не к текущим настройкам конструктора и не к последнему файлу другого шаблона. Проверка: настройки конструктора намеренно отличаются от шаблона, экспорт использует серверный шаблон; файл и ошибки проверяются по общим критериям MOS-919 B919.2–B919.4. Владение действием/выбором шаблона остаётся здесь, файловый транспорт не дублируется. Серверные отказы обрабатываются без добавления клиентского auth/RBAC.
- **B916.5 — Ошибки:** 404 при открытии/выгрузке сообщает о недоступном шаблоне и не создаёт фиктивные параметры или файл; прочие ошибки не маскируются под 404. Ошибка открытия сохраняет существующий черновик, ошибка выгрузки не показывает успех. Проверка: удалённый после получения списка шаблон, ошибка сети, отказ backend и некорректный ответ; чужие/неподтверждённые данные не раскрываются.

Карточки, параметры и экспорт не считаются реализованными после сдачи unavailable-вкладки. Демонстрационные пять шаблонов, фиксированные авторы/даты и кнопка, только переключающая вкладку, не являются заменой этих критериев.
