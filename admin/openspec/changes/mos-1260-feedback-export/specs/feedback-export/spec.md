## Purpose

Реализовать CSV-экспорт списка и карточки опросника в разделе обратной связи ЦАМ по опубликованному API, с отдельной приёмкой и сохранением ограничений первого этапа.

## ADDED Requirements

### Requirement: Server CSV export

Список SHALL экспортироваться POST /feedback/surveys/export с fields и текущим применённым search целиком, независимо от страницы. Карточка SHALL экспортироваться POST /feedback/surveys/{id}/export только с fields и только из сохранённых данных. Колонки/порядок SHALL выбираться по metadata export_fields, сейчас name/code/type_code/audience_type/status; минимум одно уникальное поле обязательно. Вложенные данные и пользовательские ответы MUST NOT обещаться в файле. Для новой несохранённой карточки export SHALL быть недоступен; для dirty существующей SHALL поясняться источник сохранённых данных.

UI SHALL скачивать реальный CSV UTF-8 с BOM из binary ответа, использовать безопасное имя из Content-Disposition и сохранять серверное содержимое, не генерировать файл из текущей страницы. CSV escaping и защита формул принадлежат backend. JSON/HTML вместо CSV, 404, 422 EXPORT_LIMIT_EXCEEDED, сеть, отмена и смена пользователя MUST NOT давать ложный файл/успех. Лимит SHALL браться из metadata export_max_rows; отсутствие строк SHALL допускать файл только с заголовками.

#### Scenario: Export beyond current page

- **WHEN** на странице 20 строк, а отбор содержит 85
- **THEN** запрос экспортирует весь search, CSV не строится из 20 отображаемых строк и сохраняет выбранный порядок полей

#### Scenario: Export saved card while editing

- **WHEN** пользователь выгружает существующую карточку с dirty draft
- **THEN** UI поясняет, что CSV содержит сохранённую запись; запрос не включает draft/questions/rules

#### Scenario: Limit or malformed file

- **WHEN** сервер вернул EXPORT_LIMIT_EXCEEDED или JSON вместо CSV
- **THEN** показана ошибка, скачивание и сообщение «Файл готов» не выполняются

### Requirement: Accessible export interactions

Область этой задачи — выбор колонок и действия скачивания — SHALL поддерживать клавиатуру, доступные названия/ошибки, предсказуемый фокус и узкую компоновку. Приёмка SHALL проверять собственные элементы; реализация и приёмка соседних UI-возможностей MUST NOT требоваться для закрытия этой задачи сверх явно указанных зависимостей интеграции. Недоступные API MUST NOT имитироваться успешными заглушками.

#### Scenario: Keyboard and narrow layout within this task

- **WHEN** пользователь работает с элементами этой задачи клавиатурой на узком экране
- **THEN** действия и ошибки доступны, содержимое не перекрывает управляющие элементы, закрытие имеющихся диалогов возвращает фокус
