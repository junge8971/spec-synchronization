## Context

См. proposal.md. Обзор уже показывает анкету; статистика не поддерживается SkillResponse. Прототип задаёт карточки результата, а не нормативные определения метрик.

## Goals / Non-Goals

**Goals:** сопоставимые серверные метрики навыка за 30 дней с понятной выборкой.

**Non-Goals:** собственная агрегация диалогов, общий dashboard, исправление качества модели и суточный мониторинг.

## Decisions

- **BLOCKED API:** согласовать источник по skill ID, границы 30 дней/часовой пояс, единицы, числители/знаменатели success и goodShare, охват, пороги, minimum sample, определение long/unfinished и различение оценки ответа/оператора. До этого не фиксировать формулы из демо как факт.
- Данные запрашиваются независимо от анкеты, под ключом skill ID и периода. Ошибка аналитики не скрывает обзор; отсутствие API, null, insufficient sample, empty и реальный 0 различаются.
- Показать три смысловых блока: участие (диалоги/успех/вложения), оценки ответов, шаги сценария. Использовать имеющиеся карточки и форматирование чисел; временные графики не требуются задачей.
- Не складывать оценки оператора в показатели ответов ассистента. При недостаточной выборке показывать причину/минимум, а не искусственный процент и не красить результат как норму.
- MOS-1025 может использовать похожее представление, но не тот же агрегат: периоды различаются. Общую абстракцию метрик не вводить до реального повторения.

## Risks / Trade-offs

- Деление на ноль/неизвестный знаменатель → backend semantics и явная недоступность значения.
- Сравнение округлённой доли с порогом → согласовать precision/comparison, форматирование не меняет бизнес-оценку.

## Migration Plan

После API-gate добавить изолированные блоки обзора. При rollback удалить только их запросы/UI. Приёмка на достаточной/недостаточной выборке и смешанных оценках не зависит от готовности dashboard.
