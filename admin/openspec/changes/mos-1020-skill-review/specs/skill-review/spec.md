## Purpose

Обеспечить серверную очередь ревью навыков и принятие решения по согласованной версии материалов с обязательными замечаниями при возврате.

## ADDED Requirements

### Requirement: Review queue and material

При наличии согласованного API вкладка ревью SHALL показывать серверную очередь, выбор навыка, анкету, фразы и результаты проверок соответствующей версии. Без API SHALL оставаться честное unavailable. Очередь MUST NOT вычисляться из текущей страницы обычного реестра.

#### Scenario: Select review item

- **WHEN** пользователь выбирает запись очереди
- **THEN** показаны материалы выбранного навыка и версии, по которой принимается решение

#### Scenario: Empty versus failed queue

- **WHEN** сервер возвращает пустую очередь либо запрос завершается ошибкой
- **THEN** первый случай показывает отсутствие ожидающих записей, второй — ошибку с повтором

### Requirement: Review criteria and return reason

Панель SHALL включать пять критериев: завершимость сценария, вариативность формулировок, редакционная политика, достаточность фраз, понятное поведение при ошибке. Решение SHALL соответствовать согласованным правилам критериев; возврат SHALL требовать причину и непустой текст замечаний.

#### Scenario: Return without remarks

- **WHEN** пользователь выбирает возврат без причины или с пустым текстом
- **THEN** решение не отправляется, незаполненные поля обозначены доступными сообщениями

#### Scenario: Confirm decision

- **WHEN** сервер принимает согласование либо валидный возврат
- **THEN** очередь и карточка обновляются из серверного результата; для возврата доступны сохранённые замечания

### Requirement: Decision consistency

UI SHALL предотвращать повторную отправку решения во время pending, сохранять ввод при ошибке и MUST NOT автоматически применять решение к новой версии после конфликта. Материалы разных версий MUST NOT выдаваться за единый проверенный снимок.

#### Scenario: Concurrent modification

- **WHEN** сервер отклоняет решение из-за изменившейся версии навыка
- **THEN** показан конфликт и необходимость перечитать материал без автоматического согласования новой версии

#### Scenario: Switch selected skill

- **WHEN** пользователь выбирает другой навык
- **THEN** замечания и состояние несохранённого решения не переносятся на другой объект
