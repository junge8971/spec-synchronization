## MODIFIED Requirements

### Requirement: Future page entry points preserve existing functionality

Маршруты `/skills/new`, `/surfaces/:surfaceId`, `/dialogs/:dialogId`, `/teams` и `/ops` SHALL открываться в общей оболочке с названием страницы и сообщением «Раздел в разработке» для незавершённого содержимого. Эти точки входа MUST NOT создавать видимость работающих бизнес-операций, запрашивать данные незавершённых карточек или проверять существование их ID. Домены SHALL оставаться незавершённой вкладкой, а реестр навыков SHALL сохранять существующую функциональность. Ревью SHALL предоставлять очередь и решения при наличии согласованного review API; до его появления SHALL показывать явное unavailable-состояние без фиктивной очереди и решений. Существующие `/surfaces/new` и `/skills/:skillId` SHALL сохранять свои экраны, валидацию и обработку ошибок. Статические пути создания MUST NOT трактоваться как ID сущности.

#### Scenario: New skill does not load a detail

- **WHEN** пользователь открывает `/tsam-panel/skills/new`
- **THEN** показана точка входа «Добавление навыка» с сообщением о разработке, запрос карточки навыка с ID `new` не выполняется

#### Scenario: Future details without business requests

- **WHEN** пользователь открывает `/surfaces/<id>` или `/dialogs/<id>` под basename
- **THEN** отображается соответственно «Поверхность» или «Диалог» с сообщением о разработке, без запроса карточки, вымышленных данных или утверждения, что объект найден

#### Scenario: Existing screens remain functional

- **WHEN** пользователь открывает `/surfaces/new` либо существующую карточку навыка
- **THEN** доступны прежний мастер регистрации либо карточка с существующей загрузкой данных и обработкой ошибок, а не новая заглушка

#### Scenario: Review with supported business API

- **WHEN** пользователь открывает `/tsam-panel/skills?tab=review` при согласованном и подключённом review API
- **THEN** показана серверная очередь с решениями, сохранены выбор URL-вкладки, крошки и история навигации

#### Scenario: Review without supported business API

- **WHEN** пользователь открывает вкладку ревью до появления согласованного API
- **THEN** видит явную недоступность функции без запросов к придуманным endpoints и без успешных локальных решений
