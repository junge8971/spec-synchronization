## Context

См. proposal.md. `skills-page.tsx` уже имеет URL-вкладку review. Основной `control-center-shell` уже допускает подключение ревью по согласованному API и сохраняет рабочие мастер регистрации и домены; delta должна сохранять эту основу. GET skills со status=review и серверной пагинацией доступен, но контракт полноценной очереди с согласованными материалами и решениями отсутствует.

## Goals / Non-Goals

**Goals:** решение по согласованному снимку навыка с явными ошибками и серверным обновлением очереди.

**Non-Goals:** роли из HTML-прототипа, выкат, локальная фильтрация страницы обычного реестра вместо review queue.

## Decisions

- **BLOCKED API:** сначала согласовать использование GET skills?status=review как источника очереди либо отдельный источник, идентичность review item, версии анкеты/фраз/проверок, критерии, причины, команды решения и concurrency. Skill version и expected_version у POST status уже опубликованы, но не гарантируют единый снимок материалов и сохранение решения/замечаний. Методы не изобретать; отдельный read-only этап требует отдельного согласования scope.
- Разместить очередь в widget, собирать в существующей review-вкладке; чтение/мутации — entities/skill. Сохранить useSectionTab, basename и историю браузера. Не строить новый роутер и отдельный дублирующий `/review`.
- Панель показывает все пять критериев из Jira. Семантика обязательного прохождения критериев для согласования — часть API-gate, не предположение на основе демо.
- Для возврата требовать причину и непустой текст. Пока решение отправляется, не создавать второе. Ошибка оставляет выбранный объект/ввод; успех инвалидирует очередь и detail.
- При смене выбранного навыка незавершённое решение не переносится. Версионный конфликт требует перечитать материал; не повторять решение автоматически с новой версией.

## Risks / Trade-offs

- Независимые чтения дали разные версии → запросить согласованный снимок/идентификаторы версий; не разрешать решение по смешанному набору.
- Частично реализованы MOS-945/MOS-1019 → read-only материал ревью можно получать по его контракту, не импортируя их features.

## Migration Plan

При готовом API заменить только review placeholder. До этого оставить честное unavailable. MOS-1021 не блокирует приёмку очереди/решений. Откат UI не отменяет принятых сервером решений.
