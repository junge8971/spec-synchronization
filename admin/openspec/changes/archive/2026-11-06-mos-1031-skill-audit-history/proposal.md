## Why

[MOS-1031](https://task.mos-team.ru/browse/MOS-1031): история карточки должна читаться из аудита по устойчивой идентичности сущности. Фильтрация по названию из прототипа смешивает одноимённые навыки и теряет историю после переименования. Состав целевой истории описан в [постановке раздела «Навыки»](https://wiki.mos-team.ru/spaces/KR/pages/241080062); локальные API-источники и их ограничения перечислены в Impact.

## What Changes

- Реализовать чтение истории по локальному контракту Query API аудита: тип `skill`, ID навыка, обязательный период и курсорная подгрузка, как требует MOS-1031. Для локальной разработки использовать существующий Express mock.
- Показывать серверные события от новых к старым: время, автора, действие и доступные подробности. Аналитика ожидает изменения карточки, содержания, подключения и токенов, переходы статусов, решения ревью, отключения и включения; прототип дополнительно указывает создание и проверки в песочнице. Состав и полноту событий должен подтвердить источник аудита; секреты токенов не раскрываются.
- Различать loading, пустой результат за период и error/retry; после успешных операций перечитывать аудит без создания локальных записей.
- Не включать полный журнал `/teams?tab=audit`, генерацию audit-событий на клиенте или объединение отдельных источников истории без согласования.

## Capabilities

### New Capabilities

- `skill-audit-history`: серверная история карточки навыка.

### Modified Capabilities

Нет. Подключение реального сервиса отдельно проверяется на совместимость с существующей сессией и допустимым адресом credentials.

## Impact

- `app/widgets/skill-details/ui/tabs/history-tab.tsx`, предметный API чтения аудита с публичным интерфейсом.
- Контракт чтения находится в локальном `../../reconcile-control-center-backlog/audit/sources/wiki-241077434-readable/r1/content.txt` (§3.2); он описывает отдельный audit-service и не входит в Control API `docs/api/contracts/openapi.json`. UI, клиент и mock можно реализовать по этому контракту, не дожидаясь подтверждения всех событий или сроков хранения.
- Перед запросами к реальному сервису отдельно проверить маршрутизацию, разрешённый адрес и совместимость его Bearer-сессии с текущей сессией MPMM. Пока безопасное подключение не подтверждено, real mode не отправляет credentials сервису аудита и показывает unavailable; это не блокирует локальную разработку и не меняет общую сессию.
- В локальном OpenAPI опубликован GET решений ревью навыка, но он не является общим аудитом и не заменяет историю карточки; объединение с Query API и изменение отдельного workflow ревью вне scope.
- Отображать доступные поля ответа без выдуманных подробностей; полноту категорий, retention и реальную доставку событий проверять отдельно от готовности reader и существующих UI-мутаций.
- Самостоятельная приёмка MOS-1031 на одноимённых и переименованных сущностях.
