## 3. Самостоятельная приёмка MOS-1031

- [x] 3.1 Проверить spec unit/component-тестами: переименование в доступном периоде, одноимённые навыки, курсор, смену периода, доступную таблицу и отсутствие секретов; проверка: каждый запрос сохраняет согласованные фильтры, общий экран журнала не изменён, полнота событий и real-интеграция не выводятся из моков.
- [x] 3.2 После отдельного явного разрешения пользователя интерактивно проверить локальный UI с моками через Playwright MCP: заполненную и пустую историю, ошибку/retry, следующую страницу и клавиатуру; проверка: записаны сценарии и результаты либо причина, почему проверка не выполнена. Автоматические E2E/browser-тесты не создавать и не запускать без отдельного разрешения.
- [x] 3.3 Выполнить yarn typecheck, yarn lint без предупреждений, yarn test, yarn format:check, yarn api:check при новых типах и yarn build при изменении сборки или production-изоляции моков; проверка: результаты сохранены и scope-diff просмотрен.

## 4. Реальная интеграция и покрытие событий

Эти проверки не блокируют реализацию клиента, локального mock и UI.

- [x] 4.1 Проверить маршрутизацию, destination и совместимость Bearer-сессии аудита с текущей сессией MPMM до отправки реальных credentials; проверка: подтверждён безопасный способ подключения либо real mode остаётся unavailable без fallback в mock. Изменение auth-модели и проверка тестового контура требуют отдельного согласования.
- [x] 4.2 Сверить целевые категории аналитики с публикацией событий; проверка: для создания, изменений карточки, содержания и подключения, действий с токенами, статусов, проверок в песочнице, ревью, отключений и включений зафиксированы подтверждённый источник и безопасные подробности либо открытая зависимость. Непроверенная полнота не считается принятой и не блокирует UI.
