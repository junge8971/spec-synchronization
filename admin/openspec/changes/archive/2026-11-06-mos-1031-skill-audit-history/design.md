## Context

См. proposal.md. `history-tab.tsx` — unavailable; подключённого frontend-reader нет. Локальный `docs/api/contracts/openapi.json` не содержит общего reader аудита. GET `/api/control/api/skills/v1/skills/{skill_id}/review/decisions` возвращает только решения ревью с собственной offset-пагинацией и не подтверждает наличие остальных событий в аудите; отдельный workflow ревью не меняется.

Контракт отдельного сервиса аудита сохранён в `../../reconcile-control-center-backlog/audit/sources/wiki-241077434-readable/r1/content.txt` (§3.2) и служит основой для клиента, UI и локального mock. Он не подтверждает deployment или совместимость сессии для реального подключения. В прототипе сопоставление по названию непригодно для реальной истории.

## Goals / Non-Goals

**Goals:** история одной устойчиво идентифицированной сущности и серверная пагинация.

**Non-Goals:** полный экран аудита, генерация локальных audit events, отображение секретов в подробностях.

## Decisions

- Использовать `GET /api/audit-service/api/v1/records`: `object_type=skill`, `object_id` равен skill ID, `occurred_from` включительно и `occurred_to` исключительно в UTC. Передавать неизменные период и сортировку вместе с `next_cursor`; `has_more` определяет наличие следующей страницы, серверный total не предполагается. Ответ содержит `items`, а не гарантированные old/new значения.
- Для ленты показывать `occurred_at` и запрашивать `occurred_at:desc`, чтобы порядок соответствовал времени действия. При задержанной доставке событие может попасть в уже просмотренный интервал: повторное чтение начинается с первой страницы, без обещания мгновенной полноты. Доступный выбор периода позволяет задать корректные границы; неизвестный лимит интервала и retention не выдумываются, серверная ошибка периода показывается пользователю.
- Предметный клиент чтения аудита разместить в entities с публичным API; history-tab использует его без импорта другого widget журнала. Ключ кеша включает тип, ID, период и сортировку, состояние страницы — курсор; изменение фильтров начинает новое чтение. Название используется только для представления.
- Показывать фактические события и доступные безопасные поля ответа, включая прежние решения ревью, если они возвращены источником. Код действия допустим, когда человекочитаемое описание не опубликовано; не синтезировать old/new, авторов или отсутствующие события. Подтверждение покрытия категорий и retention не блокирует UI и reader, но отсутствие подтверждения не объявляется полной историей.
- Мутации навыка при наличии аудита инвалидируют историю соответствующего навыка и инициируют чтение по правилам актуальности; проверить изменение карточки, фраз, статуса, toggle и существующие массовые операции. Не добавлять фальшивую строку «успех» до её появления в Query API. Учитывать задержку появления события и изоляцию сессии.
- Empty означает успешный пустой ответ за применённый период, не отсутствие истории за всё время; ошибка и отказ доступа не являются empty. Автора показывать из записи: `subject.employee_id` доступен для сотрудника, `unknown` не превращается в текущего пользователя или систему. Details рендерить безопасно, без raw HTML, секретов и несогласованных чувствительных полей.
- Локально направить запросы audit-service в существующий Express mock с синтетическими fixtures и контрактным cursor; mock не читает credentials, не проверяет роли и не попадает в production. Текущие Vite proxy и проверка demo destination допускают только `/api/control/api`: добавить точный audit-path только для same-origin mock mode, не ослабляя проверку real destination. Локальный результат не доказывает реальную интеграцию.
- Только для real mode до отправки credentials проверить адрес, маршрутизацию и совместимость `Authorization: Bearer <session_token>` из контракта аудита с действующей сессией MPMM и проверкой допустимого адреса. Не угадывать, какой токен использовать, не обходить проверку destination и не менять модель auth без отдельного согласования. При неподтверждённом подключении real mode показывает unavailable, не использует локальный mock. Существующая UI-политика и серверная авторизация сохраняются.

## Risks / Trade-offs

- Навык переименован/есть тёзка → фильтры по type+ID сохраняют историю без смешения.
- Поздний ответ предыдущего навыка, периода или пользователя → изоляция query key/AbortSignal и существующие проверки поколения сессии.
- Записи вне выбранного периода, retention или с задержанной доставкой → не объявлять пустую либо неполную выдачу полной историей; условия покрытия согласовать с владельцем API.

## Migration Plan

Реализовать клиент, mock и вкладку по локальному контракту без ожидания real-интеграции; общий `/teams?tab=audit` остаётся вне scope. Перед отправкой реальных credentials отдельно подтвердить transport и destination. Покрытие категорий и реальную доставку событий проверять отдельно, не выдавая mock за backend. Unit/component-проверки обязательны; интерактивную локальную проверку через Playwright MCP проводить только после отдельного разрешения пользователя, иначе зафиксировать её как непроверенную. Откат возвращает unavailable, серверный аудит не изменяется.
