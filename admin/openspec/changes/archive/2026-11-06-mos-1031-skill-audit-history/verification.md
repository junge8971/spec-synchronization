# MOS-1031: проверка реализации

Рабочий контур: отдельный worktree, локальные моки; реальные credentials и тестовые контуры не использовались.

## Выполнено

- `yarn typecheck`, `yarn lint`, `yarn format:check`, `yarn api:check` — успешно.
- `yarn test` — 181 файл, 1657 тестов успешно, после исправления замечания независимой проверки и добавления component-теста переименования и одноимённых навыков.
- `node --test mocks/skill-audit.test.mjs` — 3 теста успешно.
- `yarn build` — успешно; Vite предупредил о существующем крупном PDF-chunk. Поиск строк fixtures аудита в `build/client` и `build/server` совпадений не нашёл.
- Первоначальный полный тестовый запуск с `node_modules`, ссылавшимся за пределы worktree, не загрузил PDF worker из-за ограничения Vite; после локальной копии зависимостей полный набор прошёл. Параллельный с ним build также вызвал тайм-ауты двух несвязанных тестов; повторный последовательный запуск прошёл.
- Unit/component-тесты проверяют фильтры каждой страницы, старое и новое решение, разных авторов, пустой ответ, 400/403/503, retry, ошибки периода, безопасный вывод текста, запрет неподтверждённого real-запроса, отмену и изоляцию запоздавших ответов, а также сброс на первую страницу после мутаций и выборочную массовую инвалидацию. Информационная вкладка в real mode сохраняется и без wildcard, но чтение без разрешения не запускается.
- Express-тесты проверяют существование skill ID в seed, историю с прежним именем, одноимённые снимки для разных ID, UTC-границы, сортировку и курсор, некорректные запросы, работу без credentials и ролевого enforcement. Demo-reader запрашивает две записи на страницу, чтобы локальные фикстуры позволяли проверить курсор. Прокси доступен только для конкретного audit-path в mock dev mode.

## Интерактивная проверка

С отдельного разрешения пользователя выполнена интерактивная проверка через Playwright MCP на `http://127.0.0.1:5173/tsam-panel/` с локальным Express mock:

- В профиле полного доступа у навыка «Отопление» показаны две записи первой страницы с сотрудником и неизвестным автором; после «Загрузить ещё» появилась третья, предыдущие сохранились. Оба запроса содержали один skill ID, одинаковые UTC-границы и сортировку; второй — курсор.
- Период с 01.10.2026 показал пустой результат за период. При начале позже конца оба поля помечены как некорректные и показана ошибка периода.
- Для следующего локального audit-запроса однократно подставлен синтетический HTTP 503 через `window.fetch`; показаны сообщение о недоступности проверки доступа и кнопка повтора, а не empty. Нативный `fetch` автоматически восстановлен; повтор успешно загрузил данные из Express mock.
- С клавиатуры `End` и `Enter` открыли вкладку истории; `Tab` и `Enter` использованы для загрузки следующей страницы и повтора после ошибки.
- У демо-профиля просмотра вкладка сохранилась, показала «Нет доступа к истории навыка» и не инициировала дополнительный audit-запрос. Ошибок консоли на последней загрузке страницы не было.

Первоначальная загрузка во время оптимизации Vite получила временные 504 для зависимостей; после перезагрузки приложения ошибка не повторилась. Изолированный browser context расширение не разрешило, поэтому проверка выполнена в отдельной локальной вкладке. Автоматические E2E/browser-тесты не создавались и не запускались; внешние контуры не использовались.

## Транспорт и действующая сессия

Документированный reader описывает `Authorization: Bearer <session_token>`, тогда как согласованный транспорт Control API использует `X-Access-Token` и `X-Admin-Token`. Совместимость токенов, маршрутизация audit-service и разрешённый адрес назначения для браузера не подтверждены. Токен не выбирался и не отправлялся; real mode показывает unavailable и не использует mock. Изменение auth-модели или проверка тестового контура требует отдельного согласования. Локальный mock не подтверждает реальное развёртывание.

## Покрытие публикации событий

Контракт описывает общий поиск записей и тип объекта `skill`, но не подтверждает публикацию всех событий конкретного навыка, наличие исторических значений, комментариев ревью или retention. Открытые зависимости не считаются подтверждённым покрытием:

| Категория аналитики | Подтверждение источника для общего audit reader |
| --- | --- |
| Создание навыка | Публикация и безопасные подробности не подтверждены. |
| Изменения карточки и содержания | Публикация и значения до/после не подтверждены. |
| Изменение подключения | Публикация и допустимая редактированная детализация не подтверждены. |
| Действия с токенами | Публикация и безопасная детализация без секретов не подтверждены. |
| Переходы статусов и основания | Есть контракт изменения и отдельное описание хранения статусов, но проекция в audit reader и формат подробностей не подтверждены. |
| Проверки в песочнице | Публикация и безопасные подробности не подтверждены. |
| Решения ревью | Отдельный Control API решений не является общим аудитом; публикация в audit reader и поле комментария не подтверждены. |
| Отключение и включение | Есть операции Control API, но проекция их событий в audit reader не подтверждена. |

См. [контракт навыков](../../../../docs/api/contracts/skills-domains.md) и разделы AUDIT-03/04/10/11 анализа audit-service. История показывает только поля фактически возвращённых согласованных записей; mock не подтверждает доставку, полноту или давность реальных событий.
