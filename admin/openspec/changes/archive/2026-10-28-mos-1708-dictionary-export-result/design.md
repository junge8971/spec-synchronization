## Context

Мотивация и границы — в `proposal.md`; поведение — в `specs/reference-dictionaries/spec.md`. `DictionaryExportAction` уже владеет одним Dialog для трёх целей: `registry`, `card`, `values`. После успешного `useDictionaryExport` он показывает общий `ExportResult`, а форму сохраняет через React Activity. Общий результат также используется диалогами, навыками и другими optional-разделами. В `operation-feedback` уже согласованы один Dialog, честное сообщение о передаче браузеру, возврат к параметрам и управление фокусом.

`useDictionaryExport` получает поля в параметрах mutation, вызывает отдельный API для каждой цели и возвращает проверенное имя файла после запуска скачивания. Клиент проверяет CSV, BOM, Content-Disposition и безопасность имени; hook контролирует владельца сессии, отмену и освобождение object URL. В локальном `docs/api/contracts/crud-api.md` §18.3 успешный ответ экспорта — CSV, а порядок колонок соответствует запрошенным полям; отдельного счётчика записей в контракте ответа нет. Контур и фактическое развёртывание не проверены.

## Goals / Non-Goals

**Goals:**

- Предметное представление результата для двух запрошенных действий с данными именно завершившейся операции.
- Сохранить существующий поток формы, защиты скачивания и общий контракт доступности.
- Ограничить видимое изменение справочниками, не меняя результат CSV значений.

**Non-Goals:**

- Отдельный экспорт значений, реестр другого раздела, глобальный редизайн результата и точное пиксельное копирование скриншота.
- Новый API, счётчик записей, CSV-парсер, изменение формата, фильтров или auth/session-политики.

## Decisions

### 1. Результат принадлежит модулю справочников

Для `registry` и `card` использовать предметное представление результата внутри `app/optional/reference-dictionaries/ui/export/`, составленное из существующих shared Dialog/Button-примитивов. Оно показывает заголовок, заметный знак успеха с текстовым подтверждением, имя файла, CSV и «выбрано полей: N». Знак не является единственным носителем смысла. Сохраняются доступный заголовок, фокус при показе результата, обе кнопки и закрытие клавиатурой. Пример пользователя — ориентир по композиции, не основание менять все остальные экспорты.

Для `values` продолжить использовать существующий `ExportResult` без нового оформления или данных. Общий `ExportResult` остаётся прежним. Альтернатива — изменить shared-компонент или добавить в него предметный режим: она затрагивает API общей инфраструктуры ради одного optional-модуля и увеличивает риск изменения других разделов. Предметный компонент является самостоятельным представлением, а не общим новым механизмом экспорта.

### 2. Данные результата привязаны к успешному запросу

Показывать безопасное имя из существующего результата mutation и число `fields` из переменных именно успешно завершившейся mutation, доступных в React Query. Использовать сохранённые параметры операции, а не текущий metadata/list total и не редактируемый после возврата выбор. Число обозначает выбранные поля; не заявлять, что оно независимо получено из ответа сервера. Не подставлять фиктивное значение при отсутствии параметров операции.

Форма передаёт непустой упорядоченный список полей, экспорт реестра использует полный selection без пагинации, а экспорт карточки — отдельный endpoint. Эти тела и endpoint не меняются. Подсчёт количества строк через разбор CSV и использование ранее загруженного total не нужны: первое расширяет scope, второе может не совпадать с новым серверным запросом.

### 3. Сохранить существующее состояние и границы

Показывать результат только на существующем успешном пути после проверки файла, проверки владельца и передачи браузеру. Оставить Activity для сохранения выбора и порядка; «Назад» сбрасывает только статус результата, не создаёт новый запрос и не начинает скачивание. После закрытия/повторного открытия старая успешная операция не должна воспроизводиться. Сохранить предотвращение повторной отправки, отмену, освобождение object URL, ошибки и информацию о сохранённых серверных данных при dirty draft.

Альтернативы — вложенный Dialog, эффект от отдельного cached success и новый общий store — усложняют фокус или создают ложные/повторные результаты. Сообщение о фактическом сохранении файла в папку из примера не используется: браузер не подтверждает запись на диск.

## Risks / Trade-offs

- [Изменение затронет CSV значений или другие разделы] → ветвить представление по цели только в модуле справочников; проверить старый результат `values` и отсутствие изменений shared-компонента.
- [Устаревшее количество полей или повторная выгрузка при возврате] → брать параметры успешной mutation и тестировать повтор с другим числом полей и счётчик запросов/скачиваний.
- [Ложный успех при отмене, неправильном CSV или смене сессии] → сохранить существующий транспорт и guard, дополнить адресные component/hook-тесты, не показывать успех до запуска скачивания.
- [Потеря доступности при переходе с общего результата] → проверить один Dialog, доступное имя, фокус, Escape, возврат к триггеру и отсутствие конкурирующих заголовков в скрытой форме.
- [Моки выглядят корректно, но реальный контур отличается] → отдельно фиксировать местные и реальные свидетельства; контурные действия и выбранный контур требуют отдельного разрешения.

## Migration Plan

1. В существующем владельце добавить локальное представление двух результатов и подключить параметры успешной mutation; транспорт и payload не менять.
2. Обновить component/hook-тесты для реестра, карточки, ошибок и отдельного CSV значений; выполнить проверки проекта и согласованную локальную интерактивную проверку.
3. Данных и миграций нет; откат — вернуть прежнее отображение результата справочников, не меняя серверные операции.
