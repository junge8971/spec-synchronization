## Context

Пользователь принял бизнес-контракт выгрузки v1.0 от 07.10.2026 (PDF `250776803_9c94c874344540509672a745a85bfb44-071026-2008-1066.pdf`) и предложенное правило отметок. Прежний BLOCKED API снят. Старые auth-положения PDF не реализуются в рамках текущего этапа. Принятие не доказывает доступность внешнего backend/ЕСК.

## Goals / Non-Goals

**Goals:** полная серверная выгрузка трёх охватов, верные wire-запросы, доступная форма, правдивые состояния и безопасная доставка готового CSV.

**Non-Goals:** backend/ЕСК, browser CSV encoder, обход detail/search для сборки файла, jobs/polling, история/расписание, собственные auth/session/RBAC, аудит, E2E/browser-тесты.

## Decisions

1. **Принятый wire-контракт:** POST `/api/control/api/dialogs/v1/dialogs/export`, JSON, ровно один непустой `chat_ids` или `selection` (null трактуется как отсутствие). GET `/api/control/api/dialogs/v1/dialogs/{chat_id}/export`, без тела/query. Успех строго HTTP 200, binary CSV; ошибки JSON `{code,data:null,message,errors}`. Подробности публикуются в `docs/api/contracts/dialog-export.md` и OpenAPI.
2. **Отбор:** только applied selection MOS-1037/1038, без sort/cursor/draft; в форме заменяется только period. В форме today/last_7_days/last_30_days/previous_month/custom, без all_time; при исходном all_time/отсутствующем периоде явный default last_30_days. Начальные колонки — все 24, include_parameters=false. Счётчик через search с тем же selection и limit=1, с отменой устаревших поисков и без выдачи старого total за текущий. Ошибка счётчика показывается, но не подменяет результат export API.
3. **Форматы отбора:** dialogs — непустые fields из каталога 24 полей; messages — восемь фиксированных колонок, fields не отправляется, выбор полей недоступен. include_parameters доступен обоим форматам. Порядок колонок определяет серверный каталог, не порядок выбора.
4. **Отмеченные:** POST только `{chat_ids}`, без selection, периода и опций; сервер возвращает dialogs, 24 колонки, без параметров. Недоступные/несуществующие IDs пропускаются сервером без счётчика пропусков. UI объясняет это, не обещает соответствие числа строк числу отметок.
5. **Карточка:** GET отдельного метода возвращает пять колонок переписки, не messages-формат реестра. Не наследует отметки или selection; периода и формы нет.
6. **Отметки:** пользователь подтвердил очистку при изменении applied selection; сохранение при сортировке и догрузке страниц. Идентификатор — chat_id. «Отметить показанные» добавляет только загруженные IDs; снятие показанных сохраняет скрытые отметки. Число отмеченных показывается явно. Не вводится checkbox всего серверного результата.
7. **Синхронный жизненный цикл:** запрос → формирование/получение → передача браузеру. Не прерывать export по клиентскому timeout, не повторять автоматически; повтор явный. На время запроса блокировать повторный запуск и изменение параметров формы; закрытие формы во время запроса не отменяет backend-работу. Не писать «скачано»: браузер не подтверждает сохранение. Ошибки сохраняют настройки для исправления/повтора.
8. **Доставка и безопасность:** существующий binary transport поддерживает POST JSON и общую сессию по `control-center-http` и `mpmm-session`. В real mode он подготавливает сессию и отправляет оба X-токена только на разрешённый адрес; в mock mode credentials отсутствуют. HTTP 200, `text/csv; charset=utf-8`, Content-Disposition attachment с UTF-8 filename*, Content-Length, nosniff, no-store. Проверить имя, MIME, размер, UTF-8 BOM и отсутствие JSON вместо файла до создания download URL. Сохранять серверные байты без декодирования/пересборки CSV; Object URL освобождать после передачи браузеру. Для cross-origin требуются доступные заголовки проверки через CORS. Не вводить локальный предел 5000 или timeout 60s: это текущие серверные настройки, не константы клиента.
9. **Серверные обязательства:** полнота всего отбора за пределами страниц; CSV UTF-8 BOM, `;`, LF без последнего LF, quoting по необходимости, апостроф перед `= + - @ TAB CR`, затем quoting. Параметры и имя формирует сервер. Пустая выдача — файл заголовков. 413 EXPORT_TOO_LARGE — сузить отбор/число отметок; 422 — поля запроса; 503 — отказ/timeout; 401/403/404/500 сохраняются как ошибки исходного запроса. В real mode общий транспорт обрабатывает 401 по `mpmm-session`, включая переход в MPMM при невосстановимой сессии, без автоматического повтора экспорта; 403 не запускает refresh. Feature не реализует собственную auth-последовательность. У карточки нет 413/422, у реестра нет 403/404.
10. **Граница реализации:** production frontend принимает готовый серверный файл. HTTP fixtures моделируют контракт и проверяют три охвата, два формата, Unicode, кавычки, переносы, формульный текст, файл длиннее страницы и ошибки; они не подтверждают реализацию серверного CSV/ЕСК. Dev-mock не синтезирует ложный export из текущей страницы: до отдельной реализации backend отдаёт 503 с контрактным сообщением.

## Risks / Trade-offs

- При недоступном backend UI покажет ошибку, а не фиктивный CSV.
- При HTTP 200 с ошибочным MIME/JSON, отсутствующих безопасных заголовках или несовпадении длины файл не скачивается. CORS должен открыть заголовки, иначе безопасная проверка невозможна.
- Счётчик и файл — разные снимки, число может измениться; лимит проверяется сервером повторно.
- Сервер может пропустить отмеченные IDs; UI не придумывает число пропущенных.
- Политика CSV и server-side доступ проверяются backend; клиент не добавляет auth-контекст ради строки автора.

## Migration Plan

Опубликовать принятое решение/схемы, расширить binary POST, реализовать feature и отметки, подключить реестр/карточку, добавить HTTP/unit/component fixtures и явный mock 503, выполнить проверки. При недоступности backend параметры сохраняются для повтора. E2E/browser не создаются и не запускаются.
