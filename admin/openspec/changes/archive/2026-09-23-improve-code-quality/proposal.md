## Why

Незакоммиченная интеграция Control Center содержит смешение ответственностей в mock-сервере и HTTP-клиенте, а существующий lint допускает завершение с предупреждениями. До фиксации этих изменений нужно сделать код удобнее для сопровождения и закрепить проверяемые требования, чтобы следующие изменения агента не возвращали эту сложность.

## What Changes

- Уточнить проектный `AGENTS.md`: декомпозиция по ответственности, предметные имена, читаемость важнее минимального числа строк, запрет абстракций без реальной пользы и обхода проверок.
- Сделать предупреждения ESLint блокирующими для `yarn lint` и staged-проверки; сохранить текущий порог complexity 10 без массовых подавлений и новых зависимостей.
- Проверить весь текущий незакоммиченный исполняемый код, включая новые файлы в `app/`, `mocks/`, `scripts/`, тесты и конфигурацию. Рефакторить только там, где есть конкретная проблема.
- Разделить инфраструктуру и предметные обработчики mock-сервера; упростить HTTP-клиент, URL-параметры и затронутый UI без изменения внешнего поведения.
- Сохранить тестовое покрытие поведения, добавить недостающие существенные и граничные сценарии для изменяемой логики, выполнить полный набор проверок.

## Capabilities

### New Capabilities

- `code-quality-gates`: требования к работе агента и проверяемое поведение lint-команд, запрещающее успешное завершение с предупреждениями.

### Modified Capabilities

Нет. Контракты API и пользовательские сценарии не меняются; рефакторинг реализации не создаёт новых продуктовых требований.

## Impact

- `AGENTS.md`, `package.json`, `lint-staged.config.ts`, при необходимости `eslint.config.js`; затронутый незакоммиченный код приложения, моков, тестов и dev tooling.
- Существующий change `connect-control-center-http-client` остаётся источником требований интеграции; его реализация в рабочем дереве — основа рефакторинга, а не повод откатить её к HEAD.
- Генерируемый `app/shared/api/schema.d.ts`, API-контракты, seed-данные и установленные `.agents/skills/` не подлежат ручной декомпозиции. Документация обновляется только для отражения новых правил или структуры.
- Новые зависимости, новые функции продукта, изменение API и массовая переработка уже закоммиченного кода вне затронутых зависимостей не планируются.
