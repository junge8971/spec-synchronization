## Purpose

Закрепить понятные правила сопровождения кода агентом и единый проверяемый барьер качества, который не позволяет считать lint с предупреждениями успешной проверкой.

## ADDED Requirements

### Requirement: Project agent guidance defines readable decomposition

Проект SHALL предоставлять в `AGENTS.md` требования к декомпозиции по ответственности, предметным именам, явному потоку управления и сохранению поведения. Требования SHALL предпочитать читаемость краткости, запрещать дробление только ради метрик и абстракции без текущей необходимости.

#### Scenario: Function mixes responsibilities

- **WHEN** агент изменяет функцию, совмещающую самостоятельные ответственности
- **THEN** он оценивает выделение именованных операций по смыслу, а не по числу строк, и проверяет вызывающие места

#### Scenario: Existing code is already cohesive

- **WHEN** затронутая функция решает одну понятную задачу и не содержит существенного дублирования
- **THEN** правила не требуют добавлять обёртки или новые файлы ради формальной декомпозиции

### Requirement: Lint warnings block acceptance

Полная lint-проверка проекта и lint-проверка staged-кода SHALL завершаться ненулевым кодом при наличии хотя бы одной оставшейся ошибки или предупреждения. При отсутствии диагностик lint SHALL завершаться успешно. Проверки SHALL охватывать поддерживаемый рукописный код приложения, моков, скриптов, тестов и конфигурации.

#### Scenario: Warning without errors

- **WHEN** проверяемый код вызывает предупреждение о сложности, но не содержит lint-ошибок
- **THEN** полная проверка завершается неуспешно, а staged-проверка блокирует commit, если этот код входит в staged-набор

#### Scenario: Clean code

- **WHEN** в проверяемом коде нет ошибок и предупреждений
- **THEN** lint-проверка завершается с кодом 0

### Requirement: Quality rules cannot be bypassed to accept a refactor

Правила для агента SHALL запрещать повышение порогов сложности, широкие исключения файлов, отключение правил и ослабление тестовых утверждений только ради зелёных проверок. Любое необходимое исключение SHALL иметь конкретное обоснование и минимальную область действия.

#### Scenario: Refactored code still exceeds complexity limit

- **WHEN** после декомпозиции остаётся предупреждение о сложности
- **THEN** агент продолжает упрощение либо явно сообщает о препятствии, а не скрывает предупреждение изменением порога

### Requirement: Verification reports distinguish executed and missing checks

Правила для агента SHALL требовать проверки сохранения поведения, просмотра итогового diff, запуска подходящих проверок типов, lint, форматирования и тестов, а для соответствующих изменений — сборки, E2E и актуальности генерируемых API-типов. Итог SHALL различать успешные проверки, ошибки и проверки, которые не выполнялись.

#### Scenario: Environment prevents verification

- **WHEN** проверка недоступна или падает по причине вне изменения
- **THEN** агент сообщает команду и причину ограничения и не объявляет эту проверку успешной

#### Scenario: Logic is refactored

- **WHEN** меняется структура нетривиальной логики
- **THEN** существенный сценарий и граничный случай остаются покрыты исполняемыми тестами; существующие подходящие тесты переиспользуются без обязательного дублирования
