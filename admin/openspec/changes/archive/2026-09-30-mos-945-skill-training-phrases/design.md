## Context

См. proposal.md. Пользователь предоставил `/home/user/Загрузки/openapi-mos-809.json` и разрешил работать без дополнительных уточнений. GET карточки возвращает intents, PUT `/skills/v1/skills/{skill_id}/intents` принимает expected_version и набор intents, требует Idempotency-Key. `/skills/new` остаётся заглушкой.

## Goals / Non-Goals

**Goals:** серверные группы плюс локальный несохранённый draft, пригодный для вкладки и шага мастера.

**Non-Goals:** копирование локального реестра/таймера обучения из прототипа, весь мастер создания, проверка глобальных конфликтов.

## Decisions

- **API принят для текущего этапа:** использовать DTO предоставленного контракта без вымышленных полей. Имя группы 1–255 символов, текст фразы 1–500, минимум одна фраза в группе; intents допускает пустой массив. Лишних лимитов и проверки дубликатов не вводить. PUT отправляет весь редактируемый набор, включая неизменяемые редактором description/entities/is_active/sort_order и веса сохранившихся фраз. ID существующих групп сохранять, для новых ID не отправлять.
- Передавать версию загруженного набора и Idempotency-Key штатным HTTP-клиентом, не делать автоматических повторов записи. Не уточнённые ошибки обрабатывать общим механизмом API без потери draft. После успеха показывать подтверждённый PUT набор и обновлять GET карточки; ошибка повторного чтения не отменяет подтверждённое сохранение.
- По предоставленным скриншотам вкладка «Обучающие фразы» по умолчанию показывает карточки групп с фразами-чипами и кнопку «Изменить» справа сверху. В режиме редактирования сверху доступны «Отмена»/«Сохранить», каждая группа — отдельная карточка с названием, иконкой удаления, построчным полем и счётчиком, добавление группы — снизу. Сохранение и отмена возвращают просмотр; ошибка оставляет редактор. Счётчик вкладки отражает сохранённое количество групп. Служебная информация о версии остаётся компактно под группами. Конфликты фраз и блоки ревью со скриншотов не имитируются.
- Редактор — отдельная feature, API — entities/skill, композиция — widget. Не импортировать будущую feature создания в feature редактора; общую форму поднимать только к реальному общему владельцу.
- В карточке парсить непустые строки; в шаге мастера — строки и запятые по задаче. Нормализация для глобальной проверки принадлежит MOS-1018/backend; split/trim не объявляется алгоритмом конфликтов.
- Отмена возвращает последний серверный набор. Ошибка сохраняет draft. Фоновое чтение не перезаписывает изменяемую форму. При уходе со страницы защищать несохранённые изменения, при смене вкладки сохранять смонтированный редактор.
- Отображать только сохранённую версию навыка. Статус применения/дообучения отсутствует в API: явное информационное сообщение, без таймера, ETA или обещания активации.

## Dependencies and acceptance gate

Индикатор применения фраз и дообучения отложен до контрактного источника (связан с MOS-1019); отсутствие источника по решению пользователя не блокирует редактор. MOS-1018 добавляет проверку отдельным change. Для интеграции шага мастера нужен отдельный согласованный change создания навыка; пока его нет, соответствующая задача остаётся незакрытой. Component-проверка парсера не заменяет приёмку мастера.

## Risks / Trade-offs

- Потеря draft при refetch/смене навыка → явная отмена/защита несохранённого ввода.
- Сохранение новой версии при работающей старой → показывать обе версии по серверу, не переключать применённую локально.

## Migration Plan

Подключить только контракт MOS-945 из предоставленного файла и заменить intents unavailable. Откат возвращает unavailable, не откатывая сохранённые фразы на сервере.
