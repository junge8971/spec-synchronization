## Context

См. proposal.md. Источник требований — два скриншота MOS-909: «Подключить жизненный цикл и одиночный выкат навыка», «Доработать шкалу этапов и доступные команды по серверному состоянию». Пользователь явно разрешил предположения. Архивы прежних поставок не переоткрываются; delta skill-lifecycle заменяет G5. Основной spec read-only статуса сохраняется.

Новая выгрузка `/home/user/Загрузки/message.txt` структурно сравнена с полным OpenAPI: набор paths и operations идентичен, схем 156. Новые ограничения есть только у weight и ID группы. SkillResponse.required поменял порядок, не набор. Нет allowed_actions, истории этапов, результата задач или operation-status endpoint.

Наблюдения по коду: `SkillDetails` читает detail query, сохраняет старые данные при ошибке refetch. `useUpdateSkillMutation` уже отменяет устаревшие detail-запросы перед записью ответа и инвалидирует остальные skills queries. `skill-intents-schema.ts` допускает любой числовой weight. `mocks/domains-skills.mjs` уже реализует POST status с версией и идемпотентностью; принимает любой опубликованный enum. Contract-document tests сверяют все самостоятельные разделы, 40 операций и 156 схем. Генератор типов использует только repo OpenAPI.

## Goals / Non-Goals

**Goals:** законченный UI трёх одиночных команд, серверная шкала текущего этапа, обновлённый контракт и проверяемые моки; явное различение подтверждённого ответа, отказа и неизвестного исхода.

**Non-Goals:** моделирование результатов обучения/автотестов, решения ревью, bulk, отключение, новый auth-контекст, изменения мастера регистрации, фиктивное прохождение цепочки таймерами. Число version — версия записи, не релиз.

## Decisions

### 1. Матрица — продуктовое допущение, не извлечённая из OpenAPI гарантия

| Серверный status | Команда               | Целевой status |
| ---------------- | --------------------- | -------------- |
| draft            | Отправить на проверку | checking       |
| checking         | Нет команды перехода  | —              |
| training         | Нет команды перехода  | —              |
| autotest         | Нет команды перехода  | —              |
| sandbox          | Отправить на ревью    | review         |
| review           | Нет команды перехода  | —              |
| whitelist        | Выкатить в прод       | prod           |
| prod             | Нет команды перехода  | —              |

Линейная кнопка «Далее» отвергнута: она подменяла бы серверное завершение проверок и решение ревью. Отдельный `/publish` не выдумывается. Целевой контур прод соответствует `status=prod`; других контуров request не принимает. Смена статуса подтверждает состояние записи, а не факт развёртывания отдельного runtime. `rejected`, `approved`, `disabled` не входят в enum и не добавляются; неожиданный статус остаётся ошибкой detail-контракта.

### 2. Шкала без фиктивной истории

Порядок draft/checking/training/autotest/sandbox/review/whitelist/prod. Текущий элемент с текстом «Текущий этап» и aria-current=step; остальные нейтральные, без галочек «успешно». Пояснение: «Показан текущий статус. Результаты прохождения этапов API не предоставляет». Отдельная кнопка обновления использует существующий detail refetch; нет нового status-query или polling. При refetch error старые данные остаются видимыми, но команды записи блокируются до успешного чтения.

### 3. Владение и переиспользование

Новая feature `skill-lifecycle` владеет шкалой, подтверждением, матрицей в constants, состоянием операции и именованными handlers/types. Widget компонует её над вкладками и передаёт актуальный skill/refetch/error/loading. HTTP-клиент и mutation hook — entities/skill, внешний доступ через index.ts. Переиспользовать detail schema и Query-ключи, как updateSkill, без второго SkillStatus/SkillDetails. UI — имеющиеся Card/Button/Dialog; доступный заголовок, управление фокусом и отмена без POST. Не редактировать framework routes.

### 4. Команда и ошибки

Диалог показывает имя/ID навыка, исходный и целевой этап, а при prod — явное предупреждение о выкате. При открытии фиксируются status/version; если фоновые данные изменились, подтверждение становится недоступным и требуется новое открытие. Перед POST повторно проверить матрицу и snapshot. Синхронный in-flight guard плюс disabled-кнопка, `retry: false`, один UUID ключ на попытку. Отправлять только status и expected_version.

При валидном 200 использовать SkillResponse как источник истины, отменить старые detail-запросы, обновить detail и инвалидировать список/каталоги. Сообщать целевой успех лишь если status ответа равен цели; иначе показать фактический status и предупреждение о несовпадении, не подменять ответ.

При 422 показывать безопасное сообщение/ошибки полей из существующего error layer. При 409 — конфликт, перечитать detail, не повторять с новой версией. Не публиковать конкретный backend conflict code, которого нет в OpenAPI. При network error, timeout, 5xx или невалидном success DTO — неизвестный исход: запрет повторной отправки, действие только «Обновить состояние». После успешного GET показывать фактическое состояние без утверждения, что именно эта команда его вызвала. Новый осознанный запрос допустим только после нового успешного чтения и подтверждения, с предупреждением о неизвестном результате предыдущей команды; никаких автоматических replay и гарантий отмены. После reload текущий серверный status остаётся единственным источником; долговременный журнал команд не создаётся.

### 5. Контракт и фразы

Полный OpenAPI принять из новой выгрузки после проверки отсутствия потерь. Самостоятельный Skills/Domains пересобрать с замыканием локальных ссылок, остальные разделы сверить существующими тестами. Отметить в README, что актуальная поставка уже включает intents, прежнее ручное объединение больше не требуется. Не добавлять зависимость от Downloads: источник проверки — repo JSON. Generated файл только `yarn api:generate`.

Request-schema фраз получает weight.min(0); response weight не ужесточать сверх response-контракта. UUID группы разрешён любой версии, ID навыка в path остаётся UUIDv7. Проверить всех потребителей request-schema, включая мастер и редактор, не обнулять/не удалять отрицательные веса молча. Границы: 0 разрешён, отрицательный запрещён, omitted weight остаётся 1; UUIDv4 группы принимается, malformed UUID отвергается.

### 6. Моки

Существующие маршруты/seed сохраняются. Общая контрактная валидация подхватит minimum и UUID; дополнить тестами. POST status по-прежнему принимает любой enum: OpenAPI не задаёт матрицу, mock не должен запрещать установку промежуточных состояний для проверки UI. Проверить три UI-перехода, перечитывание list/detail, сохранение intents, увеличение версии один раз, replay, конфликт версии, другой body с тем же key, невалидный enum. Ошибки 409/404 и replay остаются документированной mock-конвенцией, не заявлением о production. Никаких таймеров автоматического прохождения этапов; seed уже содержит все восемь состояний.

## Risks / Trade-offs

- Backend может отклонить предполагаемый переход → сохранять фактическое состояние и показывать отказ; матрица локализована в одной feature.
- Нет operation-status/replay guarantee → при неизвестном исходе только чтение, без автоматического повторного POST; новый осознанный запрос не объявляется безопасным replay.
- Нельзя восстановить историю из одного status → нейтральные остальные этапы, без вымышленных успехов.
- Автопроцессы не моделируются mock → тестировать состояния готовым seed/явными HTTP-командами, не обещать end-to-end обучение.
- Прежние tests запрещают любой lifecycle UI → заменить только устаревшие assertions, сохранить GET-only открытие карточки, guards прочих API и ошибки неизвестного status.

## Migration Plan

Сначала контракт/типы/request-validation/mock tests, затем status client/feature/widget tests. Выполнить typecheck, lint, test, format:check, api:check; build при изменении сборки. Browser/E2E не запускать и не менять. Откат UI не откатывает серверные статусы: убрать feature, сохранить read-only status и обновлённый контракт. Перед sync проверить соседние specs/changes MOS-1019/1020/1021/1027: запреты на вымышленные операции сохраняются, три явно принятых команды принадлежат MOS-909.
