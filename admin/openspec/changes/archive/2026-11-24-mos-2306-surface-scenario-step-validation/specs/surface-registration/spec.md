## ADDED Requirements

### Requirement: Scenario step requires a valid current skill selection

На шаге «Сценарии» регистрации «Далее» SHALL быть доступна только при валидном приветствии, выборе хотя бы одного навыка и успешной текущей проверке всех выбранных навыков и их параметров по правилам `surface-skill-selection`. Пустое обязательное значение, значение вне актуальных options, некорректная схема либо неподтверждённый состав SHALL блокировать переход на шаг «Проверка». До завершения загрузки или обновления каталога и данных выбранных навыков, при ошибке их чтения либо во время подготовки окончательной отправки переход SHALL оставаться недоступным, даже если сохранены ранее загруженные данные.

Обработчик перехода SHALL соблюдать то же условие готовности независимо от состояния кнопки. Начатая проверка MUST NOT переводить мастер на следующий шаг по прежнему валидному состоянию, если к моменту перехода текущий выбор или его параметры невалидны либо данные ещё обновляются. Проверка перехода SHALL использовать уже загруженные данные; само действие «Далее» на шаге сценариев MUST NOT запускать отдельное принудительное обновление каталога, создавать или сохранять поверхность.

Причина недоступности перехода SHALL быть видна без hover и программно связана с кнопкой «Далее»; ошибки параметров SHALL оставаться у соответствующих полей с доступным обозначением невалидного состояния. Исправление параметра SHALL пересчитывать готовность без сброса анкеты, ответственных, приветствия, выбора и остальных параметров. Переход SHALL требовать нового явного действия пользователя после исправления. Возврат на шаг, очистка значения и индивидуальное либо массовое изменение выбора SHALL применять ту же проверку к текущему составу; параметры снятых навыков MUST NOT блокировать другой валидный непустой выбор.

Необязательные пустые параметры, навыки без схемы настроек и валидные defaults SHALL сохранять действующие правила `surface-skill-selection` и сами по себе не блокировать переход. Успешный переход на шаг «Проверка» MUST NOT заменять независимую повторную проверку навыков и их параметров непосредственно перед окончательным POST создания.

#### Scenario: One selected skill has an empty required parameter

- **WHEN** шаги 1 и 2 заполнены валидно, на шаге 3 выбран только один продовый навык с обязательным select без default, значение не выбрано и приветствие валидно
- **THEN** у параметра видна ошибка обязательного значения, «Далее» недоступна, мастер остаётся на шаге «Сценарии» и запрос создания не выполняется

#### Scenario: Correcting the required parameter enables explicit navigation

- **WHEN** пользователь выбирает допустимое значение обязательного параметра и остальные проверки шага успешны
- **THEN** ошибка снимается, «Далее» становится доступной, а шаг «Проверка» открывается только по новому явному действию с сохранёнными значением параметра и данными формы, без создания поверхности

#### Scenario: Handler cannot bypass an invalid selection

- **WHEN** обработчик перехода вызван при невалидных параметрах выбранного навыка независимо от состояния кнопки, в том числе повторно
- **THEN** мастер остаётся на шаге «Сценарии», ввод сохраняется и запрос создания не выполняется

#### Scenario: Loading and failed refresh do not reuse earlier readiness

- **WHEN** каталог или данные выбранного навыка ещё загружаются либо обновляются, или обновление завершилось ошибкой при наличии ранее валидных данных
- **THEN** «Далее» и обработчик блокируют переход, показано соответствующее состояние загрузки или ошибки с повтором; после успешного завершения чтения готовность пересчитывается по текущему вводу

#### Scenario: Input becomes invalid while navigation validation is pending

- **WHEN** проверка перехода начата для валидного шага, но до её завершения обязательный параметр очищен либо началось обновление данных выбранного навыка
- **THEN** прежний результат не открывает шаг «Проверка», текущий ввод сохраняется и после восстановления готовности требуется новое явное действие

#### Scenario: Optional and absent settings remain valid

- **WHEN** выбран хотя бы один проверенный продовый навык, все обязательные параметры и приветствие валидны, а часть параметров необязательна и пуста либо у выбранного навыка нет настроек
- **THEN** эти пустые значения не блокируют переход на шаг «Проверка» и не превращаются в новые обязательные поля

#### Scenario: Valid defaults can be cleared explicitly

- **WHEN** обязательный параметр получил допустимый default, а затем пользователь явно очистил его
- **THEN** до очистки default удовлетворяет проверке, после очистки переход блокируется, а фоновая инициализация не восстанавливает значение вместо пользовательского исправления

#### Scenario: Returning and changing selection recomputes readiness

- **WHEN** пользователь возвращается с шага «Проверка» и очищает обязательное значение либо добавляет навык с незаполненным обязательным параметром индивидуально, через домен или «Включить все»
- **THEN** переход снова блокируется, ранее введённые данные сохранены; снятие проблемного навыка разрешает переход при наличии другого валидного выбора, а «Снять все» оставляет переход недоступным

#### Scenario: Final creation still checks fresh skill data

- **WHEN** шаг «Проверка» открыт для валидного выбора, но обновлённые перед окончательной отправкой данные навыка больше не допускают этот выбор или параметры
- **THEN** создание блокируется действующей повторной проверкой без POST, данные сохраняются для исправления и ранее успешный переход не считается разрешением на запись
