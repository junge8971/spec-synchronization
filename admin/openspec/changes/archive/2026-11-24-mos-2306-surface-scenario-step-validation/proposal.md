# Proposal

## Why

В [MOS-2306](https://task.mos-team.ru/browse/MOS-2306) мастер регистрации поверхности разрешает переход с шага «Сценарии» на «Проверка», когда выбран один настраиваемый навык с пустым обязательным параметром: ошибка у поля уже видна, но «Далее» доступна. По текущему коду переход проверяет только наличие выбранного навыка и приветствие, а валидация параметров участвует лишь в отображении ошибок и подготовке окончательного POST.

## What Changes

- Разрешать переход с шага 3 на шаг 4 только при валидном приветствии, непустом выборе навыков и успешной текущей проверке всех выбранных навыков и их параметров.
- Использовать одно условие готовности для недоступности «Далее» и защиты самого обработчика перехода; загрузка, обновление и ошибки каталога либо данных выбранных навыков не должны разрешать переход по старому результату.
- После исправления обязательного параметра разрешать обычный переход без сброса формы. Сохранить допустимость пустых необязательных параметров, навыков без настроек и валидных defaults по действующим правилам `surface-skill-selection`.
- Сохранить ошибки у соответствующих полей и доступную причину блокировки; повторно применять готовность после возвращения на шаг и изменения выбора, включая массовые операции.
- Сохранить независимую повторную проверку каталога, статусов, схем и параметров непосредственно перед созданием поверхности. Переход к сводке сам не создаёт и не сохраняет поверхность.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `surface-registration`: добавить явное требование к готовности шага «Сценарии» и блокировке перехода до исправления обязательных параметров выбранных навыков.

## Impact

- Планируемые точки интеграции: `app/widgets/surface-registration/ui/surface-registration.tsx`, модель и типы `app/features/surface-registration/`, необходимые элементы доступного сообщения в UI регистрации.
- Переиспользуются публичный контроллер `surface-skill-selection`, его `issues` и состояния загрузки/ошибок. Правила предметной валидации и API общего редактора не требуют нового контракта; отдельная delta для `surface-skill-selection` не нужна.
- Регрессии закрепляются существующими unit/component-контурами обработчиков и виджета регистрации. Точный fixture воспроизведения должен иметь обязательный select без default; текущий интеграционный fixture содержит необязательный параметр с default.
- Новые зависимости, endpoints, DTO, миграции и изменения auth/session/permissions не требуются. Пустой состав при редактировании существующей поверхности остаётся допустимым.
- MOS-2303 закрыта по решению пользователя и не входит в change. Создаются только планирующие артефакты; код приложения, основные specs и внешние задачи не изменяются. Browser/E2E-тесты не входят в scope.
