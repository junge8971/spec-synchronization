## Context

См. proposal.md для источников и границы согласования. `app/routes/dialogs.tsx` — PlaceholderPage; предметной модели диалога нет. Соседние entities используют Zod, общий apiRequest и TanStack Query; route-модули остаются тонкими адаптерами React Router. `app/shared/api/http-client.ts` сейчас разбирает errors только как `{ message }`, теряя дополнительные field/code, нужные новому контракту.

## Принятый контракт

Пользователь подтвердил принятие контракта в текущем обсуждении («принимаем контракт»).
Опубликованная бизнес-часть: [контракт реестра](../../../docs/api/contracts/dialogs.md).
Принята бизнес-часть [PDF v1.0](/home/user/Загрузки/241085439_bf1810bba3974ef1b9dbac2d3a41d66b-051026-1642-740.pdf), разделы 2.4, 2.6, 3.1–3.2:

- `chat_id` адресует диалог; ЕСК выполняет серверный поиск, сортировку и курсорную пагинацию по принятому контракту.
- Календарные периоды включают обе даты; относительные границы определяет сервер и фиксирует в cursor. Часовой пояс центра управления — `Europe/Moscow`, время ответов — UTC.
- Справочники приходят из ЕСК в порядке источника; неизвестные IDs сохраняются в отборе и ничего не находят.
- `data_updated_at` — момент обновления поисковых данных источника, при отсутствии — null.

Это согласование бизнес-контракта, не результат проверки доступности развёрнутого ЕСК. Auth/session/RBAC из PDF не входят в принятый scope. Методы detail/attachments остаются у MOS-1041.

## Goals / Non-Goals

**Goals:** один владелец selection/search/dictionaries, серверная пагинация без гонок, проверяемая интеграция после gate.

**Non-Goals:** экспорт, локальный поисковый индекс, live polling, auth/session/RBAC, перенос прототипных ролей и демонстрационных данных.

## Decisions

1. **Контрактный gate принят пользователем.** Бизнес-часть PDF v1.0 принята в указанном выше объёме. До интеграции зафиксировать принятую бизнес-часть в `docs/api/contracts`, обновить OpenAPI и generated DTO штатным генератором. Не редактировать schema.d.ts вручную. Наличие spec не подтверждает готовность ЕСК. Другие changes добавляют свои методы к тому же контракту, не создают восемь DTO-моделей.
2. **Владение:** `entities/dialog` содержит wire-схемы и общий selection; реестр компонуется в `pages/dialogs` (widget только при оправданной ответственности). Features конструктора/сохранения получают selection и callbacks от владельца страницы, не импортируют друг друга. Типы, runtime-справочники операторов и обработчики размещаются в сегментах владельцев; внешние импорты через index.ts.
3. **Без нового state framework:** использовать существующий TanStack Query, для страниц — infinite query с ключом из применённого selection и sort, AbortSignal и непрозрачным next_cursor. Новый отбор/сортировка сбрасывает цепочку. Не переносить getAllSkills/offset-паттерн на диалоги и не загружать всё ради фильтрации. Общие JSON-ошибки сохраняют field/code без ослабления проверки envelope, это нужно всем формам диалогов.
4. **Selection v1:** q, period, channel_ids, skill_ids, condition_group, time_zone. Быстрые фильтры и группа соединяются AND. Пустые массивы не ограничивают; неизвестные справочные IDs не удаляются молча. Без периода — all_time в пределах глубины хранения. Пресеты today/last_7_days/last_30_days/previous_month/all_time/custom; custom передаёт календарные даты включительно. UI не вычисляет UTC-границы относительного периода. Для отображения времени использовать Intl с согласованным поясом, не локальный пояс браузера.
5. **Выдача:** шесть колонок, первые два навыка и количество остальных, независимые has_operator/has_failure. authorized_in_dialog в реестре также получает пометку «без авторизации» согласно PDF. sort: ±started_at, ±ended_at, ±channel, ±operator_rating, ±duration; дефолт -started_at. Nulls-last и второй ключ chat_id обеспечивает сервер. Limit по умолчанию 25, допустимо 1–100.
6. **Ошибки и актуальность:** отдельно initial error и ошибка следующей страницы; повтор последней не теряет строки. total — последний серверный снимок, data_updated_at null скрывает подпись. Новая выдача не смешивается со старой. Инвалидный cursor предлагает начать заново, а не повторяется бесконечно. 401/403 — ошибка бизнес-запроса без auth-последовательности. Справочники независимы от текстового/периодного поиска.
7. **URL не решать здесь ценой утечки:** до gate MOS-1040 не сериализовать чувствительный selection в адрес автоматически. React Router управляет переходом в detail и basename; перенос поискового состояния в URL выполняется по согласованному формату MOS-1040, без ручной замены history API.

## Risks / Trade-offs

- ЕСК не поддержит весь поиск (8.2) → остановить интеграцию неподтверждённых возможностей, не эмулировать на странице.
- Изменяемые поля сортировки → keyset не означает неизменный snapshot; total может меняться, не обещать frozen-выборку.
- Общий errors-parser потеряет JSON Pointer → regression-тест общих HTTP-ошибок и тест адреса условия.
- Длинный текст обращения → безопасный текстовый рендер и сокращение представления без изменения исходного значения; подсветка без raw HTML.
- Период пересекает полночь → не пересчитывать selection между курсорными запросами; границы фиксирует серверный cursor.

## Migration Plan

После gate опубликовать бизнес-схемы, реализовать HTTP и fixtures только в штатном mock server/tests, затем заменить route placeholder. MOS-1037 принимается без конструктора/сохранения/экспорта. Проверить unit/component/server-сценарии; браузерные проверки не входят. При откате вернуть точку входа к честной заглушке, не подключать runtime fixtures.
