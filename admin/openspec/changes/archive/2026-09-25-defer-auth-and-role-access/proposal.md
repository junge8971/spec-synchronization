## Why

Ролевая модель и API авторизации Центра управления ещё не согласованы, но текущие спецификации требуют их использования, а отсутствие источника прав блокирует навигацию. На текущем этапе нужны UI и бизнес-логика без зависимости от сессии, выдуманных разрешений и технической авторизации локальных моков.

## What Changes

- Закрепить в `AGENTS.md` и `openspec/config.yaml` ограничение текущего этапа: UI, бизнес-логика и согласованные бизнес-API; авторизация, сессии и разграничение доступа отложены до отдельного согласования и изменения спецификаций.
- **BREAKING** Удалить модель доступности по permissions, запрос текущего пользователя и заготовку выхода. Существующие маршруты доступны без сессии; отсутствие маршрута остаётся самостоятельной причиной недоступности.
- Сохранить справку и доступность оболочки, отвязав их от профиля; отметку просмотра хранить локально по версии справки без user ID.
- **BREAKING** Согласованно удалить token provider и автоматическую подстановку Bearer из транспорта, обязательный Bearer из mock server и mock текущего пользователя. Не вводить auth bypass, фиктивного администратора или переключатель ролей.
- Сохранить бизнес-валидацию, идемпотентность, реальные HTTP-ошибки 401/403 и изоляцию mock server от production.
- Актуализировать требования и unit/component/server-тесты; E2E не создавать, не изменять и не запускать без отдельного разрешения.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `control-center-shell`: ограничения текущего этапа, навигация без прав, оболочка без профиля/выхода, локальная справка без пользователя.
- `control-center-api-integration`: исключение current principal из обязательных интеграций, отсутствие auth-запросов оболочки, проверка сценариев без обязательного browser smoke.
- `control-center-http`: транспорт без автоматической авторизации с сохранением заголовков мутаций и ошибок.
- `control-center-mock-server`: бизнес-операции без Bearer, исключение auth endpoint из текущего покрытия, сохранение контрактной валидации и production isolation.

## Impact

- `app/shared/config/application-routes.ts`, widgets navigation/layout/header, `app/entities/user`, `app/shared/api/http-client.ts` и связанные тесты.
- `mocks/app.mjs`, access handler/seed и server-тесты, mock-документация; `vite.config.ts` — удаление клиентского define, если после удаления dev-токена он больше не используется.
- `AGENTS.md`, `openspec/config.yaml`, четыре спецификации и актуальные указатели объёма работ в `docs/tasks/control-center/`.
- Исходные OpenAPI и сгенерированные DTO не переписываются: наличие auth-схем в поставленном контракте не означает разрешение на их реализацию. Покрытие локального mock server явно ограничивается 27 бизнес-операциями вместо прежних 28 операций с Access.
- Новых зависимостей нет. Серверная безопасность реального backend не меняется; открытый локальный mock server не является production-режимом доступа.
- Уже имеющиеся пользовательские изменения сохраняются; архивные OpenSpec-артефакты не переписываются. Параллельный change `enforce-fsd-code-decomposition` остаётся самостоятельным.
