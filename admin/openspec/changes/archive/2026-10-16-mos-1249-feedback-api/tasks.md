- [x] 2.3 Зафиксировать реальные HTTP-результаты CRUD/search/lookup/metadata, envelope ошибок/null и доступные результаты MPMM/global scope; завершить приёмку с известными исключениями по явному решению пользователя от 15.10.2026. Проверка: предоставленный отчёт контура Т (117 запросов, 28 PASS / 7 FAIL / 1 SKIP / 2 OWNER), классификация двух GET 503 и пяти избыточных ожиданий leaf-путей; неактивная ссылка, ограниченный global scope и refresh явно непроверены, а не отмечены успешными. Известная проблема и решение о закрытии записаны в proposal/design/specs и ACCEPTANCE.md.

Первоначальные пробы GET metadata и lookup без credentials на контуре Т вернули HTTP 403 от nginx с пустым телом и не подтверждали бизнес-API. Позже пользователь предоставил авторизованный HTTP-прогон `mos1249_1792078927540_77d6ebe5` от 15.10.2026: CRUD/search/lookup/metadata и очистка тестовых записей подтверждены, два контрольных GET вернули 503. Причина 503 не установлена; атомарность именно двух сценариев после PUT 422 не подтверждена. Пять FAIL возникли из-за более строгих, чем опубликованный контракт, ожиданий путей ошибок; бизнес-валидация вернула 422, а для четырёх PUT неизменность данных подтверждена. Неактивная ссылка, ограниченный global scope и refresh не проверены. Пользователь явно решил: «Зафиксируй это в спеках как известную проблему и закрывай задачу». Пункт 2.3 закрыт с этими принятыми исключениями, без утверждения о полном прохождении стенда или исправлении 503.

Актуальный источник включён в aggregate; не возвращать старую выгрузку. Фактические моки уже используют generic managed handlers без unavailable-перечня: специализировать только feedback CRUD/search/lookup/metadata, не менять существующие CSV/saved-filters и соседние разделы.
