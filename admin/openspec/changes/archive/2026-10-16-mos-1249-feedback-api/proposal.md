## Why

[Jira MOS-1249](https://task.mos-team.ru/browse/MOS-1249): [FE][Обратная связь] Подключить API опросников, справочных значений и метаданных.

Нужна отдельная реализуемая поставка этой FE-подзадачи по обновлённому API и принятой границе прототипа. План, приёмка и выполнение учитываются отдельно от остальных задач MOS-1246.

## What Changes

- Типизированные CRUD, поиск, lookup и metadata в `app/optional/feedback`; проверка contract/typegen и контрактные моки. Клиенты saved-filters и CSV реализуются соответственно в MOS-1259 и MOS-1260.
- Сохранить ограничения API, ввод при ошибках, доступность и действующую безопасность.

### Deferred scope

UI реестра/карточки и самостоятельные клиенты saved-filters/CSV принадлежат соседним задачам; общий CRUD справочников и база знаний не подключаются.

## Capabilities

### New Capabilities

- `feedback-api`: Обособленный модуль CRUD, поиска, lookup и metadata с runtime-валидацией, моделью и контрактными моками. Клиенты saved-filters и CSV реализуются соответственно в MOS-1259 и MOS-1260.

### Modified Capabilities

Нет. Общие capabilities HTTP, permissions и MPMM сохраняются; scope соседних FE-подзадач сюда не переносится.

## Impact

`app/optional/feedback` (API, runtime-схемы, модель, типы, константы и тесты), адресные правила архитектурных границ и Express-моки. Aggregate OpenAPI и generated DTO используются из актуальных локальных источников.

Зависимости: Существующие HTTP/session механизмы проекта; переданные API-контракты.

Граница: весь раздел обособлен по примеру `app/optional/knowledge-base`; внешние потребители используют публичный `index.ts`, будущие UI entrypoints подключаются в application. Исполнение правил и сбор реальных ответов пользователей не входят. Новые зависимости не требуются без отдельного обоснования. Новая UI-policy, mappings permissions и ограничения интерфейса по пользователю не входят; существующие защитные механизмы сохраняются.

## Acceptance decision — 2026-10-15

По результатам предоставленного пользователем HTTP-прогона на контуре Т MOS-1249 закрывается с известной проблемой стенда и принятыми ограничениями. Пользователь явно поручил: «Зафиксируй это в спеках как известную проблему и закрывай задачу». Все 9 задач завершены с учётом этого решения; оно не означает успешного выполнения всех стендовых проверок или устранения 503.

Исходный отчёт содержит 117 запросов, 28 PASS, 7 FAIL, 1 SKIP и 2 OWNER. Два FAIL вызваны GET 503 после отклонённых PUT 422; атомарность именно этих двух изменений не подтверждена. Пять FAIL связаны с избыточно точными ожиданиями путей ошибок в ручном Console-скрипте: сервер вернул 422, для четырёх PUT подтверждена неизменность данных, запрос поиска отклонён; ошибки относятся к объекту или форме. Неактивная ссылка, ограниченный глобальный доступ и обновление MPMM-сессии на стенде не проверены и приняты как известные ограничения. Подробные evidence, классификация и оставшиеся действия описаны в design и `/Users/lisa-codesrc/Desktop/feedback/ACCEPTANCE.md`; бизнес-требования и scope реализации сохраняются.
