## Context

См. `proposal.md` для мотивации. `Documentation` хранит query в `useState`, читает только article из `useSearchParams`; `DocumentationCatalog` уже является управляемым компонентом. `searchDocumentationArticleGroups` покрывает все виды блоков и сохраняет порядок каталога. Handler выбора копирует URLSearchParams и сохраняет посторонние параметры. Текущий effect фокусирует статью на узком экране при любом изменении selectedArticleId — при автовыборе это будет прерывать ввод.

Design нужен для согласованной обработки URL, истории и причины выбора статьи. Существующий component-тест ожидает сохранение старой статьи во время фильтрации; это ожидание заменяется новым поведением, не ослабляется.

## Goals / Non-Goals

**Goals:** единый источник состояния в URL; различение ввода, ручного выбора и восстановления навигации; отсутствие промежуточного состояния с новым q и старой статьёй.

**Non-Goals:** новый поисковый движок, ранжирование, подсветка, API, зависимости, изменение текста статей и auth. Не переносить документацию в новый FSD-слой ради этой задачи.

## Decisions

### 1. URL — источник состояния

Читать поле из `searchParams.get('q') ?? ''`, выдачу вычислять существующим поиском. Использовать React Router `useSearchParams` и стандартный URLSearchParams. Отдельный синхронизируемый useState и двусторонние effects не нужны: они создают гонки при истории. На небольшом локальном каталоге debounce не нужен.

Для локального изменения q, ручного выбора article и коррекции неконсистентного URL передавать `defaultShouldRevalidate: false` вместе с `preventScrollReset: true`. Это штатная опция установленного React Router 8.3.1: URL обновляется без повторного выполнения существующих loaders. Иначе root clientLoader повторно вызывает demo bootstrap, публикует checking и скрывает всю оболочку через SessionBoundary, прерывая ввод. Первичная загрузка, явный retry/revalidate и штатная POP-навигация сохраняют свои проверки; root и session runtime не изменяются. Проверять это интеграционно через настоящий ApplicationRoot/clientLoader, а не только изолированный Documentation.

Технические defaults: сохранять исходную строку q, включая регистр и пробелы; нормализовать только сравнение существующим поиском. Пустая строка удаляет q, строка пробелов сохраняется, но показывает полный каталог. Повторяющиеся q/article читать по первому значению согласно URLSearchParams.get; при записи конкретного параметра оставлять одно значение. Остальные параметры, включая повторы, сохранять без изменений. `query` не становится alias для q: существующая legacy-ссылка с query сохраняет прежнее поведение.

### 2. Причины переходов обрабатывать отдельно

| Причина                      | Выбор статьи                                                              | История                                         |
| ---------------------------- | ------------------------------------------------------------------------- | ----------------------------------------------- |
| Изменение поля               | Первый результат нового поиска, даже если прежняя статья всё ещё подходит | replace q и article вместе                      |
| Очистка поля                 | Первая статья полного каталога                                            | replace, удалить q, записать article            |
| Ручной выбор                 | Выбранная статья текущей выдачи                                           | push article, сохранить q                       |
| Прямая ссылка / reload / POP | Подходящий article из URL; иначе первый результат                         | Сохранить валидный URL; коррекция через replace |
| Пустая выдача                | Нет статьи                                                                | replace, удалить article, сохранить q           |

Нельзя реализовывать автовыбор effect-ом «при любом изменении q»: POP тоже меняет q и должен восстановить ручной выбор из той же записи истории. В обработчике ввода вычислять оба новых параметра за один переход. Повторный выбор уже открытой статьи не создаёт дубликат истории.

Default для неконсистентной прямой ссылки: неизвестный или не входящий в выдачу article заменяется первым результатом. При непустом q записывать fallback ID через replace; без q сохранять существующий fallback полного каталога без обязательной канонизации article. Пустая выдача всегда удаляет article. Вычислять допустимую статью до рендера; коррекция URL не должна показывать старую статью, создавать цикл навигации или забирать фокус.

### 3. Фокус зависит от действия

Автовыбор при вводе и коррекция URL не фокусируют статью и не вызывают scrollIntoView. Сохранить фокус/прокрутку после ручного выбора другой статьи на узком экране, а также существующее поведение истории при смене статьи, если оно не вызвано вводом или коррекцией. Первый вход и desktop не прокручивать. Отделить причину выбора от общего наблюдения за ID; учесть отсутствие статьи и отмену отложенного requestAnimationFrame.

### 4. Владение остаётся у документации

URL-разбор и вычисление допустимого выбора разместить в model сегменте `widgets/documentation`, обработчики UI — в handlers владельца. Обновить props для отсутствующего selectedArticleId и условный рендер статьи. Именованные типы хранить в types владельца, использовать публичный API `entities/documentation`. Существующий поиск переиспользовать, не копировать.

Тесты — unit для переходов/нормализации и component с router для реальной истории, фокуса и выдачи. E2E/browser-тесты не создавать, не редактировать и не запускать.

## Risks / Trade-offs

- [Ввод уводит фокус на мобильном] → различать ручной и автоматический выбор; проверять непрерывный ввод нескольких символов и отсутствие scrollIntoView.
- [Восстановление URL сбрасывает ручной выбор] → автовыбор только в обработчике ввода; отдельный тест прямой ссылки на второй результат и POP.
- [Потеря query-параметров или промежуточный URL] → копировать текущие параметры и менять q/article одной навигацией; проверить повторяющиеся посторонние параметры.
- [replace не хранит историю каждого поискового запроса] → намеренный компромисс: история хранит явные переходы между статьями, ввод меняет текущую запись.
- [Старый тест/спека обещают первую статью даже при пустой выдаче] → обновить ожидание и полный requirement оболочки через delta; сохранить сценарии sidebar и legacy redirect.

## Migration Plan

Миграция данных не нужна. Ссылки без q сохраняют прежний выбор; старый /documentation перенаправляется штатно с сохранением параметров. После unit/component и проектных проверок изменение может войти в обычную frontend-сборку. Откат возвращает старое поведение поиска: q останется безопасным неиспользуемым параметром, article продолжит открывать статью.
