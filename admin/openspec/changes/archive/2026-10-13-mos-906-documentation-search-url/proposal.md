## Why

MOS-906 требует воспроизводимый поиск документации по прямой ссылке. Поиск по содержимому уже реализован, но запрос живёт только в локальном состоянии; URL сохраняет лишь статью, поэтому повторное открытие теряет фильтр.

## What Changes

- Связать поле поиска с `q` в URL, сохранив существующий локальный поиск по названию, описанию и блокам с порогом два символа.
- При изменении запроса автоматически открывать первый результат в порядке каталога и записывать его ID в `article` одним обновлением URL.
- Сохранять ручной выбор найденной статьи до следующего изменения запроса; восстанавливать выбранную статью и поиск из прямой ссылки и истории.
- При пустой выдаче показывать «Ничего не нашлось», скрывать статью и удалять `article`.
- Сохранить basename, посторонние query-параметры и доступность. Автовыбор при вводе не должен забирать фокус поиска.

## Capabilities

### New Capabilities

- `documentation-search`: локальный поиск, URL-состояние, автовыбор результата, ручной выбор, пустая выдача и история.

### Modified Capabilities

- `control-center-shell`: уточнить fallback статьи с учётом поисковой выдачи; без фильтра сохранить первую статью полного каталога, при пустой выдаче не показывать статью.

## Impact

- `app/widgets/documentation`: состояние URL, выбор статьи, условный рендер статьи, мобильный фокус и component-тесты.
- `app/entities/documentation`: переиспользование текущего поиска и его unit-тестов; новые API, зависимости и серверный поиск не нужны.
- Существующий тест сохранения прежней статьи при фильтрации заменяется согласованным автовыбором. Спецификация оболочки уточняется явно, основные спеки на этапе proposal не изменяются.
- Auth, содержимое статей и E2E/browser-тесты вне scope.
