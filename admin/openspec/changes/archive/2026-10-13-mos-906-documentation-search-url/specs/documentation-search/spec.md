## Purpose

Обеспечить воспроизводимый поиск по встроенной документации: ссылка сохраняет запрос и выбранную статью, а изменение запроса сразу открывает первый результат.

## ADDED Requirements

### Requirement: Local documentation search

Документация SHALL искать подстроку по названию, краткому описанию и тексту всех блоков, включая заголовки и элементы списков и шагов. Поиск SHALL игнорировать регистр и крайние пробелы, начинать фильтрацию с двух нормализованных символов, сохранять порядок статей и групп полного каталога и скрывать пустые группы. Более короткий запрос SHALL показывать весь каталог. Поиск MUST NOT требовать серверного API.

#### Scenario: Search text inside a block

- **WHEN** введено `НЕОДНОЗНАЧНОСТИ`
- **THEN** каталог содержит статью `skill-register`, найденную по тексту блока, без пустых групп

#### Scenario: Short query

- **WHEN** запрос пуст, состоит из пробелов или содержит один символ после удаления крайних пробелов
- **THEN** каталог содержит все статьи в исходном порядке

### Requirement: Query and article are restored from URL

Страница SHALL читать запрос из `q`, а выбранную статью из `article`. Прямой вход, перезагрузка и навигация назад/вперёд SHALL восстанавливать поле, выдачу и выбранную статью без принудительного выбора первого результата, если `article` входит в выдачу. При отсутствующем, неизвестном или не входящем в выдачу `article` SHALL отображаться первый результат; при отсутствии результатов статья SHALL отсутствовать. Исправление URL SHALL заменять текущую запись истории: при непустом `q` с результатами записывать ID fallback, при пустой выдаче удалять `article`. Обычный вход без `q` и `article` MUST NOT требовать добавления параметров.

#### Scenario: Direct link to a manually selected result

- **WHEN** открыта или перезагружена ссылка с `q` и ID второго подходящего результата
- **THEN** поле содержит `q`, каталог отфильтрован, открыта вторая статья, а не первая

#### Scenario: Invalid or mismatched article with search

- **WHEN** непустой `q` даёт результаты, но `article` отсутствует, неизвестен или не входит в результаты
- **THEN** открыт первый результат, его ID записан в URL заменой текущей записи истории

### Requirement: Query changes select the first result

Каждое изменение значения поля поиска пользователем SHALL одновременно сохранять новый `q` и выбирать первый результат в порядке каталога с записью его ID в `article`. Очистка поля SHALL удалять `q`, возвращать полный каталог и выбирать его первую статью. Ввод SHALL заменять текущую запись истории; выбор другой найденной статьи SHALL сохранять `q` и добавлять запись истории. Ручной выбор MUST NOT сбрасываться до следующего изменения запроса пользователем. Все обновления SHALL сохранять basename и посторонние query-параметры, включая повторяющиеся значения.

#### Scenario: Change query after manual selection

- **WHEN** пользователь выбрал вторую найденную статью и затем изменил поисковый запрос
- **THEN** открыт первый результат нового запроса, `q` и `article` обновлены вместе

#### Scenario: Clear search

- **WHEN** пользователь очищает поле
- **THEN** `q` удалён, показан полный каталог, открыта его первая статья и её ID записан в `article`

#### Scenario: History and unrelated parameters

- **WHEN** пользователь ищет, выбирает другую статью, затем выполняет назад/вперёд на странице с `filter=a&filter=b`
- **THEN** существующие записи истории восстанавливают свои `q` и `article`, ввод не создаёт запись на каждый символ, оба значения `filter` и basename сохранены

### Requirement: Empty results hide the article

При отсутствии результатов страница SHALL показывать доступный статус «Ничего не нашлось», скрывать содержимое статьи и удалять `article` из URL с заменой текущей записи истории, сохраняя `q`. Это SHALL работать как при вводе, так и при открытии прямой ссылки. Последующее изменение запроса с результатами SHALL снова показывать первую найденную статью.

#### Scenario: No results from typing or direct link

- **WHEN** запрос `несуществующий текст` не находит статей, в том числе при наличии прежнего `article` в прямой ссылке
- **THEN** виден статус «Ничего не нашлось», ни одна статья не отображается, `article` отсутствует в URL

#### Scenario: Recover from empty results

- **WHEN** пользователь заменяет запрос без результатов на `неоднозначности`
- **THEN** пустое состояние исчезает, открыта статья `skill-register`, её ID записан в `article`

### Requirement: Search preserves accessible interaction

Автоматический выбор при вводе SHALL сохранять фокус в поиске без прокрутки к статье, включая мобильную компоновку. Ручной выбор другой статьи на узком экране SHALL сохранять существующие фокус и прокрутку к статье; на desktop и при первом открытии прямой ссылки автоматическая прокрутка MUST NOT выполняться. Поле, статус выдачи и выбранный пункт SHALL оставаться доступны с клавиатуры и для вспомогательных технологий.

#### Scenario: Mobile typing

- **WHEN** на узком экране ввод меняет первый результат поиска
- **THEN** статья обновляется, фокус остаётся в поле и прокрутка к статье не выполняется

#### Scenario: Typing inside the application shell

- **WHEN** после первичного подтверждения сессии пользователь непрерывно вводит запрос, выбирает результат или UI корректирует article в URL
- **THEN** локальное обновление документации MUST NOT повторно запускать загрузку корневого маршрута и скрывать оболочку проверкой сессии; при вводе поле сохраняет тот же DOM-узел, фокус и полный текст, а первичное подтверждение и явный повтор проверки сессии остаются рабочими

#### Scenario: Manual mobile selection

- **WHEN** пользователь на узком экране выбирает другую найденную статью
- **THEN** её пункт обозначен выбранным, область статьи получает фокус и прокручивается в видимую область
