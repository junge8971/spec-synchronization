## Why

[Jira MOS-1260](https://task.mos-team.ru/browse/MOS-1260): [FE][Обратная связь] Реализовать CSV-экспорт списка и карточки опросника.

Нужна отдельная реализуемая поставка этой FE-подзадачи по обновлённому API и принятой границе прототипа. План, приёмка и выполнение учитываются отдельно от остальных задач MOS-1246.

## What Changes

- CSV всего применённого отбора и сохранённой карточки: сценарий определяется актуальной MOS-1260, состав данных и формат — локальными `docs/api/contracts/openapi.json`, `managed-resources.openapi.json` и разделом 10 `crud-api.md`. Аналитический прототип не расширяет опубликованный API.
- Модальное окно настройки с выбором и порядком колонок из metadata (drag-and-drop за ручку и доступные кнопки перемещения), сохранением выбора в рамках сессии, блокировкой повторной отправки и сохранением ввода при ошибках.
- Отдельное модальное окно результата только после получения корректного файла: имя из Content-Disposition, фактическое количество выгруженных записей списка либо код/идентификатор сохранённой карточки; для списка — возврат к параметрам. Счётчик текущего реестра не подменяет фактический результат выгрузки.
- Сохранить ограничения API, доступность, отмену и изоляцию сессии; ошибки не дают ложного скачивания или успеха. Для dirty карточки явно показать, что экспортируются сохранённые данные.

### Deferred scope

Вложенные вопросы/варианты/правила/ответы не экспортируются; данные несохранённого draft не подменяют серверную карточку.

Приёмка ограничена описанным UI и его прямыми интеграциями. Закрытие всей группы MOS-1246 в эту задачу не входит.

### Open agreement: UI permissions

Требование Jira о `ManagedResource:read` + `ManagedResource:export` для UI остаётся отдельным открытым вопросом согласования: действующие specs feedback исключают новые UI permission mappings. Раздел 1 CRUD публикует отдельное право `TSAM.ManagedResource:export`, а §10.2 содержит противоречивую формулировку о правах чтения. Эта ревизия не утверждает новую UI-политику и не ослабляет существующую защиту или серверную авторизацию. До согласования нельзя объявлять соответствующий критерий Jira выполненным.

## Capabilities

### New Capabilities

- `feedback-export`: серверный CSV всего применённого отбора и сохранённой карточки, модальные окна настройки и результата, выбор/порядок полей, фактический счётчик записей списка, безопасное скачивание и ошибки. Вложенные данные не экспортируются.

### Modified Capabilities

Нет. Общие capabilities HTTP, permissions и MPMM сохраняются; scope соседних FE-подзадач сюда не переносится.

## Impact

Два binary клиента, модель экспорта, выбор колонок и действия существующих реестра/карточки принадлежат `app/optional/feedback/`; перенос раздела в entities/features не требуется. Используются общие transport/session и UI-механизмы без зависимости от других optional-модулей. Затрагиваются профильные тесты и CSV-моки в существующем Express; новый backend API не требуется.

Зависимости: [MOS-1249](../mos-1249-feedback-api/proposal.md); [MOS-1250](../mos-1250-feedback-registry/proposal.md); [MOS-1251](../mos-1251-feedback-editor/proposal.md); [MOS-1258](../mos-1258-feedback-conditions/proposal.md)

Граница: сценарий по Jira, операции и данные по локальному API, неподдержанное отложено. Исполнение правил и сбор реальных ответов пользователей не входят. Новые зависимости не добавляются без отдельного обоснования. Unit/component и mock HTTP проверки сохраняются; интерактивная проверка затронутых сценариев на локальных моках через Playwright MCP планируется с отдельным явным разрешением по правилам проекта. Автоматизированные E2E и внешний контур требуют отдельного разрешения; моки не подтверждают реальную интеграцию. Текущая ревизия меняет только планирование, не код приложения и не Jira.
