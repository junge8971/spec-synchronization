## Context

См. proposal.md. GET карточки уже возвращает обязательный SkillStatus. useSkillDetailsQuery использует TanStack Query с ключом по skill ID и передаёт AbortSignal существующему валидируемому клиенту. SkillDetails показывает серверный статус, шкалу MOS-909, ручное обновление и ошибку фонового чтения; checks-tab сообщает об отсутствии результатов проверок.

Пользователь согласовал сокращённый MOS-1019: автообновление в checking/training/autotest без результатов запусков. Публикация статусов не гарантирует, что backend самостоятельно выполняет переходы; frontend только наблюдает за ответами.

## Goals / Non-Goals

**Goals:** актуальный серверный этап на открытой карточке с минимальным дополнением существующего запроса.

**Non-Goals:** API запусков, run ID, ML/backend, проценты и ETA, локальная история успешных этапов, логи, повтор обучения, проверка готовности версии фраз, песочница и её токены. Не добавлять новые команды или polling реестра/всех навыков.

## Decisions

- **Штатный polling вместо отдельного процесса.** Добавить refetchInterval в существующий useSkillDetailsQuery: 5 секунд для checking/training/autotest, false для остальных статусов или ошибки чтения. Интервал — технический default MVP, не backend SLA; предметные значения разместить у entity по соглашениям проекта. Не создавать setInterval, новый query key, второй запрос во вкладке, SSE/WebSocket или настраиваемый scheduler.
- **Один владелец наблюдения — открытая карточка.** Использовать существующий ключ по skill ID и AbortSignal. Согласовано: добавить в useSkillDetailsQuery параметр включения polling, по умолчанию выключенный; включать его только в SkillDetails. SkillDetailsBreadcrumbs сохраняет существующий запрос и получает обновления общего кеша без собственного refetchInterval: общий query key сам по себе не устраняет таймер каждого QueryObserver. Переключение внутренних вкладок не создаёт дополнительных циклов. При выходе из наблюдаемых статусов отключать периодическое чтение, при уходе со страницы прекращать его; polling в скрытой вкладке браузера не включать. Стандартные чтения при открытии/фокусе и ручное обновление сохраняются и не считаются фоновым polling вне этих статусов.
- **Ошибка чтения не равна ошибке процесса.** После ошибки остановить периодическое чтение, оставить последний серверный этап с существующим сообщением о неактуальности и ручным повтором. Успешное чтение снова определяет интервал по status. Не строить собственный backoff поверх политики Query и не синтезировать ошибку обучения из HTTP failure.
- **Переиспользовать отображение MOS-909.** Общая шапка и шкала продолжают показывать одну карточку из query. Во вкладке проверок показать текущий этап из тех же данных и пояснить, что доступны только статусы; отсутствие API результатов и проверки пересечений не скрывать. Не отмечать предыдущие этапы успешными по порядку enum и не выводить готовность фраз/песочницы из sandbox.
- **Никаких побочных команд.** Получение checking/training/autotest не отправляет POST. Таймер инициирует только чтение и никогда не меняет status локально. Если сервер оставляет статус неизменным, UI не назначает срок завершения или собственный timeout процесса.
- **Сохранить редакторы.** Обновления карточки не должны сбрасывать несохранённые изменения анкеты, фраз или подключения. Переиспользовать существующие правила владения черновиком и конфликта версии; не добавлять новую модель форм ради polling.

## Risks / Trade-offs

- [Backend не выполняет переходы самостоятельно] → UI продолжает показывать фактический статус; работа backend не входит в приёмку этого MVP и не заменяется таймером успеха.
- [Чтение полной карточки раз в 5 секунд создаёт нагрузку] → только открытая видимая карточка и три наблюдаемых статуса; отдельный status endpoint и оптимизации отложены до реальной необходимости.
- [Обновление не удалось] → последние данные явно помечены, периодическое чтение приостановлено, ручное обновление сохраняется.
- [Поздний ответ другого навыка] → существующие query key по ID и отмена чтения, без общего локального состояния процесса.

## Migration Plan

Дополнить существующий query и вкладку проверок, сохранив команды MOS-909 и формы. Проверить ответы HTTP и течение времени unit/component-тестами без реального обучения и браузера. Отдельно проверить остановку polling и сохранение черновика. Откат убирает автоматическое чтение; ручное обновление остаётся, серверный процесс не меняется.
