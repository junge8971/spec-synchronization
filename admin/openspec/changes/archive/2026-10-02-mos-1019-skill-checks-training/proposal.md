## Why

MOS-1019: во время проверки, обучения и автотестов пользователь должен видеть актуальный серверный этап без постоянного ручного обновления карточки. Для первой поставки достаточно наблюдать опубликованный SkillResponse.status, не ожидая полноценного API запусков и результатов.

## What Changes

- Согласованный MVP: автоматически перечитывать открытую карточку при status=checking, training или autotest и показывать текущий серверный этап.
- Прекращать периодическое чтение при выходе из этих статусов и уходе со страницы; после повторного открытия определять необходимость обновлений по серверным данным.
- Сохранить ручное обновление и явную ошибку чтения с отметкой последних загруженных данных, не выдавая её за ошибку обучения.
- Не имитировать переходы, проценты, ETA и успешное завершение предыдущих этапов. Если backend не меняет статус, UI продолжает показывать тот же этап.
- Отложить run ID, результаты отдельных проверок, логи, ошибки процесса, повторный запуск и подтверждение готовности конкретной версии/песочницы до появления соответствующего API.

## Capabilities

### New Capabilities

- `skill-checks-training`: автоматическое наблюдение за текущим серверным статусом проверки, обучения и автотестов навыка.

### Modified Capabilities

Нет. Существующие команды и шкала skill-lifecycle сохраняются; change добавляет периодическое чтение карточки, а не новые переходы или модель запуска.

## Impact

- `app/entities/skill/model/use-skill-details-query.ts`, `app/widgets/skill-details/`: существующий запрос карточки, отображение текущего этапа и ограничений на вкладке проверок.
- Используется опубликованный GET `/api/control/api/skills/v1/skills/{skill_id}`. API-блокер для согласованного наблюдения снят; новые endpoints, схемы и зависимости не нужны.
- MOS-909 уже предоставляет отправку draft → checking и ручное обновление. MOS-1019 не добавляет POST status ради запуска/повтора обучения и не гарантирует автоматическую обработку на backend.
- Готовность MOS-1018, MOS-1020 и MOS-1023 не блокирует этот MVP. Проверка конфликтов, ревью и токены не входят в него.
- Приёмка относится только к наблюдению за status. Полноценные проверки, обучение и доступность песочницы не объявляются реализованными по результатам этой поставки.
