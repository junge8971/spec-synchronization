## Context

См. proposal.md. В проекте конструктора диалогов нет; общий selection и HTTP-ошибки предоставляет MOS-1037. HTML показывает inline-панель, скриншот MOS-1038 просит drawer. Пользователь подтвердил реализацию по HTML: inline-панель над таблицей. Бизнес-модель редактора не зависит от контейнера.

## Goals / Non-Goals

**Goals:** явный переход draft → applied, соответствие типов/операторов, один контракт отбора.

**Non-Goals:** рекурсивный AND/OR, универсальный query builder, фильтрация загруженной страницы, восстановление потерянных полей догадками.

## Decisions

1. **Gates согласованы пользователем:** общий selection MOS-1037 принят; контейнер — inline-панель «Условия отбора» над таблицей по HTML-прототипу. operator_group, error_type, widget_button остаются видимыми в каталоге из 35 атрибутов, но недоступны для выбора до согласования серверной семантики, с объяснением причины. Уже полученные условия с этими атрибутами не удаляются молча: редактор блокирует применение до их явного удаления/замены. No-op поведение прототипа не переносится.
2. **Небольшая feature, не новый движок:** `features/dialog-selection` использует предметный каталог атрибутов из `entities/dialog`; списки значений приходят через dictionaries. Фиксированные enum ended_by/answer_rating/attachment_recipient принадлежат контракту, не извлекаются из текущих строк.
3. **Draft отделён от applied:** открытие копирует применённую группу; закрытие без применения её не меняет. Применение валидирует все строки и атомарно передаёт группу владельцу реестра. Смена атрибута очищает несовместимые оператор/значения, а не отправляет невидимые поля. Локальный ID строки допустим только для UI, в API отправляется контрактная структура.
4. **Два явных сброса:** действие редактора очищает только черновик группы; после применения пустая группа не ограничивает выдачу. Общий «Сбросить всё» реестра очищает q, period до all_time, поверхности, навыки и группу. Не переносить неочевидный demo-handler, очищающий всё из панели условий.
5. **Типизированный каталог (PDF 2.4.5):**
   - phrase: phrase;
   - текст: chat_id, session_id, user_sso_id, user_device, operator, url, operator_rating_comment, answer_rating_comment, category, operator_group, error_type, widget_button;
   - число: duration_sec, step_count, operator_rating, message_count, attachment_count;
   - дата: started_date, ended_date;
   - список: channel, skill, answer_rating, operator_rating_reason, end_reason, ended_by, subsystem, answer_rating_reason, attachment_recipient;
   - boolean: user_authorized, has_operator, has_failure, knowledge_base_used, authorized_in_dialog, has_attachments.
6. **Операторы:** текст contains/not_contains/equals/is_empty/is_not_empty; числа equals/not_equals/greater_than/less_than/between/is_empty/is_not_empty; дата equals/after/before/between/is_empty; список in/not_in/is_empty; boolean equals; phrase contains/not_contains с any_order/exact и dialog/user/assistant/operator/skill. between включителен; отрицательные операторы множественного атрибута означают отсутствие подходящих значений, а не наличие одного неподходящего.
7. **Валидация на границе:** 30 условий, 500 символов текста, 100 значений списка, целые числа и корректные даты/диапазоны. Не добавлять отсутствующие контрактные ограничения. JSON Pointer errors связывать с конкретной строкой текущего отправленного набора; не прикреплять ответ старого запроса к переставленным условиям. Неизвестные ошибки показывать общим сообщением, не терять их.

## Risks / Trade-offs

- Три атрибута не имеют семантики → согласованная недоступность с объяснением, без no-op фильтров.
- Смена оператора оставляет скрытые значения → нормализовать структуру по выбранному типу; проверять исходящий JSON.
- Справочники недоступны → объяснить недоступность соответствующих полей, не подставлять пустую успешную выдачу; существующие IDs не стирать.
- Большой редактор → подписи всех полей, клавиатурное управление, доступные ошибки; для согласованного drawer — focus containment, Escape и возврат фокуса.

## Migration Plan

После gates добавить feature к MOS-1037 без изменения search endpoint. Проверить каждую строку каталога таблицей unit-тестов и существенные сценарии component-тестами. При откате убрать редактор, не интерпретировать сложные сохранённые selection как пустые.
