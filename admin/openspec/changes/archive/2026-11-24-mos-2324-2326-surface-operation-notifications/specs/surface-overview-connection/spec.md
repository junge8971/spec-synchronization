# Spec Delta

## MODIFIED Requirements

### Requirement: Connection displays saved server values

Вкладка «Подключение» SHALL отображать `connection.embed_code`, `connection.authorization`, `channel_id` и все `domains` из ответа `GET /api/control/api/surfaces/v1/surfaces/{surface_id}`. Код SHALL показываться как текст без исполнения HTML или скриптов. UI MUST NOT генерировать код, токен, channel_id либо сведения об авторизации из прототипа или домена. Для nullable-полей SHALL отображаться явное отсутствие данных; `authorization=null` MUST NOT трактоваться как подтверждение отсутствия авторизации. Сведения подключения и обзора SHALL оставаться только для чтения. Вкладка «Подключение» SHALL сохранять действие публикации, а «Обзор» — блок lifecycle-действий согласно `surface-lifecycle-publication`, включая её ограничения по статусам, порядок сохранения и свежего чтения и общую блокировку операций. Публикация в «Подключении» SHALL запускаться без подтверждающего окна и использовать тот же единственный нотификатор с серверным числом сценариев, что и запуск из шапки. Открытие вкладки само по себе MUST NOT отправлять запись или воспроизводить старое уведомление успеха.

#### Scenario: Server connection values

- **WHEN** пользователь открывает подключение поверхности с заполненными серверными значениями
- **THEN** показаны серверный код как текст, channel_id, полный список доменов и сведения об авторизации, без выполнения встроенного скрипта

#### Scenario: Connection values unavailable

- **WHEN** `embed_code`, `authorization` или `channel_id` равны `null`
- **THEN** соответствующие поля явно обозначают отсутствие данных, остальные сведения остаются видимыми и значения не достраиваются из домена или HTML-прототипа

#### Scenario: Tab actions use the common lifecycle policy

- **WHEN** пользователь открывает «Подключение» или «Обзор»
- **THEN** запись не выполняется автоматически и старый успех не появляется; публикация и lifecycle-действия доступны только по общей политике карточки, а значения подключения и обзора не становятся редактируемыми

#### Scenario: Connection and header publication share one result

- **WHEN** пользователь запускает доступную публикацию из «Подключения» либо из шапки
- **THEN** выполняется одна и та же последовательность проверок и запросов без модалок, после подтверждённого успеха появляется один нотификатор «Поверхность опубликована» с числом сценариев из итоговой карточки, а вторая точка запуска не создаёт дубликат

#### Scenario: Connection publication preserves separately saved drafts

- **WHEN** конфигурация или сценарии изменены без отдельного сохранения либо после записи требуется обязательное свежее чтение
- **THEN** публикация в «Подключении» заблокирована так же, как в шапке; она не сохраняет конфигурацию автоматически и не подменяет серверные факты checklist локальным выбором
