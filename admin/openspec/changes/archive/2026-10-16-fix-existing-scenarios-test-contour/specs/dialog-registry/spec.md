## ADDED Requirements

### Requirement: Quick filter application is visibly explicit

Быстрые фильтры SHALL иметь видимую текстовую кнопку «Найти», применяющую текст, период, поверхности и навыки вместе, и пояснение о необходимости её нажатия. Управление SHALL быть доступно с клавиатуры, включая submit через Enter. Пока значения отличаются от применённого отбора, UI SHALL показывать доступное сообщение о неприменённых изменениях. Изменение контролов без submit MUST NOT менять серверную выдачу, счётчик, состав экспорта или сохраняемого фильтра. После валидного применения сообщение SHALL исчезать, поиск SHALL начинаться без старого cursor с сохранением применённой группы сложных условий. Общий сброс SHALL очищать и черновик быстрых фильтров, и применённый отбор по существующим правилам.

#### Scenario: Surface selected but not applied

- **WHEN** пользователь выбирает другую поверхность без нажатия «Найти»
- **THEN** рядом с формой видны инструкция и сообщение о неприменённых изменениях, а строки, total и экспорт продолжают использовать прежний отбор

#### Scenario: Apply filters with keyboard

- **WHEN** пользователь отправляет валидную форму кнопкой «Найти» или Enter
- **THEN** выполняется поиск с полным новым отбором без прежнего cursor, группа сложных условий сохранена, сообщение о неприменённых изменениях исчезает

#### Scenario: Invalid period remains a draft

- **WHEN** пользователь пытается применить обратный диапазон дат
- **THEN** доступная ошибка объясняет проблему, запрос не отправляется, прежняя выдача и применённый отбор сохранены

#### Scenario: Reset pending changes

- **WHEN** пользователь нажимает общий сброс при неприменённых изменениях
- **THEN** сбрасываются черновик и применённый отбор, исчезает сообщение о неприменённых изменениях и выполняется поиск со сброшенными условиями
