## Why

[MOS-1510](https://task.mos-team.ru/browse/MOS-1510) требует реестр описаний API с серверными поиском, редактированием и выгрузкой. Контракт и локальные mock-обработчики существуют, но соответствующего frontend-раздела нет; прототип не подтверждает постоянное хранение и реальные операции.

## What Changes

- Добавить раздел «API» в группе «Платформа»: `/api-registry`, `/api-registry/new`, `/api-registry/:endpointId`, прямые ссылки, крошки и подсветку в общей оболочке.
- Реализовать серверный реестр с вкладками групп и счётчиками одинакового отбора, поиском, мультифильтрами, условиями, сортировкой, пагинацией, воспроизводимым URL и именованными серверными фильтрами. Пользователь подтвердил включение именованных фильтров; фактическое серверное хранение и изоляция владельцев остаются отдельными release gates.
- Добавить создание и редактирование единого черновика карточки с вкладками «Основное», «Запрос» и «Ответы», доступным изменением порядка параметров, корректным JSON, атомарным сохранением и защитой несохранённого ввода. Настройки публикации и поле `auth_required` являются данными описываемого API, не настройками сессии админки.
- Поддержать только согласованные статусы: сохранять их вместе с новой карточкой либо через существующий PUT; архивировать после подтверждения. Кнопку «Приостановить» скрыть по решению пользователя: `paused` не согласован для этого ресурса. Не подменять архивацию DELETE или другим статусом.
- Добавить реальный CSV всего отбора и сохранённой карточки по поддерживаемым полям, без фиктивного успеха или экспорта неподдерживаемых вложенных разделов.
- По согласованию пользователя изолировать frontend в `app/optional/api-registry/`, предметные серверные mock fixtures, handlers и проверки — в `mocks/api-registry/`, не внутри базы знаний. Добавить адресную FSD-границу и проверяемую инструкцию независимого удаления; сохранить другие разделы, общие контракты и строгую проверку отсутствующих mock handlers.
- Использовать существующие session/access boundary, transport и API пользователей; не вводить новые auth, роли, permissions или ролевой enforcement в моках. Формирование лендинга, выполнение описанных вызовов, проверка доступности систем и журнал вызовов не входят в change.

## Capabilities

### New Capabilities

- `api-registry-module`: маршруты, оболочка, состояния, изоляция модуля и моков, независимое удаление.
- `api-registry-search`: серверный реестр, счётчики, условия, URL и именованные фильтры.
- `api-registry-editor`: карточка, параметры и ответы, валидация, статусы, безопасное сохранение.
- `api-registry-export`: серверная CSV-выгрузка списка и сохранённой карточки.

### Modified Capabilities

- `code-quality-gates`: адресное optional-исключение для API registry с существующими границами и без ослабления lint.

## Impact

Затрагиваются application composition и маршруты, новый frontend-модуль, адресные FSD-инструкции и проверки, а также текущие `mocks/api-endpoints.mjs` и API-части `mocks/managed-registry-{model,seed,handlers,validation,test}.mjs`. Общие механизмы реестра шаблонов ответов, справочников, saved-filters и generated DTO должны сохраняться. Новые зависимости не предполагаются.

Используются опубликованные `/api/control/api/v1/managed-resources/api/{metadata,endpoints...}`, `/catalogs/lookups/api`, `/saved-filters` и `/api/control/api/users/v1/search`. Сверенный OpenAPI T от 29.10.2026 содержит связанные операции и DTO, но не доказывает реальное поведение; старый CRUD Markdown противоречит ему в части saved filters. Значения lookup, соответствие источника группе, CSV/CORS и изоляция фильтров требуют отдельного подтверждения на контуре.

Проверки: unit/component, mock HTTP и архитектурные тесты, typecheck/lint/test/format/api-check/build, удаление в отдельной временной копии. Интерактивный Playwright MCP на локальных моках выполнять только после отдельного явного разрешения по проектным правилам; без него или при недоступности инструментов оставить проверку незавершённой. Автоматизированные E2E и внешнее UI-тестирование требуют отдельного разрешения. Mock-результаты не подтверждают интеграцию.
