## Context

См. `proposal.md`. React Router работает в SPA Framework mode, маршруты собираются из application registry; существующие optional-разделы подключаются через публичный descriptor. `react-router.config.ts` задаёт basename `/tsam-panel/`. Общая сессия и UI-политика уже существуют; для неразмеченного ресурса применяется fallback явного `*`.

Локальный снимок OpenAPI содержит восемь операций API registry, шесть lookup-наборов, managed saved-filters и поиск внешних пользователей. При чтении OpenAPI T 29.10.2026 связанные операции и проверенные схемы совпали с локальными после исключения известной согласованной нормализации security. Общий live-снимок изменился (123 пути/476 схем против локальных 117/449); это не основание импортировать несвязанные дельты. Ни операции, ни runtime-значения на стенде не вызывались.

Текущие API registry mock descriptor, каталоги и seed находятся вместе с инфраструктурой шаблонов ответов в `mocks/managed-registry-{model,seed,handlers,validation}.mjs`; `mocks/api-endpoints.mjs` содержит предметную валидацию. Общий Express требует handler для каждой операции контракта. У существующего удаления шаблонов уже выявлен сбой startup при отсутствии таких handlers; его нельзя повторить или скрыть глобальным fallback.

## Goals / Non-Goals

**Goals:** обеспечить изолированное владение, серверный источник истинного отбора, один агрегат карточки и сохранение реальных защит на границах. Реализацию можно проверить локально и отдельно удалить без ущерба соседним разделам.

**Non-Goals:** новый auth/RBAC, роль администратора по названию, real-backend enforcement в моках, собственный router/mock framework, исполнение описанных запросов или cURL, генерация лендинга, проверка сетевой доступности и журналы вызовов. Удаление UI не означает удаление серверных данных.

## Decisions

### 1. Композиция и изоляция

`app/optional/api-registry/` владеет UI, состоянием, клиентами, схемами и route adapters. Публичный `index.ts` предоставляет descriptor; композиция добавляет его один раз, framework entrypoints сохраняют штатный доступ к своим экранам. Модуль использует только собственный код, shared и публичные API entities, включая `searchBusinessUsers`; зависимости от KB, templates и других optional-слайсов запрещены. Новый адресный допуск закрепляется в `AGENTS.md`, `scripts/eslint-fsd-config.mjs` и исполняемых тестах без ослабления границ.

`mocks/api-registry/` владеет предметными descriptor, fixtures, validation и тестами. Общие операции поиска, CSV, сохранённых фильтров и каталоги остаются общими и получают необходимые ресурсы через минимальную mock composition; они не зависят от кода KB или templates через API registry. При переносе сохранить поведение шаблонов и центральных справочников. Локальные данные должны покрывать все три группы, включая допустимый исходящий источник, и местоположение `body`; примерные коды — mock-конвенция, не доказательство миграции backend. Существующие fixture ID и независимые тесты сохраняются, если на них есть потребители.

Инструкция удаления перечисляет route/lint/mock/test регистрации. В отдельной копии после удаления папок и регистраций сохраняется shared OpenAPI и строгий missing-handler guard. Если для восьми удалённых операций нет корректного общего handler, рецепт явно переводит только эти конкретные operationId в существующий механизм 501 unavailable; это делается только при удалении, а не как fallback установленного раздела. Lookup остальных разделов, saved-filters, шаблоны и центральные справочники продолжают работать. Альтернативы — хранить оба раздела в одной папке либо игнорировать missing handlers — нарушают независимость и диагностику.

### 2. Один отбор для таблицы, счётчиков, URL и CSV

Валидированное состояние содержит query, выбранную вкладку `all/internal/outgoing/incoming`, method/source/status, AND/OR conditions, sort, limit и offset. Query отправляется только длиной 2–200; единичный символ остаётся незапущенным вводом с пояснением. Новый применённый отбор сбрасывает offset. Таблица получает серверную страницу; никакой фильтрации или сортировки только по ней.

Для счётчиков сохраняется весь отбор кроме вкладки: `all` — запрос без быстрого `group_code`, остальные — три запроса с соответствующим `group_code`, `limit=1`, `offset=0`. При необходимости ответ активного поиска переиспользуется. Условие по `group_code` внутри AND/OR остаётся частью отбора; смена вкладки не меняет его. Независимые запросы не дают транзакционного снимка, поэтому UI не обещает синхронности при конкурентных изменениях. Отменённые/устаревшие ответы не обновляют текущий отбор; ошибка отдельного счётчика отображается как ошибка, не ноль.

Metadata определяет допустимые поля, типы и операторы. Пересечение с опубликованной схемой необходимо: `landing_category` отсутствует в `api_endpointCondition`, несмотря на Wiki, и не отправляется в условиях. Сортировка использует только опубликованные ключи; у составного столбца «Группа / Источник» не придумывается серверная составная сортировка. Третий клик возвращает серверный default `-updated_at`.

Один URL codec восстанавливает группу, поиск, мультиселекты, условия, сортировку и страницу; Back/Forward и копируемая ссылка используют тот же отбор. Некорректное состояние не уходит в API. Экспорт получает тот же полный отбор без ограничения текущей страницей.

### 3. Серверные именованные фильтры

Использовать существующие managed saved-filters с `resource=api-endpoints`, не локальный массив. Группа представляется контрактным `search.group_code`, а условия — `search.conditions`, без дополнительных frontend-полей в search. При применении используется первая страница; имя, пагинация списка, ошибка создания/удаления и невозможность применить некорректный search обрабатываются явно. Вкладка выражает отсутствие группы либо одну группу; сохранённый массив нескольких групп или неизвестную группу нельзя молча превращать во вкладку «Все». Не реализовывать недокументированную перезапись по совпадающему имени.

Ответ создания содержит только ID, а общий `search` формально допускает произвольный объект. Поэтому после сохранения повторное чтение по ID должно подтвердить семантическое сохранение полного поддерживаемого отбора и группы; одна группа строкой или одноэлементным массивом эквивалентна; при ошибке или несовпадении UI различает факт принятого POST и неподтверждённое восстановление, предлагает повторить GET, но не повторяет POST автоматически. Пользовательская изоляция выполняется backend; фиксированный mock-владелец её не доказывает. Исторический CRUD Markdown отрицает поддержку, актуальный OpenAPI и комментарий MOS-1386 её описывают; реальный round-trip и isolation остаются release gates.

### 4. Один черновик карточки и безопасный статус

Карточка независимо загружается по UUID, `new` не является ID. Данные трёх вкладок принадлежат одному черновику; переключение вкладок не сбрасывает ввод. Создание и частичный PUT выполняются только по «Сохранить». Переданные массивы параметров/ответов заменяются целиком, существующие IDs передаются, для новых IDs выдаёт сервер; отсутствие поля и пустой массив различаются. После ошибки draft и dirty сохраняются. Успешный POST с ID и неуспешный последующий GET требует повтора GET, не повторного создания; неизвестный исход записи не объявляется отменой.

Статус редактируется в общем черновике; выбор архива запрашивает подтверждение и сохраняется только после успешного POST новой карточки или PUT существующей. `paused` и кнопка «Приостановить» скрыты до отдельного согласования; `deprecated`, `archived` и DELETE не подменяют паузу. Выборы берутся из lookup, неизвестные или неактивные сохранённые значения не стираются и не предлагаются как новые.

Соблюдать код/длины/path, group/source, URI, JSON и массивные ограничения по контракту и бизнес-правилам. Ошибки уникальности name/code/(method,path,version) окончательно принадлежат серверу, а не видимой странице. Пустой JSON-текст преобразуется в null, непустой сохраняется с исходным форматированием; коды ответов уникальны в диапазоне 100–599. Список параметров можно переставлять мышью и клавиатурой; preview рендерит данные как текст. Реальный cURL, URL и примеры не выполняются.

Группа internal скрывает источник; outgoing требует источник панели, incoming — внешней системы по аналитике. Серверный lookup даёт коды, но Wiki противоречит самой себе (`mpmm`/`mppm`); не выводить код из подписи и не подставлять неподтверждённый alias. Пока применимое соответствие неизвестно/справочник недоступен, сохранить существующее значение и показать ограничение новых назначений; подтверждение соответствия и реальных данных — release gate. Ответственный — внешний строковый ID, не UUID; ранее выбранный ID сохраняется при отсутствии в текущей странице или ошибке поиска.

Использовать штатную защиту router navigation/beforeunload с dirty-only подтверждением, учитывая повторное монтирование при сессии и регрессию Activity/blocker в соседнем разделе. Не импортировать его внутренний обход и не копировать private router API без отдельной причины; тестировать переходы и устранить корень при обнаружении проблемы.

### 5. Достоверная выгрузка и изоляция сессии

Оба export endpoint возвращают `text/csv`; список экспортирует весь текущий отбор, карточка — только сохранённую серверную версию. Поля ограничены девятью значениями опубликованного DTO и metadata. На dirty-карточке объяснить, что будет выгружена сохранённая версия; для new экспорт недоступен. Применять общий безопасный HTTP/CSV/download путь, существующие проверки заголовков, размера и owner/generation, а также доступный результат выгрузки по `operation-feedback`. Выбор полей сохраняется после ошибки. Ошибки и CORS/неожиданный content type не превращаются в успех.

Соблюдать существующий UI fallback `*` и серверную авторизацию без новых разрешений. За запрещённой границей запросы не монтируются; после смены пользователя/сессии устаревшие запросы и экспорт не обновляют новый UI. Не вводить клиентские ACL в transport или mock business handlers.

## Risks / Trade-offs

- [Непроверенные live-сценарии] → mock HTTP и unit/component тесты отделяются от release gate; фактические lookup/source-коды, saved-filter ownership, CSV headers/CORS и серверные конфликты проверяются отдельно с разрешением на конкретный контур и действия.
- [Два возможных написания источника] → использовать присланный код только при согласованном соответствии группе; отсутствие соответствия не заменять вымышленным значением.
- [Одновременное редактирование] → опубликованный managed API не содержит expected_version или Idempotency-Key; не обещать защиту от конфликтующих записей или безопасный автоматический replay.
- [Удаление ломает запуск остальных моков] → адресная политика восьми unavailable-операций только после удаления, строгий guard, mock startup и регрессии в изолированной копии.
- [Четыре подсчёта увеличивают запросы] → лимит 1, переиспользование активного результата и отмена устаревших; не заявлять атомарность разных ответов.
- [CSV и lookup отличаются в production] → сохранять текущую строгую обработку ошибок и явные release gates, не подменять ответ локальными данными.

## Migration Plan

1. Добавить адресные границы, перенести только предметную часть существующего mock с регрессиями общих сценариев; подключить маршруты и функциональность без флага в обоих режимах.
2. Выполнить unit/component/HTTP и архитектурные проверки, build и проверку отсутствия mock fixtures в production. Для локального интерактивного Playwright MCP сначала получить отдельное разрешение; без него оставить проверку открытой. Автоматизированные E2E и внешнее UI-тестирование отдельно не разрешены.
3. Провести удаление в отдельной копии по инструкции: удалить только модуль и документированные регистрации, точечно обозначить недоступные операции при необходимости и проверить typecheck/build/start/смежные моки. Не менять рабочую копию ради репетиции.
4. Rollback — удалить модуль и точки композиции по проверенному рецепту, сохранив shared DTO и серверные данные. Live-проверки и изменения внешних данных не входят в этот план без отдельного разрешения.
