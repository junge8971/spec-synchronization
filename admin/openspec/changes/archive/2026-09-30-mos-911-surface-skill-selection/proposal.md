# Proposal

## Why

Выбор сценариев при регистрации поверхности сейчас сохраняет только ID навыков с пустыми параметрами, а карточка поверхности не позволяет редактировать их состав. MOS-911 требует общего редактора выбора и параметров для обоих сценариев с проверкой данных перед сохранением.

## What Changes

- Добавить общий редактор сценариев для регистрации и карточки существующей поверхности: группировка по доменам, выбор навыка и домена, массовые действия и счётчики.
- Получать список из общего реестра навыков, а схемы параметров — из `connection.parameters` карточек навыков. Строить поля по `key/title/type/required/default/options`; актуальный контракт поддерживает только `select`.
- Хранить параметры по `skill_id`, сохранять введённые значения при переключении выбора и отправлять `{}` для навыка без параметров.
- Загружать сохранённый `enabled_skills` поверхности; сохранять редактирование через отдельный `PUT .../enabled-skills`, регистрацию — через существующий POST создания.
- Показывать исчезнувшие выбранные навыки и ошибки получения схем; блокировать невалидное сохранение без молчаливого удаления данных.
- Зафиксировать отличие от исходного тикета: единственный актуальный источник — приложенный `api-29:09.txt`. В нём нет `available-skills` и признака prod/доступности навыка для поверхности. UI не обещает такую фильтрацию; `PUT .../configuration` для навыков не используется.

## Capabilities

### New Capabilities

- `surface-skill-selection`: выбор и параметры навыков при регистрации и редактировании поверхности, контрактные запросы и обработка неполных/устаревших данных.

### Modified Capabilities

Нет. Существующие требования HTTP-интеграции и достоверного отображения API сохраняются.

## Impact

- `entities/skill`, `entities/surface`: контрактные чтения, схемы, query-кэш и мутация состава навыков.
- `features/surface-registration`, новая общая feature редактора, `widgets/surface-details`: интеграция в два пользовательских сценария.
- Unit/component-тесты и локальные mock fixtures/server-тесты в рамках имеющихся операций. Новые зависимости и API endpoints не нужны.
- Оформление поверхности, публикация, auth/session/RBAC и изменения backend-контракта вне объёма. Прототип служит визуальным ориентиром, а не источником дополнительных API-возможностей.
