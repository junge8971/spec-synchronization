## Context

См. proposal.md. HTML сохраняет чипы в локальном состоянии и копирует window.location.href; это не production-поведение. Новый PDF 3.3–3.4 предоставляет серверное хранение, а 8.23 оставляет риск чувствительных критериев в URL. MOS-1037 владеет selection, MOS-1038 — только его редактором.

## Goals / Non-Goals

**Goals:** одинаковый selection при поиске, сохранении и восстановлении; отсутствие ложного успеха и скрытого расширения выборки.

**Non-Goals:** localStorage-база фильтров, CRUD сверх create/list, employee selector, сервер коротких ссылок без контракта.

## Decisions

1. **Оба gate согласованы пользователем при реализации:** бизнес-методы PDF 3.3–3.4 приняты без auth/session/employee API. Для ссылок разрешены q и user_sso_id во fragment; пользователь подтвердил риск истории браузера и доступа скриптов страницы. Короткие ссылки и дополнительные endpoint не нужны.
2. **Один источник данных:** feature получает применённый selection от владельца реестра и передаёт выбранный selection обратно. Список и создание используют общий HTTP transport/query pattern. Нет импорта feature конструктора; нет копии его сериализатора. Сортировка, курсор, выбранные строки и неприменённый draft не сохраняются.
3. **Имя и конфликты:** trim, 1–100 символов; уникальность без регистра проверяет сервер. HTTP 201 добавляет серверный элемент в чипы с порядком сохранения из контракта. При 409 NAME_CONFLICT не выдавать дубликат за успех; при повторе после неоднозначного сетевого сбоя перечитать список и дать проверить сохранённый отбор. LIMIT_REACHED — отдельное сообщение; текущий предел 50 конфигурируемый, не считать его вечным клиентским лимитом.
4. **Относительный период хранится как preset:** не превращать last_7_days в даты во время сохранения. Удалённый справочный ID сохраняется, поскольку контракт поиска разрешает неизвестные значения; отображать его без молчаливого удаления.
5. **Принятый формат ссылки:** `#selection=<URLSearchParams-encoded JSON>`, schema_version внутри selection. Максимум 8192 байта UTF-8 JSON до URL-кодирования; ограничение проверяется при кодировании и декодировании. Fragment ограничен также максимальным percent-encoded представлением этого объёма. Сериализация сохраняет time_zone и все критерии. Повреждение, лишние/дублированные параметры, потеря полей при валидации и неизвестная версия блокируют поиск до явного сброса. React Router управляет basename, чтением fragment и сбросом; URLSearchParams — кодированием. Ссылка строится только из origin, пути реестра и selection, без query/credentials/сортировки/курсора/draft. Автоматической записи отбора в адрес нет. Fragment не передаётся HTTP-серверу, но не является защитой от истории браузера и скриптов страницы.
6. **Clipboard:** await результата записи, успех только после fulfilled; при отказе — доступная ошибка/ручное копирование согласованного безопасного адреса. Ссылка содержит только критерии, не credentials и не утверждение о правах получателя.

## UI refinement по примеру пользователя

- Компактная адаптивная панель: поиск, период, поверхности/навыки, переключатель условий, сброс и меню «…». Поиск остаётся явным действием (Enter или кнопка с иконкой); автоматическое применение draft не вводится.
- Сохранение и копирование находятся в меню; предупреждение о приватности видно в нём до копирования. После закрытия диалога фокус возвращается к кнопке меню. Сообщения результата не исчезают вместе с закрытием меню.
- Редактор условий — отдельная карточка с применением в шапке, компактными строками и доступными скрытыми подписями. Сведения о недоступных атрибутах доступны через раскрытие.
- Сводка выдачи перенесена вправо в панель, таблица — в компактную карточку с горизонтальным скроллом на узком экране. Чипы остаются отдельными от действий и результатов поиска.
- Выгрузка и выбор строк из примера не добавляются: уточнение касается оформления существующих функций.

## Risks / Trade-offs

- История и скрипты страницы раскрывают q/user_sso_id → согласованный риск; копирование только явным действием, предупреждение в UI, без отдельного логирования selection.
- Потерян ответ create → перечитать список, не автоматически повторять мутацию бесконечно.
- Серверные фильтры доступны при отказе ЕСК → разделить загрузку чипов и результат поиска; применение может завершиться ошибкой независимо от хранения.
- Закэшированный список устарел → использовать серверные ошибки и повтор, не фиксировать локальную проверку имени как окончательную.

## Migration Plan

Сначала общий selection MOS-1037 и принятые saved-filter методы, затем create/list/apply. URL-часть поставляется только после собственного gate; неполная задача не считается закрытой. Unit/component-тесты проверяют round-trip и отказы, без browser/E2E. Откат не удаляет серверные фильтры.
