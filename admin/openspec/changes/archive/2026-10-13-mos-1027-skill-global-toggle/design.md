## Context

См. proposal.md. Текущий контракт содержит GET карточки, POST disable/enable и SkillStatus.disabled. Старое утверждение об отсутствии API снято. UI-референс — `/home/user/Загрузки/Прототип. Центр управления.html`, компонент Dx: полоса состояния и два диалога. Исходник прототипа прочитан как пример, браузерная проверка не выполнялась.

Прототип использует локальные действия, роли superadmin/platform, справочник incident/maintenance/sla и статистику. Они не подтверждают wire-семантику, серверные права, момент применения или наличие аудита. В частности, API требует reason при включении, хотя прототип не показывает это поле.

## Goals / Non-Goals

**Goals:** серверное состояние → валидная форма → подтверждённая команда → актуальная карточка; безопасное восстановление при потере ответа.

**Non-Goals:** длительности, даты отключения, список поверхностей, статистика, инциденты, журнал, impact/replay API, новые permissions и управление lifecycle через POST status.

## Decisions

### UI и формы

- В карточке — компактная полоса с индикатором и текстом состояния слева, действием справа; перенос на узком экране без горизонтального переполнения. Цвет не заменяет текст. Для prod показывать «Активен» / «Отключить», для disabled — «Отключён» / «Включить», для прочих статусов блок скрывать. Переход prod → disabled → prod и текущая UI-политика согласованы с backend по подтверждению пользователя от 13.10.2026; доступность ответов навыка отдельно не измерялась.
- Отключение: заголовок «Отключить навык «<название>»?», указание действия на всех поверхностях, где навык подключён; текстовое поле «Основание», textarea «Что увидит пользователь», «Отмена» и destructive-кнопка «Отключить навык». Не обещать мгновенное применение, отсутствие релиза или запись в журнал.
- Включение: отдельный заголовок «Включить навык «<название>»?», пояснение той же области действия, поле «Основание», «Отмена» и «Включить навык». fallback_text в эту форму и запрос не включать.
- Оба reason вводятся пользователем: trim, длина 1–32. API задаёт строку, не enum; вместо селектора из прототипа используем текстовое поле. fallback_text отключения — trim и минимум один символ; произвольного максимума сверх контракта не добавлять. Начальные значения пустые, reason и fallback_text не синтезировать.
- Ошибки у полей, доступные label, управление фокусом и возврат на инициатор после закрытия. Pending исключает повторную отправку; отказ сохраняет ввод. При смене навыка закрывать старую форму и очищать её ввод, поздний ответ не применять к другой карточке.
- Использовать действующую матрицу permissions. Для непокрытой операции сохранять её существующее правило явного `*`; не назначать самостоятельно TSAM.Skill:disable/enable и не проверять названия ролей из прототипа. Backend авторизует запросы.

### Контракт и владение

База путей: `/api/control/api/skills/v1/skills/{skill_id}`, skill_id — UUIDv7.

| Операция      | Запрос                                                             | Успешный ответ                          |
| ------------- | ------------------------------------------------------------------ | --------------------------------------- |
| GET карточки  | skill_id                                                           | SkillResponse, включая status и version |
| POST /disable | reason, fallback_text, expected_version >= 1; UUID Idempotency-Key | envelope с skill_id, status, action     |
| POST /enable  | reason, expected_version >= 1; UUID Idempotency-Key                | тот же envelope                         |

Action содержит id, action (disable/enable), reason, nullable fallback_text, actor_id и created_at. Ответ команды не является полной карточкой и не содержит новую version. OpenAPI описывает 200 и 422 HTTPValidationError; не назначать неизвестные business-коды для concurrency. Другие отказы обрабатываются штатным transport без подмены в успех.

Типы и runtime-валидация — entities/skill; формы — feature; композиция — существующий widget карточки. Переиспользовать текущие transport, Query и UI, соблюдать публичные API слайсов. Не добавлять зависимость или собственный transport.

### Актуальность и результат

- Подтверждение привязано к skill_id, status и version успешно загруженной карточки. Если известен новый status/version, старое подтверждение недействительно; перечитать данные и получить новое. Ошибка чтения не означает disabled, старые данные не разрешают команду.
- Отправлять expected_version из подтверждаемого снимка. UUID Idempotency-Key создаётся для одной осознанной команды; двойное нажатие не создаёт второй запрос. Автоматические повторы мутации отключены; наличие ключа не означает согласованный replay-протокол.
- Валидировать envelope, совпадение skill_id и action с запросом. Не синтезировать целевой status и не делать optimistic update. Несоответствующий/невалидный ответ не считать подтверждённым успехом; предложить перечитывание.
- После валидного успеха обновить связанные запросы карточки и реестра. Перечитать GET карточки для новой version; до успешного чтения следующая команда недоступна. При отказе перечитывания сообщить, что команда подтверждена, но карточка не обновлена; не повторять мутацию и не выдавать старую version за новую.
- При потере ответа показать неизвестный исход и действие перечитывания. Не сообщать успех или гарантированную отмену. Успешный GET показывает текущее состояние без утверждения, что именно потерянный запрос его установил. Новая команда возможна после актуального чтения и нового подтверждения; обратную команду автоматически не отправлять.

### Подтверждение backend — 13.10.2026

Пользователь уточнил реализацию у backend и подтвердил: «твоя реализация корректна, закрепляем ее». На этом основании gate согласования закрыт. Закреплены переход prod → disabled → prod через отдельные disable/enable, глобальная область действия на подключённых поверхностях и текущая обработка expected_version, отказов и неизвестного исхода.

Момент отображения результата остаётся прежним: валидный ответ команды и перечитывание карточки для актуальной version. Мгновенное применение на поверхностях и конкретный срок не обещаются. Конкретный HTTP/business-код устаревшей версии не установлен; сохраняется штатная обработка отказа без локального успеха и автоматического повтора.

Источник согласования — подтверждение пользователя после консультации с backend. Swagger проверен в открытой вкладке Chrome: формы disable/enable/status доступны, но матрица переходов и concurrency-коды не описаны. Реальные команды на стенде не выполнялись; согласование не является отчётом об интеграционном прогоне.

## Risks / Trade-offs

- [Прототип богаче контракта] → минимальная полоса и формы; без таймеров, аудита и неподтверждённых статистических данных.
- [Нет новой version в результате] → повторный GET и запрет следующей команды до его успеха.
- [Ответ потерян] → неизвестный исход и чтение без автоматической повторной/обратной команды.
- [Схемы не задают серверную семантику переходов] → текущее поведение согласовано с backend через пользователя 13.10.2026; реальный интеграционный прогон не выполнен.

## Migration Plan

Подключить клиент и валидацию существующих схем, собрать полосу и формы, проверить unit/component-сценарии. При изменении Express-моков прочитать change add-local-session-demo; моки без credentials и ролевого enforcement, mock-результат не является подтверждением backend. Согласование текущей реализации получено от пользователя после консультации с backend. Фактический интеграционный прогон остаётся непроведённым и не заявляется результатом этого согласования. Откат UI не восстанавливает состояние навыка и не отменяет серверную команду.
