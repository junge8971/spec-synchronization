## Context

См. proposal.md. В прототипе используется поиск по локальному массиву. DTO фраз, GET карточки с intents, PUT intents, редактор MOS-945 и мастер MOS-942 уже реализованы. Опубликован single-phrase preflight по глобальному реестру: метод существовал в snapshot `openapi-2026-10-15.raw` без description, текущие descriptions уточняют его семантику, а не вводят новый метод; сохранение фраз не подтверждает отсутствие конфликтов.

## Goals / Non-Goals

**Goals:** актуальная серверная подсказка по одной фразе во всём реестре; чёткое отделение подсказки от проверок сохранённого набора и серверной валидации продвижения.

**Non-Goals:** собственный классификатор, обход всех страниц GET навыков, клиентские permissions или имитация семантической близости.

## Decisions

- Опубликованные факты: preflight проверяет одну фразу по активным группам неудалённых навыков во всём реестре, исключая собственный навык; exact блокирует, semantic предупреждает. Близость выражена в процентах, exact идут первыми, semantic — по убыванию близости; настраиваемый порог по умолчанию 0.75 не означает клиентский порог. По согласованию используется опубликованный ответ с обязательными `skill/domain` (`id/name`), включая названия других команд; дополнительных запросов на раскрытие нет.
- API-gate снят согласованием live OpenAPI `https://nchat-a-tech.mos.ru/api/control/openapi.json` (проверен 23.10.2026). Нормализация — исключительно ответственность сервера: клиент не меняет текст ради сравнения и не вычисляет exact/semantic. Граничные примеры пробелов, регистра, Unicode и пунктуации остаются вопросом к backend, а не условием завершения UI.
- Разделять transient single-phrase preflight, который ничего не сохраняет и не меняет readiness checks, сохранение полного набора групп через PUT intents с транзакционным пересчётом проверок и повторную валидацию согласованной отправки. No-op сохранения не пересчитывает проверки и не увеличивает версию; результат сохранения не содержит checks, описания направляют к карточке навыка. Чистый preflight одной фразы не подтверждает остальные группы/текущие правки и не разблокирует отправку.
- Preflight относится только к конкретной фразе и skill ID. При изменении любого из них сбрасывать результат; поздний ответ старого запроса не заменяет актуальную подсказку. Использовать существующий transport и AbortSignal. Успех не является подтверждением полного набора или версии навыка.
- Exact в preflight обозначает блокирующий конфликт для дальнейшего продвижения; semantic предупреждает. Pending/stale/error не означают «конфликтов нет», показываются доступные состояние ожидания, ошибка и retry. Ни эти состояния, ни exact не блокируют сохранение фраз и `draft -> checking`.
- При продвижении, требующем readiness, сервер заново проверяет сохранённые данные и возвращает `409 SKILL_CHECKS_BLOCKED` при блокирующем результате; semantic сам по себе не мешает. Клиент не заменяет эту проверку preflight или сохранёнными checks. Существующие точки продвижения обрабатывают отказ, не показывая успешный переход; реализация отсутствующих lifecycle-команд относится к MOS-1019, не к этому change.
- Сценарий скрытых данных отложен до появления DTO: сейчас `skill/domain.id/name` обязательны, отсутствие полей — malformed response, а не придуманная редактированная форма. Клиентский RBAC не добавляется.
- Композицию редактора MOS-945 и результата выполнять общим widget/страницей, API-предикаты актуальности держать у предметного владельца, без cross-feature импорта.

## Risks / Trade-offs

- TOCTOU после проверки → серверная проверка при отправке обязательна в согласовании; UI не гарантирует глобальную уникальность самостоятельно.
- Противоречие wiki MAC-6/T-19 и API разрешено пользователем в пользу live API: сохранение и `draft -> checking` не блокируются конфликтами. Сервер пересчитывает readiness при продвижении из checking и далее, кроме опубликованных исключений `whitelist -> review` и `rejected -> review`; клиент не вводит собственную политику переходов.
- Ложная независимость от данных MOS-945 → переиспользовать редактор и формат фраз, привязать подсказку к текущей фразе, но принимать отображение конфликтов отдельно. В мастере MOS-942 проверка требует уже созданного skill ID: не создавать навык вторым POST ради preflight.

## Migration Plan

Заменить unavailable-сценарий single-phrase проверки существующим API; добавить unit/component проверки гонки, exact/semantic, ошибки и сохранения без preflight-блокировки. Сохранить протокол частичной регистрации и восстановления мастера без второго POST. Граничные серверные примеры нормализации и скрытые данные отложены явно; локальная имитация успешной проверки недопустима.
