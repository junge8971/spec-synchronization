## Why

MOS-1018: локальное сравнение фраз в HTML-прототипе не гарантирует отсутствие конфликтов по всему реестру. Нужны серверная подсказка по текущей фразе и достоверная серверная проверка сохранённых данных при продвижении навыка.

## What Changes

- Показать конфликтующую фразу, тип, близость, навык и домен в пределах серверного ответа.
- Single-phrase preflight показывает подсказку: exact — блокирующий конфликт для продвижения, semantic — предупреждение. Сохранение фраз и `draft -> checking` конфликтами не блокируются.
- При дальнейшем продвижении сервер заново проверяет сохранённые данные; preflight не подтверждает готовность полного набора.
- Изменение фразы или skill ID делает прежнюю подсказку неактуальной; ошибка запроса не означает отсутствие конфликтов.
- Использовать один сценарий проверки в существующих редакторе MOS-945 и мастере MOS-942, не реализуя их повторно.

## Capabilities

### New Capabilities

- `skill-phrase-conflicts`: серверная проверка конфликтов обучающих фраз.

### Modified Capabilities

Нет. Не отменяет запрет синтетических данных в `control-center-api-integration`.

## Impact

- `app/entities/skill/`, редактор MOS-945, вкладка проверок `app/widgets/skill-details/`.
- Принят live OpenAPI `https://nchat-a-tech.mos.ru/api/control/openapi.json`, проверенный 23.10.2026: single-phrase preflight, PUT intents и серверная повторная проверка при продвижении. Новые endpoints не требуются.
- Нормализация выполняется только сервером; граничные примеры остаются вопросом к backend, не блокирующим UI-интеграцию. Используются обязательные `skill/domain` с `id/name`; сценарий скрытых данных отложен до появления соответствующего DTO.
- Противоречие wiki send-to-checking разрешено в пользу live API: `draft -> checking` не требует проверок. Полный lifecycle UI не входит в этот change.
- Отдельная приёмка MOS-1018; функционально связана с MOS-945 и MOS-1019, не требует реализации клиентских ролей.
