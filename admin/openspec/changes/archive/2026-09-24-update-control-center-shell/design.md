## Context

См. `proposal.md` для мотивации и границ MOS-904. Приложение использует React Router Framework в SPA-режиме с basename `/tsam-panel/`. `ApplicationLayout` уже объединяет header, navigation и breadcrumbs. Профиль загружается `useCurrentPrincipalQuery`; документация уже использует query-параметр `article`. Sidebar поддерживает мобильный drawer и закрытие после перехода.

В HTML оболочка Bb использует демонстрационные роли, фиктивные организации, переход на login вместо logout и переключатели роли/команды. Эти механизмы не являются контрактом. Актуальный `/me` содержит пять функциональных ролей и scope, но не permissions, организацию или активную команду. Общего auth-контекста и маршрутов `/teams`, `/ops` сейчас нет. Текущие спецификации HTTP и API integration запрещают выдумывать авторизацию и серверные данные.

## Goals / Non-Goals

**Goals:** переиспользовать widgets и конфиг маршрутов; отделить отображение от решений о доступе и сессии; дать проверяемый UI при отсутствующих интеграциях.

**Non-Goals:** новый auth-provider, вычисление матрицы ролей внутри навигации, session API, guards прямых URL, новый роутер, копия каталога документации, произвольный выбор активной команды, инфраструктура туров.

## Decisions

### 1. Доработать существующие widgets

Обновить `NavigationBrand`, `ApplicationHeader`, `ApplicationNavigation` и при необходимости композицию `ApplicationLayout`. Использовать знак из предоставленного HTML как отдельный локальный asset, не копировать bundle прототипа. Сохранить заголовок раздела вместо демонстрационных селекторов и существующие breadcrumbs. Постоянный бейдж «Демо» удалить; новую систему режимов не вводить.

Меню и диалог строить на установленной UI-библиотеке и соглашениях проекта. В `app/shared/ui` пока нет dropdown-menu/dialog: при реализации сначала проверить доступные primitives и документацию, добавить только минимальную нужную композицию. Библиотека onboarding не требуется. Альтернатива полного переноса оболочки прототипа отвергнута: теряются текущие mobile-поведение и маршрутизация.

### 2. Отображение профиля не владеет авторизацией

Переиспользовать текущий query и форматирование имени, ролей, scope без второго состояния пользователя. Меню открывается настоящей кнопкой с доступным именем; мобильная версия может скрывать длинную подпись, но не кнопку. Организацию не показывать, пока источник данных её не предоставляет; не выводить её из списка команд.

В меню: «Команды и доступ», «Пройти обучение заново», «Выйти». Размещение перехода к командам в профиле — локальное UI-решение: в Bb такого пункта нет, но он явно нужен по MOS-904.

Выход вызывает только обработчик внешнего слоя сессии. Pending блокирует повторный вызов; ошибка остаётся видимой и позволяет повтор. При отсутствии обработчика пункт недоступен с пояснением «Выход недоступен: интеграция сессии не подключена». Никакого запроса к придуманному endpoint, очистки токена вместо logout или перехода на несуществующий login. Очистка auth/query state и конечный redirect принадлежат CC-FE-002.

### 3. Доступность — вход UI, не новая политика

Точки интеграции ограничить небольшими входами компонентов: подтверждённая доступность разделов, состояние её загрузки/ошибки и обработчик выхода. Точные типы согласовать с готовым общим auth-слоем, не создавать параллельный provider. До его готовности использовать явное unavailable-состояние, а не разрешения по умолчанию. Test doubles разрешены только в тестах.

Для бизнес-раздела ссылка активна только при подтверждённом разрешении и существующем маршруте. Отказ скрывает пункт; неподтверждённые права не дают ссылок, рядом отображается состояние загрузки/недоступности навигации. Документация остаётся доступной как статическая справка. Пустые группы скрываются. Потеря подтверждённых прав убирает старые доступные пункты, но не заменяет route guards.

Состав основной группы: навыки, поверхности, песочница, без заголовка «Подключение»; затем аналитика; эксплуатация содержит «Состояние системы». Для разрешённого, но ещё не реализованного `/teams` или `/ops` показывать недоступный пункт с пояснением, без `href`. Для `/teams` это пункт профиля. Регистрацию маршрутов и экраны не включать в этот change. Расширять текущий конфиг только для UI-потребностей; не создавать второй реестр роутера.

Альтернатива скопировать roles из zb отвергнута: enum прототипа отличается от API, роли могут быть множественными. Скрытие меню не является мерой серверной безопасности.

### 4. Документация — ссылки на существующие статьи

Кнопка footer открывает dropdown, не contextmenu по правому клику. Использовать первые шесть статей `documentationArticles` в их текущем порядке, затем «Все разделы». Ссылки остаются `/documentation?article=<id>` и `/documentation`, React Router сохраняет basename. Не вводить `/docs` или `/metrics` в этом change. Выбор статьи закрывает dropdown и мобильный sidebar. Существующее поведение неизвестного article сохраняется.

### 5. Подсказки — локальная справка

Пошаговый диалог с заголовком, текстом, «Где найти», номером шага, действиями «Далее», «Прекратить», «Начать работу». Использовать общий краткий сценарий о навигации, профиле и документации, без матрицы ролей, обещаний недоступных функций и демонстрационного `noonb`.

Автопоказ только после получения валидного `user_id` и отсутствия отметки для текущей версии подсказок. Хранить в localStorage только факт просмотра, namespace по user_id и версии; не ФИО, роли или токены. Закрытие любым способом (включая Escape) и завершение ставят отметку. Повторное открытие начинает с первого шага. При смене пользователя закрыть прежний диалог и проверить отметку нового пользователя. При ошибке storage диалог работает, а in-memory отметка предотвращает повтор в текущем сеансе оболочки; после перезагрузки показ возможен снова. Между устройствами отметка не синхронизируется.

### 6. Доступность и проверка

Использовать штатные menu/dialog primitives для клавиатуры, Escape и возврата фокуса. После навигации из мобильного меню фокус не должен оставаться в скрытом drawer. Длинные строки не расширяют viewport, полные данные доступны в меню. Проверять UI без интеграций и интегрированные состояния отдельно.

## Risks / Trade-offs

- [Нет общего источника прав] → UI проверяется с test doubles; runtime показывает недоступность вместо выдачи всех прав. Это ограничивает промежуточную поставку; полноценная приёмка ожидает CC-FE-003.
- [Нет logout и новых маршрутов] → недоступные действия с пояснениями, без ложного успеха/404; интеграционные задачи остаются открытыми.
- [Старый backlog описывает другой API] → ориентироваться на текущий OpenAPI; документацию backlog не переписывать в рамках change.
- [Общие подсказки менее персональны] → безопасны без согласования ролей; ролевые сценарии можно добавить отдельным изменением.
- [localStorage очищен или заблокирован] → справка доступна вручную, повторный автопоказ после reload допустим; серверную синхронизацию не обещать.

## Migration Plan

1. Реализовать независимые UI-блоки и безопасные состояния отсутствующих зависимостей без изменения API или URL.
2. Подключить внешний источник прав, выход и новые маршруты только после готовности соответствующих задач. Не отмечать интеграционные пункты выполненными по component mocks.
3. Пройти локальные проверки и browser-сценарии под `/tsam-panel/`; отдельно зафиксировать недоступные интеграционные проверки.
4. Rollback — откат UI-коммита; миграций API/данных нет. Локальная отметка справки безвредна для предыдущей версии.
