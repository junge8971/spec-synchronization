# Proposal

## Why

В мастере добавления поверхности длинный идентификатор канала и описательный текст навыка не имеют требуемого визуального ограничения, а список владельца использует режим раскрытия с перекрытием поля. После подтверждённого отказа создания обработка `422 FAILED` уже позволяет исправление, но результат регистрации не предоставляет предусмотренный баг-репортом переход к реестру; требуется завершить исправление и закрепить регрессии четырёх задач.

## What Changes

- [MOS-1164](https://task.mos-team.ru/browse/MOS-1164): визуально ограничить предпросмотр идентификатора канала на шаге «Регистрация» и устранить растягивание формы длинным значением. Полный текст остаётся доступным; домены, расчёт предпросмотра и серверное назначение `channel_id` сохраняются.
- [MOS-1165](https://task.mos-team.ru/browse/MOS-1165): привязать список «Владелец поверхности» на шаге «Ответственные» к полю без перекрытия, вызванного совмещением выбранного пункта с trigger. Сохранить штатное позиционирование и управление Select мышью и клавиатурой.
- [MOS-1166](https://task.mos-team.ru/browse/MOS-1166): визуально ограничить описательный текст навыка на шаге «Сценарии», сохранив полное значение и доступное описание переключателя. Учесть второго потребителя общего редактора — карточку поверхности.
- [MOS-1907](https://task.mos-team.ru/browse/MOS-1907): после распознанного отказа создания оставить доступными «Назад» и «К реестру поверхностей», сохранить введённые данные и предупреждение об уходе. Закрепить точный сценарий `422 FAILED` с ошибкой `/domains`, пустым верхнеуровневым `message` и отправкой на проверку.
- Сохранить существующее различие подтверждённого отказа и неизвестного результата: потеря ответа и нераспознанный формат не разрешают повторный POST.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `surface-registration`: добавить требования к длинному предпросмотру канала и привязке списка владельца; уточнить доступное восстановление после подтверждённого отказа создания.
- `surface-skill-selection`: добавить требование к визуальному ограничению описательного текста без изменения данных, выбора и доступности общего редактора.

## Impact

- Планируемая реализация: `app/features/surface-registration/ui/` и общий элемент `app/features/surface-skill-selection/ui/surface-skill-selection-editor/skill-selection-item.tsx`. Проверки размещаются у соответствующих компонентов и в `app/widgets/surface-registration/ui/tests/`.
- Переиспользуются существующие Tailwind utilities, Base UI Select и Tooltip. Новые зависимости, endpoints, DTO и изменения общих defaults Select не требуются.
- Значение около 200 символов используется как пример воспроизведения, а не новый лимит данных. Текущий список показывает `skill.purpose`; переход на detail-поле `description` в scope не входит.
- Проверка поведения — unit/component-тесты. Браузерные/E2E-тесты не создаются и не запускаются без отдельного разрешения. Статический анализ и jsdom не подтверждают фактическую геометрию или состояние развёрнутой сборки.
- Этот change создаёт только план. Код приложения, основные specs, архивы и внешние задачи при его подготовке не изменяются.
