## Why

[MOS-2350](https://task.mos-team.ru/browse/MOS-2350) требует отдельное окно с итогом массового выката в prod. Сейчас результаты отображаются под кнопками реестра, а общий отчёт хранит последние исходы по ID навыков и может смешивать разные запуски и цели.

## What Changes

- По завершении `whitelist → prod` показывать «Результаты выката»: сколько навыков подтверждено в prod из выбранных для этого запуска, исход и фактический статус каждого навыка, если он известен.
- Открывать результат автоматически один раз, без отдельной кнопки. Если выкат завершился вне реестра, открыть окно при первом возврате. Для неизвестных исходов сохранить перечитывание состояния без повтора команды, в том числе в реестре после закрытия окна.
- Не открывать модалку после `approved → whitelist` и сохранить действующий построчный отчёт этого перехода. Основание для границы: [аналитика «Админка. Навыки», T-08 и T-09](https://wiki.mos-team.ru/spaces/KR/pages/241080062) разделяет сценарии, а [MOS-1772](https://task.mos-team.ru/browse/MOS-1772) требует построчный результат, но не окно итогов. [MOS-1021](https://task.mos-team.ru/browse/MOS-1021) уже задаёт основу массового действия и отчёта по каждому навыку.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `skill-bulk-rollout`: доступная модалка итогов конкретного выката в prod с отдельным чтением фактического состояния при неизвестном исходе.

## Impact

Изменения ограничены feature `app/features/skill-bulk-rollout/`, её подключением в реестре при необходимости и затронутыми тестами. Переиспользуются `Dialog`, действующие POST смены статуса и GET карточки; API, правила переходов, доступы, зависимости и аудит не меняются.

При реализации проверить затронутые сценарии, ошибки и клавиатуру через Playwright MCP на локальном приложении с моками, в дополнение к unit/component-тестам. Автоматические E2E и внешние контуры требуют отдельного разрешения. Зафиксировать результаты или блокеры; проверки на моках не подтверждают интеграцию с реальным backend.
