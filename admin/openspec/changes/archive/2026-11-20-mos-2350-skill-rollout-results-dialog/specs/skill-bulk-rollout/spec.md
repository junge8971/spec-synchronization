## ADDED Requirements

### Requirement: Production rollout results dialog

По завершении массовой операции с целью `prod` реестр SHALL показывать модальное окно «Результаты выката», если пользователь находится на вкладке реестра. Окно SHALL показывать один запуск: число навыков, для которых ответ на команду подтвердил `prod`, из числа выбранных при подтверждении, и отдельную строку с названием и ID каждого выбранного навыка, в том числе неотправленного. Результаты других запусков или целей MUST NOT попадать в этот итог. Завершение `approved → whitelist` MUST NOT открывать окно; построчный результат этой операции SHALL оставаться доступным в реестре.

Для каждого навыка UI SHALL отличать текстом подтверждённый успех (`success`), ответ с другим статусом (`warning`), конфликт (`conflict`), неизвестный исход (`unknown`), явный отказ и неотправленную команду. UI SHALL показывать фактический статус из валидного ответа на команду, если он получен, и явно отмечать отсутствие подтверждённого статуса иначе. Исходный статус из подтверждения MUST NOT выдаваться за фактический. При ручном перечитывании для `unknown` UI SHALL показывать текущее состояние отдельно от исхода команды; чтение MUST NOT менять исход команды или счётчик подтверждённых в `prod`.

Пользователь SHALL иметь возможность закрыть окно кнопкой и Escape. После закрытия фокус SHALL возвращаться к индикатору выбора в панели массовых действий. Отдельной кнопки открытия отчёта MUST NOT быть. Если запуск завершился на другой вкладке раздела «Навыки», окно SHALL автоматически появляться при первом возврате в реестр, а не поверх другой вкладки. После закрытия обновление данных, перечитывание карточки или повторный возврат на вкладку MUST NOT снова открывать отчёт. Неизвестные исходы, для которых нужна сверка перед новой попыткой, SHALL оставаться доступны для перечитывания из реестра после закрытия окна и после завершения более позднего запуска.

#### Scenario: Mixed production outcomes

- **WHEN** для пяти выбранных навыков сервер подтверждает `prod` для одного, возвращает другой статус для второго, конфликт для третьего, неизвестный исход для четвёртого и явный отказ для пятого
- **THEN** активный реестр открывает «Результаты выката» с итогом «1 из 5», показывает пять строк с различимыми текстовыми исходами, статусы из валидных ответов и отсутствие подтверждённого статуса там, где его нет
- **AND** прежние результаты не влияют на строки и счётчик

#### Scenario: Read current state after an unknown outcome

- **WHEN** из строки с неизвестным исходом пользователь перечитывает состояние и получает ошибку чтения, а затем успешно перечитывает карточку со статусом `prod`
- **THEN** ошибка сохраняет неопределённость, а успешное чтение показывает текущий `prod` отдельно от неизвестного исхода команды
- **AND** чтение не отправляет POST смены статуса, не увеличивает счётчик и не выдаёт неизвестную команду за успешную

#### Scenario: Close the results with the keyboard

- **WHEN** пользователь закрывает результат выката клавишей Escape, затем данные реестра обновляются или пользователь перечитывает состояние навыка
- **THEN** фокус после закрытия возвращается к индикатору выбора, окно не открывается снова и кнопки повторного открытия нет
- **AND** перечитывание для неизвестных исходов доступно в реестре без новой мутации

#### Scenario: Finish off the registry tab

- **WHEN** пользователь уходит на «Домены» или «Ревью» во время выката и не возвращается до завершения уже отправленной команды
- **THEN** окно на другой вкладке не открывается, а при первом возврате в реестр автоматически показывает итог по всему подтверждённому составу, включая неотправленные навыки
- **AND** после закрытия повторный возврат не открывает тот же итог, а неотправленные команды не возобновляются и не засчитываются как успех

#### Scenario: A later run does not hide an unresolved result

- **WHEN** после неизвестного исхода одного выката пользователь завершает отдельный выкат других навыков
- **THEN** окно и счётчик относятся только к более позднему запуску, а исход предыдущего навыка, для которого требуется сверка, можно перечитать отдельно

#### Scenario: Whitelist transition keeps its inline report

- **WHEN** пользователь завершает массовый перевод `approved → whitelist` после выката в `prod`
- **THEN** результат перевода остаётся построчным в реестре, не запускает модалку и не заменяет последний отчёт выката в `prod`
