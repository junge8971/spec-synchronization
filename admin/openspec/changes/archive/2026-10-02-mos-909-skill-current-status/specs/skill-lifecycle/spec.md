## MODIFIED Requirements

### Requirement: Contract-gated lifecycle

Карточка SHALL показывать опубликованный текущий SkillResponse.status как read-only сведения независимо от готовности API переходов. Полная шкала жизненного цикла и допустимые команды SHALL отображаться только после согласования и подключения API состояния этапов, переходов, конкурентной версии, идемпотентности и восстановления неизвестного исхода. До этого UI MUST NOT отображать шкалу, самостоятельный блок жизненного цикла, заглушку его недоступности и связанные команды обучения, отправки на проверку и выката, включая disabled-кнопки. Наличие SkillStatus и POST status MUST NOT считаться согласованием этих сценариев. Отложенный lifecycle MUST NOT блокировать поддерживаемые анкету, фразы и подключение; создание анкеты является отдельным сценарием и зависит от протокола регистрации, а не от наличия lifecycle API. Наличие обычного PATCH анкеты MUST NOT считаться поддержкой lifecycle; неизвестный статус MUST NOT сопоставляться с «Черновик» или «Прод» по умолчанию.

#### Scenario: Current skill API

- **WHEN** карточка получена по текущему контракту с опубликованным status без данных о прохождении этапов
- **THEN** показан только текущий статус, сведения анкеты, фразы и подключение доступны; шкала, заглушка lifecycle и его команды отсутствуют, POST status и PATCH status не выполняются ради отображения

#### Scenario: Unknown server state

- **WHEN** ответ карточки содержит status вне опубликованного enum
- **THEN** UI показывает штатную ошибку чтения контракта без вымышленного статуса, шкалы и предложений перехода; правило совместимости неизвестных строк в списке не расширяет валидацию карточки

## ADDED Requirements

### Requirement: Read-only current skill status

Общая шапка карточки SHALL показывать текст «Статус: <подпись>» из последнего успешно полученного и валидного SkillResponse.status. Подписи SHALL совпадать с реестром: draft — «Черновик», checking — «Проверка», training — «Обучение», autotest — «Автотесты», sandbox — «Песочница», review — «Ревью», whitelist — «Белые списки», prod — «Прод». Статус SHALL оставаться видимым при переключении вкладок и различаться текстом, а не только цветом; на узком экране сведения шапки SHALL переноситься без потери текста. Показ статуса MUST NOT добавлять отдельные запросы, polling или мутации. Текущий статус MUST NOT означать успешное прохождение предыдущих этапов, готовность текущей версии фраз или согласование ревью. Integer version SHALL оставаться версией записи, не номером релиза.

#### Scenario: Published statuses

- **WHEN** карточка успешно загружена с любым из восьми опубликованных статусов
- **THEN** в шапке видна соответствующая текстовая подпись; например training отображается как «Статус: Обучение», без таймера, прогресса или утверждения об успешных проверках

#### Scenario: Switch detail tabs

- **WHEN** пользователь переключается между обзором, проверками, обучающими фразами, подключением и историей
- **THEN** текущий серверный статус остаётся в общей шапке, не порождая дополнительных запросов ради статуса и не заменяя содержимое вкладок

#### Scenario: Server status changes on a subsequent read

- **WHEN** существующий механизм чтения получает валидную карточку с другим status
- **THEN** подпись отражает новое серверное значение без отдельного локального состояния и без вывода истории переходов

#### Scenario: Missing or non-string status

- **WHEN** ответ карточки не содержит status либо возвращает null, число, boolean, объект или массив
- **THEN** загрузка показывает штатную ошибку контракта, а не «Черновик», «Прод» или синтетическое значение «Неизвестный статус»
