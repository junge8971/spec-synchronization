## Context

См. proposal.md. Короткий design фиксирует различие двух моделей чтения и границу lifecycle, чтобы не перенести допускающую неизвестные строки модель списка в строгую карточку. SkillDetailsHeader получает валидный SkillDetails от существующего query; status уже проверяется через z.enum(skillStatuses). Публичный entities/skill экспортирует skillStatusLabels, используемый реестром. Шапка общая для всех вкладок, но показывает только version/type, не status.

## Goals / Non-Goals

**Goals:** показать уже загруженное поле без новых запросов и дублирования состояния/словаря.

**Non-Goals:** смягчение detail-валидации, общий компонент статуса для всех сущностей, новый hook, шкала процесса и команды переходов.

## Decisions

- Добавить существующий Badge в SkillDetailsHeader с текстом «Статус: {skillStatusLabels[skill.status]}». Статический read-only текст не требует live-region role=status. Отдельный компонент/словарь не нужен: JSX локален, публичный API сущности уже достаточен.
- Сохранить type/version рядом со статусом; разрешить перенос группы badges. Дублировать статус строкой overview не нужно: общая шапка доступна на всех вкладках.
- Не добавлять локальный state: обновлённый skill из существующего query сразу обновляет подпись. Отдельный status-запрос или polling отвергнуты как лишние.
- Оставить строгую runtime-схему SkillResponse: неизвестные, отсутствующие и нестроковые значения являются ошибкой контракта. Fallback списка «Неизвестный статус» здесь неприменим; не расширять OpenAPI или read-model карточки.
- В существующем component-тесте заменить запрет любого текста «Черновик» проверкой опубликованного статуса и отдельным запретом шкалы/ETA/фиктивных успехов. Сохранить проверки отсутствия lifecycle-кнопок и GET-only поведения; это обновление ожидаемого поведения, не ослабление регрессий.

## Risks / Trade-offs

- Статус prod/review ошибочно воспринимается как доказательство всех проверок → показывать только подпись без отметок завершения, готовности и дополнительных обещаний.
- Новая подпись расширяет шапку → перенос badges, сохранение текстовых подписей. Browser-проверка не разрешена, визуальное совпадение не заявлять.
- Backend добавит enum → карточка сохранит штатную ошибку контракта до согласованного обновления; это намеренно прежняя строгая семантика, не новое поведение списка.

## Migration Plan

Изменить шапку и целевые тесты, выполнить проверки из tasks.md. Миграции данных/контракта нет; rollback удаляет отображение статуса, не меняя серверное состояние. Полный MOS-909 остаётся отложенным до согласования lifecycle API.
