## Purpose

Реализовать расширенные условия отбора опросников в разделе обратной связи ЦАМ по опубликованному API, с отдельной приёмкой и сохранением ограничений первого этапа.

## ADDED Requirements

### Requirement: Advanced conditions and reproducible selection

Условия SHALL строиться по metadata condition_fields: одна плоская группа and/or, максимум 50 условий. Поля — name/code/description/type_code/status/audience_type/owner; операторы только разрешённые для поля. Справочные in/not_in SHALL использовать 1–100 уникальных кодов; is_empty/is_not_empty SHALL не требовать значения. Обычные фильтры и query SHALL объединяться с группой через AND. В первом этапе аудитория SHALL выбираться только внутри конструктора; независимый мультиселект аудитории и условие tags MUST NOT предлагаться.

Применённый search SHALL полностью восстанавливаться из URL, истории и скопированной ссылки, включая conditions, сортировку и пагинацию. Дополнительный лимит размера URL MUST NOT ограничивать валидный отбор; большой отбор MUST NOT усекаться или молча применяться без полного адреса. При доступном приложению отказе формирования или записи адреса либо копирования SHALL сохраняться ввод и показываться ошибка; прежний или неполный адрес MUST NOT выдаваться за ссылку на новый отбор. При отказе `pushState` штатный fallback роутера MAY вызвать переход с перезагрузкой: в этом согласованном случае показ ошибки и сохранение ввода не гарантируются. Успешное копирование SHALL подтверждать только запись в clipboard, не гарантируя открытие ссылки в любом окружении. Неприменённый draft условий MUST NOT попадать в экспорт/сохранённый фильтр. Повреждённые параметры SHALL давать явное пояснение и валидное состояние; неполный отбор MUST NOT молча выдаваться за исходный.

Для contains/not_contains/eq/ne/starts_with/ends_with value SHALL быть строкой 1–1000 символов. Для in/not_in каждая из 1–100 уникальных строк SHALL иметь 1–1000 символов; очистка последнего выбранного значения SHALL удалять условие, не отправлять пустой массив. Для is_empty/is_not_empty value SHALL отсутствовать либо быть null. Пробелы MUST NOT обрезаться: строка из пробелов не пуста, регистр и буквальные символы SHALL сохраняться. eq/ne/in/not_in сравнивают с учётом регистра; contains/not_contains/starts_with/ends_with — без него. UI MUST NOT заменять серверную семантику локальной фильтрацией.

После локально валидного применения search SHALL записываться в URL до серверного ответа. При ответе 422 URL SHALL сохранять отправленный отбор без отката к предыдущему; редактор и ввод SHALL оставаться доступными, а ошибка JSON Pointer SHALL отображаться у соответствующего условия. Старые результаты MUST NOT выдаваться за результаты отклонённого запроса. Ошибка SHALL сопоставляться с отправленным снимком, а не приписываться изменённой или другой строке; если достоверное сопоставление невозможно, SHALL показываться общая ошибка с сохранением серверных деталей. Ответ устаревшего отбора MUST NOT показываться ошибкой текущего отбора.

#### Scenario: Or group with basic filter

- **WHEN** status=active и условия name contains «оценка» OR owner eq «ЦАМ» применены
- **THEN** сервер получает status отдельно и плоскую or-группу, URL восстанавливает весь отбор, счётчики/экспорт используют тот же search

#### Scenario: Large valid selection retains its complete link

- **WHEN** пользователь применяет 50 валидных текстовых условий длиной 1000 символов каждое и окружение позволяет записать полный адрес
- **THEN** URL и запрос содержат все условия без дополнительного лимита или усечения; при получении полного адреса из истории или скопированной ссылки приложение восстанавливает тот же отбор

#### Scenario: Address or clipboard error reaches the application

- **WHEN** приложению доступна ошибка формирования или записи полного адреса либо копирования ссылки
- **THEN** пользователь видит ошибку без потери ввода; старый или усечённый адрес не выдаётся за ссылку на новый отбор, успех не объявляется

#### Scenario: Router falls back after history push refusal

- **WHEN** запись истории отклонена и роутер выполняет штатный переход с перезагрузкой
- **THEN** сохранение ввода и показ ошибки не гарантируются; отдельная запись истории не подменяется незаметным усечением отбора

#### Scenario: Server rejects an applied condition

- **WHEN** сервер возвращает 422 с указателем на условие отправленного отбора
- **THEN** URL остаётся с этим отбором, ввод доступен для исправления, ошибка показана у соответствующей строки, а предыдущие результаты не выдаются за новый успешный поиск

#### Scenario: Delayed or unmappable condition error

- **WHEN** до ответа строка черновика изменилась либо указатель нельзя достоверно сопоставить с условием отправленного снимка
- **THEN** сообщение с серверными деталями доступно в общем контексте и не приписывается другой строке
- **WHEN** ответ относится к отбору, уже заменённому текущим
- **THEN** он не показывается ошибкой текущего отбора

#### Scenario: Audience does not change logic secretly

- **WHEN** пользователь хочет аудиторию вместе с условиями ИЛИ
- **THEN** аудитория доступна как явная строка этой группы с той же логикой; UI не обещает дополнительное независимое AND и не подмешивает скрытые условия

#### Scenario: String length and whitespace

- **WHEN** введено значение из пробелов либо строка длиной 1000/1001 символ
- **THEN** пробелы сохраняются буквально, 1000 символов допустимы, 1001 блокирует применение с ошибкой без потери draft

#### Scenario: Clear the final membership value

- **WHEN** пользователь убирает последний код из in/not_in
- **THEN** условие удаляется из draft; после применения оно отсутствует в search, пустой массив не отправляется

### Requirement: Accessible conditions interactions

Область этой задачи — редактор условий и панель применённого отбора — SHALL поддерживать клавиатуру, доступные названия/ошибки, предсказуемый фокус и узкую компоновку. Приёмка SHALL проверять собственные элементы; реализация и приёмка соседних UI-возможностей MUST NOT требоваться для закрытия этой задачи сверх явно указанных зависимостей интеграции. Недоступные API MUST NOT имитироваться успешными заглушками.

#### Scenario: Keyboard and narrow layout within this task

- **WHEN** пользователь работает с элементами этой задачи клавиатурой на узком экране
- **THEN** действия и ошибки доступны, содержимое не перекрывает управляющие элементы, закрытие имеющихся диалогов возвращает фокус
