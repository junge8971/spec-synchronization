## Why

[Jira MOS-1259](https://task.mos-team.ru/browse/MOS-1259): [FE][Обратная связь] Реализовать серверные сохранённые фильтры опросников. [MOS-2140](https://task.mos-team.ru/browse/MOS-2140) рассматривается совместно: модальное окно сохранения фильтра опросников.

Нужна отдельная реализуемая поставка этой FE-подзадачи по обновлённому API и принятой границе прототипа. План, приёмка и выполнение учитываются отдельно от остальных задач MOS-1246.

## What Changes

- Персональные серверные фильтры поверх существующего реестра: создать, список, применить, явно обновить выбранный ID через PUT, удалить; resource=feedback-surveys. Источник API — локальный `docs/api/contracts/crud-api.md`, раздел 9, и согласованные с ним локальные OpenAPI; PATCH из Jira не используется.
- Модальное окно сохранения текущего отбора с наименованием, подтверждением, отменой и обработкой ошибок.
- Сохранить ограничения API, ввод при ошибках, доступность и действующую безопасность.

### Deferred scope

Автоматическая перезапись фильтра по имени и localStorage fallback не входят.

## Capabilities

### New Capabilities

- `feedback-saved-filters`: Персональные серверные фильтры: создать, список, применить, явно обновить выбранный ID, удалить; resource=feedback-surveys.

### Modified Capabilities

Нет. Общие capabilities HTTP, permissions и MPMM сохраняются; scope соседних FE-подзадач сюда не переносится.

## Impact

Клиенты saved-filters, персональные отборы реестра и mock handlers.

Основа интеграции: существующий реестр MOS-1250 и реализованные условия MOS-1258 ([feedback-conditions](../../specs/feedback-conditions/spec.md)). Сохранение использует полный применённый отбор, не черновик условий; повторная реализация реестра и конструктора не входит.

Граница: UI по прототипу, операции по API, неподдержанное отложено. Исполнение правил и сбор реальных ответов пользователей не входят. Новые зависимости не требуются без отдельного обоснования. Это planning change: код приложения и Jira при разделении не меняются.
