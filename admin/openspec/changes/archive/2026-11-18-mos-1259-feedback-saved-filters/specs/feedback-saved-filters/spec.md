## Purpose

Реализовать серверные сохранённые фильтры опросников в разделе обратной связи ЦАМ по опубликованному API, с отдельной приёмкой и сохранением ограничений первого этапа.

## ADDED Requirements

### Requirement: Personal saved searches

Фильтры SHALL храниться сервером через /saved-filters с resource=feedback-surveys и полным search. Имя SHALL иметь 1–150 символов и не состоять из пробелов. UI SHALL предоставлять создание, постраничный список, применение, явное обновление выбранного по ID и удаление. Одинаковые имена SHALL допускаться и MUST NOT вызывать автоматическую перезапись. PUT SHALL частично обновлять поля верхнего уровня name и search: пропущенное поле SHALL сохранять прежнее значение; переданный search SHALL целиком заменять прежний search, а пропущенные внутри него параметры SHALL получать значения по умолчанию, не значения предыдущего поиска; resource MUST NOT изменяться. При применении SHALL восстанавливаться query, обычные фильтры, conditions, sort, limit с offset=0. Недоступный фильтр SHALL обрабатываться как 404; устаревший search SHALL показывать ошибку без молчаливого частичного применения/localStorage fallback.

Контракт операций SHALL соответствовать разделу 9 локального `docs/api/contracts/crud-api.md`: обновление использует HTTP PUT, не PATCH. POST SHALL сохранять полный применённый search, включая offset, без неприменённого draft условий и без результатов поиска. После 201 с ID клиент SHALL читать detail отдельным GET без повторения POST. Список SHALL запрашиваться с resource=feedback-surveys и собственной пагинацией limit/offset. Чтение записи MUST NOT отклоняться только из-за устаревшего search; проверка применимости SHALL выполняться отдельно до замены текущего отбора.

#### Scenario: Applied selection rather than condition draft

- **WHEN** применённый отбор содержит offset=40, а пользователь изменил условия, но ещё не применил их
- **THEN** сохранение передаёт применённые условия и offset=40; последующее применение сохранённого отбора использует offset=0

#### Scenario: Independent saved-filter pagination

- **WHEN** пользователь открывает следующую страницу сохранённых фильтров
- **THEN** GET списка использует resource=feedback-surveys и пагинацию списка, не изменяя текущий отбор опросников или сохранённый search

#### Scenario: Replace search through PUT

- **WHEN** PUT выбранного ID передаёт только search без прежнего query
- **THEN** имя сохраняется, search заменяется целиком и прежний query не переносится; пустой PUT возвращает 422 EMPTY_PATCH, null не принимается

#### Scenario: Read an obsolete search without partial application

- **WHEN** GET возвращает запись с неподдержанными параметрами search
- **THEN** запись остаётся доступной для отображения, применение показывает пояснение, текущий отбор не заменяется частично или значениями по умолчанию

#### Scenario: Duplicate names

- **WHEN** пользователь сохраняет новый фильтр с уже существующим именем
- **THEN** создаётся новый filter ID; только отдельное действие обновления выбранного фильтра вызывает PUT его ID

#### Scenario: Apply and update complete search

- **WHEN** сохранённый фильтр содержит две conditions, sort и offset=40, затем применяется
- **THEN** реестр восстанавливает все параметры с offset=0; явное обновление передаёт полный текущий search, ошибки сохраняют форму

### Requirement: Save selection dialog

Действие сохранения текущего отбора SHALL открывать модальное окно с обязательным полем «Наименование», подсказкой о длине 1–150 символов и кнопками «Сохранить» и «Отмена». Имя из одних пробелов MUST NOT приниматься. Подтверждение SHALL отправлять POST с полным текущим search; во время запроса повторная отправка MUST NOT выполняться. Только подтверждённое сохранение SHALL закрывать окно и обновлять список подборок. Ошибки SHALL оставлять окно и ввод доступными: ошибки имени связываются с полем, ошибки вложенного search и общие ошибки отображаются в окне с сохранением серверных деталей и MUST NOT ошибочно приписываться имени. Неизвестный исход MUST NOT выдаваться за успех; мутация MUST NOT повторяться автоматически.

#### Scenario: Validation and pending

- **WHEN** пользователь вводит пустое имя, одни пробелы или более 150 символов
- **THEN** сохранение не отправляется и доступна ошибка валидации; имя длиной 150 символов с непробельным символом допустимо
- **WHEN** отправлено валидное имя и запрос ещё выполняется
- **THEN** повторное подтверждение не создаёт ещё один запрос

#### Scenario: Failure and confirmed success

- **WHEN** сервер возвращает ошибку имени, вложенного `/search/...` или общую ошибку сохранения
- **THEN** окно остаётся открытым, имя сохраняется и ошибка отображается в соответствующем контексте
- **WHEN** сохранение подтверждено сервером
- **THEN** окно закрывается и список сохранённых подборок обновляется

#### Scenario: Cancel without changing the selection

- **WHEN** пользователь отменяет окно кнопкой, Escape или кликом вне окна до отправки
- **THEN** запрос сохранения не выполняется, текущий отбор сохраняется и фокус возвращается на кнопку открытия

### Requirement: Accessible saved-filters interactions

Область этой задачи — формы и список сохранённых фильтров — SHALL поддерживать клавиатуру, доступные названия/ошибки, предсказуемый фокус и узкую компоновку. Приёмка SHALL проверять собственные элементы; реализация и приёмка соседних UI-возможностей MUST NOT требоваться для закрытия этой задачи сверх явно указанных зависимостей интеграции. Недоступные API MUST NOT имитироваться успешными заглушками.

#### Scenario: Keyboard and narrow layout within this task

- **WHEN** пользователь работает с элементами этой задачи клавиатурой на узком экране
- **THEN** действия и ошибки доступны, содержимое не перекрывает управляющие элементы, закрытие имеющихся диалогов возвращает фокус
