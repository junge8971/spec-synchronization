# Proposal

## Why

В [снимке OpenAPI от 09.11.2026](../../../docs/api/contracts/README.md) появился отдельный метод проверки занятости доменов. В рамках MOS-958 планируется подключить его к первому шагу мастера и показывать ошибки создания по примерам ответов, которые передала backend-команда.

## What Changes

### Готово к реализации по опубликованному контракту

- На первом шаге мастера подключить [`POST /api/control/api/surfaces/v1/surfaces/domains/check`](../../../docs/api/contracts/surfaces.md#проверка-занятости-доменов) через существующий API-клиент. Передавать непустой список `domains` после локальной нормализации и валидации. Проверка учитывает все команды и статусы, включая архивные и логически удалённые поверхности. Локальная проверка повторов во введённом списке сохраняется.
- В ответе `200` читать `data.occupied_domains`. Список содержит только занятые домены в нижнем регистре, без повторов и в алфавитном порядке. Показать занятые адреса в доступном сообщении у поля, в том числе при частичном конфликте, и дать исправить ввод. Пустой список означает, что на момент проверки все переданные домены были свободны.
- Запускать проверку по «Далее» после локальной валидации. Ответ применяется к проверенному набору доменов и теряет силу при изменении ввода. При сбое мастер остаётся на первом шаге, показывает, что занятость неизвестна, и даёт повторить проверку. Сервер повторно проверяет занятость при создании.
- Заменить заглушку `501` для этой операции локальным мок-обработчиком по опубликованному контракту. Покрыть unit/component-тестами свободный и частично занятый список, ошибку проверки и устаревший ответ после изменения ввода. Перед включением на целевом контуре подтвердить доступность метода там.

### Ответы backend при создании

Backend-команда передала примеры `POST /api/control/api/surfaces/v1/surfaces` 12.11.2026. По её ответу `422` сейчас возвращает `errors[]`. Схема `HTTPValidationError` с `detail[]` в разделе `responses` устарела. Команда планирует отдельно привести схемы ошибок в порядок. Текущий обработчик мастера распознаёт `detail[]`, поэтому для актуальных ответов нужно добавить обработку `errors[]`. [Локальный OpenAPI](../../../docs/api/contracts/surfaces.openapi.json)

**`409 DOMAIN_ALREADY_IN_USE`** возвращает все занятые домены в `details.domains` элемента с `field: "/domains"`. Мастер покажет эти адреса у поля, в том числе если конфликт возник уже после предварительной проверки.

```json
{
  "code": "DOMAIN_ALREADY_IN_USE",
  "data": null,
  "message": "Домен уже назначен другой поверхности",
  "errors": [
    {
      "field": "/domains",
      "code": "DOMAIN_ALREADY_IN_USE",
      "message": "Домен уже назначен другой поверхности",
      "details": {
        "domains": ["assistant.mos.ru", "services.mos.ru"]
      }
    }
  ]
}
```

**`422 VALIDATION_ERROR`** возвращает ошибки валидации с путями к полям. Если поле недоступно для редактирования в мастере, ошибка показывается в общем сообщении.

```json
{
  "code": "VALIDATION_ERROR",
  "data": null,
  "message": "Ошибка валидации запроса",
  "errors": [
    {
      "field": "/configuration/accent_color",
      "code": "INVALID",
      "message": "String should match pattern '^#[0-9a-fA-F]{6}$'"
    }
  ]
}
```

**`422 FAILED`** может возвращать пустой верхнеуровневый `message`. Для несуществующего ответственного причина и путь к полю берутся из `errors[]`.

```json
{
  "code": "FAILED",
  "data": null,
  "message": "",
  "errors": [
    {
      "field": "/responsible/product",
      "code": "INVALID",
      "message": "User {user_id} not found"
    }
  ]
}
```

Пустой `product_context` допустим по ответу команды. Исправление backend готово к развёртыванию. Мастер сохраняет поле необязательным, а доступность исправления на целевом контуре ещё предстоит подтвердить.

Backend-команда подтвердила, что при описанных `409 DOMAIN_ALREADY_IN_USE`, `422 VALIDATION_ERROR` и `422 FAILED` сервер не сохраняет поверхность, конфигурацию и привязку к команде. При распознанном отказе мастер сохраняет ввод, показывает ошибку и разрешает пользователю явно повторить POST после исправления формы. Потеря ответа и нераспознанный формат по-прежнему блокируют повторный POST.

### Что уже реализовано в мастере

- Мастер отправляет приветствие в `configuration` одним POST и показывает сохранённое значение по GET. Более широкий редактор конфигурации при регистрации требует отдельного согласования.
- Мастер выбирает ответственных из справочника и отправляет строковые бизнес-ID в `responsible.product` и `responsible.connection`. Перед включением на целевом контуре остаётся подтвердить чтение старых назначений и отказы для удалённых или недоступных пользователей.
- Если доработка затронет выбор владельца, отдельно уточнить связь `owner` и `team_id`.
- После `201` мастер сохраняет ID и читает карточку, чтобы показать серверный статус и `channel_id`. При сбое чтения повторяется только GET по тому же ID.

### Безопасное восстановление результата POST отложено

При потере ответа мастер блокирует повтор POST в текущей форме. Проверка доменов и `409` сообщают о занятости домена, но не позволяют установить, какая попытка создала поверхность. Для восстановления после перезагрузки или в другой вкладке нужен согласованный серверный механизм, например идемпотентность. Срок действия ключа и правила повтора относятся к отдельному согласованию.

## Capabilities

### New Capabilities

Нет. Базовая `surface-registration` уже существует.

### Modified Capabilities

- `surface-registration` получит предварительную проверку занятости доменов, отображение структурированных отказов создания и возможность повторить отправку после исправления подтверждённого отказа.
- `control-center-mock-server` получит проверку занятости доменов и подтверждённые форматы отказов создания поверхности.

## Impact

- Проверка доменов затронет API-клиент `app/entities/surface`, мастер `app/features/surface-registration`, локальные моки и unit/component-тесты. Опубликованные DTO и generated-типы для проверки уже есть.
- Обработка `409` и `422` продолжает [незакрытую задачу 3.2 обновления API-контрактов](../archive/2026-10-15-update-control-center-api-contracts/tasks.md#3-поверхности-отказы-и-атомарные-моки). Локальные моки создания нужно сверить с примерами выше. Состояние до получения этих примеров описано в [заметке об источниках](../../../docs/api/contracts/surface-error-provenance.md).
