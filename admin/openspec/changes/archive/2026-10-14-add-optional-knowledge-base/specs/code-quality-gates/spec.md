## MODIFIED Requirements

### Requirement: Application code respects FSD ownership and public APIs

Весь рукописный код приложения SHALL соблюдать направление зависимостей от слоя приложения через pages, widgets, features, entities к shared, кроме адресного optional-исключения ниже. Слайсы одного слоя SHALL NOT зависеть друг от друга. Внешние потребители SHALL обращаться к слайсу через его публичный API, а не внутренние файлы. Внутри слайса SHALL использоваться прямые внутренние импорты без обращения через собственный публичный API. Shared и слой приложения SHALL организовываться по сегментам без искусственных предметных слайсов. Эти ограничения SHALL одинаково применяться к алиасам, относительным путям, type-only импортам и re-export.

Единственное дополнительное исключение SHALL разрешать размещение нового предметного кода базы знаний в `app/optional/knowledge-base/` вместо глобальных FSD-слайсов ради изолированного удаления вместе с документированными точками регистрации. Его внешние runtime-потребители SHALL ограничиваться композицией приложения через публичный API; framework-конфигурация SHALL сохранять специальные route entrypoints. Модуль SHALL зависеть только от собственных модулей, shared и публичных API entities, а не от application internals либо чужих pages/widgets/features. Другие бизнес-слайсы и shared MUST NOT импортировать KB. Исключение MUST NOT отключать lint, проверки компонентов/деклараций и границ или распространяться на другие optional-модули автоматически.

#### Scenario: Dependency points to a higher layer or sibling slice

- **WHEN** код импортирует более высокий слой или другой слайс того же слоя вне адресного исключения
- **THEN** архитектурная проверка завершается ошибкой с указанием нарушающей зависимости

#### Scenario: External consumer bypasses a slice public API

- **WHEN** внешний потребитель импортирует внутренний файл слайса через алиас, относительный путь или re-export
- **THEN** архитектурная проверка отклоняет зависимость

#### Scenario: Internal implementation uses a local module

- **WHEN** модуль слайса напрямую импортирует допустимый внутренний модуль того же слайса
- **THEN** архитектурная проверка разрешает такой импорт

#### Scenario: New slice is introduced

- **WHEN** появляется новый слайс, не существовавший при первоначальной настройке проверок
- **THEN** к нему автоматически применяются те же ограничения границ и публичного API

#### Scenario: Optional module consumes stable dependencies

- **WHEN** KB импортирует shared либо публичный API entities, а приложение подключает публичный API KB или framework route entrypoint
- **THEN** архитектурная проверка разрешает адресную зависимость, сохраняя структурные проверки файлов

#### Scenario: Business code depends on optional implementation

- **WHEN** другой бизнес-раздел/shared импортирует KB либо KB импортирует чужой feature или application internals, в том числе относительным/type-only импортом или re-export
- **THEN** архитектурная проверка отклоняет зависимость и не позволяет сделать удаление KB зависимым от другого раздела
