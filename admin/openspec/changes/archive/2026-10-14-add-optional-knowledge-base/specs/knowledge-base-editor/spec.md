## Purpose

Обеспечить редактирование материала базы знаний на четырёх вкладках прототипа с сохранением ссылок, связей и правил по действующему контракту без потери черновика.

## ADDED Requirements

### Requirement: Complete editor and validated defaults

Карточка SHALL содержать шапку с названием, описанием, статусом, кодом, категорией, серверными created_at/updated_at и вкладки «Основное», «Материалы», «Навыки», «Правила показа». Основное SHALL предоставлять name/code/category_code/description/owner/responsible_user_id/tags/material_type/language/valid_until/open_in_new_tab. Owner SHALL быть строкой, responsible_user_id внешним строковым ID, дата — YYYY-MM-DD/null. Новая запись SHALL предлагать draft, zhkh, instruction, russian, open_in_new_tab=true и правила user_asks/inline_link/3/50/false/true, только если соответствующие справочные коды доступны для нового выбора. Отсутствующий default SHALL требовать явного выбора, не неактивной подстановки.

#### Scenario: New draft

- **WHEN** создаётся материал при активных значениях справочников из прототипа
- **THEN** предложены defaults прототипа, ссылки и навыки пусты, даты создания/изменения не выдаются за серверные до сохранения

#### Scenario: Default missing

- **WHEN** zhkh отсутствует или неактивен
- **THEN** категория требует явного допустимого выбора, не отправляется скрыто выбранный zhkh

### Requirement: Field validation and reference preservation

UI SHALL проверять обязательность/длины, code pattern ^[a-z][a-z0-9_]*$, date и числовые границы API. Рядом с name SHALL быть пояснение, что серверная проверка уникальности названия не подтверждена; неполная клиентская выборка MUST NOT выдаваться за гарантию уникальности. Серверные конфликты/validation errors SHALL отображаться у соответствующих полей, включая вложенные пути. Неактивный сохранённый справочный код SHALL отображаться и сохраняться без изменения, но не выбираться заново. Ошибка справочника MUST NOT подставлять demo values.

#### Scenario: Server rejects nested field

- **WHEN** PUT возвращает ошибку /links/1/url
- **THEN** черновик сохраняется, показана ошибка отправленной ссылки и открыта соответствующая вкладка; сообщение не относится к другой строке после reorder

#### Scenario: Inactive stored category

- **WHEN** у существующей записи категория неактивна
- **THEN** она видна и допустима для неизменённого сохранения, но недоступна как новый выбор другой записи

### Requirement: Persisted aggregate semantics

Создание SHALL использовать POST и полученный ID для последующего GET без повторного создания при ошибке чтения. PUT SHALL сохранять пропущенные верхнеуровневые поля; изменённые links/skill_ids SHALL передаваться целиком, [] очищает список. Существующий link id SHALL сохраняться; новые ссылки SHALL не передавать фиктивный server ID. Порядок массива SHALL задавать порядок без sort_order. При изменении display_rules SHALL отправляться полный объект. Очистка nullable полей SHALL передавать null, для остальных null запрещён. Успех SHALL объявляться только по валидному подтверждению, пустой diff не отправляется.

#### Scenario: Reorder and clear

- **WHEN** две сохранённые ссылки переставлены, затем навыки очищены
- **THEN** PUT сохраняет исходные link IDs в новом порядке и skill_ids=[], последующий GET воспроизводит результат

#### Scenario: POST succeeded and GET failed

- **WHEN** сервер вернул ID созданного материала, но чтение карточки упало
- **THEN** повтор выполняет чтение известного ID, а не второй POST

### Requirement: Link editing and safe preview

Материалы SHALL предоставлять до 100 ссылок с title, HTTP/HTTPS URL, description, tags, выбором, удалением и перестановкой. SHALL соблюдаться длины title 1–255, URL 1–1024, description/tags до 500. Перестановка SHALL работать мышью и клавиатурой. Предпросмотр SHALL отражать выбранную ссылку текущего черновика, показывать теги и пустое состояние, не исполнять пользовательский HTML и не загружать внешний URL. После удаления выбранной ссылки SHALL выбираться оставшаяся либо пустое состояние.

#### Scenario: Keyboard reorder preserves selection

- **WHEN** выбранная ссылка перемещена доступной кнопкой вверх
- **THEN** порядок изменён, выбранная ссылка и её draft fields сохранены, preview показывает ту же ссылку

#### Scenario: Unsafe URL or excess items

- **WHEN** введён javascript URL либо добавляется 101-я ссылка
- **THEN** сохранение небезопасного значения/добавление сверх лимита блокируется с объяснением, preview не исполняет URL

### Requirement: External skills and responsible user

Навыки SHALL выбираться по существующим ID с названием, доступной предметной областью, ID и счётчиком. Каталог SHALL не ограничиваться первой серверной страницей; максимум связей — 100. Ответственный SHALL выбираться через опубликованный поиск внешних пользователей с пагинацией, не через текущий principal. Неизвестный сохранённый ID навыка/пользователя SHALL оставаться видимым как ID и не удаляться или заменяться молча. Ошибка reference lookup SHALL сохранять черновик.

#### Scenario: Existing user not found

- **WHEN** сохранённый responsible_user_id отсутствует среди результатов поиска
- **THEN** значение остаётся видимым и неизменённым, UI не назначает первый результат и не выдумывает ФИО

#### Scenario: Skill on later page

- **WHEN** нужный навык находится за пределами первой страницы каталога
- **THEN** его можно найти и выбрать без потери уже выбранных ID; серверный REFERENCE_NOT_FOUND объясняется у связи

### Requirement: Display rules are settings not execution

Редактор SHALL предоставлять trigger_mode, trigger_words, reply_format, max_links, priority, exclusive, region_relevant. Max_links SHALL быть целым от 1 до 2147483647 с пояснением минимального значения API; priority — signed int32. Статический пример чата SHALL явно называться иллюстрацией с отсутствием API проверки срабатывания. Сохранение правил MUST NOT объявляться проверкой триггеров, региональности или доставкой в чат.

#### Scenario: Zero max links

- **WHEN** введён max_links=0
- **THEN** сохранение блокируется, рядом объяснено ограничение API минимум одной ссылкой

#### Scenario: Rules saved

- **WHEN** корректные правила сохранены
- **THEN** подтверждено сохранение настроек, но нет утверждения, что правило сработало или материал отправлен пользователю

### Requirement: Explicit status actions

Для сохранённой чистой записи paused SHALL предоставлять «Возобновить» с target active, другие поддержанные неархивные статусы — «Приостановить» с target paused. Новая или dirty-карточка SHALL объяснять необходимость сохранения/отмены изменений до команды. Status SHALL изменяться через PUT и подтверждаться сервером, не только локально. «В архив» SHALL оставаться недоступной с label об отсутствии поддержки archived. DELETE и disabled MUST NOT подменять архив.

#### Scenario: Dirty pause

- **WHEN** пользователь изменил описание и видит действие приостановки
- **THEN** действие недоступно с пояснением сохранить или отменить изменения; черновик не теряется и status PUT не отправляется

#### Scenario: Pause rejected

- **WHEN** сервер отклоняет смену статуса
- **THEN** сохранённый статус остаётся прежним, видна ошибка без успешного toast

### Requirement: Draft safety and uncertain mutation outcomes

Dirty-карточка SHALL запрашивать подтверждение ухода через закрытие, крошки, меню, Back или другой ID и защищать закрытие документа штатным механизмом. Смена вкладки SHALL сохранять черновик без запроса ухода; чистая карточка SHALL закрываться без подтверждения. Pending SHALL предотвращать двойную отправку. Неоднозначный сетевой исход мутации MUST NOT приводить к автоматическому replay или ложному утверждению отмены. Существующие same-user refresh и account-replacement гарантии SHALL сохраняться.

#### Scenario: Leave or stay

- **WHEN** dirty-карточка закрывается через крошки
- **THEN** отказ от ухода сохраняет все вкладки/черновик, подтверждение уходит без сохранения; чистая карточка не задаёт этот вопрос

#### Scenario: Network failure after submit

- **WHEN** после отправки нет подтверждённого результата
- **THEN** нет автоматического повтора мутации, видна неопределённость результата и возможность сверить серверные данные без потери черновика
