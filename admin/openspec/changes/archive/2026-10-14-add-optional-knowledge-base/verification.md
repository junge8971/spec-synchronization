# Проверки реализации

Итог после согласованного подключения KB без отдельного флага.

## Пройдены

- `yarn typecheck` — обычный typegen и TypeScript без настройки включения KB.
- `yarn lint` — без предупреждений.
- `yarn format:check`.
- `yarn api:check` — generated-контракт не менялся.
- `yarn test` — Vitest: 137 файлов / 1306 тестов; Node: 120 тестов, 0 ошибок.
- `node scripts/knowledge-base-verify.mjs` — выполняет `yarn build` с dev-настройкой CONTROL_API_MOCKS=true, проверяет обычный route config, browser manifest, реальные module IDs/import graph и отсутствие production fixtures. Три маршрута KB доступны под `/tsam-panel/` без отдельной настройки раздела.
- Проверки конфигурации подтверждают неизменность базовых маршрутов, отсутствие дубликатов, приоритет new над ID и независимость регистрации от mock/real режима.
- Компонентные проверки используют application registry по умолчанию и сохраняют запрет бизнес-запросов до разрешённого session/access.
- `git diff --check`; просмотрены изменённые подключения, тесты, документация и оставшиеся внешние ссылки. Parser/define/условная композиция удалены, настройки моков и сессии сохранены.

В сборке остаётся предупреждение Vite о крупных chunks. Порог не повышался.
Во время изменения исправлены несовместимый с route typegen alias-импорт и
ожидание прежнего базового реестра в `app/routes.test.ts`; итоговые проверки выше
завершены успешно, исходные проверки существующих маршрутов сохранены.

Матрица сценариев: `app/optional/knowledge-base/ACCEPTANCE.md`.
Запуск и удаление: `app/application/knowledge-base-integration.md`.

## Визуальное уточнение контента по скриншотам

Изменён только контент модуля; шапки приложения и раздела не затрагивались.
Переиспользованы Card, line Tabs, Badge, Popover и Bubble без новых dependencies,
глобальных стилей или изменения shared-компонентов. Поведение редактора и API
сохранено. Для компактных раскрываемых фильтров добавлены проверки Enter/Escape,
возврата фокуса, множественного выбора, сброса и сохранённого неизвестного кода;
пояснение недоступного архива остаётся доступным в раскрытом списке.

Повторно пройдены `yarn typecheck`, `yarn lint` без предупреждений,
`yarn format:check`, `yarn build` и `yarn test` — 138 Vitest-файлов / 1308 тестов
и 120 Node-тестов, без ошибок. В build остаётся прежнее предупреждение о крупных
chunks. API-контракт не менялся. `git diff --check` и OpenSpec strict validation
пройдены. Визуальное сходство оценивалось по структуре кода и предоставленным
изображениям, не по браузерным скриншотам реализации.

## Браузерная проверка по отдельному разрешению пользователя

После предыдущего этапа пользователь явно разрешил проверку результата в браузере.
Выполнены адресные Playwright/Chromium-сценарии на `yarn dev` с локальным профилем
full, без реальных credentials и backend. Просмотрены screenshots реестра, всех
четырёх вкладок, фильтра статусов, условий, экспорта списка/карточки, поиска
ответственного, ошибок новой формы, длинных тегов и серверного снимка. Основной
проход выполнен на 1440 и 390 px; граничные сценарии — на 360 и 768 px.

Исправлены отступы и переносы контента, обрезанные мобильные вкладки, перегруженные
UUID чипсы, оформление ответственного, условий, экспорта и серверного снимка,
слишком светлый край тёмного preview. Устранён горизонтальный overflow страницы
из-за абсолютного sr-only заголовка: scroll-контейнер таблицы теперь containing block.
Все сценарии повторно прошли, pageerror отсутствуют; таблица прокручивается локально.
Шапки приложения/раздела и shared UI не изменялись.

Браузер также выявил потерю черновика и ошибок после смены query-вкладки в demo:
`useRouteAccess` преждевременно трактовал checking как отказ и размонтировал форму.
Теперь существующий SessionBoundary сохраняет скрытое дерево в обоих режимах до
ready; подтверждённый отзыв прав по-прежнему удаляет запрещённое содержимое.
Регрессионный host-тест сначала воспроизвёл remount только в mock mode, после
исправления проходит для mock/real. В браузере подтверждены сохранение длинного
тега между вкладками и видимые ошибки пустой новой формы без POST. Добавлен
component-тест компактных чипсов с доступным по клавиатуре ID.

Итоговые `yarn typecheck`, `yarn lint`, `yarn format:check`, `yarn test` и `yarn build`
прошли: 138 Vitest-файлов / 1311 тестов, 120 Node-тестов. Осталось прежнее
предупреждение сборки о крупных chunks. API-контракт не изменялся; `api:check`
на этом этапе повторно не запускался. `git diff --check` и strict OpenSpec validation
прошли. Временные browser-сценарии и screenshots находятся в `/tmp/kb-browser-*`,
итоговый отчёт размеров — `/tmp/kb-browser-verification.json`; общий E2E-набор
не запускался и не менялся.

## Адресное оформление верхнего блока карточки

По последующему скриншоту пользователя переработан именно header редактора,
не общая шапка приложения. Использован существующий page-intro паттерн проекта:
отступы, заголовок, вторичные метаданные, Separator и читаемые даты с исходными
значениями в `time[datetime]`. Экспорт расположен в панели действий вне формы;
Save связан с формой нативным атрибутом `form`. Тесты проверяют эту связь,
независимость экспорта, даты сохранённой записи и отсутствие дат у новой.
Повторно прошли typecheck, lint, format:check, полный `yarn test` и адресные
Chromium-сценарии desktop/mobile, включая отправку пустой формы и сохранение
черновика. Скриншоты результата просмотрены. Build/API-check после этой
локальной UI-правки повторно не запускались.

## Удаление технических подписей

По запросу пользователя удалены четыре указанные подписи и отдельные блоки
«Ссылок / Навыки» под условиями. Недоступные пункты выбора поля сохраняют
disabled и пояснения; component-тест проверяет именно их и отсутствие
дублирующих блоков. Удалены связанные с исчезнувшими подписями aria-describedby.
Повторно прошли typecheck, lint, полный yarn test, format:check и diff check.
Браузер, build и API-check после удаления текста повторно не запускались.

## Не проверялось

- Другие браузеры и общий E2E-набор приложения.
- Реальный backend, production credentials/session и backend authorization.
- Производительность одновременного отображения 100 подробных карточек ссылок:
  лимит/добавление проверяются компонентно, без performance-утверждений.

Backend-контракт и модель auth/permissions не расширены. Изоляция KB в собственной
папке и документированное удаление с точками регистрации сохранены.
