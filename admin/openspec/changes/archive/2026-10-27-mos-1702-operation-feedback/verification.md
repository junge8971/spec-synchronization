# Проверка реализации MOS-1702

## Реализация и аудит

- Краткий успех переведён в событийные toast по всей матрице `design.md`: диалоги, регистрация и обучающие фразы навыка, база знаний, A/B, шаблоны ответов, справочники, обратная связь.
- Экспорты диалогов, навыков и optional-разделов используют общий результат. Формы сохраняются через React Activity; результат заменяет содержимое существующего Dialog. Прямые выгрузки имеют только «Закрыть». Экспорт значений справочника не имеет настраиваемых полей и также не предлагает возврат к параметрам.
- Тесты проверяют возврат без повторного запроса/скачивания, сохранение параметров, закрытие/новое открытие, единственное модальное окно, ошибки и ограничения. Сохранены проверки payload, отмены, MIME/CSV, безопасного имени и освобождения object URL.
- Общий hook уведомлений проверен на событийный запуск, замену предыдущего уведомления, отсутствие дублей при rerender, очистку при смене контекста и игнорирование позднего завершения прежнего контекста/после unmount.
- Успешное уведомление переживает навигацию после подтверждённого действия (регистрация навыка, удаление справочника); это не повторный показ cached success.
- Проверены production diff, оставшиеся `isSuccess` и сообщения сохранения/копирования. Обоснованно оставлены inline: ошибки и валидация, pending, «нет изменений», частичные результаты справочника и необходимость readback, предупреждение о внешних системах, recovery и createdId, ссылка на созданный навык, постоянные предметные результаты/диагностика. Технические mock-инструменты не менялись.
- Существующие toast поверхностей не изменялись и не дублируются. Нет новых зависимостей, API, auth/session-логики, изменений E2E или ослабления lint. Optional-модули используют собственные владельцы и публичный shared UI.

## Интерактивная проверка 27.10.2026

После явного разрешения пользователя «Делай» проверены реальные бизнес-компоненты через Playwright MCP на `http://127.0.0.1:5174/tsam-panel/`, со штатными локальными моками. Автоматические E2E-файлы не создавались и не запускались; ответы API не подменялись.

- Навыки: прямой CSV-экспорт, результат только с «Закрыть», повторный явный запуск, закрытие кнопкой/Escape. После завершения анимации фокус возвращается к «Экспорт CSV», Dialog отсутствует.
- База знаний: копирование — один toast, фокус остаётся на кнопке; закрытие уведомления; сохранение фильтра — один toast. Экспорт со снятым «Служебный код»: один Dialog, возврат сохраняет поле, за переходы выполнен ровно один POST export. Закрытие и новое открытие показывают форму, не старый результат.
- A/B: копирование из блока действий — один toast. Экспорт с добавленным «Код»: один Dialog, возврат сохраняет выбор, ровно один POST export.
- Шаблоны ответов: копирование — один toast; экспорт со снятым «Код», возврат с сохранением выбора, ровно один POST export.
- Справочники: сохранение отбора и копирование внутри Dialog показывают toast. Его закрытие мышью не закрывает форму. F6 → Tab → Tab переводит фокус на «Закрыть уведомление»; уведомление сохраняется при фокусе и закрывается Enter. Экспорт со снятым «Код»: один Dialog, возврат сохраняет выбор, ровно один POST export.
- Обратная связь: копирование — один toast. Создание без обязательного типа показывает inline-валидацию без успеха. После выбора типа создание подтверждается одним toast и переходом в карточку. Повторное изменение описания даёт новое уведомление; сохранение без изменений показывает «Нет изменений для сохранения», без toast успеха.
- Диалоги: экспорт со сменой периода на `today` и включением параметров получает штатный 503; ошибка остаётся в форме, период сохраняется, успешного результата нет. Реестр также корректно показывает ошибку загрузки сохранённых фильтров.
- При создании опросника наблюдалось предупреждение `A router only supports one blocker at a time`; это тот же класс предупреждения, для которого выше зафиксировано воспроизведение тестового сбоя на HEAD. Отдельное сравнение именно браузерного сценария создания опросника с HEAD не выполнялось.
- Исходный demo-профиль `viewer` восстановлен после проверки; варианты ответов API не менялись. В памяти локальных моков оставлены тестовые записи с явными именами `MOS-1702 browser KB`, `MOS-1702 browser dictionary`, `MOS-1702 browser survey` (код `mos_1702_browser`). Внешних данных это не касается.
