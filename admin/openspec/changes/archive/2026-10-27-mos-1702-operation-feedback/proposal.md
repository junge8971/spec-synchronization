## Why

В [MOS-1702](https://task.mos-team.ru/browse/MOS-1702) сообщения об успешных операциях теряются среди содержимого страниц. Требуется единое представление результатов во всех реализованных бизнес-разделах: неблокирующие уведомления для обычных операций и модальный результат для выгрузки.

## What Changes

- Заменить inline-подтверждения успешного копирования, сохранения фильтров, изменений и других бизнес-операций на доступные toast-уведомления без перехвата фокуса и дублирования текста на странице.
- Показывать успешную выгрузку модальным результатом. Если параметры уже открыты в диалоге, переключать содержимое этого диалога, не создавать вложенное окно.
- Для выгрузок с формой предоставить «Назад к параметрам» (с сохранением настроек и без повторного запроса) и «Закрыть». Для прямых выгрузок без формы — только «Закрыть».
- Показывать результат только после подтверждённой операции. Для выгрузки сообщать о передаче файла браузеру, а не гарантированном сохранении на диск.
- Сохранить текущие ошибки, валидацию, загрузку, ограничения, бизнес-результаты проверок и диалоги подтверждения опасных действий. Уже работающие toast не дублировать; технические mock-инструменты не включать в миграцию бизнес-UI.

## Capabilities

### New Capabilities

- `operation-feedback`: сквозные правила представления подтверждённых успешных операций, доступных toast и модальных результатов выгрузки.

### Modified Capabilities

Нет. Новая сквозная capability дополняет предметные спецификации, не меняя API, состав данных, правила подтверждения успеха и обработки ошибок. В частности, требования `dialog-export` о достоверной передаче файла и `dialog-saved-filters` о подтверждённом копировании сохраняются.

## Impact

- Общие UI-примитивы в `app/shared/ui/`, композиция provider в `app/application/ui/application-root.tsx`.
- Features диалогов, экспорта навыков, сохранения фраз; сообщения редакторов/реестров в optional-модулях базы знаний, A/B, шаблонов ответов, справочников и обратной связи. Существующие уведомления поверхностей сохраняют поведение, новые дубли не добавляются.
- Новые API и зависимости не требуются: установлены `@base-ui/react` с Toast API, React Query и общие Dialog-компоненты. Optional-модули сохраняют независимость и обращаются только к общему UI, не друг к другу.
- Не реализуются отсутствующие бизнес-операции из других changes. Пересечение с `add-skill-csv-export` касается только представления уже реализованного результата.
- Проверки реализации: unit/component-тесты успешных и ошибочных путей, повторов, сохранения параметров и клавиатуры; typecheck, lint, test, format:check. Интерактивные проверки через Playwright MCP на локальных моках планируются после отдельного явного разрешения по AGENTS.md; автоматические E2E и внешние контуры не разрешены этим change. Недоступность или отсутствие разрешения фиксируется как непроверенное, mock-проверки не доказывают реальную интеграцию.
