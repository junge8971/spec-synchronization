## Why

[MOS-1509](https://task.mos-team.ru/browse/MOS-1509) требует управления типовыми ответами ассистента без изменения кода и релиза. Контракты и моки ресурса уже есть, но frontend-раздел отсутствует; HTML-прототип демонстрирует интерфейс, а не надёжное сохранение, фильтры и экспорт.

## What Changes

- Добавить включённый по умолчанию, независимо удаляемый раздел «Шаблоны ответов» в группе «Контент»: реестр, создание, карточка с вкладками «Основное»/«Связи», прямые ссылки под действующим basename.
- Реализовать серверный поиск, мультифильтры, условия И/ИЛИ, сортировку, пагинацию, полный URL-отбор и именованные серверные фильтры.
- Создавать новый шаблон как draft с пустыми связями; текст, метаданные, связи и статус редактировать в одном черновике и сохранять явно. Предупреждать при выходе только с несохранёнными изменениями.
- Предоставить безопасный текстовый предпросмотр без исполнения HTML и подстановки плейсхолдеров; выбор навыков, поверхностей и ответственного из существующих API.
- Реализовать CSV списка и сохранённой карточки в пределах опубликованных полей. Не переносить фиктивный экспорт прототипа.
- Следовать актуальному Swagger T, прочитанному 26.10.2026: ресурс поддерживает saved filters, CSV и строковый внешний ID ответственного. Старый запрет saved filters в CRUD Markdown не применять.
- Изолировать предметный frontend в `app/optional/response-templates/`, серверный предметный код в `mocks/response-templates/`; перенести туда существующее mock-покрытие без потери поведения других ресурсов. Добавить адресные архитектурные проверки и инструкцию удаления по модели KB.
- Сохранить существующие session/access и HTTP-механизмы, обработку ошибок и доступность. Не добавлять собственные permissions, auth, runtime-исполнение шаблонов, журнал, мультиязычность или UI удаления только потому, что DELETE опубликован.

## Capabilities

### New Capabilities

- `response-templates-module`: изолированное владение, регистрация, маршруты, состояния и проверка удаляемости.
- `response-templates-registry`: поиск, фильтры, URL, серверные сохранённые отборы и пагинация.
- `response-templates-editor`: черновик, валидация, предпросмотр, связи, статусы и защита несохранённых изменений.
- `response-templates-export`: реальный CSV по отбору и сохранённой карточке.

### Modified Capabilities

- `code-quality-gates`: дополнительное адресное optional-исключение для response-templates с теми же запретами межмодульных зависимостей; существующие исключения не расширяются автоматически.

## Impact

Затронуты композиция `app/application/constants/application-routes.constants.ts`, новый optional-модуль и route entrypoints, архитектурные проверки `scripts/eslint-fsd-config*`, существующие `mocks/response-templates.mjs` и template-части `mocks/managed-registry-{model,seed,handlers,test}.mjs`. Общие DTO/генератор остаются общими; изменения актуального контракта импортируются только в необходимом объёме, generated-файлы не правятся вручную. Новые зависимости не требуются.

API: `/api/control/api/v1/managed-resources/response-templates`, его metadata/search/export/detail; managed saved filters; section lookups; опубликованные API навыков, поверхностей и `/api/control/api/users/v1/search`. Опубликованная схема не считается доказательством авторизованной интеграции.

Проверки: unit/component и mock HTTP, typecheck/lint/test/format/api-check/build, проверки границ и удаления. Интерактивная проверка нового UI через Playwright MCP на локальных моках должна быть отдельно явно разрешена перед запуском, если применимые проектные инструкции требуют такого разрешения; отсутствие разрешения/доступа фиксируется как незавершённая проверка. Автоматизированные E2E и внешние стенды требуют отдельного согласования. Исследование HTML-прототипа не заменяет проверку реализации.

Источники: [эпик MOS-1388](https://task.mos-team.ru/browse/MOS-1388), [аналитика и HTML-прототип](https://wiki.mos-team.ru/spaces/KR/pages/247744768), [Swagger T](https://nchat-t-tech.mos.ru/api/control/docs), [OpenAPI T](https://nchat-t-tech.mos.ru/api/control/openapi.json). Решения пользователя: единый черновик и явное сохранение; dirty-only подтверждение выхода; новый draft без связей; актуальный Swagger при расхождениях; изоляция по модели KB. Дополнительных ограничений архива не вводить.
