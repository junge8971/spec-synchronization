# Published rule parity evidence

This is historical representative evidence, not a proof of all rule variants or complete compatibility with the Oxlint JavaScript-plugin bridge. The dedicated lint, formatter and architecture test files named below were removed at the user's request; they are no longer executable regression coverage.

- `mocks/lint-rule-parity.test.mjs` runs 134 valid/invalid rule fixtures in one Oxlint process, asserting diagnostic counts and severities. For TypeScript declaration merging, the native implementation emits one diagnostic on both declarations while the original published plugin emits two; the configuration uses the published plugin. The original published `consistent-type-assertions` rule crashes in Oxlint when its fixer requests parser services; the native rule remains configured and passed the representative angle-bracket case.
- `mocks/import-order.test.mjs` exercises the original published import plugin with its original group options, parser/resolver settings, mixed JS/TS targets, a non-interop missing default, a malformed export, namespace/export checks, warning severities and the exact approved worker URL. `esModuleInterop` synthesizes a default for a direct named export in the original plugin; a re-export without a default remains rejected. Side-effect ordering and comment movement match the published plugin. Individual Oxlint `--fix` passes may require repetition.
- `mocks/restricted-imports.test.mjs` checks the original path-pattern rule and per-layer replacement semantics, including an explicit `/index` alias, independently of the dependency graph. It would be weaker to rely on resolved graph targets alone. `mocks/dependency-cruiser-config.test.mjs` verifies that an absent target of the exact approved PDF worker URL is still reported as unresolved.
- `mocks/oxlint-hooks.test.mjs` checks original `config` and `gating` error severity with no options. Their default React Compiler settings do not enable dynamic gating. An isolated explicitly configured example proves that the plugin bridge reports an invalid gating identifier; this does not prove every bridge case. Other compiler rules also use the published plugin, and `mocks/oxlint-config.test.mjs` exercises global mutation and impure render diagnostics.
- The user accepted declaring globals in Oxlint configuration, using JS-plugin aliases in inline suppressions, the exact `pdfjs-dist/build/pdf.worker.min.mjs?url` core-module exception, and original import-order movement of a standalone comment. These are not general permission to suppress other differences.
- `import/no-unresolved` remains a different implementation (dependency-cruiser). Its precise equivalence in every resolver case remains unproved; the focused graph fixtures cover unresolved modules and FSD/public APIs.
