## Why

Клиенты навыков и поверхностей сейчас возвращают локальные данные через `Promise.resolve`, поэтому интерфейс не проверяет реальный HTTP-путь, ошибки и новые контракты. Нужен единый транспорт Центра управления и автоматически запускаемый Express mock server, чтобы разработка и тестирование использовали тот же API, что и интеграция с backend.

## What Changes

- Добавить общий HTTP-клиент на native `fetch`: базовый URL, query-параметры, Bearer, отмена запросов, JSON, ошибки и поддержка `Idempotency-Key` там, где он требуется контрактом.
- Использовать `docs/api/contracts/openapi.json` как источник DTO и HTTP-контрактов: все 28 операций четырёх предоставленных разделов должны быть доступны на Express mock server.
- Запускать сервер автоматически вместе с `yarn dev`; в `vite.config.ts` настроить dev-only proxy с rewrite. При остановке dev-сервера освобождать порт моков. В production моки не запускать и не включать в клиентскую сборку.
- Перенести все существующие runtime-моки навыков, карточек, справочников фильтров и поверхностей на сервер; заменить фиктивный профиль шапки запросом `/auth/v1/me`. Согласовать seed-данные между связанными сущностями.
- **BREAKING**: обновить модели, фильтры, сортировку, URL-параметры и тесты под UUID/UUIDv7, новые enum, snake_case DTO и `limit`/`offset`; старые текстовые ID моков больше не являются ID API.
- **BREAKING**: убрать выдуманные статусы и метрики навыков, ревью, интенты, проверки, историю и токены из активных данных API, если их нет в предоставленном контракте. Соответствующие блоки показывают явное отсутствие поддержки, а не синтетический успех. Не создавать фиктивные backend-контракты для семи отсутствующих разделов.
- Обновить HTTP-, контрактные и UI/E2E-проверки, инструкции разработки. Статические статьи справки, навигация, подписи enum и изолированные test doubles не являются runtime-моками backend и остаются локальными.

## Capabilities

### New Capabilities

- `control-center-http`: общий транспорт, контрактные типы и обработка запросов/ошибок.
- `control-center-mock-server`: Express API по предоставленным контрактам, связанное in-memory состояние, автоматический dev lifecycle и Vite rewrite.
- `control-center-api-integration`: перевод существующих экранов и query hooks с локальных моков на HTTP с адаптацией UI к реальным возможностям контрактов.

### Modified Capabilities

Нет: в `openspec/specs/` отсутствуют существующие спецификации.

## Impact

- `app/shared/api/`, `app/entities/skill/`, `app/entities/surface/`, новая сущность текущего пользователя и API доменов/команд для справочников.
- Query hooks, фильтры и URL-state в `app/features/`, реестры, карточка навыка и шапка в `app/widgets/`.
- Новый сервер в `mocks/`, dev-only Vite plugin, `vite.config.ts`, `package.json`, `yarn.lock`, конфигурации Vitest/Playwright и README.
- Express и его типы — devDependencies; генератор OpenAPI TypeScript и валидатор JSON Schema 2020-12 для контрактных тестов — инструменты разработки. Native fetch и уже установленный Zod используются в приложении; Axios, MSW, отдельный process supervisor и БД не нужны.
- Контракты не переписываются под старые моки. Полная SSO-интеграция, новые экраны CRUD и неподтверждённые backend business rules не входят в изменение.
