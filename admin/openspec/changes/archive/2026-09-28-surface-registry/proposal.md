# Proposal

## Why

MOS-910 завершает интеграцию реестра поверхностей после базовых MOS-707/708: серверные фильтры уже реализованы, но строки не открывают карточку, отсутствующая статистика целиком не поддерживается и остаются пробелы в проверках доступа и ошибочных состояний. Нужно довести существующую страницу до критериев задачи и актуального прототипа, сохранив работающую основу.

## What Changes

- Сохранить серверные поиск, фильтры, сортировку, пагинацию и URL; проверить маппинг `data.items` / `data.pagination` по OpenAPI и счётчик всей отфильтрованной выборки.
- Принимать `stats: null` на границе фронтенда и показывать отсутствие статистики как «—», сохраняя настоящий ноль.
- Довести подписи и отображение списка до прототипа, сохраняя API enum и сортировки.
- Добавить доступный переход по названию и строке на `/surfaces/:surfaceId`. Поскольку маршрут отсутствует, предусмотреть минимальную карточку только для чтения через существующий GET detail; использовать готовую карточку, если она появится до реализации.
- Использовать общую проверку ролей для кнопки и прямого открытия создания поверхности.
- Дополнить проверки пустой выдачи, ошибок и повтора, навигации, ролей и восстановления URL.
- Уточнять контракт в ходе разработки, записывая недостающие данные, рабочие предположения и ответы в `docs/MOS-910-backend-questions.txt`.

## Capabilities

### New Capabilities

- `surface-registry`: серверный реестр поверхностей, отображение данных, навигация в карточку, доступ к созданию и состояния выдачи. Спецификация новая для OpenSpec, хотя часть поведения уже существует в коде.

### Modified Capabilities

Нет: существующие основные спецификации отсутствуют.

## Impact

- `app/entities/surface`, `app/widgets/surfaces-registry`, существующие features фильтров и пагинации; страницы карточки и регистрации, конфигурация маршрутов.
- Существующие HTTP client, current principal query, React Query и React Router переиспользуются; новые библиотеки не требуются.
- API: GET `/api/control/api/surfaces/v1/surfaces`, GET `/api/control/api/surfaces/v1/surfaces/{surface_id}`, GET `/api/control/api/auth/v1/me`.
- Тесты API-клиента, UI, маршрутов, моков и целевой E2E. Проверка реального контура зависит от доступа и авторизации.
- Контрактные расхождения не блокируют локальную разработку. Рабочие допущения: список `items`, nullable `stats`, создание для `client_service`/`surface_owner`, видимость определяет сервер.

## Non-goals

- Переписывание MOS-707/708, создание нового механизма пагинации или локальная фильтрация серверной страницы.
- Полная карточка из прототипа: редактор конфигурации, навыки, публикация, отключение, архивирование.
- Разработка SSO, новых backend endpoint или самостоятельное изменение опубликованного API-контракта без подтверждения.
