## Why

Текущий API `https://nchat-a-tech.mos.ru/api/control/openapi.json` опережает локальные контракты: изменены ответственные поверхностей, добавлены условия поиска, два managed-раздела и опубликован экспорт диалогов. Простое обновление типов ломает runtime-валидацию существующего UI и запуск Express-моков; пользователь согласовал все необходимые совместимые изменения и приоритет текущего API над прежними спецификациями.

## What Changes

- Обновить aggregate/split OpenAPI, generated DTO и документацию по воспроизводимому live-снимку. Сверять все операции и схемы, а не только изменения со скриншотов; сохранять явно обоснованную нормализацию security AND двух заголовков.
- **BREAKING**: перевести регистрацию поверхностей с произвольного ФИО на ID бизнес-пользователей, чтение ответственных — на `{id, full_name, email}` с nullable сведениями. Обновить обработку подтверждённых отказов создания и mock-проверки занятости доменов/существования пользователей.
- Поддержать optional `configuration` в контракте создания и моках с атомарным сохранением; сохранить backend defaults при отсутствии/null. Не добавлять скрытый второй PUT после создания. Существующий мастер без редактора конфигурации вправе опускать это поле; самостоятельный конфигуратор и одностраничный редизайн не являются частью контрактной миграции.
- Включить `links_count` и `skill_names` в условиях KB и `groups_count` в A/B, включая metadata, runtime-валидацию, редакторы, URL, сохранённые фильтры, CSV и моки. Удалить устаревшие запреты этих возможностей из спецификаций и пользовательских пояснений.
- Добавить контрактное mock-покрытие всех 16 операций API registry/response templates, девяти справочников и новых ресурсов saved-filters согласно live enum. Полноценные новые UI-разделы не создаются этим change: обновляются опубликованный контракт, моки и существующие потребители.
- **BREAKING**: заменить локальное дополнение экспорта диалогов опубликованными operationId/DTO; сохранить бизнес-валидацию и безопасную передачу CSV, даже если формальная схема менее выразительна описания операции.
- Актуализировать описания ошибок/permissions аналитики и диалогов, таблицы операций, тестовые fingerprints и устаревшие ссылки в активном feedback API plan. Изменение auth/session или UI permission-policy требует отдельного согласования; обновление описаний не ослабляет текущие ограничения.

## Capabilities

### New Capabilities

- `surface-registration`: контрактное создание поверхности с ID ответственных, опциональной конфигурацией и различением подтверждённого отказа и неизвестного исхода.

### Modified Capabilities

- `control-center-api-integration`: приоритет live-снимка, воспроизводимость источников и полная миграция контрактных потребителей.
- `control-center-mock-server`: полное покрытие новой дельты, типизированные условия KB/A/B, новые managed resources и сохранённые фильтры вместо устаревшей недоступности.
- `surface-overview-connection`: отображение ответственных как серверных пользователей с nullable сведениями.
- `knowledge-base-registry`: числовые условия ссылок и текстовые условия навыков, включая URL и сохранённый отбор.
- `ab-testing-registry`: числовые условия количества групп при сохранении ограничений остальных неподдержанных условий.
- `dialog-export`: опубликованный live-контракт вместо исторического локального дополнения.

## Impact

- `docs/api/contracts/*`, `app/shared/api/schema.d.ts`; генератор остаётся штатным `scripts/generate-api-types.mjs`.
- `app/entities/surface`, `app/features/surface-registration`, `app/widgets/surface-details`, их fixtures/tests; существующие API поиска бизнес-пользователей.
- `app/optional/knowledge-base` и `app/optional/ab-testing`: независимые изменения без взаимных импортов и нового общего предметного движка.
- `app/entities/dialog`, `mocks/dialogs.mjs`, контрактные проверки и документация экспорта.
- `mocks/surfaces.mjs`, managed helpers, отдельные handlers/model/fixtures новых ресурсов, lookup/catalog registry, saved-filters и server-тесты. Моки остаются локальными, без credentials и role enforcement.
- Delta-specs текущего change и адресная актуализация provenance/предпосылок `mos-1249-feedback-api` при реализации, без отметки его feature tasks выполненными.

Новые зависимости, backend-миграции и E2E/browser-тесты не требуются. Неподтверждённые форматы surface errors и поведение новых saved-filters фиксируются как интеграционные вопросы, а не вымышленные гарантии backend.
