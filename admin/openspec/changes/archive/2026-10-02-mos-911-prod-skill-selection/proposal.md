# Proposal

## Why

Обновлённый API предоставляет status навыка и серверный фильтр status=prod, но реализованный MOS-911 продолжает предлагать все навыки. Нужно использовать новый контракт в регистрации и карточке поверхности и предотвращать сохранение выбора, если навык вышел из prod.

## What Changes

- Загружать для нового выбора полный пагинированный список навыков с status=prod; ограничить им выбор домена и массовое включение в обоих экранах.
- При загрузке сохранённого состава и перед отправкой проверять актуальный статус выбранных навыков по detail. Отдельно показывать навык вне prod, подтверждённое отсутствие и ошибку чтения, сохраняя черновик до явного исправления.
- Сохранять параметры, группировку, существующие POST создания и PUT enabled-skills, а также различие требований к пустому выбору в регистрации и редактировании.
- Обновить пользовательские тексты и документацию: prod-фильтр уже существует, но разрешённость для конкретной поверхности по-прежнему не описана API.
- Привести затронутые тестовые fixtures к обязательным status/intents и покрыть фильтрацию, смену статуса, ошибки повторной проверки и массовые действия.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `surface-skill-selection`: продовый каталог, массовый выбор только из него и проверка выбранных навыков с различением смены статуса, удаления и ошибки запроса. Заменить прежнее требование общего реестра без prod-фильтрации.

## Impact

- `entities/skill` — запрос каталога и query key с учётом статуса; контрактные методы и generated-типы уже присутствуют.
- `features/surface-skill-selection` — статус в модели проверки, классификация проблем, тексты и выбор; интеграции `widgets/surface-registration` и `widgets/surface-details` сохраняются.
- Unit/component-тесты, соответствующие fixtures и `mocks/README.md`. Новый API или зависимость не нужны; существующий mock status-фильтр переиспользуется.
- Актуальный источник — `docs/api/contracts/openapi.json`, а не прежний api-29:09.txt. Архив MOS-911 не переписывается; main spec обновляется при завершении нового change.
- Не вводить available-skills, surface-specific eligibility, управление статусами навыков, auth/session/RBAC или дополнительные типы параметров.
