## Purpose

Позволить просматривать, создавать и редактировать предметные домены навыков по существующему бизнес-контракту без потери ввода и перезаписи конкурентных изменений.

## ADDED Requirements

### Requirement: Server-backed domain registry

Вкладка «Домены» SHALL показывать серверный список с названием и API-адресом, описанием, владельцем, зонами, числом навыков и действием редактирования. Пагинация SHALL использовать серверный total; число навыков SHALL браться из `skills_count`. Переход по числу SHALL открывать реестр навыков с `domain_id` и первой страницей. Домены навыков MUST NOT смешиваться с DNS-доменами поверхностей.

#### Scenario: Domain with skills beyond the loaded skill page

- **WHEN** сервер сообщает `skills_count=42`, а на текущей странице каталога загружено только 10 навыков
- **THEN** таблица доменов показывает 42; ссылка открывает реестр с ID этого домена, а не фильтрует локальные 10 записей

#### Scenario: Empty or failed registry

- **WHEN** список доменов пуст либо его загрузка завершилась ошибкой
- **THEN** первый случай предлагает создание домена, второй показывает ошибку и повтор, не подменяя её пустым списком

### Requirement: Domain creation form

Пользователь SHALL создавать домен через форму с `name`, `description`, `owner`, `api_url`, `team_id` и `zones`. Команда SHALL выбираться из серверного справочника без фиктивного текущего пользователя. Зоны SHALL соответствовать `authenticated` и `anonymous`. Подписи и сообщения SHALL отражать согласованные ограничения; frontend MUST NOT обещать подтверждённую уникальность по проверке только загруженного списка или самовольно переносить ограничения из демо.

#### Scenario: Successful domain creation

- **WHEN** сервер подтверждает создание корректно заполненного домена
- **THEN** диалог закрывается, реестр и варианты домена в связанных формах обновляются по серверным данным

#### Scenario: Domain validation failure

- **WHEN** сервер отклоняет поля или согласованное правило уникальности
- **THEN** введённые значения остаются в форме, ошибки доступны и связаны с полями при наличии такой привязки в ответе, успех не показывается

#### Scenario: Team directory unavailable

- **WHEN** справочник команд не загрузился или не содержит вариантов
- **THEN** форма объясняет проблему и не отправляет вымышленный team_id; при ошибке доступен повтор

### Requirement: Version-safe domain editing

Редактирование SHALL начинаться с актуальной карточки домена, отправлять PATCH с `expected_version` и обязательным `Idempotency-Key`, сохранять dirty-ввод при ошибке или фоновом обновлении. Повтор того же логического запроса SHALL сохранять ключ, изменённое тело SHALL получать новый. Конфликт MUST NOT приводить к автоматической перезаписи с новой версией. Отмена MUST NOT отправлять мутацию.

#### Scenario: Concurrent modification

- **WHEN** сервер отклоняет PATCH из-за изменения версии
- **THEN** пользователь видит конфликт и возможность перечитать данные, его ввод сохранён, автоматический PATCH с новой expected_version не выполняется

#### Scenario: Retry after network failure

- **WHEN** пользователь повторяет неизменённую логическую операцию создания или редактирования после сетевой ошибки
- **THEN** запрос использует прежний ключ идемпотентности; во время отправки повторное нажатие не создаёт параллельную запись

#### Scenario: Keyboard cancellation

- **WHEN** пользователь открывает форму с клавиатуры и отменяет изменения
- **THEN** запрос записи не выполняется, фокус возвращается к действию открытия, а форма имеет доступные заголовок и подписи полей
