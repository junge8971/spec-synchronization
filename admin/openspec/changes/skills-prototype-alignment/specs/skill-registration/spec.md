## Purpose

Обеспечить последовательную регистрацию навыка с проверкой обязательных данных, сохранением групп фраз и явным восстановлением после частично завершённой серверной записи.

## ADDED Requirements

### Requirement: Four-step registration flow

`/skills/new` SHALL предоставлять шаги «Анкета», «Обучающие фразы», «Подключение», «Проверка», индикатор текущего шага и действия назад/далее. Переходы SHALL сохранять локальный ввод и проверять применимые ограничения текущего шага. Уход с несохранёнными изменениями SHALL требовать подтверждения; восстановление полного локального черновика после перезагрузки не обещается. Данные MUST NOT записываться в URL.

#### Scenario: Backward navigation

- **WHEN** пользователь заполнил анкету и фразы, затем вернулся на первый шаг
- **THEN** данные всех посещённых шагов сохранены, текущий шаг обозначен доступным способом

#### Scenario: Invalid step or leaving the wizard

- **WHEN** обязательное поле некорректно либо пользователь пытается покинуть мастер с несохранённым вводом
- **THEN** показана связанная с полем ошибка без перехода вперёд либо запрошено подтверждение ухода соответственно

### Requirement: Contract-complete questionnaire

Анкета SHALL собирать `name`, `purpose`, `expected_result`, `domain_id`, `zones`, `team_id` и `contact_user_id`. Домен и команда SHALL использовать серверные ID. Контакт SHALL выбираться только из согласованного предметного источника; до его появления финальная отправка SHALL быть недоступна с пояснением. Список участников команды MUST NOT самовольно ограничивать допустимые контакты. `zones` MUST NOT подменяться значением `connection.auth_required`.

#### Scenario: Missing contact source

- **WHEN** обязательный контакт невозможно выбрать из согласованного источника
- **THEN** мастер позволяет подготовить остальные данные, объясняет недоступность сохранения и не подставляет «Вы», случайный UUID или первый элемент стороннего списка

#### Scenario: Valid questionnaire

- **WHEN** пользователь выбрал реальные связи и заполнил обязательные поля
- **THEN** итоговая проверка отображает выбранные значения, а запрос создания использует контрактные поля и wire-значения зон

### Requirement: Phrase groups in registration

Шаг фраз SHALL поддерживать именованные группы, добавление и удаление, разделение фраз переводами строк либо запятыми, счётчики непустых фраз и контрактную валидацию. Имя группы SHALL содержать 1–255 символов; каждая добавленная группа SHALL содержать хотя бы одну непустую фразу длиной 1–500 символов. Пустой набор групп SHALL оставаться допустимым по текущему контракту и не блокироваться лишь на основании демо. Сохранение групп MUST NOT считаться обучением или применением модели.

#### Scenario: Mixed separators

- **WHEN** фразы введены через запятые и переводы строк с пустыми промежутками
- **THEN** счётчик и отправляемый набор содержат только непустые фразы, ошибки указаны у соответствующей группы

#### Scenario: No groups

- **WHEN** пользователь удалил все группы при текущем контракте
- **THEN** мастер показывает нулевой счётчик и не вводит отсутствующее в контракте ограничение на обязательность хотя бы одной группы

#### Scenario: Conflict check unavailable

- **WHEN** API проверки пересечений не согласован или не подключён
- **THEN** сводка явно сообщает, что пересечения не проверены, вместо успешного «Пересечений нет»

### Requirement: Connection and truthful final review

Шаг подключения SHALL собирать поддерживаемый endpoint в структуре `connection`, не смешивая рабочие зоны и требования транспортного подключения. Финальный шаг SHALL показывать анкету, связи, зоны, группы/число фраз, параметры подключения, ошибки и доступный возврат к их редактированию. Проверка заполненности SHALL отличаться от серверных проверок. Действия «Сохранить черновик» для неполных данных и «Отправить на проверку» MUST оставаться недоступными до согласования соответствующих операций; сохранение полной анкеты SHALL называться созданием/сохранением навыка, а не отправкой на проверку.

#### Scenario: Optional connection omitted

- **WHEN** пользователь не указал необязательное подключение и остальные обязательные данные валидны
- **THEN** мастер передаёт предусмотренное контрактом отсутствие connection без вымышленного endpoint и без заявления о готовой реализации

#### Scenario: Final review before lifecycle integration

- **WHEN** пользователь дошёл до итогового шага до появления lifecycle API
- **THEN** видит заполненность и доступные операции сохранения без обещания обучения, токена песочницы или серверного статуса draft/checking

### Requirement: Recoverable non-atomic registration

Создание навыка и запись фраз SHALL считаться разными подтверждаемыми операциями до появления согласованного атомарного API. После подтверждения создания интерфейс SHALL сохранять ID ресурса, получать актуальную серверную версию для записи фраз и не повторять создание при ошибке последующей записи. Для мутаций SHALL использоваться контрактные ключи идемпотентности и версии. Неизвестный исход создания MUST NOT трактоваться как отсутствие ресурса или оправдывать новый ключ неизменённой операции. Полный успех SHALL объявляться только после подтверждения всех требуемых записей.

#### Scenario: Skill created but phrases rejected

- **WHEN** создание подтверждено, но сервер отклонил сохранение групп
- **THEN** UI сообщает о созданном навыке и несохранённых фразах, сохраняет ID и ввод, позволяет открыть карточку или повторить запись групп без второго создания

#### Scenario: Lost create response

- **WHEN** ответ создания потерян и неизвестно, был ли ресурс создан
- **THEN** UI показывает неизвестный исход и повторяет ту же логическую операцию только по согласованным правилам идемпотентности, не создавая новый запрос с новым ключом для обхода неопределённости

#### Scenario: Phrase version conflict

- **WHEN** между созданием и сохранением групп серверная версия изменилась
- **THEN** UI сохраняет локальные фразы и требует разрешения конфликта вместо автоматической перезаписи нового набора

#### Scenario: Completed registration

- **WHEN** сервер подтвердил создание и требуемое сохранение фраз
- **THEN** открывается карточка созданного навыка, реестр отражает серверный результат, а UI не объявляет дообучение начавшимся
