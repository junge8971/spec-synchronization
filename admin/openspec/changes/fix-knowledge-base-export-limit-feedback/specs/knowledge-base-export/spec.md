## MODIFIED Requirements

### Requirement: Full selection CSV export

Экспорт списка SHALL передавать выбранные metadata export_fields в выбранном порядке и полный применённый search. Он SHALL выгружать весь отбор независимо от limit/offset страницы в пределах серверного export_max_rows, не более документированного лимита 10000 при текущем контракте. Пустой выбор SHALL блокировать отправку. UI MUST NOT экспортировать только загруженные строки или молча усекать результат.

При HTTP 422 с кодом EXPORT_LIMIT_EXCEEDED UI SHALL показывать ограничение и предложение сузить отбор даже без такого предложения в сообщении сервера, сохранять выбранные поля и их порядок и не создавать файл или сообщение об успешной выгрузке. UI MUST NOT считать любую другую ошибку HTTP 422 превышением лимита только на основании статуса.

#### Scenario: Export from a later page

- **WHEN** пользователь находится на второй странице и выгружает name/category_code/skill_names
- **THEN** запрос включает применённый отбор и выбранные поля, CSV включает весь серверный отбор, не только вторую страницу

#### Scenario: Server limit exceeded

- **WHEN** сервер отклоняет экспорт из-за превышения лимита
- **THEN** показано ограничение и предложение сузить отбор, частичный файл не объявляется полным

#### Scenario: Limit envelope without supplied advice

- **WHEN** экспорт списка возвращает HTTP 422 с кодом EXPORT_LIMIT_EXCEEDED и сообщением «Mock export exceeds 10000 rows» без предложения сузить отбор
- **THEN** UI показывает ограничение и предложение сузить отбор, сохраняет выбранные поля и их порядок, не скачивает файл и не показывает успешную выгрузку

#### Scenario: Unrelated validation failure

- **WHEN** экспорт списка возвращает HTTP 422 с кодом ошибки валидации, отличным от EXPORT_LIMIT_EXCEEDED
- **THEN** UI показывает эту ошибку без добавления сообщения о превышении лимита или предложения сузить отбор на основании статуса, сохраняет выбранные поля и не скачивает файл и не показывает успешную выгрузку
