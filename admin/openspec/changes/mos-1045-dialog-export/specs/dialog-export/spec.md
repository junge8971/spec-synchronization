## Purpose

Обеспечить полную серверную CSV-выгрузку диалогов и сообщений по выбранному охвату, не подменяя её частичным экспортом загруженной страницы.

## ADDED Requirements

### Requirement: Export remains blocked without a dedicated contract

До согласования отдельного export-контракта UI MUST NOT отправлять запросы на придуманный endpoint, собирать CSV из страниц поиска или объявлять выгрузку успешной. Если действие экспорта показано, оно SHALL быть недоступным с видимым объяснением. Завершение этого состояния MUST NOT считаться реализацией полной MOS-1045. Метод, wire-схема, периоды, колонки, лимиты и способ доставки SHALL быть приняты до реализации следующих требований.

#### Scenario: Only dialog PDF is available

- **WHEN** доступен только контракт диалогов v1.0, исключающий экспорт
- **THEN** рабочая выгрузка не предлагается, локальный CSV и фиктивное задание не создаются

### Requirement: Export supports three explicit scopes after agreement

После contract gate UI SHALL различать весь применённый серверный отбор, явно отмеченные chat_id и один диалог карточки. Выгрузка всего отбора SHALL включать результаты за пределами загруженных страниц. Правила пересечения IDs, selection и отдельного периода SHALL следовать принятому контракту и объясняться в форме, а не молча отбрасывать выбранные строки. Неприменённый draft MUST NOT попадать в экспорт.

#### Scenario: Full selection spans multiple pages

- **WHEN** в реестре загружено 25 строк, а серверный отбор содержит больше
- **THEN** режим всего отбора запрашивает полную серверную выгрузку, не файл из 25 строк

#### Scenario: Export from a card

- **WHEN** сотрудник выбирает выгрузку текущей карточки
- **THEN** охват однозначно ограничен её chat_id и не наследует случайные отметки реестра

### Requirement: Row selection has an explicit boundary

После согласования поведения отметки SHALL идентифицировать строки через chat_id. Действие «Отметить показанные» SHALL затрагивать только показанные строки и MUST NOT обещать выбор всего серверного результата. Правила сохранения/очистки отметок при смене отбора и сортировки SHALL быть согласованы до включения экспорта; интерфейс SHALL явно показывать фактическое число отмеченных диалогов.

#### Scenario: More results than visible rows

- **WHEN** пользователь отмечает показанные строки при наличии следующей страницы
- **THEN** отмечены только показанные chat_id, а режим всего отбора остаётся отдельным действием

### Requirement: CSV options follow the accepted format

После gate форма SHALL поддерживать период, режим «строка на диалог»/«строка на сообщение», контрактные колонки и флаг добавления параметров в конец CSV. UI MUST NOT придумывать коды колонок или считать HTML-демо схемой файла. Состав, порядок, quoting, переносы строк, кодировка и защита от spreadsheet formulas SHALL соответствовать принятому CSV-контракту. Параметры SHALL быть отделены от строк данных по согласованному формату без несогласованного раскрытия чувствительных критериев.

#### Scenario: Message format

- **WHEN** выбран режим строки на сообщение
- **THEN** серверный файл содержит сообщения по согласованному составу колонок и порядку, а не сводные строки диалогов с другим названием файла

### Requirement: Export progress and failures are truthful

UI SHALL различать запрос, формирование и готовность результата согласно принятому sync/async-контракту. Превышение лимита, ошибка сервера и ошибка скачивания SHALL иметь понятное состояние без ложного успеха. JSON-ошибка MUST NOT сохраняться как CSV; частичный или усечённый файл MUST NOT выдаваться за полную выгрузку. Повтор/отмена SHALL следовать контракту, без заранее выдуманного job API.

#### Scenario: Oversized export

- **WHEN** сервер отклоняет объём по согласованному лимиту
- **THEN** UI объясняет ограничение и сохраняет параметры для изменения, не выгружая только первые доступные строки

#### Scenario: Error body instead of file

- **WHEN** вместо CSV получен JSON-envelope ошибки
- **THEN** отображается ошибка, файл с расширением csv не создаётся и успех не показывается
