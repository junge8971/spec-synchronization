# Design

## Context

Мотивация и подтверждённый scope приведены в [proposal.md](proposal.md); наблюдаемое поведение определяют [delta оболочки](specs/control-center-shell/spec.md) и [delta жизненного цикла](specs/skill-lifecycle/spec.md). Дизайн нужен для двух владельцев UI и согласования с активными MOS-2397 и MOS-909, а не для введения новой архитектуры.

Исследование выполнено на `56741d4`. Описания и DoD MOS-2467 и MOS-2472 прочитаны в открытых вкладках Jira; комментариев и вложений нет. Пользователь отдельно подтвердил возврат только справочников, скрытие всего lifecycle-блока с сохранением статуса и переключателя и отсутствие отдельного условия для Т. Пользовательские сценарии приложения в браузере не запускались.

## Goals / Non-Goals

**Goals:**

- Использовать существующие метаданные видимости и композицию владельца карточки, сохранив FSD и публичные API слайсов.
- Проверить конечное сочетание видимости: справочники вернулись, пять пунктов остались скрытыми, lifecycle отсутствует, статус и переключатель сохранены.
- Отделить изменение точки подключения lifecycle от коррекции матрицы его сохранённой реализации.

**Non-Goals:**

- Удаление модуля справочников или общей lifecycle-feature, изменение их API и мутаций, отдельного ревью, регистрации или глобального переключения.
- Новые экраны, альтернативное размещение lifecycle-команд, флаги окружения, hostname-политика, серверные настройки видимости или зависимости.
- Переписывание существующих changes, синхронизация основных specs или архивирование в рамках этого proposal и последующей реализации UI.

## Decisions

### 1. Вернуть справочники через их descriptor

При реализации удалить только `navigation.hidden: true` из корневого descriptor `/dictionaries`. Отсутствующий признак уже означает видимый пункт. Группа, иконка, `matchPaths`, карточка, вкладки и регистрация сохраняются; общие фильтры sidebar и существующая проверка доступа не меняются.

Альтернатива с исключением `/dictionaries` в JSX дублирует данные маршрута. Новый конфиг или `hidden: false` не нужны: штатное отсутствие флага уже поддерживается и покрыто тестами. Отмена всех меток MOS-2397 вернула бы лишние пять пунктов и выходит за подтверждённый scope.

### 2. Убрать lifecycle в точке композиции карточки

При реализации убрать `SkillLifecycle` из `SkillDetails` вместе с его импортом и ставшими неиспользуемыми локальными чтением `useSession` и импортом. Шапка, `SkillGlobalToggle`, вкладки, `Activity`, snapshot данных и параметры `useSkillDetailsQuery(skillId, true)` остаются. Обработчик обновления глобального переключателя и его собственная привязка к сессии не меняются.

Реализация `features/skill-lifecycle`, её публичный экспорт, матрица команд и общий status-клиент сохраняются. Не добавляется другое место для кнопки обновления, переходов или диалога. Сохраняются существующие повтор чтения при ошибке и серверное наблюдение; уход отдельной кнопки «Обновить состояние» входит в скрытие всего блока.

CSS-скрытие сохраняло бы смонтированные hooks, диалоги и обработчики. Ранний `return null` внутри feature менял бы её поведение для всех потребителей и смешивал отсутствие блока на странице с контрактом самой feature. Удаление в композиции ограничивает изменение одним владельцем и не затрагивает остальные lifecycle-операции.

### 3. Одинаковая композиция без политики по контуру

Применить две статические правки во всех режимах. Т — место развёртывания согласно уточнению пользователя. API base URL, текущий выбор mock/real и существующие проверки доступа не управляют этим изменением и остаются прежними.

### 4. Явно согласовать требования с активными changes

- В активном `mos-2397-hide-menu-sections` требование `Menu-only section visibility` скрывает шесть пунктов. В текущем основном `control-center-shell` этого требования ещё нет. Поэтому delta этого change использует **ADDED** с тем же именем и полной актуальной политикой из пяти скрытых пунктов и видимых справочников. Это новое решение заменяет только часть MOS-2397 о справочниках; остальные его уточнения оболочки сохраняют силу.
- При последующей отдельно запрошенной синхронизации/архивировании обеих работ SHALL сохраняться порядок решений: сначала baseline MOS-2397, затем актуальная политика MOS-2467. Если baseline уже синхронизирован, одноимённое требование нужно обновить как существующее, не создавать дубль и не возвращать шесть скрытых пунктов. Эта механическая сверка состава основных specs не входит в реализацию UI; ранее созданные артефакты сейчас не переписываются.
- Основная `skill-lifecycle` требует шкалу и команды в карточке. Delta изменяет четыре связанных требования целиком: подключение lifecycle, шкалу, одиночные команды и уведомление. Обязательность показа в карточке снимается, но безопасность сохранённой общей возможности переходов не ослабляется. Требование `Read-only current skill status` остаётся без изменений.
- `mos-909-restore-approved-lifecycle-actions` исправляет матрицу сохранённой feature и сейчас также требует её присутствия в карточке. Его исправление матрицы не выполняется и не считается завершённым этим change; его прежние утверждения о mounted-карточке уступают новому решению MOS-2472. При отдельном возобновлении MOS-909 потребуется сверить его тестовый target с текущим деревом и сохранить отсутствие lifecycle в композиции. Для реализации данного change выполнение MOS-909 не является prerequisite.

### 5. Проверить композицию через существующие unit/component-инструменты

- В `app/application/model/reference-dictionaries-config.test.ts` сохранить утверждения о маршрутах, basename, крошках и вкладках; заменить ожидание скрытого пункта явной проверкой его видимости.
- В `app/application/model/ab-testing-config.test.ts` обновить точный список скрытых путей с шести на пять для mock/real и отдельно подтвердить отсутствие скрытия справочников. Не ослаблять проверку полного списка.
- В `app/widgets/navigation/ui/application-navigation.test.tsx` использовать актуальные descriptors приложения для существенного сценария: доступные справочники видимы, пять остальных пунктов отсутствуют, реестр и карточка подсвечивают справочники. Сохранить generic-тесты обработки `hidden`, пустых групп и `false`/отсутствующего флага; синтетический скрытый пункт не является актуальной конфигурацией приложения. Проверить mobile-закрытие и клавиатурную доступность.
- Добавить `app/widgets/skill-details/ui/skill-details.test.tsx` у владельца композиции. Проверить загруженную карточку, смену вкладки и повторное чтение в другой статус: lifecycle отсутствует и не инициирует мутацию/toast, статус шапки отражает данные. Для prod/disabled проверить сохранение настоящего глобального переключателя и его штатного действия с корректным ответом, без замены его инертной заглушкой.
- Граничные случаи карточки: ошибка первого чтения с повтором и ошибка обновления при ранее полученных данных. Сохраняются прежние состояния ошибки и ограничения глобального переключателя; исчезнувший блок не возвращается. Test fixtures и именованные типы при необходимости принадлежат ближайшему владельцу и размещаются по соглашениям проекта.

## Risks / Trade-offs

- [Возврат остальных скрытых пунктов при слишком широкой отмене MOS-2397] → одна правка descriptor и точная проверка пяти скрытых путей плюс component-сценарий полного меню.
- [Удаление статуса или глобального переключателя вместе с lifecycle] → изменение только точки подключения `SkillLifecycle`; отдельные проверки шапки и действующего переключателя.
- [Потеря наблюдения за серверным статусом или восстановления после ошибки] → сохранить query с `observeStatus=true`, snapshot и `Activity`, проверить последующее чтение и ошибки у владельца композиции.
- [Повторное включение lifecycle либо откат меню при применении старых plans] → актуальный приоритет требований и граница MOS-909 описаны выше; исторические tasks не отмечаются выполненными.
- [Нет отдельного ручного обновления из lifecycle] → это часть согласованного скрытия всего блока; новое действие не добавляется, существующие механизмы чтения и повтора сохраняются.
- [Локальные проверки не подтверждают стенд] → отчёт отдельно перечисляет unit/component и статические проверки; browser/E2E и состояние развёрнутого Т не объявляются проверенными.

## Migration Plan

Миграции данных и backend не требуются. После отдельного запроса реализации изменить descriptor и композицию, выполнить регрессии и обязательные проверки из tasks. Развёртывание использует обычную сборку без новых параметров.

Откат состоит в возврате флага скрытия справочников и прежнего подключения lifecycle в композиции. Восстановление бизнес-кода, API или данных не требуется. Синхронизация основных specs и архивирование выполняются отдельно с учётом порядка решений выше.
